## 実行する本番コード

- `DreamforgeUi.CacheSecureText` とそのキャッシュフィールドを、変更せずに抽出してコンパイルする。
- `DrawSecurePrompt` の実際の `CacheSecureText(...)` 呼び出しを使う。日替わり倍率の渡し方も本番と同じ。
- `HostAuthority.ProcessSpawns` の `pressureMult` / `mult` の式、および `HostAuthority.Waypoints.RollWaypointNightmare` を変更せずに抽出する。
- 確率曲線・装備倍率・夢の圧・道標・乱数・悪夢化抽選は、本物の `SodRpg.Core` を参照する。
- 参加者は1人。ホストのパーティ装備倍率の最大値はその1人の `GearChanceMult` になる。UI のセッション状態、ホストの保持状態、敵の型判定、色タグだけを狭い代替 API に置き換える。
- 通常敵・エリート各20,000回の固定シード抽選を実行し、独立に計算した期待確率との差が2パーセントポイント以内であることも各ケースで確認する。抽選は描画前の一般的な悪夢化経路を対象とし、変種・宿敵の優先分岐は含めない。

既存の Core の friend assembly を利用するため、実行ファイルの assembly 名は `SodRpg.Core.Tests` とする。既存テストプロジェクトと出力先は共有しない。

## 判断したこと・次工程への制約

- ここでは再現だけを行い、本番コード・通信形式は変更しない。
- 装備倍率のケースは「正確な確率」または「既知の圧・道標を反映した最低確率」のどちらも許容する。同期方式の選択を再現工程では確定しない。
- 表示用計算を複製せずに本番 UI の文字列を検証する。抽選側の期待値を独立に計算し、実際の抽選結果でも裏付ける。共有計算関数への切り出しは未実施。
- 入力不変での文字列再利用と、道標・同期済み圧だけの変更時の更新を区別して確認する。毎フレームの確保量は測定しない。
- 抽出対象の宣言・引数・ヘルパーを次工程で変更する場合、ハーネスの抽出方法と代替 API も変更に合わせる必要がある。抽出失敗・ビルド失敗を再現成功として扱わない。
- 旧版相手との省略可能フィールドの互換性は未検証。通信を追加する修正を選ぶ場合、次工程で確認する。
