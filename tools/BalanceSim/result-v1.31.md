# Dreamforge RPG 星振りシミュレーション（v1.31）

## 条件と仮定

- 新規プロフィールに星経験 StarProgression.TotalXpForPoints(300) を与え（ポイント 300、図鑑ボーナスなし）、節目 0/50/100/150/200/250/300 まで `Rules.AddTalentRank` / `Rules.SetKeystone` で実際に購入します。計算はすべて `Build.Compute` の実経路です。
- ツリーは実行時に登録されているもの（`HeroSigils.TreeFor`）をそのまま使い、authored 星群の追加・差し替えにコードの変更は要りません。対象は HeroStarRoutes に現れる旅人 9 人（Vesper・Lacerta・Cetus・Yubar・Husk・Mist・Nachia・Aurena・Bismuth）。
- 熟練度は最初から満タン（撃破数 1,000,000 → Mastery.Level=10、核の前提 HeroSigils.KeystoneMastery=3 を充足）。星の払い戻しはせず、節目をまたいで同じ割り振りを続けます。
- 夢のレベルは入力仮定 --dream-level=30（上限 30）。300ポイント（星経験 285,900）に要する遊戯量を考えると、終盤の節目では夢レベルが天井に張り付く想定です。
- 戦略は3種。能力値優先＝プロキシ増分/ポイントが最大の購入を毎回選ぶ。記憶特化＝星数最大の星群（authored 星群がなければ記憶ルート）を登録順で完成させ、閉じている間は核以外の最安のつなぎ星を買い、完成後は能力値優先。核先行＝核の前提（6ランク＋到達）を最安で満たして `Rules.SetKeystone`、残りは能力値優先。
- 力の代理値（プロキシ）は本体が悪夢化抽選の強さに使う式（攻撃力%か魔力%の大きい方＋最大HP%の半分）をクランプ前のまま使います。戦闘の出力ではありません。仕掛け・連携・固有効果は条件付きのまま Host へ渡されるため、件数（効果の幅）のみ別掲します。
- 夢の圧は `DreamPressure.ForPlayer(夢Lv, 使用ポイント).WithRunModifiers(深度)` の実式、深度の効果は `DreamDepth` / `Nightmares` の実式です。ゲームの定数は一切変更していません。
- 乱数を使わない決定的なシミュレーションです（--seed は使いません）。
- シミュレーション実行時間（レポート整形・ファイル書込・ビルドを除く）：219.495 秒。

## コアAPIの不足と測定の限界

- 戦闘の出力・勝率・時間あたりの発動率の公開シミュレーションAPIはありません。プロキシは Build の能力値だけから出しており、仕掛け・連携・固有効果・核の実際の価値は件数でしか見えません。
- 選択の星は両選択肢を評価して良い方を買いますが、実際のプレイヤーの好み・装備との相互作用はモデル外です。
- 夢レベルと星ポイントの対応は本体のプレイ速度に依存するため、ここでは夢レベルを入力仮定として固定し、感度表で補います。
- 悪夢化の抽選・接頭効果の戦闘的影響は行わず、`Nightmares.Chance` / `DepthBonus` の式と装備倍率の範囲のみ示します。
- authored 星群の登録状態は実行時のものです。この表の「出自」列で確認できます。

## 係数の提案（手動考察）

この節だけは生成後に手で書いた考察です。上の表の数値に基づきますが、ゲームの定数はどれも変更していません。数値は3戦略ともほぼ同じだったため、特に断らない限り能力値優先の表の値を使います。

### 1. まず前提：300ポイントの約3割が今は使えない

300ポイント目標時点での平均使用ポイントは 212.2（残り 87.8、29.3%）。振れ方は Vesper 191 〜 Lacerta 220。使えない理由はコアの C15 割り当て検証が実効のない購入を恒久却下するためで、内訳は (a) 夢の輪の守り・防御の星が既に強い同種連携に支配される、(b) エッセンス枠の星が上限1で飽和、(c) 例えば `h.vesper.route.charge.2` は authored 機構の検証器に「Native memory sources require a verified non-movement identity」で拒否され、charge ルート全体が閉じる、の3種です。9旅人の authored 星群が登録された後はこの表が全部入れ替わるため、係数の本調整はその後に行ってください。この節の提案は「満額が使えるようになった場合」の目安です。

### 2. DreamPressure の星係数（0.0025 / 0.00125）

現行では星300ポイント満額で敵HP ×1.75・被ダメージ ×1.375。これは深度5帯そのもの（HP ×1.75・被ダメージ ×1.40）です。深度には部屋 +10・レア運・覚醒・星XP倍率（×2.00）の報酬側が付くため、星の圧が深度帯いっぱいに達すると「深度を上げる意味」が圧の面から消えます。提案は星のHP係数を 0.0025 → 0.0020、被ダメージ係数を 0.00125 → 0.00100 に下げ、満額時を HP ×1.60・被ダメージ ×1.30（深度5の約9割）に収めることです。実際に使える平均 212 ポイントでは現行でも HP ×1.53・被ダメージ ×1.27 なので、当面は体感への影響が小さく、満額が使えるようになった後の保険として機能します。

### 3. 費用対効果の落ち込みと CostForPoint の傾き

平均プロキシは 0→50 で +27.78、100→150 で +1.67、150→200 で +1.11、250→300 で +0.00。最後の100ポイント（星XP 155,300、総必要XP 285,900 の 54.3%）が買う力は平均 +1.11 で、最初の50ポイント（XP 10,150）の4%です。一方で `StarProgression.CostForPoint` は 6k+50 の線形です。効果が最初の50ポイントに集中し費用は後半に跳ね上がるため、提案は2通りです。(a) 力を上げる側：上限付近の星（ルート頂点・夢の輪・星群の Notable）の実効値を星データ側で引き上げる。(b) 費用を平らにする側：`CostForPoint` の傾き 6 → 8（300個目 1,850 → 2,450、総XP 285,900 → 375,900）で後半の1ポイントあたりの期待値の落ち込みを緩くする。効果の伸び方自体が問題なら (a)、遊戯量の割に「伸びた実感」が出ないのが問題なら (b) です。

### 4. 夢レベル項と FreeDreamLevels は現状維持

夢Lv30・深度0では、レベル項が +0.625（HP）/ +0.30（被DMG）、星項は満額で +0.75 / +0.375。レベルは天井30で止まり星は300まで伸びるため、星:レベル ≈ 1.2:1 の構図はそのまま維持してよいと読めます。`FreeDreamLevels = 5` の免除も序盤の急上昇を正しく抜いています。変更不要です。

### 5. HP系とDMG系の比率は整合している

星項は 2:1（0.0025:0.00125）、レベル項は 2:1（0.025:0.012）、深度項は 1.875:1（0.15:0.08）。300ポイント時のプレイヤー側の伸びは平均で攻撃力% 12.7・魔力% 16.0・最大HP% 21.8・防御 18.0 と、耐久も攻撃も同程度に伸びています（プロキシ平均 35.22 = 最大攻/魔 24.33 + HP% の半分 10.89）。敵HP ×1.75 に対して被ダメージ ×1.40 の深度帯とも整合します。比率の変更は不要です。

### 6. 悪夢化の装備倍率は星図の影響が小さい

`Nightmares.GearChanceMult` は300ポイント時点で全旅人・全戦略 1.05〜1.12。上限 1.5 の半分以下で、星図だけでは悪夢化率を大きく動かせません。装備の強化と合わせて初めて効く設計のまま、変更不要です。

### 7. 実効圧の読み方（注意）

`DreamPressure` は `Build.SpentStarPoints`（実際に使ったポイント）を見るため、使えないポイントは圧を上げません。夢Lv30・深度0では、満額300の名目 HP ×2.38 に対し、実際に使える平均 212 ポイントでは HP ×2.16 が実効値です。深度5を合わせると名目 ×4.16 に対し実効 ×3.77。上の「夢の圧」の表は式の掃引であり、現在のコンテンツでは後半の行は名目値であることに注意してください。
