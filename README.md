# Shape of Dreams 大規模RPG化MOD 開発計画書

**Ver 1.0**    2026年10月1日

本計画は、キャラクター育成、戦闘、装備、探索、報酬、協力プレイを一つの進行構造として再設計し、長期的に遊べるRPG体験をShape of Dreams上に構築するための計画書である。マルチプレイ対応はユーザー指定の必須要件であり、初期設計と最初のプレイ可能な版から前提に置く。

## 0  Ver1.0 の位置づけ

### Ver1.0 が意味すること

v0.1 は方針の「たたき台」だった。Ver1.0 は、**計画書として実装に着手できる状態**を指す。具体的には次の四点を満たす。

1. 方針が決まっている。恒久化の範囲、死亡時の損失、既存星座との関係、装備枠、育成差、取引と途中再開、公開対象を第21章で決定済みにした。
2. ゲームの面白さを設計として書いてある。何が楽しさの源か、その瞬間をどの仕組みで作り、どう測るかを第2章と第19章に置いた。
3. 各システムに初期値と代表例がある。数値は付録B、装備・専門化・敵・ボスの代表例は付録Aにある。
4. 完成を判定する基準がある。段階ごとの通過条件と、遊びの質を測る指標を第18・19章と付録Dに置いた。

実装、実機試験、性能測定は行っていない。ゲーム本体のアセンブリと現行の係数も確認していない。したがって、本書の数値は次の区分のいずれかである。

## 1  企画の到達点と設計原則

### 背景

本作では、ビルドの組み替え、Travelerごとの個性、協力時の相互作用がゲーム体験の核になっている。公式説明でも、MemoryとEssenceの組合せ、キャラクター固有能力、最大4人の協力プレイが示されている。これらを大規模RPG化の基盤として生かす。［S1・S2］

企画の起点となるプレイ上の観察は、特定構成への偏り、後半の難度上昇、戦闘の見づらさ、長時間プレイ時の重さである。加えて、星座による恒久成長の一部が周回内レベルと固定加算に依存し、レベルが上がりにくい局面で敵の成長に追いつかなくなるという問題意識がある。これはユーザー本人が最新版でも感じている点であり、現行バージョンの全計算式を検証した結論ではない。

### 目的

成長によって自分のキャラクターの戦い方が深まり、冒険ごとの発見が次の挑戦へつながり、複数の構成と協力の組合せで高難度へ到達できるゲームシステムを作る。通常攻撃、装備、経験値、星座は全体を構成する要素として扱い、探索や経済、保存、表示、性能まで含めて整合させる。

### 目指すプレイ体験

プレイヤーは拠点で育成方針と探索先を選び、遠征中に得たMemory、Essence、イベント効果によってその場の戦術を変える。帰還後には装備素材、研究、物語や地域の進行が残り、次の冒険で試せる選択肢が増える。長期育成で戦い方の軸を持ち、周回ごとの偶然性で完成形を更新できる体験を目指す。

後半の挑戦では、敵の数値が増えるだけでなく、優先して倒す敵、守る対象、地形、攻撃の読み取りが変わる。強い装備は成功率を高めるが、回避や位置取り、役割の組合せも成果に結びつく。長く遊んだ結果として画面と処理が破綻する状態を、強さの到達点にはしない。

### 設計原則

- 成長の手応えを複数の経路で作る。基礎能力の改善に加え、新しい行動、構成の転換、探索先の開放を報酬とする。

- キャラクターの個性を守る。共通装備と共通成長が同じ最適解へ集約しないよう、固有能力との関係と代償を設計する。

- 失敗しても次の選択が生まれる。すべてを持ち帰れる設計にも、長時間の成果をすべて失う設計にも寄せず、損失と救済を事前に説明する。

- 強さの内訳と発動条件を見せる。隠れた乗算、説明と異なる発動、予兆の埋没を避ける。

- ソロと協力を両立する。支援型でも一人で進行でき、協力時は相互作用が増えるようにする。

- 保存と性能を早期に検証する。大量のコンテンツを作る前に、長時間プレイと育成データを支える土台を確かめる。

- 遊びの質を測ってから増やす。装備や地域の数を増やす前に、少数の代表例で第19章の指標を満たす。

### 成功と判断する状態

一つの構成で勝てることに加え、異なる戦い方でも段階的に進めること、敗北理由を理解できること、帰還時に次の目標が見えることを確認する。数値だけ強化して短時間で全敵を処理する状態は、成功条件の一部を満たすにとどまる。

初回公開の完成条件は、複数人で準備、遠征、帰還、各自の保存までの一連の体験を遊べることとする。装備数やステージ数は、その体験が成立した後に増やす。

## 2  面白さの設計

本章はVer1.0で最も重く書き足した章である。数値やシステムは、ここで定める「楽しさの瞬間」を作るための手段として位置づける。

### 面白さの五つの柱

| 柱 | 作りたい瞬間 | 主な仕組み | 避けたい状態 |
| --- | --- | --- | --- |
| 一 読み合いのある戦闘 | 敵の予兆を読んで避け、そこへ反撃を決める | 予兆の規則、回避と防御の見返り、通常攻撃の拡張 | 画面が埋まって予兆が見えない。数値で押し切れる |
| 二 構成を発見する | 拾ったものが噛み合い「これは強い」と気づく | Memory・Essence・装備のタグ互換、図鑑、狙い系統 | 最適解が事前に決まっている。必要部品が出ない |
| 三 帰還を決断する | 「あと一戦行くか、持ち帰るか」で迷う | 安全地点、未確保報酬、遺失物ノード、帰還画面 | 迷う余地がない。失敗が理不尽に見える |
| 四 自分の戦い方ができる | 「このキャラはこう戦う」と言える | 専門化、刻印、固有能力の保持 | 全員が同じ能力値ツリーを歩く |
| 五 協力で化学反応が起きる | 仲間の行動が自分の行動を強くする | 状態の受け渡し（印・拘束・障壁）、共鳴、役割の流動性 | 人数分の火力が足されるだけ。役割が固定される |

### 報酬のリズム

楽しさは、小さな満足を一定間隔で受け取りつつ、大きな節目を期待できる時に続く。下の表は、満足を与える間隔の設計値である。

| 時間幅 | 与えるもの | 設計の狙い |
| --- | --- | --- |
| 10秒 | 予兆を読んだ回避、反撃の命中、撃破の手応え | 操作そのものが気持ちよい |
| 90秒以内 | レベルアップ、素材、装備の拾得、短い演出のいずれか | 立ち止まらず前へ進める |
| 5分以内 | 分岐の選択、構成の変化、エリート戦の勝利 | 判断の機会を絶やさない |
| 1遠征（15〜60分） | 構成の完成、ボス撃破、帰還判断の結果 | 遠征ごとに物語がある |
| 3〜5遠征 | 専門化ノード、製作の完成、図鑑の新しい組合せ | 次の目標が見える |
| 20〜30時間 | 地域の解放、固有品、エンドゲームの扉 | 長期の到達点がある |

後半の成長が鈍る局面でも、「90秒以内に何かが起きる」を守る。レベルアップの間隔が延びた時は、ノード到達ごとの選択報酬が代わりを担う（第7章）。

### 一遠征の緊張曲線

一つの遠征は、一定の高さの緊張が続く形にしない。圧力が高まる局面と休める局面を交互に置く。

| 区間 | 内容 | 緊張 | 目的 |
| --- | --- | --- | --- |
| 導入 | 易しい戦闘、最初の選択報酬 | 低 | 操作と構成の確認 |
| 圧力 | 通常戦闘とイベントの連続 | 中 | 構成を作りながら消耗する |
| 安全地点 | 休憩、整理、帰還判断 | 休息と緊張 | 続行か帰還かの決断 |
| 山場 | エリート戦、任意の試練 | 高 | 構成の試験と大きな報酬 |
| 準備 | ボス前の補給と最後の選択 | 中 | 苦手の補強、覚悟 |
| 決戦 | 地域ボス | 最高 | 学習して勝つ |
| 余韻 | 結果画面、獲得と次の目標 | 低 | 次の遠征への動機 |

安全地点は標準遠征で2か所に置く。長い遠征では3か所に増やし、遠征の長さに比例して判断の回数も増える。

### 帰還判断の設計

「あと一戦」の迷いは、情報があって初めて面白い判断になる。帰還画面と安全地点の画面には次を表示する。

- 今回確保済みの成果と、未確保の成果（素材、装備、依頼の進行）
- 次の安全地点までのノード数と、そこにいる敵の系統と危険の目安
- 消耗の状態（灯の残り、主要な強化の残り）
- 続行した場合に狙える報酬の系統

迷う余地を作るため、続行の報酬は「同じものがもう一つ増える」ではなく、**今の構成の弱点を補う機会**（たとえば守勢の素材が手に入る節、エリートが落とす固有効果）として置く。

### 失敗を面白くする

敗北は「やり直し」ではなく、「次に試すこと」が見える結果にする。

- 敗北画面に、被ダメージの内訳の上位三つ、予兆を見逃した攻撃、最後の十秒の記録を出す。
- 次の遠征への提案を一つ示す（例：「守勢の素材が不足。防具の強化が効果的」）。ただし提案は強制しない。
- 未確保の装備は消えず、次の遠征で**遺失物ノード**として現れる。これを取り戻す試練が、敗北から次の挑戦への橋になる（第5章）。
- 地域ボスには、拠点から直接再挑戦できる「ボス挑戦」を用意し、敗北から再挑戦までの手間を減らす。
- 協力プレイでは、倒れた味方を蘇生する機会が緊張と助け合いを生む。全滅の場合も、個人ごとの確保分は残る。

### 発見の楽しさを守る

図鑑は、効果説明、発見済みの組合せ、取得先の傾向を記録する。未発見の組合せは「？」で示し、タグの手掛かりだけを見せる。完全な攻略表を最初から公開せず、設定で手掛かりの量を選べるようにする。

構成が噛み合った瞬間を強調する。たとえば二つの効果が相乗した時、画面に短く条件の達成を示し、戦闘ログで内訳を確認できるようにする。「何が起きたか分からないが強い」ではなく、「自分で作った」と感じられるようにするためである。

### 協力で生まれる楽しさ

協力の面白さは、役割を宣言して分担することではなく、**他人の行動が自分の行動を変える**ことにある。そのため、協力には次の三つの仕組みを置く。

- **状態の受け渡し**：印、拘束、障壁、加速、挑発、露出の六つを共通の状態とする。仲間が付与した状態を、自分の装備や専門化が参照して強くなる（付録A）。
- **共鳴**：二人以上が同じ時間窓で条件を満たした時に起きる追加効果。一人でも発動できる弱い版を併せ持つ。
- **役割の流動性**：固定の「タンク・火力・回復」にせず、構成によって誰でも敵を集め、弱体化し、攻撃機会を作れる。

ソロでは、同じ状態を自分で作る弱い版（自己付与）で進行できる。協力の効果が、ソロで進めない壁にならないようにする。

### 面白くない状態を許さない

次の状態を検出したら、コンテンツの追加より先に修正する。検出の方法は第19章に置く。

- 一つの構成の使用率が突出し、他の構成が選ばれない。
- 敗北しても理由を答えられない。
- 帰還判断で迷う余地がなく、常に続行か常に帰還が最適である。
- 戦闘中に予兆が見えない、あるいは操作に関係なく勝敗が決まる。
- 整理や管理の時間が戦闘より長い。
- 簡単な場所の反復が最も効率的である。

## 3  現行システムの理解と問題仮説

### 既存の面白さと発展の余地

Memoryは戦闘能力、EssenceはMemoryに装着して性質を変える要素として説明されている。Traveler MemoryとIdentity Memory、恒久的なConstellation、Way of Starsも存在する。Way of Starsには物語、イラスト、新しい結末につながる進行が含まれており、既存の恒久要素を単純な能力値ツリーだけと捉えない。［S1］

難度設定、Lucid Dreamの修飾条件、周回継続、Limboは異なる仕組みとして扱う（Traveler MasteryがWay of Starsへ拡張されたことはS1で確認でき、Limboの存在と解放条件は二次資料で確認できた。いずれも係数は未確認。付録B0）。通常進行の難しさと無制限に近い挑戦の限界を同じ問題として調整すると、序盤が過度に簡単になったり、報酬設計が破綻したりする。まず各モードの実測を分ける。［S2・S3］

| 観察された課題 | 考えられる原因 | 最初に確認するもの | 本書の対応 |
| --- | --- | --- | --- |
| 一部の構成へ偏る | 乗算や連鎖の恩恵が特定系統に集中 | 発動回数、実効火力、必要部品、成立時期 | 加算枠と乗算枠の上限（第7章）、連鎖の世代上限（第8章） |
| 後半で成長が鈍る | 経験値ペース、段階上限、敵成長の不整合 | 区間別レベル増分、敵耐久、撃破時間 | 周回内レベルに依存しない成長層（第6章）、ノード報酬（第7章） |
| 攻撃が見づらい | 味方演出、敵予兆、数値表示の重なり | 被弾場面の録画と表示設定の比較 | 予兆の優先規則と演出調整（第8・13・15章） |
| 長時間で重くなる | 召喚・弾・履歴・イベント数の蓄積 | 経過時間別の処理量、メモリ、通信量 | 管理対象の上限と計測（第15章、付録C） |

### 星座の問題をどこまで断定できるか

過去の非公式データには、特定レベル到達時に加算する星、各レベルで能力を加算する星が確認されている。前者は条件を満たした後に伸びず、後者もレベルが上がらなければ新たな増分を得られない。ただし固定値の加算自体が必ず弱いわけではなく、基礎値・他の補正・敵の成長との比率で価値が変わる。［S4］

したがって「星座を一律に割合強化へ変更する」は採用しない。恒久星の取得段階、周回内Heroレベル、Masteryを区別し、現在の効果・上限・適用順序を抽出する。その上で、どの時点で通常の成長経路が機能しなくなるかを検証する。古い係数や最大ランクを最新版の値として採用しない。

S4は旧版を含む非公式資料である。星座の構造を考える補助資料に限定し、現行値の仕様根拠には使わない。

公開情報で現行の数値を整理した結果（付録B0）でも、この仮説は**数値で検証できず、判定保留**である。星の効果量、最大ランク、レベル上限、経験値曲線、敵の成長式が、いずれも確認できなかったためである。支持寄りと反証寄りの傍証が両方あるため、確認項目（付録B10）の抽出が済むまで、再設計の要否を決めない。

本書は、この問題に二段で対処する。第一に、既存の星座は変更せず、MOD独自の成長を**周回内レベルに依存しない層**として加える。レベルが上がらない局面でも成長の手応えが残るため、星座の問題が顕在化しても体験が止まらない。第二に、現行値の抽出後に、次の基準で星座の再設計を検討する（第6章）。

## 4  要求範囲とシステムの責任

### プレイヤー向けの必須要件

- 途中で帰還する選択に意味があり、再開時に進行と所持品が正しく戻る。

- マルチプレイを初期設計と最初のプレイ可能な版から必須とし、ソロと育成差のある協力の双方で同じ進行構造が成立する。

- 説明、戦闘ログ、装備比較によって、強くなった理由と負けた理由を追える。

### 既存要素との関係

ConstellationとWay of Starsは既存進行として尊重し、MOD独自の育成を別層に置く（決定）。重複する能力補正は共通の成長予算に組み込み、二重計上を防ぐ。置き換えが必要と判明した場合は、移行表と返還方針を示してから変更する。公式の物語や報酬を勝手に解放する前提にはしない。

大規模な装備、独自保存、協力同期を同時に導入すると検証範囲が急増する。初期実装は少数の装備・地域・キャラクター構成に絞るが、データ形式と基本ルールは後の全体拡張を受け止められる形にする。

## 5  拠点と遠征をつなぐゲームループ

### 基本の進行

拠点で育成・装備・目標を選ぶ。遠征先でルートと危険度を判断し、戦闘、探索、イベントを通じてその回の構成を作る。帰還時に成果を整理し、装備製作、専門化、地域開放を進める。この循環に、節目のボスや物語条件を置く。

| 局面 | プレイヤーの選択 | 次の局面へ残る結果 |
| --- | --- | --- |
| 出発前 | キャラ、装備、依頼、危険度、狙い系統、遠征の長さ | 初期の戦い方と狙う報酬 |
| 探索中 | 分岐、任意戦闘、イベントの代償 | 一時強化、素材、遠征リスク |
| 帰還判断 | 続行、ボス挑戦、安全帰還 | 保全される成果と未回収報酬 |
| 拠点整理 | 保管、分解、製作、再配分 | 次の遠征の選択肢 |
| 節目達成 | 地域解放、専門化、物語進行 | 新しい敵・報酬・挑戦条件 |

### 遠征の構造

遠征は、ノードを順に選んで進む地図形式とする。長さは三段階から選び、同じ経済につなぐ。

| 長さ | 目安の時間 | ノード数 | 安全地点 | 最終目標 |
| --- | --- | --- | --- | --- |
| 短 | 15分 | 6 | 1（第3ノード） | 守護体（小ボス） |
| 標準 | 35分 | 10 | 2（第4・第8ノード） | 地域ボス |
| 長 | 60分 | 14 | 3（第4・第8・第12ノード） | 地域ボスと追撃戦 |
| ボス挑戦 | 約8分 | 2（補給、ボス） | 0 | 地域ボス（一度遭遇した地域のみ） |

ボス挑戦は、ボスの行動を学ぶための再挑戦用の短い遠征である。素材の倍率は0.5、エピックの救済の進行と抽選は対象外とし、反復の稼ぎの手段にしない。補給ノードは回復と整理のみで、確保の対象となる報酬はない。初回撃破の確定報酬（エピック1個）、進行、専門化のポイントは通常と同じに得られる。遺失物は持ち越され、分解されない。

ノードの種類は次のとおりである。時間は設計値である。

| 種類 | 内容 | 主な報酬 |
| --- | --- | --- |
| 戦闘 | 通常の敵群 | 経験値、素材、装備 |
| エリート | 接頭効果を持つ強敵 | 固有効果を持つ装備の可能性、系統素材 |
| イベント | 選択を迫る出来事 | 一時強化、または代償付きの報酬 |
| 発見 | 素材の採取、隠し通路 | 系統素材、地域印 |
| 試練 | 任意の条件付き戦闘（時間、被弾禁止など） | 調律石、図鑑の手掛かり |
| 補給 | 休憩と整理（安全地点に併設） | 回復、構成の再確認 |
| 遺失物 | 前回失った未確保装備の回収 | 失った装備1個（個人ごと） |
| ボス | 地域ボスなど | 確定報酬、初回撃破の進行 |

分岐は各ノードで二つか三つの行き先を示し、系統と危険度の目安を見せる。報酬の詳細は探索中に明らかにする（第12章）。

### 何を持ち帰るか（決定）

装備、製作素材、キャラ育成、研究や地域の進行は恒久保存する。遠征内のレベル、拾ったMemoryやEssenceのその回だけの強化、一時イベント効果は遠征終了時にリセットする。獲得済みの使用権や研究成果と、実際に今回装着している個体を別データにする。

### 確保と損失の規則（決定）

- **確保**：安全地点に到達した時点で、そこまでの未確保報酬が確保される。ボス撃破、任意帰還でも確保される。
- **任意帰還**：安全地点でのみ選べる。確保済みと未確保の成果をすべて持ち帰る。
- **全滅**：最後の確保以降の**未確保の素材と一時報酬を失う**。ただし未確保素材の25％（切り上げ、最低1）を「残響」として拠点に持ち帰る（設計値）。
- **装備は消失しない**：全滅時、未確保の装備ドロップは「遺失物」として個人の台帳に保存される。
- **遺失物ノード**：次の遠征の第2〜第3ノードに一度だけ現れる。ここの敵群を倒すと、遺失物のうち最も等級の高い1個を取り戻せる。残りの遺失物は消えず、次の遠征の遺失物ノードで続けて取り戻せる（ボス挑戦を挟んでも持ち越される）。保管の上限は10個で、超えた分は最も等級の低いものから通常の分解で欠片になる。この分解は発生前に画面で予告する。
- **協力時**：確保と損失は個人ごとに計算する。遺失物も個人の台帳に属する。
- 試作では装備の耐久損失などの追加の損失は入れない。体験が緩ければ後から強める方向で調整する（逆方向は不満を生む）。

損失の対象は出発画面と帰還画面で事前に見せる。救済枠（保険枠）は、遺失物ノードの体験を検証した後に追加を判断する。

### 複数の長さで遊べる構造

短い探索でも素材、依頼、装備更新のいずれかが進み、長い遠征では追加の危険に見合う報酬を得る。報酬は時間当たりで大きく差が出ないようにし、短時間の反復だけが最適解にならないか検証する（付録Bの経済表、付録Dの指標）。

### 中断と再開

遠征の中断は**安全地点のみ**で可能とする（決定）。安全地点では遠征状態を保存し、再開時に同じ安全地点から始める。対応していない地点で保存できるように見せない。協力部屋の全状態が復元されると約束せず、再開の範囲は第14章に定める。

### 飽きへの対策

目標を「高い数値の装備を拾う」に集中させず、構成の完成、未攻略の敵、地域条件、キャラ固有課題、図鑑、外見の収集へ広げる。すべての目標を日課にせず、プレイヤーが選んで追える形にする。

## 6  長期成長とキャラクターの個性

### 成長を三つの時間軸で扱う

| 時間軸 | 名称 | 役割 | 周回内レベルへの依存 |
| --- | --- | --- | --- |
| 遠征内 | 周回内レベル、Memory、Essence | 今回の戦闘に追いつく成長と構成の完成 | あり（既存の仕組み） |
| キャラ単位 | 専門化 | 継続して遊ぶことで戦い方を深める | **なし** |
| アカウント共通 | 研究 | 別キャラでも試しやすくする | **なし** |

既存のMasteryや星座と同一の名称・意味で上書きせず、対応関係を画面とデータで明示する。専門化と研究が周回内レベルに依存しない点が、後半に成長が鈍る問題への第一の対処である（第3章）。

キャラの基本的な強さをすべて後払いにすると、育成前のキャラが意図した遊び方をできなくなる。主要な操作感と固有の強みは初期状態で成立させ、成長で運用の幅、特化、代替行動を増やす。最終段階の強化は序盤の欠陥を埋めるための必須品にしない。

### 専門化

各キャラに**三つの専門化ルート**を設ける。同じ近接キャラでも、連撃維持、反撃、範囲制圧を選べる。専門化は攻撃力だけの枝分かれではなく、資源の得方、攻撃を続ける条件、防御行動との関係を変える。キャラ固有能力の核は維持し、共通ツリーで全員を同じ挙動へ変えない。

| 項目 | 設計値 |
| --- | --- |
| ルート数 | キャラごとに3 |
| ルートの構成 | 基礎ノード4、転換ノード3、到達ノード1の計8 |
| 取得費用 | 基礎1点、転換2点、到達3点。1ルート全取得で11点（転換は2つまで） |
| 点数の上限 | キャラごとに18点（1ルート全取得と、別ルートの一部まで） |
| 排他 | 転換ノードは同時に2つまで。到達ノードの効果は、キャラごとに「刻印」として**1つだけ**有効 |
| 点数の入手 | 標準以上の遠征の完了（ボス撃破、または第8ノード以降の安全地点からの帰還）で1点（10回まで）、地域ボスの初回撃破で2点（3地域）、キャラ固有課題で1点（2つ）。目安として約12〜15遠征（約8〜9時間）で上限（付録B4） |
| 再配分 | 拠点で無料。遠征中は不可 |

- **基礎ノード**は小さな能力補正と操作の補助を担う。数値は小さく、取得の順序で苦労させない。
- **転換ノード**は連撃から単発への変更、自己防御から味方保護への変更など、利点と制約を組にする。
- **到達ノード**は新しい行動規則を与える。装備と合わせた無制限の乗算を避け、成長予算の枠に収める（第7章）。
- 同時取得できない選択を一部に設け、保有ポイントだけで全ての長所を持てないようにする。

ルート間の乗り換えを促すため、再配分は費用を取らない。ポイント上限が18点で、1ルートの全取得（11点）に別ルートの基礎と転換を少し足せる程度なので、二つのルートの全取得には届かず、選択に意味が残る。代表例は付録Aに置く。

### 研究

アカウント共通の研究は、別キャラの育成を助ける**利便と選択肢の開放**に絞る。能力値への寄与は合計で+5％以内とする（設計値）。

| 系統 | 主な効果 | 例 |
| --- | --- | --- |
| 探索 | 地図情報、安全地点の便益 | 分岐先の危険度の詳細表示、補給の回復量 |
| 製作 | 製作・強化の幅 | 特性の候補数、分解の予告精度 |
| 協力 | 協力時の便益 | 蘇生の補助、共鳴の発動窓の拡大（+0.5秒） |
| 記録 | 図鑑と検証 | 図鑑の手掛かりの量、戦闘記録の保存数 |

費用は地域印で支払う。研究は一度行えば別キャラにも効く。

### 成長停滞への対処

レベルアップが遅くなる後半では、節目報酬、専門化の選択、素材による装備改良など、別の進行が見えるようにする。経験値を無制限に増やしてすべての問題を覆うと、敵や装備の水準まで再び引き上げる必要が生じるため、成長経路ごとの責任を保つ。

画面には現在の寄与、次の成長条件、上限を表示する。これにより、成長の量が足りない問題と、次の条件に届かず止まる問題を別々に改善できる。

### 星座の再設計を検討する基準

既存の星座は保持する（決定）。ただし、現行値の抽出後に次のいずれかを満たす場合は、複合方式の再設計を検討する。

| 判断基準 | しきい値（設計値） |
| --- | --- |
| 標準構成で、次のレベル1で得られる実効火力または耐久の増分が1％未満になる星の割合 | 全体の3分の1以上 |
| 標準遠征の終盤で、星座由来の寄与が周回内レベルの停滞により頭打ちになる区間の長さ | 遠征の4分の1以上 |
| 星座の寄与が基準能力に対して占める割合の遠征内での変化 | 序盤から終盤で半減以下 |

星座の効果量、最大ランク、レベル上限は現時点で確認できていないため（付録B0）、上の基準は判定できず、しきい値は設計値のまま保留する。星のスロットには色があり、同色以外では性能が半分になる（プレイヤーの発言、二次的な確認）といった既存の規則も、再設計の前に整理する。

再設計案は、序盤は固定加算で変化を感じやすくし、後半は定義した基準能力に対する**上限付き**の寄与へ移す複合方式とする。現在値へ繰り返し乗算する方式にはせず、参照する基準と上限を明示する。段階上限に達した星は、遠征の節目で効果を選択・変形できる案を検討する。全ての星を同じ方式に変えず、基礎補強、専門化、行動変更へ役割を再配分する。実施する場合は、移行表と返還方針を先に示す。

### 試行錯誤の負担

再配分は拠点で可能にする（決定）。序盤は負担を小さくし、構成を試すことを罰しない。装備プリセット（キャラごとに5つ）、専門化プリセット（3つ）、訓練場を組み合わせ、別キャラを始める際には研究と図鑑だけを引き継ぐ。キャラ固有の熟練を丸ごと免除するかは、試作後に判断する。

## 7  能力計算と成長予算

### 成長予算を先に決める

恒久成長、装備、星座、遠征内強化、協力効果がそれぞれ独立に強い乗算を持つと、完成構成と未完成構成の差が極端になる。まず基礎能力、同種の加算補正、条件付き補正、限定された乗算を分類し、どの層がどの能力へ作用するかを一覧化する。新しい効果がどの枠に入るかを決めずに追加しない。

### 計算の層

| 層 | 名称 | 内容 | 上限（設計値） |
| --- | --- | --- | --- |
| L0 | 基礎 | キャラとレベルによる基礎能力 | なし |
| L1 | 固定加算 | 装備の基礎値、星座の固定加算 | 装備のアイテムレベルで規定 |
| L2 | 加算枠（A枠） | 装備特性、専門化、研究の同種％補正を合算 | MOD由来の合計+120％ |
| L3 | 条件付き乗算（B枠） | 状態や条件を満たした時の独立補正 | 各×1.30まで、有効は同時に3個まで、合計×1.8まで |
| L4 | 遠征内強化 | Memory、Essence、既存の効果 | 既存の仕組みに従う。MODは変更しない |
| L5 | 協力補正 | 部屋の目標難度への数値圧縮（第14章） | 圧縮係数の範囲内 |

最終的な能力は、おおむね **（L0＋L1）×（1＋L2の合計）×L3の積×L4** で与える。L5は最終の数値を目標難度へ近づける後処理として適用する。

計算例：基礎攻撃力100、装備による固定加算20、A枠の補正合計50％、B枠が×1.10の一つなら、（100＋20）×1.50×1.10＝198となる。この例は計算順序を説明するための仮値であり、本作の現行式でも採用済み仕様でもない。

### 力の配分目標

完成構成の強さの内訳を**対数で配分**し、特定の層だけが突出しないようにする。

| 由来 | 配分の目標（設計値） | 理由 |
| --- | --- | --- |
| 遠征内（Memory・Essence・遠征内レベル） | 40％ | 毎回の構成の発見が最大の面白さであり続ける |
| 装備 | 30％ | 長期の方向付けと狙い撃ちの目標 |
| 専門化と研究 | 20％ | キャラの個性と別キャラへの引継ぎ |
| 既存の星座 | 10％ | 既存の進行を尊重する |

測定は、完成構成と素の構成の火力比（および耐久比）を求め、各由来を外した時の低下を対数で比べて行う。配分が目標の±10ポイントを超えた層は、補正枠を見直す。現行の星座とMemoryの実際の強さは現行値の抽出で確かめ、配分は較正する。

完成構成と未完成構成の火力比は**3.0以内**を目標とする。この比が大きいと、未完成構成の遠征が楽しめない。

### レベルと経験値

経験値曲線は序盤、中盤、終盤、任意の高難度で区分して評価する。区間の長さ、敵密度、探索時間が違うため、総経験値だけではなく「戦闘と移動を含む一定時間当たりの成長」と「ボス到達時の構成完成度」を測る。自動的に敵がプレイヤーと同じだけ強くなる方式は、成長の実感を消すおそれがあるため限定的に扱う。

レベルアップの**間隔**を、標準遠征での目標とする（設計値）。

| 区間 | レベルアップ間隔の目標 |
| --- | --- |
| 序盤（開始〜25％） | 90秒以内 |
| 中盤（25〜70％） | 150秒以内 |
| 終盤（70％〜ボス） | 240秒以内 |
| 上限 | 360秒を超えない |

間隔が目標を超える区間は、**節目報酬**で補う。ノードを一つクリアするごとに「三択の選択報酬」（Memoryの強化候補、素材、一時効果の中から一つ）を与える。これで間隔の穴を補う。90秒以内の小さな満足は、戦利品、素材、短い演出が担う（約3.5分ごとの選択報酬だけでは足りない）。1遠征で得るレベル数は、現行の経験値曲線を抽出した後に決める。

レベル上限を伸ばす場合は、上限後のUI、経験値型、セーブ容量、レベル参照効果、報酬判定をまとめて確認する。上限解除だけで強くなる星と、旧来の段階数で止まる星が混在すると格差が広がる。上限到達後は無限数値上昇より、構成変更や挑戦条件の開放に報酬を移す案を優先する。

### 防御と回復

耐久はHP、軽減、回避、障壁、回復を別々に測る。軽減と回復の組合せが敵の行動を無視できる状態を作る場合は、個別の数値だけでなく効果の同時成立を調整する。敵側へ一律の回復無効を与えると支援型そのものを否定するため、対策可能な短時間の制約や敵の種類を使う。

- 軽減の合計は**75％を上限**とし、これ以上は障壁と回避で表現する（設計値）。
- 回復は、一回あたりの上限と、同一由来の内部クールダウンを持つ。
- 障壁は、被弾を受ける順序（障壁→HP）を固定し、画面に残量を表示する。
- 回避は、予兆に反応した場合の見返り（反撃の機会）を主とし、確率回避への依存を避ける。

### 計算の規則

- 同種補正の加算枠と上限、減衰の有無を説明する。
- 攻撃速度、クールダウン短縮、追加発動は回数増加としても評価する。
- 継続ダメージ、召喚、反射、障壁破壊による攻撃の継承規則を分ける。
- 倍率を変える前後で、一般的な構成と極端な構成の両方を同じ条件で比較する。

### 調整の順序

現在の成長量と敵耐久を実測し、通常構成の基準線を決める。次に少数の外れ値を発動規則や重複条件から修正し、その後で報酬と敵配置を調整する。全体を一律に上方修正するだけでは、強い構成の先行をさらに大きくする可能性がある。

## 8  戦闘と発動ルールの共通化

### 複数の構成を成立させる

通常攻撃中心、スキル連発、溜め・詠唱、召喚、継続ダメージ、反撃、防御支援を主要な検証対象とする。各系統について、雑魚処理、単体への決定力、移動への対応、耐久、資源維持の得意不得意を定義する。すべてを同じ火力にせず、苦手に対する装備・行動・協力の解決策を残す。

| 系統 | 得意 | 苦手 | 補う手段 |
| --- | --- | --- | --- |
| 通常攻撃 | 単体、持続 | 範囲、遠距離の敵 | 範囲を持つ装備、移動補助 |
| スキル連発 | 雑魚処理、爆発力 | 資源切れ、長期戦 | 資源循環の装備 |
| 溜め・詠唱 | 大技、ボスの隙 | 移動する敵、中断 | 障壁、拘束 |
| 召喚 | 手数、移動中の火力 | 範囲攻撃、単体の決定力 | 更新の速い装備、保護 |
| 継続ダメージ | 耐久の高い敵、長期戦 | 短時間で倒せる敵 | 爆発的な加速 |
| 反撃 | 被弾が多い敵、ボス | 遠距離の敵 | 移動、遠距離手段 |
| 防御支援 | 協力時、持続戦 | ソロでの決定力 | 自己付与の弱い版 |

通常攻撃には既存の発動支援もあるため、現在何も対応していないとは断定しない。課題は、連撃、最後の一撃、間合い、溜め、回避後の反撃などへ組合せを広げ、スキルと同じ深さで構成を考えられるかである。現行の固有能力と最新効果を確認して、重複しない拡張を設計する。［S3・S5］

### 通常攻撃の拡張

通常攻撃には、次の**変化の型**を装備と専門化で与える。キャラ固有の通常攻撃の核は変えない。

| 型 | 内容 |
| --- | --- |
| 連撃 | 連続命中で段階が上がり、途切れると失う |
| 最後の一撃 | 連撃の最終段に追加効果 |
| 間合い | 距離に応じて効果が変わる |
| 溜め | 溜めの長さで性質が変わる |
| 回避後 | 回避成功後の次の一撃が変化 |
| 防御後 | 防御成功後の次の一撃が変化 |

### 共通の発動イベント

攻撃開始、命中、会心、撃破、被弾、防御成功、回避成功、回復、召喚、詠唱完了を**共通のイベント**として定義する。各イベントは、発動元、所有者、対象、直接攻撃か追加効果か、継続ダメージか、発動の世代を持つ。装備、Essence、専門化は同じイベントを参照し、説明と処理の食い違いを減らす。

### 共通のタグ

能力と装備の性質を、次の**十のタグ**で表す。数を増やしすぎず、プレイヤーが使い道を判断できる言葉に揃える。

通常攻撃、投射、近接、詠唱、召喚、継続、範囲、防御、支援、移動

### 連鎖の制御

| 規則 | 初期値（設計値） | 目的 |
| --- | --- | --- |
| 発動の世代上限 | 原発動を世代0とし、世代2まで（世代3以降は発動しない） | 無限循環の防止 |
| 内部クールダウン | 同一由来・同一対象に0.25秒 | 同時多発の抑制 |
| 同一由来の再発動 | 自分自身が起こした追加効果では、同じ効果を再発動しない | 自己増殖の防止 |
| 一回の行動と命中回数 | 区別して数える | 多段・範囲攻撃の過大評価を防ぐ |
| 協力による撃破 | 撃破の最後の一撃ではなく、直近5秒の貢献者に配分 | 公平性 |

すべてを一律に弱める上限ではなく、無限循環を止める規則と、通常の強い組合せを許す規則を分ける。制限はツールチップと詳細画面に表示する。

想定外の相乗効果も楽しさの一部として残す。ただし無限発動、協力相手の操作不能、セーブ破損、極端な処理負荷を起こす組合せは修正対象とする。変更時は何が危険で、どの成立条件を変えたかを説明し、関連する育成の再配分を可能にする。

### 戦闘の可読性

- 敵の予兆は味方の演出より**常に優先して描画**する。
- 味方の装飾的なエフェクト、ダメージ数値、画面揺れ、点滅の強さを個別に調整できる。
- 色だけで敵味方を区別せず、輪郭や形状も使う。
- 予兆の最短の提示時間は、通常攻撃で0.6秒、大技で1.2秒を下限とする（設計値）。

## 9  装備と戦利品

### 装備の役割

装備はキャラの長期的な戦い方を支え、遠征ごとのMemoryやEssenceを受け止める土台とする。単なるレベル依存の攻撃力置換にせず、攻撃の間合い、資源循環、防御行動、支援条件などの得意を作る。

### 装備枠（決定）

試作から公開版まで**三枠**とする。枠は固定せず、データ定義で追加できる形にする。二刀流・盾の扱いは対象外とし、「主装備」の挙動として吸収する。

| 枠 | 担う能力の範囲 | 主な特性の方向 |
| --- | --- | --- |
| 主装備 | 通常攻撃の型、間合い、資源の得方 | 通常攻撃の変化、攻撃速度、資源 |
| 防具 | 防御行動、耐久の方向、移動 | 防御・回避後の変化、障壁、軽減 |
| 装飾品 | 条件付きの効果、支援、状態の受け渡し | 状態の付与と参照、共鳴、補助 |

どの枠にも同じ強力な汎用倍率が付く状態を避ける。各枠が担う能力の範囲は第7章のL2・L3の入口を枠ごとに分けて制限する。

### レア度とアイテムレベル（決定）

レア度は特性数や固有効果の存在を表し、アイテムレベルは数値の水準を表す。

| レア度 | 特性数 | 固有効果 | 入手の主な経路 |
| --- | --- | --- | --- |
| コモン | 1 | なし | 通常戦闘、分解の素材 |
| アンコモン | 2 | なし | 通常戦闘、製作 |
| レア | 3 | なし | エリート、製作 |
| エピック | 3 | 1 | エリート、ボス、製作 |
| 固有品 | 3 | 2（専用） | 特定の敵・依頼・試練 |

アイテムレベルは地域の帯で与える。地域1が10〜19、地域2が20〜29、地域3が30〜39を基準とし、危険度が上がると同じ帯の中で上がる（危険度1段階につき+2、最大で帯の上限まで）。低レアにも製作素材や特性の抽出元としての用途を持たせる。最上位品を複数集めるだけで完成する仕組みより、組合せと不足能力の補完で選ぶ余地を残す。

### 特性と代償

各装備の特性は、**利点と制約の組**を基本とする。代表例は付録Aに置く。装備例はすべて仮称である。

| 装備例（仮称） | 構成への効果 | 代償または制約 |
| --- | --- | --- |
| 反撃の籠手 | 防御成功後に次の通常攻撃を変化 | 防御のタイミングが必要 |
| 追憶の触媒 | 長い詠唱を成立させた時に資源回復 | 中断と移動に弱い |
| 共鳴の護符 | 味方への障壁が支援効果を生む | 自己完結した火力は控えめ |
| 群れの紋章 | 召喚の数より連携行動を強化 | 同時召喚数と更新間隔に制限 |

### 拾う量より選ぶ質を重視する

戦利品は敵の種類、地域、依頼に傾向を持たせ、狙って遊べる経路を作る。完全固定ドロップだけでは発見が薄れ、完全抽選だけでは目標が見えなくなるため、狙い撃ちできる素材と偶然得る完成品を併用する。

- **狙い系統**：出発時に「攻勢」「守勢」「共鳴」の三系統から一つを選ぶ。選んだ系統の装備と素材の出現の重みを2倍にする。
- **救済**：エピックのドロップは、ボス撃破ごとに確率が上がる。基礎8％、未取得の撃破ごとに+4.8％、未取得が19回続いた次の撃破（20回目）で確定する（設計値）。協力時も個人ごとに計算する。
- **初回撃破**：各地域ボスの初回撃破で、エピックを1個確定で得る。

拾得時には現在装備との主な差、発動条件、既存構成との関係を確認できるようにする。倉庫、保護、お気に入り、フィルター、一括分解を拠点の最初の版から用意し、戦闘より整理に時間がかかる状態を防ぐ。売却・分解の対象を確認でき、保護品が混入しないことをテストする。

### セットと固有品

セット効果は構成の方向を示すが、必要数を揃えるまで無価値になる設計を避ける。公開版では**二つ揃えで効果が出る小セット**を基本とし、混成装備が競争できる余地を残す。固有品の必須化は避け、入手経路、代替品、完成までの体験を一緒に評価する。

## 10  MemoryとEssenceの拡張

### 既存の組合せを残して広げる

本作の中心であるMemoryとEssenceの関係を保持し、MOD独自装備や専門化がそれを支える構造にする。既存Essenceを無条件で全装備へ付け替える方式は、発動対象や能力参照の前提を崩すため、採用しない。公開APIのGemLocationもスキル側の位置を扱っており、独立した装備ソケットは別仕様として検証が必要である。［S8］

**装備側ソケットは公開版（1.0）では導入しない**（決定）。装備はMemory/Essenceの外側で、通常攻撃、移動、防御といったスキル枠外の行動を支える。ソケットは試作後に、専用のルーンを用いる案と、既存Essenceを限定互換にする案を比較して判断する。

### 共通タグと互換条件

Memory、Essence、装備の性質は第8章の十のタグで表す。Essence側には対象タグ、発動イベント、排他条件、効果の継承先を定義する。

装着できない場合には理由を表示する。装着できるが部分的にしか働かない状態を許すなら、適用される要素と適用されない要素を説明する。召喚物の攻撃へ本人の会心率が引き継がれるかなど、影響の大きい例外は詳細画面で確認できるようにする。

### 役割の分担

| 層 | 担うこと |
| --- | --- |
| 装備の特性 | 長期の方向付け。通常攻撃・移動・防御の変化 |
| Memoryの構成 | 今回の行動選択 |
| Essence | 行動の性質の変化 |
| 専門化 | キャラの運用の幅と資源の得方 |

- スキルそのものの連鎖、分裂、挙動変更はMemoryとEssenceの役割を基本とする。
- 同じ効果の重複装着時は、**同系統は上書き（強い方が有効）**とし、異なる系統は加算枠に従う（設計値）。
- 着脱、入れ替え、再接続で能力補正が残留・重複しないことを確認する。

### 発見と持ち込みの均衡

恒久的に覚えた構成をそのまま毎回持ち込めると、遠征で拾う意味が弱くなる。本書では、**出発時に方針を選べる一方、完成は遠征中の選択にも依存する構造**を採用する（決定）。具体的には、出発時に狙い系統と初期の一つのMemory候補群の方向を選べ、遠征中の選択報酬で完成に近づく。完全な長期RPG寄りの構成への変更は、試作後の比較で判断する。

必要部品が全く出ず構成が成立しない回を減らすため、限定的な**再抽選**（1遠征で2回まで、選択報酬の候補を引き直す）を用意する（設計値）。

図鑑は効果説明、発見済みの組合せ、取得先の傾向を記録する。未発見要素の手掛かりの量は設定で調整し、攻略の手引きと発見の楽しさを両立する（第2章）。

## 11  製作と経済の循環

### 通貨と素材を整理する

現行のGold、Dream Dust、Stardustは用途と保存範囲を確認してから接続する。外部の解説では周回内の購入・強化と恒久進行の通貨が区別されているが、現行の消費先を実機で再確認する。本MODは**既存通貨の消費先を変更しない**。MOD独自通貨は、名前やアイコンが既存通貨と混同しないようにする。［S6］

MOD独自の資源は次の**四種類**に絞る（決定）。

| 資源 | 入手先 | 主な使い道 |
| --- | --- | --- |
| 欠片 | 装備の分解、通常戦闘 | 製作、強化 |
| 系統素材（攻勢・守勢・共鳴） | エリート、発見、狙い系統の選択 | 製作（系統の指定） |
| 地域印 | ボス、発見、依頼 | エピックの製作、研究、地域解放 |
| 調律石 | 依頼、試練、ボスの初回撃破 | 特性の変更 |

終盤の余剰の処理として、欠片は系統素材へ変換できる（比率は付録B）。用途が一つしかない素材を大量に増やして倉庫を埋めない。

### 製作の段階

| 操作 | 狙い | 制限と救済の考え方 |
| --- | --- | --- |
| 製作 | 欲しい系統を選んで得る | 系統は指定でき、完成品の全特性までは固定しない |
| 強化 | 気に入った装備を継続使用 | +1〜+5の確定成功。上限と必要素材を先に見せる |
| 特性変更（再調律） | 構成に合わない部分を調整 | 1装備につき3回まで。費用は逓増（調律石1・2・3） |
| 分解 | 不要品を次の試行へ変える | 保護品を除外し、結果を予告 |
| 継承（刻印移植） | 更新時の喪失感を減らす | 特性1つを別装備へ移す。固有効果は移せず、値は移植先で再計算 |

初期案では素材を消費すれば確実に一定の改善が得られ、理想値の追求だけが長期目標になる構造を採る。強化の失敗による消失や段階後退は採用せず、低確率の大当たりを必須の進行条件にもしない。費用の一覧は付録Bに置く。

### 周回を作業にしない

製作費用は遊んだ時間だけでなく、依頼達成や新しい敵の攻略に報いる。序盤素材を終盤でも大量に要求して、簡単な地域を繰り返すことが最適にならないようにする。

- 時間当たりの素材獲得を、**危険度が高いほど増え、危険度0は下げる**（付録B）。
- 地域の帯より低いアイテムレベルの分解で得る素材は減らす。
- 初回の撃破や依頼の達成には、反復では得られない一回限りの報酬を置く。
- 低段階素材の変換と、適正難度での代替入手を用意する。

### 報酬の信頼性

協力プレイの報酬は、誰に何が確定したかをホスト側で決め、同じ処理が再送されても二重に受け取れないようにする（付録C）。取引は初回公開で見送り、個人報酬だけで成立させる（決定）。取引を将来導入する場合は、所有権の移転、キャンセル、切断、同時操作を一つの処理として扱う。

経済の評価では、装備更新までの時間、使われない素材、所持量の偏り、製作とドロップの比率を見る。稼ぎの抜け道を見つけた際は、獲得源だけを減らすのではなく、通常進行で必要量が足りるかも再測定する。

## 12  世界と探索と進行目標

### 地域ごとに選ぶ理由を作る

地域は見た目だけでなく、敵の行動、地形上の危険、報酬系統、イベント傾向を持つ。移動を制限する地域、継続的な圧力を受ける地域、単体の強敵と戦う地域を分け、構成の得意不得意を試せるようにする。名称や世界観は本作の設定と整合を確認してから確定する。以下は**仮称**である。

| 地域（仮称） | 帯 | 試す戦い方 | 環境の圧力 | 主な報酬系統 | ボス（仮称） |
| --- | --- | --- | --- | --- | --- |
| 一 微睡みの浅瀬 | 10〜19 | 基本の読み合い、通常攻撃 | 弱い。予兆の学習が中心 | 攻勢 | 潮鳴りの番人 |
| 二 霧の回廊 | 20〜29 | 移動、射程の維持、状態の活用 | 霧で視界が狭まり、拘束する床がある | 共鳴 | 霧織りの双子 |
| 三 砕けた天蓋 | 30〜39 | 継続圧力、速攻、防御 | 時間とともに危険床が増える | 守勢 | 天蓋の王 |
| 終 夢の螺旋 | 全帯 | 構成課題、連続挑戦 | 周回ごとに修飾条件が変わる | 称号、外見、選択肢 | 夢食い |

各地域の詳細（敵の構成、環境、ボスの行動）は付録Aに置く。公開版（1.0）は上の**三地域とエンドゲーム**を範囲とする。最初のプレイ可能な試作は地域一のみとする（第18章）。

地図上では、ボスへの最短経路、素材を狙う寄り道、危険な追加戦闘を比較できるようにする。報酬の内容を完全に隠すと選択が偶然になり、完全に固定すると最適手順になるため、**系統と危険度を見せて詳細を探索中に明らかにする**。

### 依頼と地域進行

依頼は特定の敵の討伐、危険なイベントの解決、探索物の発見、味方を守る条件など、異なる行動を促す。基本進行に必須の依頼は分かりやすくし、特殊なプレイを要求する依頼は任意にする。装備やキャラを持っていないために主要進行が止まる条件を避ける。

- 初回攻略は地域や物語の進行を担い、繰り返し攻略は装備や製作素材を担う。
- 地域の開放は育成値だけで決めず、節目の敵や目標の達成と結びつける。次の地域は、前の地域ボスの初回撃破で開く。
- 同じ依頼の繰り返しには報酬の変化や短縮を用意し、単純な回数要求を主目的にしない。
- 協力時は参加者ごとの達成状況を記録し、ホストだけが進行する問題を避ける。
- 依頼は常時三件まで受けられ、遠征の長さに合わせた短・標準・長の種類を混ぜる。

### 拠点の機能

拠点には装備整理、製作、専門化、図鑑、依頼、訓練場をまとめる。機能開放を物語の節目へ結びつける場合も、基本操作を長く制限しない。成長のたびに多数の画面を巡る必要がないよう、**前回から変わった項目と次の候補**を拠点の最初の画面に集約する。

拠点の見た目の発展や会話は、数値強化以外の継続目標となる。ただし新規NPC、文章、演出は制作負担が大きいため、初期は既存UIに無理なく組み込める機能から作り、物語の追加量は別途見積もる。

### エンドゲーム

地域攻略後は、条件の異なる連続挑戦、特殊ボス、構成課題、収集の完成へ目標を移す。高難度だけに実用上必須の基礎機能を閉じ込めない。限界挑戦の報酬は称号、外見、選択肢、専用の進行を中心にし、通常進行との能力差が無制限に広がらないようにする。

| 内容 | 概要 |
| --- | --- |
| 螺旋挑戦 | 週ごとに入れ替わる修飾条件の下で、連続した戦闘を進む。進行の途中に安全地点がある |
| 構成課題 | 「通常攻撃のみ」「召喚主体」など、指定された戦い方での攻略。クリアで外見と称号 |
| 特殊ボス | 夢食い。地域ボスの要素を組み合わせた最終戦 |
| 収集 | 図鑑の組合せ、固有品、外見の完成 |

## 13  難度と敵とボスの設計

### 難度の軸を分ける

基礎難度、任意の修飾条件、周回継続による増加、特殊モードを別の軸として扱う。既存の各設定を参照し、同じ敵HPや攻撃力へ重複して倍率を掛けない。公開APIにも周回前後の係数を扱う設定があるが、現行の既定値や実際の適用順序は検証が必要である。［S9］

既存の難易度は4段階である（S2。Nap、Deep Sleep、Nightmareの名称が確認でき、完全な一覧と順序、各段階の敵の倍率は未確認）。高難易度ほどボス撃破ごとのStardustが増えるとされる（二次資料、倍率は不明）。Lucid DreamとHunterも別の軸として存在する（付録B0）。

本MODの**危険度**（0〜5）は、出発時に選ぶ。既存の難度設定と併存する形で、まず適用順序を段階0で照合する。その確認までは、危険度の敵の耐久補正は仮置きとする。MODの素材の倍率は、既存のStardustの増減とは独立して扱う。

| 危険度 | 敵の変化 | 素材の倍率 | 位置づけ |
| --- | --- | --- | --- |
| 0 練習 | 敵の攻撃を弱め、予兆を長くする | ×0.8 | 操作の習得 |
| 1 標準 | 基準 | ×1.0 | 通常のバランス対象 |
| 2 | エリートの出現が1つ増え、敵の耐久+10％ | ×1.2 | 通常のバランス対象 |
| 3 | ボスに追加の行動が1つ。敵の組合せが変わる。敵の耐久+20％ | ×1.45 | 通常のバランス対象（上限） |
| 4 | 修飾条件を1つ付与。ボスの安全地帯が縮小 | ×1.75 | 挑戦 |
| 5 | 修飾条件を2つ付与。追加の試練が加わる | ×2.1 | 挑戦 |

**危険度3までを通常のバランス対象**とし、複数の戦い方が成立することを検証する。4と5は挑戦であり、全構成の到達を保証しない。限界挑戦についてこの境界を公開仕様として示す。

### 敵の役割

雑魚敵は、接近して圧力をかける敵、遠距離から移動を促す敵、強化や回復を行う敵など、**優先順位**を作る。硬い敵を増やすだけでなく、配置と組合せで戦術を変える。

| 役割 | 内容 | 求める対応 |
| --- | --- | --- |
| 群れ | 数で押す | 範囲、位置取り |
| 突進 | 一直線の接近 | 回避、反撃 |
| 狙撃 | 遠距離から攻撃 | 距離の詰め、遮蔽 |
| 守護 | 前面を守る | 側面、障壁破壊 |
| 支援 | 味方を強化、回復 | 優先して倒す |
| 拘束 | 移動を妨げる | 解除、移動手段 |
| 破壊 | 障壁を割る | 障壁に頼らない対応 |
| 召喚 | 敵を増やす | 発生源の撃破 |

各地域の敵は、この八つの役割から組み合わせる。エリートには**接頭効果**を付けて変化をつける（付録A）。処理負荷を増やす大量出現は、画面の読みやすさと同時に上限を検証する。

### ボスの設計

ボスは予兆、回避可能な範囲、攻撃できる時間、失敗した時の損失を明確にする。上位難度では行動の組合せや安全地帯を変えるが、視認できない即死攻撃や長時間の無敵を主要な難しさにしない。初見時に学習し、再挑戦で改善できる設計を目指す。

- **予兆**：すべての大技に、地面の表示と音の合図を持たせる。最短の提示は通常攻撃0.6秒、大技1.2秒。
- **全体攻撃の禁止**：回避、遮蔽、防御のいずれかで対応できない攻撃を置かない。
- **隙**：大技の後に攻撃できる時間（目安2〜4秒）を置く。
- **段階**：HPの一定割合で行動が変わる。変化の瞬間は演出で明示する。
- **再挑戦**：ボスの手前には安全地点（標準の遠征では第8ノード）があり、敗北してもそこまでの確保は残る。拠点から「ボス挑戦」（第5章）を選べば、補給とボスだけの短い遠征で、覚えた行動の対処をすぐ試せる。
- **協力時**：攻撃の対象を一人に固定せず、分散させる。蘇生の機会を戦闘中に作る。

三つの地域ボスの行動の設計は付録Aに置く。

### 成長の手応えを残す

適正より低い地域では成長によって明確に楽になる。適正地域では構成と操作が問われ、上位地域では準備と理解が必要になる。この差を残すため、敵の完全な自動追従は標準にしない。協力の人数補正は敵耐久だけでなく、敵数、危険の同時発生、蘇生のしやすさも含めて評価する（第14章）。

### 撃破時間の目標

| 対象 | 標準構成の目標（設計値、危険度1、ソロ） |
| --- | --- |
| 群れの敵1体 | 2〜4秒 |
| 通常の敵 | 5〜8秒 |
| エリート | 25〜40秒 |
| 地域ボス | 4〜6分 |
| 守護体（小ボス） | 2〜3分 |

完成構成の撃破時間は、標準構成の**0.4倍（約2.5倍の速さ）を下回らない**ことを目標とする。下回る場合は、第7章の補正枠と敵の組合せを見直す。

| 評価対象 | 観測すること | 調整に使う判断 |
| --- | --- | --- |
| 雑魚の撃破時間 | 通常構成と完成構成の差 | 長い停滞と瞬間処理の偏り |
| ボス戦 | 行動周期数と失敗原因 | 学習可能か、消耗だけか |
| 耐久 | 連続被弾までの余地 | 回避不能な死亡が多くないか |
| 難度報酬 | 危険と所要時間の増分 | 低難度の反復が唯一解でないか |

### 難度変更の透明性

出発画面に主要な条件と報酬の差を表示し、遠征中に条件が変わる場合も通知する。プレイ状況に応じて敵を見えない形で強化する方式は慎重に扱い、標準では採用しない。補助設定を設ける場合は、敵速度や演出量など影響範囲を明示し、セーブや協力参加条件との整合を取る。

## 14  必須要件としての協力プレイ

マルチプレイ対応は確定した必須要件である。後から追加する機能として切り離さず、育成、装備の所有権、報酬、遠征の進行、保存を初期から複数参加者向けに設計する。最初のプレイ可能な版にも協力プレイを含め、ソロ専用の状態を第一版の完成とは扱わない。

### 一人でも進められ協力で広がる

支援や防御の構成はソロでも敵を倒して進行できる基礎手段を持つ。協力時は、敵を集める、弱体化する、攻撃機会を作る、障壁を渡すといった相互作用が増える。役割を固定せず、複数のキャラと装備から同じ役割へ近づけるようにする。

### 状態の共有と共鳴

協力の相互作用は、六つの共通の状態（印、拘束、障壁、加速、挑発、露出）を介して作る。一人が付与した状態を、別の人の装備や専門化が参照して強くなる。共鳴は、二人以上が同じ**時間窓（2秒）**の内に条件を満たした時の追加効果である。詳細は付録Aに置く。

### 育成差のある参加（決定）

部屋の目標難度（地域と危険度）を選び、参加者の**数値だけ**を許容範囲へ圧縮する。育成で得た行動や選択肢は残す。

| 項目 | 設計値 |
| --- | --- |
| 基準 | 地域と危険度ごとに基準の力 R を定める |
| 圧縮 | 参加者の力 P を、比率 r＝P÷R の0.5乗で近づける（r′＝r^0.5） |
| 範囲 | r′を0.7〜1.4に収める |
| 対象 | 火力と耐久の数値のみ。スキル、特性、専門化の効果の種類は保持する |
| 例 | r＝2.0なら1.41→1.4へ。r＝0.5なら0.71。r＝0.3なら0.7（下限） |

初心者を完全には引き上げず、上位者を完全には引き下げないため、育てた実感と一緒に遊びやすさの両立を狙う。完全に同じ能力へ揃える方式、上位者だけを補正する方式とも、試作後の測定で比較する（付録D）。

人数に応じた敵の補正は、次の設計値とする。

| 人数 | 敵のHP | 敵の数 | 灯（蘇生の資源） |
| --- | --- | --- | --- |
| 1 | ×1.0 | ×1.0 | 2 |
| 2 | ×1.6 | ×1.25 | 3 |
| 3 | ×2.2 | ×1.5 | 4 |
| 4 | ×2.8 | ×1.75 | 5 |

灯は、蘇生のたびに1つ消費する共有の資源である。協力では、倒れた味方を8秒の猶予の中で、近くの味方が3秒の動作で蘇生する。猶予内に蘇生されなかった者と、灯が尽きた後に倒れた者は、その遠征のあいだ脱落し、次の安全地点で復帰する。ソロでは、倒れると灯を1つ消費してその場で復帰する（HP30％、2秒の無敵）。**蘇生できる味方がいなくなった時（全員が倒れた、または脱落した時）が全滅**で、灯が残っていても同様とする。ソロでは灯が尽きた状態で倒れた時が全滅である。既存の蘇生の規則と衝突しない形に、段階0で整合する（要確認）。

### 報酬と進行の公平性

- 経験値や基礎報酬を撃破の最後の一撃だけで配分しない。直近5秒の貢献者で配分する。
- 支援、弱体化、敵の誘導など、火力以外の貢献が報われるようにする。状態を付与した味方の撃破にも貢献が及ぶ。
- 装備は個人抽選を基本とし、受け渡しは初回公開で見送る。
- 依頼と地域開放は各参加者の条件を個別に判定し、結果画面で達成を確認できるようにする。
- 初心者に高難度報酬を無条件で渡さない。報酬は参加者個人の到達段階（開放済みの地域と危険度）に応じて決める。共通の遊び場と個人報酬を併用する。

### 同期の責任

敵、報酬、取引、成長の確定はホスト側で管理し、クライアントは操作要求を送る構造を基本とする。画面演出や操作感のための予測と、実際に保存する結果を分離する。各プレイヤーの恒久装備と成長は本人のプロフィールへ属し、部屋の一時状態とは分ける。参加者全員のMOD版と設定を照合し、不一致時の参加可否を明示する。JSON上書きの自動同期が独自のC#状態や装備台帳まで保証するわけではない。［S7］

### 途中参加、切断、再接続、ホスト終了（決定）

| 事象 | 扱い |
| --- | --- |
| 新規参加 | 拠点または安全地点のみ許可 |
| 再接続 | 既存参加者のみ。確定済みの結果を再表示し、報酬は再配布しない |
| 切断（遠征中） | 90秒の猶予の間、キャラは無敵の待機状態。超えると離脱扱いで確保分のみ保全 |
| ホスト終了 | 直近の確定成果を保全し、安全地点から再開 |
| ホスト移行 | 初期は保証しない。別の技術検証とする |
| 取引 | 初回公開では見送り |
| 遠征の途中再開 | 安全地点のみ |

### 互換性と同意

部屋にはMOD名、版、設定、必要な依存関係を示す。ゲーム内容を変えるMODとして適切に表示し、参加前に条件が分かるようにする。公式クロスプレイの存在から、MOD入り環境のコンソール対応まで推定しない。初期対象は検証したPC環境とする。［S1・S7］

## 15  保存と表示と長時間プレイ

### 保存をシステムとして扱う

MOD独自のデータは、プロフィールと結び付けた**版番号付きの独立保存**とする（決定）。装備ID、所持権、成長、研究、地域進行、報酬の確定履歴を保存する。公式APIのpersistentDataという名称だけから、周回をまたぐ永続保存や全プロフィール対応が保証されると判断しない。［S10・S11］

| 保存の区分 | 内容 | 寿命 |
| --- | --- | --- |
| 恒久・個人 | 装備台帳、素材、専門化、研究、図鑑、地域進行、遺失物 | プロフィールとともに |
| 恒久・確定履歴 | 確定済みの報酬ID（再送の重複防止用） | 遠征終了後に圧縮 |
| 遠征・個人 | 安全地点時点の遠征の状態 | 遠征の終了まで |
| 部屋・一時 | 参加者、危険度、進行のノード | 部屋の終了まで。保存しない |

書き込み途中の終了に備え、**一時ファイルへ書いてから置換**し、直前三世代のバックアップ、整合性の検査値（ハッシュ）を用意する。旧版からの移行は元データを残し、失敗時にはロードを止めて復旧手順を示す。MODを外した時に本体データが壊れたり、恒久補正が残留したりしないことを確認する。形式と手順は付録Cに置く。

### 情報設計

プレイヤーが頻繁に見る情報は、装備差分、能力の内訳、発動条件、次の成長、目的地の報酬へ絞る。詳細計算は開いて確認できるようにし、常時表示で画面を埋めない。短い説明と詳細説明を共通データから作り、数値変更時の説明漏れを減らす。

| 画面 | 最初に見せる情報 |
| --- | --- |
| 拠点の最初の画面 | 前回から変わった項目、次の候補（製作可能な装備、取得可能な専門化） |
| 出発画面 | 危険度と報酬の差、狙い系統、損失の対象、装備と専門化の確認 |
| 安全地点 | 確保済みと未確保、次の安全地点までの危険の目安、帰還の選択 |
| 装備比較 | 現在装備との主な差、発動条件、構成との相性 |
| 結果画面 | 獲得、失った未確保、不足素材、敗北時は被ダメージの内訳 |

戦闘では敵の危険予兆、自分の位置、被弾と防御、味方の重要な支援を優先する。味方の装飾的なエフェクト、ダメージ数値、画面揺れ、点滅の強さを個別に調整できるようにする。色だけで敵味方を区別せず、輪郭や形状も使う。

### 性能を機能追加の条件にする

同時に存在する弾、召喚、継続効果、発動イベント、ドロップ、履歴の量を計測する。表示を減らしても戦闘判定が増え続けるなら問題は残るため、描画とロジックを別々に測る。プール再利用、不要状態の破棄、処理の集約は実測で効果を確認して採用する。

**MODが管理する対象の予算**を初期値として置く（設計値、実測で較正）。

| 対象 | 上限 |
| --- | --- |
| プレイヤー1人あたりの召喚 | 6 |
| プレイヤー1人あたりのMOD発動イベント | 毎秒60（部屋で毎秒160） |
| 一つの対象に付く継続効果 | 40 |
| 遠征中の戦闘履歴 | 直近500件、超過は古い順に破棄 |
| 部屋のMOD由来の通信量（クライアントあたり） | 平均30 KB/s |

- 同じ場面でプレイ開始直後と長時間経過後を比較する。60分の遠征でメモリの増加が50 MB以内を目標とする。
- ソロと最大人数、一般構成と発動回数の多い構成を別に測る。
- フレーム時間の平均だけでなく、遅い場面の割合（99パーセンタイル）、メモリ増加、通信量を見る。
- 画質設定を下げた際も敵予兆と判定の一致を維持する。

### 運用上の安全性

不明な効果、存在しない装備、上限外の値を読み込んだ時は、黙って別物へ置き換えず、隔離や修復の結果を表示する。ログには診断に必要な版と状態を含め、個人情報や不要な通信内容を保存しない。報告用データの送信はユーザーが選べる形にする。

### アクセシビリティ

色覚、画面の揺れ、点滅への配慮として、予兆の形状による区別、点滅の強さの調整、揺れの無効化、文字サイズの調整を最初の版から用意する。操作は、キーボード・マウスとコントローラーの双方で、同じ情報量で装備整理ができるようにする。

## 16  一連のプレイ体験の例

### 初回の遠征

以下はシステムの接続を説明する仮のプレイ例であり、実在するキャラや装備の確定仕様ではない。プレイヤーは近接型のTravelerを選び、連撃を続ける方向と防御後に反撃する方向の違いを短い説明で確認する。初期装備でも通常攻撃と回避が機能し、訓練場で両方を試せる。

出発時には地域一と標準の遠征、危険度1、狙い系統「攻勢」を選ぶ。探索では、装備素材が得られる発見のノードと、直接エリートへ向かう経路が見える。遠征中に範囲処理に向くMemoryを拾い、通常攻撃の単体への強さと組み合わせる。三つ目のノードを終えた時には、ノードの選択報酬で、最初の「構成が噛み合った」瞬間を迎える。戦闘後には強くなった能力と新しい発動条件だけが短く示される。

### 帰還と次の目標

第4ノードの安全地点で、消耗したため帰還を選ぶ。確保した装備と素材、依頼の進行が残り、遠征内レベルと一時強化は戻る。結果画面には獲得品、未確保だった報酬、次の製作までに不足している素材が表示される。敗北や撤退が、同じ状態からのやり直しにならない。

拠点で拾った防具を比較すると、単純な攻撃力は下がるが、防御成功後の反撃を強められる。使わない装備を分解し、反撃用の補助効果を製作する。専門化の再配分を行い、次の遠征で反撃を主体に戦う。装備更新と戦い方の変化が同じ目標へつながる。

### 敗北と遺失物

別の遠征の第7ノードで、エリートに敗れる。最後の安全地点以降に拾った素材は失うが、25％が残響として残る。拾ったレアの防具は消えず、「遺失物」として保存される。結果画面は、被ダメージの上位が「突進の連続」だったことを示し、「守勢の素材が不足。防具の強化が効果的」と提案する。次の遠征の第2ノードで遺失物ノードが現れ、これを取り戻す試練が、前回の続きを始める動機になる。

### 中盤の構成転換

別の地域では接近しにくい敵が多く、反撃だけでは処理が遅い。プレイヤーは移動を補助するMemoryを選ぶか、遠距離手段を残すかを判断する。装備をすべて捨てて最適構成へ乗り換える必要はなく、苦手を一部補うことで攻略できる余地を持たせる。

新しい固有装備を得ると、反撃で生まれる障壁を味方へ渡す構成を試したくなる。図鑑には相性のある支援効果の取得先が示される。次にどの地域へ行くかが、経験値効率だけでなく構成の目標によって決まる。

### 協力と終盤

育成が進んだ友人と同じ難度帯へ参加する。能力差は圧縮されるが、獲得した行動や構成の特徴は残る。友人が敵に印を付けて集め、プレイヤーが危険な攻撃を受け止めて反撃し、別の味方が拘束した敵へ高火力を出す。二人の動きが同じ時間窓に重なると共鳴が起きる。画面では敵予兆が味方演出より優先される。一人が倒れた時には、灯を一つ使って蘇生の機会が与えられ、全員が最後まで戦う理由が生まれる。

地域ボスを倒した後は、次の地域、より難しい任意条件、別構成の完成のどれを目標にするか選ぶ。長時間の連続挑戦を続ける場合も、帰還時に何を持ち帰れるかが分かり、処理負荷が増え続けない。成長、発見、協力、快適さが一つの体験としてつながる。

## 17  技術方針と実現性の前提

### 実装方式の基本案

公式のMOD機構を利用し、静的な設定変更で済む箇所はJSON上書き、独自の状態や挙動が必要な箇所はC#のMOD処理として分ける。Harmony等の利用方法、ゲーム内容変更の表示、終了時の後片付けは公式資料に従う。公開APIが存在しても、対象バージョンで同じ署名と動作があるかは実機で確認する。［S7］

| 機能領域 | 確認できる入口の例 | 未確認であること |
| --- | --- | --- |
| 経験値とレベル | Hero ReceiveExperience など | 現在の係数、上限変更時の全影響 |
| 能力補正 | EntityStatusの補正追加と削除 | 適用順、重複、他MODとの競合 |
| Memory装着 | HeroSkillとGemLocation | 装備独自ソケットの実装方法 |
| 保存 | DewSaveとプロフィール識別子 | 独自保存の寿命、移行、同期 |
| 表示 | DewGUIなどのUI入口 | 大規模画面、操作機器別の使いやすさ |

### 内部の分担

能力計算、発動イベント、装備定義、報酬、保存、協力同期、UIを独立した責任に分ける。ゲームへの接続部分は薄く保ち、コンテンツの数値や説明をデータから変更できるようにする。同じ計算をUIと戦闘で別実装しない。新しい装備を追加する際に個別の例外処理が増え続ける構造を避ける。

| 部品 | 責任 |
| --- | --- |
| 接続層 | ゲームのAPIとの境界。薄く保つ |
| 能力計算 | 第7章の層と上限。UIと戦闘が共用する |
| イベント | 第8章の共通イベントと世代・内部クールダウン |
| データ定義 | 装備、特性、専門化、敵、地域。起動時に検証する |
| 台帳と報酬 | 装備の所有、報酬の確定、重複防止 |
| 保存 | 独立保存、移行、バックアップ |
| 同期 | ホストの確定、クライアントの要求、再接続 |
| UI | 共通データから説明を生成 |

保存するデータには安定したIDを使い、表示名や配列の順番に依存しない。ランダム報酬は再現に必要な情報を記録し、抽選結果の確定と獲得処理を区別する。データ定義の検証で、重複ID、存在しない参照、上限外の値を起動前に発見できるようにする。

### 開発開始時に確かめる接続点

- 能力補正を一つ追加し、着脱・ロード・切断後に正しく除去できるか確認する。
- 独自装備を一つ保存し、プロフィール切替と旧データ移行を試す。
- 協力で一つの報酬を確定し、再送や再接続でも重複しないことを確認する。
- 発動連鎖を意図的に作り、停止規則と性能計測が機能するか確認する（技術プロトタイプ計画では段階1で行う）。

### 技術プロトタイププラン

別資料として技術プロトタイプ計画を作成した（[docs/tech-prototype-plan.md](docs/tech-prototype-plan.md)）。純C#コアと自動試験は実装済みで、[src/SodRpg.Core](src/SodRpg.Core)（`src/README.md`に概要）と`tests/SodRpg.Core.Tests`にある（`dotnet test`で確認する）。本書の第17章の「確かめる接続点」を、最小の縦断スライスとして実機で確かめる計画で、要点は次のとおりである。

| 項目 | 内容 |
| --- | --- |
| 範囲 | A 能力値の変更1つ、B 保存アイテム1つ、C 重複しない協力報酬1つ。四つ目の発動連鎖と性能計測は、装備と発動規則が先に要るため、段階1へ回す |
| 構成 | 純C#コア（補正の定義、台帳、報酬の確定、原子的な書き込み）と、ゲーム接続層（補正の追加・削除、保存先、独自メッセージ）を分ける。コアはゲームなしで単体試験できる |
| 手順 | P0 環境確認、P1 スパイク（SP-1〜7）、P2 コア実装、P3 接続、P4 協力検証、P5 判定 |
| 判断 | A・Bがソロで全件通り、Cで重複0件なら、段階1へ進む。独立保存、報酬の重複、補正の除去のいずれかが確保できなければ、コンテンツの拡張を止めて方式を見直す（第19章の停止条件） |

この計画を本書の仕様へ次のように反映した。

- **報酬ID**：同じ出来事と同じ受取人からは、何回呼んでも同じIDが出る形（遠征ID、契機、報酬定義、受取人のハッシュ）にする（付録C4）。
- **確定の点**：保存の確定点は一時ファイルから本体への**置換の完了**であり、付与の確定点はクライアントの保存完了とする。確定前の一時ファイルは読み込まない（確定前の内容を読むと、受領の確認を返していない付与を「あった」ことにして、後の書き込みの失敗で失う恐れがある。純C#コアの模擬試験で見つかった欠陥で、修正済み）。ホストは受領の確認（ack）を受けて閉じる。付与と確定済みIDの追記は同一の保存で行う。
- **取りこぼしと重複**：別の指標として数える。重複は即時に不合格、ホストが確定後に送信前に終了した場合の取りこぼしは、記録して通知する方針とする（付録C6）。
- **版の照合**：初期は版番号の比較のみ実装し、不一致時の方針は次段階で詳細化する。

公開資料から確認できた事項（出典 S7、S14）は、MODの入口が `ModBehaviour` であること、JSON上書きはホストからクライアントへ自動で同期されること、`OnDestroy` で後片付けとHarmonyの解除が必要なこと、Workshopへの初回の公開が非公開（Hidden）になることである。EntityStatusやDewSaveなどの署名と挙動、ネットワーク層、保存領域の寿命、同一環境での2人協力の検証手段、対象ランタイム（既存MODは.NET Framework 4.x系を対象にしている）は未確認で、スパイクで確かめる。

実機の作業（ゲームの導入、テンプレートの導入、2人協力の検証、本体アセンブリの確認）は、ゲーム本体のある環境でのみ行える。純C#コアと模擬ネットワークの自動試験は、ゲームがなくても作成できる見込みである。既存MODのコードは流用せず、方式を読む事例にとどめる。

現行数値の整理（共有フォルダの `data/current-spec-numbers.md`）は付録B0に要約し、逆コンパイルと実機で確認する13項目を付録B10にまとめた。

### 現時点の制約

本計画ではゲーム本体のアセンブリ、実際のテンプレート、対象.NET環境、実機動作を確認していない。したがって実装可能性は公開資料に基づく見通しであり、工数確定の根拠ではない。技術試作で制約が判明した場合は、同じ体験を保つ代替仕様へ調整する。

API参照 S8〜S12。具体的な既定値や内部挙動は公開ページだけで断定しない。

## 19  検証計画と面白さの測定

今回は計画書の作成であり、実装、実機試験、性能測定は作業対象に含めない。本章は、開発が進んだ際に**面白さを確かめる方法**を定める。詳細は付録Dに置く。

### 何を測るか

| 柱 | 測ること | 目標（設計値） |
| --- | --- | --- |
| 読み合い | 初見ボスの再挑戦での被弾の減少、予兆の見逃しの申告 | 参加者の70％以上で、3回目の挑戦の被弾が初回の半分以下になる |
| 構成の発見 | 構成の使用率、噛み合いの申告、必要部品が出なかった遠征の割合 | 主要構成が4種以上で各10％以上、最大でも35％以下。必要部品なし遠征は5％以下 |
| 帰還判断 | 安全地点での続行と帰還の割合、判断に迷った時間 | 続行・帰還がそれぞれ30〜70％の間に収まる |
| 個性 | 「このキャラはこう戦う」と説明できる割合 | 80％以上 |
| 協力 | 共鳴の発動、役割の入替、協力が楽しかったとの回答 | 協力時の「もう一度遊びたい」が70％以上 |
| 失敗 | 敗北理由を言えた割合、敗北後の再挑戦率 | 理由を言えた80％以上、再挑戦70％以上 |
| 負担 | 拠点での整理時間の遠征時間に対する割合 | 25％以下 |

### 進め方

- 段階2から、毎週の遊びの試験を行う。参加者は6〜8人を目安に、初見の人と熟練者を混ぜる。
- 記録は、画面の録画、行動の記録（付録Dのイベント）、終了後の質問票で取る。
- 質問票は短く、「もう一度遊びたいか」「何で勝ち（負け）たか」「構成を作った実感」を必ず聞く。
- 数値の調整は、第7章の順序（基準線→外れ値→報酬）に従い、一度に一つの変数を変える。

### 自動試験

- データ定義の検証（重複ID、参照切れ、上限外の値）。
- 能力計算の層と上限の単体試験。UIと戦闘が同じ結果を返す。
- 保存の往復、移行、破損時の復旧、プロフィール切替。
- 協力の報酬確定の再送、再接続、同時操作。
- 連鎖の世代上限と内部クールダウン。長時間の疑似戦闘での処理量の計測。

### 止める条件

独立保存の安全性を確保できない、協力報酬を一意に確定できない、通常構成で後半の成長が成立しない、長時間負荷が制御できない場合には、コンテンツ拡張を止めて基本方式を見直す。表示だけの応急処置や倍率の追加で隠さない。第2章の「面白くない状態」の検出も、同様に拡張を止める条件とする。

## 20  リスクと対処と公開方針

| リスク | 早期の兆候 | 対処と判断 |
| --- | --- | --- |
| 規模の拡大 | 基本ループより追加機能の数が先行 | 小規模試作へ戻り、後回しの機能を明示 |
| 同じ最適解への収束 | 汎用倍率の装備が全キャラで必須 | 補正枠と代償を見直し、代替経路を作る |
| 育成の作業化 | 簡単な場所の反復が最も効率的 | 適正難度の報酬と素材変換を調整 |
| 保存事故 | 移行失敗、二重報酬、補正の残留 | 独立保存、バックアップ、移行試験 |
| 性能悪化 | 経過時間でイベントやメモリが増える | 連鎖制限、状態破棄、上限の説明 |
| 協力の不整合 | 取引や再接続で所有権が食い違う | 確定処理の一元化と重複防止 |
| 本体更新への依存 | APIやデータ構造の変更 | 対応版の固定、差分確認、互換試験 |
| 権利と保守 | 外部MODの許諾や更新方針が不明 | 独自実装を基本にし再利用条件を確認 |
| 面白さの欠如 | 第19章の指標が目標に届かない | 拡張を止め、第2章の柱に戻って設計を見直す |
| 数値の乖離 | 現行値の抽出で設計値が成り立たない | 比率と目標時間で較正し直す（第0章） |

### 他のMODとの関係

既存MODは機能の事例と問題点を知る資料として調べる。装備追加、経験値やレベル、ソケット数、パッシブツリー、無限進行などを個別に変えるMODがあっても、それらを同時に入れれば本計画が成立するとは扱わない。保存範囲、計算順序、同期、UI、更新状況が異なるためである。［S13］

同じ能力値や報酬処理へ変更を加えるMODは、競合の可能性が高い。初期公開では検証済みの組合せを明記し、未知の組合せでの安全性を保証しない。公開コードが見えることと、再利用・改変・再配布できることは別に確認する。

### 公開対象（決定）

公開対象は**検証したPC版の構成のみ**とする。コンソールとのMOD相互運用は対象外である。他MODとの併用は検証済みの組合せのみ明記する。

### 配布と更新

公式の手順ではWorkshopへのアップロード後や更新後に非公開状態となり、公開へ切り替える運用が示されている。公開前に対応版、必要環境、既知の不具合、導入・削除・復旧方法を確認する。実際の公開操作と利用規約への同意は、別途の承認を得て行う。［S7］

リリースは試験版と安定版を区別し、保存形式の変更は変更履歴の先頭で示す。緊急修正では無限発動、データ破損、進行不能を優先する。通常のバランス調整は影響を説明し、必要なら素材返還や再配分を用意する。
