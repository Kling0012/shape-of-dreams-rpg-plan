# Dreamforge RPG 開発計画

次に作るものを、実装の前に単独のコミットとしてここへ記す。完了した版は「完了」に移す。

## 方針（2026-10-01 改定）

Dreamforge は単独のゲームではなく **Shape of Dreams のMOD**。新しい要素は、本体の仕組み（Memory・Essence・属性・旅人の固有能力・祭壇・商人・ハンター・Limbo の深度）に乗り、それを強めるものを優先する。各項目に、土台にする本体のAPIを明記する。

## 次：v1.4「実際に遊べる形へ」（最適化・動線・ボリューム）

利用者の目標（2026-10-02）：実際に遊ぶことを考えて十分なボリュームと最適化・システム・構成にする。ロードすると動作が非常に重くなるので十分に最適化する。初めて触るときからの動線を考えて実装する。

1. **最適化（最優先）**
   - 毎フレームの処理を減らす：HUD は GUILayout をやめ、文字列を状態が変わったときだけ作り直して GUI.Label で描く。メニューの一覧・強さの集計は変更時だけ計算してキャッシュ。通知の大きさは作成時に一度だけ測る。描画イベントの種類で処理を絞る。
   - 保存をメインスレッドから外す：JSON化はメイン、ディスクへの書き込み（fsync・置換）は別スレッドでまとめて行う。保存の頻度も間引く。
   - ログを減らす：拾得・通知ごとの `Debug.Log` をやめ、重要なものだけ。
   - ホスト：敵の出現待ち行列に寿命を付けて溜まらないようにする。範囲検索は対象の固有効果を持つときだけ。
   - フォント：文字サイズの種類を減らし、動的フォントの作り直しを抑える。
   - 計測：`dreamforge_perf` で Update/OnGUI/保存の時間を表示できるようにする。
2. **初めて触るときの動線**
   - 初回の案内パネル（はじめての夢鍛）：F6 メニュー、遺物が落ちる、確保と潜行、装備の変え方、を順に。
   - 場面ごとのヒント（初めての拾得・確保地点・全滅・レベルアップ・刻印の解放など）。一度見たものは出さない。
   - 初期装備：最初の起動で各枠1つずつ遺物を配り、すぐ装備を試せるようにする。
   - 遠征中でも「確保地点で装備できる」ことが分かる表示、空の画面には次にやることを出す。
3. **ボリューム**
   - 本体の旅人9人それぞれの専用固有品（キットに効く固有効果の組み合わせ）。
   - 依頼・出来事・今日の夢の追加。
4. **試験**：ヒントの進行と一度きり、初期装備、保存の非同期化（順序・取りこぼしなし）。
