# 付録D  検証計画

[← 計画書に戻る](../README.md)

本付録は、開発が進んだ時に**遊びの質**と**安全性**を確かめる方法を定める。今回の計画書作成では、実装、実機試験、性能測定は行っていない。目標値は設計値であり、試験の結果で較正する。

## D1  遊びの質の指標

| 柱 | 指標 | 定義 | 目標 | 測り方 |
| --- | --- | --- | --- | --- |
| 読み合い | 再挑戦での被弾の減少 | 同じボスの3回目の挑戦での被弾数が、1回目の半分以下 | 参加者の70％以上 | 記録 |
| 読み合い | 予兆の見逃し | 「攻撃が見えなかった」との申告 | 1回の遠征あたり1件以下 | 質問票 |
| 構成 | 主要構成の使用率 | クリアした遠征の構成を分類し、使用率を出す | 4種以上が各10％以上、最大でも35％以下 | 記録 |
| 構成 | 構成が噛み合った実感 | 「自分で構成を作った実感があった」への肯定 | 80％以上 | 質問票 |
| 構成 | 必要部品なしの遠征 | 狙い系統で主要な部品が全く出なかった遠征の割合 | 5％以下 | 記録 |
| 帰還 | 続行と帰還の割合 | 安全地点での選択の比率 | 各30〜70％ | 記録 |
| 帰還 | 迷いの時間 | 安全地点の画面で選択までに要した時間 | 中央値が5〜30秒 | 記録 |
| 個性 | キャラの説明 | 「このキャラはこう戦う」を一文で言える | 80％以上 | 質問票 |
| 協力 | 共鳴の発動 | 4人の遠征での共鳴の発動数 | 1遠征あたり10回以上 | 記録 |
| 協力 | 役割の入替 | 同じ参加者が、遠征の中で複数の状態（印、障壁、拘束など）を付与した割合 | 60％以上 | 記録 |
| 協力 | 協力の満足 | 「協力でもう一度遊びたい」 | 70％以上 | 質問票 |
| 失敗 | 敗北理由の説明 | 敗北後に理由を言える | 80％以上 | 質問票 |
| 失敗 | 再挑戦率 | 敗北後の次の遠征の開始 | 70％以上 | 記録 |
| 失敗 | 遺失物の回収 | 遺失物ノードで回収を試みた割合 | 80％以上 | 記録 |
| 負担 | 整理の時間 | 拠点の時間÷遠征の時間 | 25％以下 | 記録 |
| 成長 | 停滞の感覚 | 「成長が止まった」と感じた区間の申告 | 標準遠征で1件以下 | 質問票 |
| 難度 | 初回クリア率（危険度1） | 初見の参加者による地域ボスの撃破率 | 40〜60％（3回の遠征まで） | 記録 |
| 難度 | 熟練者のクリア率（危険度1） | 熟練者の撃破率 | 85％以上 | 記録 |
| 難度 | ボスの初回撃破までの挑戦回数 | 中央値 | 2〜4回 | 記録 |

## D2  記録するイベント

記録は**プレイヤーが選べる**形にし、個人情報や不要な通信内容を保存しない。試験の参加者の同意を得て、ローカルに保存する。送信は参加者が選ぶ。

| イベント | 主な項目 |
| --- | --- |
| 遠征の開始・終了 | 地域、長さ、危険度、狙い系統、人数、結果、所要時間 |
| ノードの進入・完了 | ノードの種類、所要時間、被ダメージ、撃破数 |
| レベルアップ | 遠征内の経過時間、間隔 |
| 戦利品の拾得 | レア度、系統、アイテムレベル、拾った時点 |
| 装備の変更 | 枠、前後の装備、比較に要した時間 |
| 安全地点の選択 | 続行か帰還か、確保済み・未確保の量、迷いの時間 |
| 被弾 | 攻撃の種類、予兆の有無、ダメージ |
| 回避・防御の成功 | 攻撃の種類、反撃の成立 |
| 共鳴の発動 | 種類、参加者 |
| 状態の付与 | 状態、付与者、対象 |
| 全滅・蘇生 | 灯の消費、原因の攻撃 |
| 製作・強化・分解・再調律 | 対象、消費、結果 |
| 専門化の変更 | 前後のノード |
| 画面の滞在 | 拠点の各画面の滞在時間 |
| 性能 | フレーム時間、イベント数、メモリ、通信量（付録C7） |

## D3  試験の進め方と質問票

### 進め方

- **頻度**：段階2から、週に1回の遊びの試験を行う。
- **参加者**：6〜8人。初見の人と熟練者を半数ずつにする。協力の試験には、2人または4人の組を含める。
- **所要**：1回あたり約90分（拠点10分、遠征2回、質問票10分）。
- **観察**：画面の録画と、プレイ中の発言（考えを声に出す）を許可を得て記録する。
- **進行**：説明は最小限にし、ゲーム内の説明だけでどこまで理解できるかを見る。

### 調整のルール

- 数値の調整は、**一度に一つの変数**を変える。変えた内容と理由を記録する（D7）。
- 指標が目標を満たさない場合は、第7章の順序（基準線、外れ値、報酬）で調整する。
- 追加のコンテンツ（装備、敵、地域）は、その段階の通過条件を満たすまで増やさない。

### 質問票（短縮版）

1回の試験の後に、次を尋ねる（5段階または自由記述）。

1. もう一度遊びたいか。
2. 今回、何で勝てた（負けた）と思うか。
3. 構成を自分で作った実感があったか。
4. 攻撃の予兆は見えたか。見えなかった場面は。
5. 帰還か続行かで迷った場面はあったか。何に迷ったか。
6. 成長が止まったと感じた場面はあったか。
7. 拠点での整理は苦にならなかったか。
8. このキャラの戦い方を一文で言うと。
9. （協力）仲間の行動で、自分が強くなった瞬間はあったか。
10. その他、気になった点。

## D4  段階ごとの通過条件

各段階の通過条件は、**すべて満たすこと**を原則とする。満たさない項目は、次の段階へ進む前に解消するか、範囲を狭める。

### 段階0  設計の具体化

- [ ] 対象のゲーム版が固定されている。
- [ ] 星座、レベル、Mastery、難度の現行値と適用順序を表にした（公開情報の整理は済み。付録B10の13項目の抽出が残っている）。
- [ ] 第7章の層と配分を、現行値で較正した。
- [ ] 既存の蘇生の規則、難度設定、通貨の消費先を確認した。
- [ ] 技術試作の三つの接続点（能力補正の着脱、独自装備の保存、協力の報酬確定）の可否が分かった。連鎖の停止と性能計測は段階1で確かめる。
- [ ] 仮称を既存の名称と照合し、置き換えた。

### 段階1  共通基盤

- [ ] 能力計算の単体試験（層、上限、UIと戦闘の一致）が通る。
- [ ] 保存の往復、破損時の復旧、プロフィール切替、旧データの移行が通る。
- [ ] 報酬の確定が、再送・再接続でも重複しない（自動試験）。
- [ ] 連鎖の世代上限と内部クールダウンが働く。意図した無限循環が止まる。
- [ ] 装備と進行を、個人と部屋に分けて扱える。
- [ ] 性能の測定の仕組みが動く。

### 段階2  最初の協力プレイ版

- [ ] 2人が、準備、遠征、帰還、各自の保存、製作、遺失物までを通して遊べる。
- [ ] D1の指標のうち、読み合い、帰還、失敗、負担、難度が**初回の基準**を満たす。初回の基準は、割合の下限を持つ指標は目標の80％、上限を持つ指標（25％以下、1件以下など）は目標の125％以内、範囲を持つ指標は範囲の両端を10ポイント広げた値とする。
- [ ] 試験の参加者の70％が「もう一度遊びたい」と答える。
- [ ] 保存と報酬の事故（二重付与、消失）が試験中に0件である。
- [ ] 性能の予算を満たす（2人）。

### 段階3  戦い方と協力の拡張

- [ ] 主要構成が4種以上で、使用率が目標の範囲（各10％以上、最大35％以下）にある。
- [ ] 4人の協力で共鳴の発動数と役割の入替が目標を満たす。
- [ ] 育成差のある参加（r＝0.5と2.0）で、両者が「楽しかった」と答える割合が70％以上。
- [ ] 危険度0〜3で、複数の戦い方が地域ボスを撃破できる。
- [ ] 経済の指標（装備更新までの時間、素材の死蔵）が目標の範囲にある。

### 段階4  遊びやすさの仕上げ

- [ ] 再接続、ホスト終了、切断の復旧が、試験項目（D5）をすべて通る。
- [ ] 60分の遠征で、メモリの増加と通信量が予算内にある（4人）。
- [ ] 敵の予兆が、味方の演出より優先して見えることを、録画で確認した。
- [ ] エンドゲーム（螺旋挑戦、構成課題、夢食い）が遊べる。
- [ ] 色覚、揺れ、点滅の調整が動く。
- [ ] D1の全指標が目標を満たす。

### 段階5  公開候補

- [ ] 導入、削除、復旧の手順が文章になっている。
- [ ] 検証した環境と、検証した他MODの組合せの表がある。
- [ ] 既知の問題の一覧がある。
- [ ] 保存形式の変更と移行の方針が変更履歴の先頭にある。
- [ ] Workshopの公開は、別途の承認を得てから行う。

## D5  試験項目

### 自動

| 領域 | 項目 |
| --- | --- |
| データ定義 | 重複ID、参照切れ、上限外の値、タグの範囲、説明の生成 |
| 能力計算 | 層の順序、上限（L2、L3、軽減）、UIと戦闘の一致、着脱後の残留 |
| 保存 | 往復、検査値の不一致、書き込み中の終了の模擬、バックアップの世代、移行（版ごと） |
| 報酬 | 再送、再接続、同時操作、救済のkの更新 |
| 連鎖 | 世代の上限、内部クールダウン、同一由来の再発動の禁止、夢食いの牙の例外 |
| 協力の補正 | r′の式、範囲の境界値、人数の補正 |
| 経済 | 費用と収入の表の整合、分解の予告と結果の一致 |
| 性能 | 疑似戦闘での長時間の測定（付録C7） |

### 手動

| 領域 | 項目 |
| --- | --- |
| 切断と再接続 | 遠征中、安全地点、結果画面、ボス戦中の各場面 |
| ホスト終了 | 直近の確定成果の保全、安全地点からの再開 |
| 途中参加 | 拠点・安全地点で参加でき、遠征中は参加できない |
| プロフィール | 切替、削除、MODの除去と再導入 |
| 損失 | 全滅時の残響、遺失物の保存、遺失物ノードの回収、取り戻せなかった遺失物の持ち越し、保管の上限（10個）を超えた場合の分解の予告 |
| 装備の整理 | 保護品が分解されない、プリセットの保存と復元、フィルター |
| 協力の公平性 | 経験値の配分、状態付与の貢献、個人抽選 |
| 表示 | 予兆の優先、演出の調整、色以外の区別 |
| 操作機器 | キーボード・マウスとコントローラーで装備整理が同じ手順でできる |

## D6  面白くない状態の検出と対応

第2章の「面白くない状態」を、次の手順で検出し、コンテンツの追加より先に直す。

| 状態 | 検出 | 最初の対応 |
| --- | --- | --- |
| 一つの構成が突出 | 使用率が35％を超える。採用された部品が偏る | その構成の加算枠・条件付き枠の上限を見直し、他の構成の苦手を補う手段を増やす |
| 敗北の理由が分からない | 理由を言える割合が80％未満 | 敗北画面の内訳、予兆の表示、戦闘ログを見直す |
| 帰還の判断に迷う余地がない | 続行または帰還が70％を超える | 未確保の量、次の安全地点の距離、続行の報酬の見せ方を調整する |
| 予兆が見えない | 見逃しの申告が多い。録画で埋没が確認できる | 味方の演出の優先順位と、予兆の描画の規則を見直す |
| 整理に時間がかかる | 拠点の時間が遠征の25％を超える | フィルター、一括分解、プリセットの機能を強化する |
| 簡単な場所の反復が最適 | 時間あたりの効率が低い危険度で高い | 危険度の倍率、低い帯の素材の変換比率を見直す |
| 成長が止まる | レベルアップの間隔が目標を超える | 節目報酬と専門化の入手、敵の経験値の比率を見直す |
| 構成が成立しない遠征 | 必要部品なしの遠征が5％を超える | 狙い系統の重み、再抽選、救済を見直す |

## D7  調整の記録

調整は、次の形で変更ログに残す。

| 項目 | 内容 |
| --- | --- |
| 日付と版 | MODの版、データ定義の版 |
| 変更 | 変更した変数と、前後の値 |
| 理由 | どの指標が目標を満たさなかったか |
| 影響 | 影響する層、構成、報酬 |
| 結果 | 次の試験での指標の変化 |
| 補償 | 素材の返還、専門化の再配分の有無 |

プレイヤーに影響する調整は、変更履歴で説明する。大きな調整では、素材の返還や再配分を用意する（第20章）。
