# v1.29 wave 1 — モンスター側 / Monster side

既存13変種を維持して **26変種**、既存10性質のビットを維持して **20悪夢性質**にする。本体に存在する敵を再利用する行動変種であり、新規3Dモデルや追加攻撃ではない。新しい性質は追加のダメージ技・行動不能を与えず、位置、攻撃後の隙、味方の分離、攻撃を続ける判断を変える。

## 新しい悪夢性質

各性質の軽減は30%。同時に有効な新しい軽減は加算後に通常40%、ボス20%で止まる。本体の防御・既存性質とは別の層。新しい性質自体に常時攻撃力・魔力・防御を足さない。ランダム悪夢には共通の最大HP +40%だけが残る。

## 強さを重ねる順序と予算

1. 本体の敵能力に、変種（または悪夢共通能力）と既存の深度能力を**加算**する。通常・MiniBossの深度1当たりHP +8%・攻撃+4%、深度3以降の防御+10は維持。ボスは深度4以降HP +10%/深度のみ。
2. その結果に`DreamPressure.HealthMultiplier` / `DamageMultiplier`を**乗算**する。新性質は追加の常時攻撃・魔力を持たない。
3. 新しい軽減を、状況に応じて適用する。通常上限40%で有効耐久倍率は最大1/0.6≈1.67、ボス上限20%では最大1.25。Committedの回復中やPhaseOpeningは軽減を無視して受ける量を1.2倍にする。無期限の防御だけを積む設計ではない。
4. 回復要求は10%の有限予算、障壁は15%・6秒・一生に一度。Beaconは出現後2秒に一度だけ試行し、孤立していても試行を消費して後から不意に付与しない。受け手は同じ非null区画内で判定し、同距離はnetIdで決める。BeaconとLastStandは受け手の同一障壁枠を使い重複しない。支援元を倒すと付与済みの味方障壁も消える。LastStandは0.1秒刻みで閾値を確認し、2秒予告後に一度だけ6秒の障壁。従来のWarded等の数値は変更しない。

例：深度5のMist SpitterはHP `(1 + 0.60 + 0.40) × pressure`、攻撃 `(1 + 0.20) × pressure`。夢レベル25・使用星40の参加者ならpressureはHP1.70、攻撃1.34なので、本体比HP3.40、攻撃1.608。距離条件を満たす間だけHP相当が約4.86となり、6m以内へ入れば3.40へ戻る。Eclipse Demonは深度5でHP `(1 + 0.20 + 0.50) × pressure`、新ガード中もボス上限20%で止まり、二度の攻撃機会でさらに下がる。

DreamPressureは人間参加者の夢レベル・使用星ポイントの**平均**。等しいビルドが1人でも4人でも同じ倍率であり、人数分の乗算はしない。本体の人数補正をMODで二重に掛けない。装備が未受信の参加者も夢1・星0として平均に含める。

完全成長（夢レベル30・使用星150）では、圧はHP2.375・攻撃1.675。深度5の通常・MiniBoss新変種は、常時HPが本体比4.275〜4.9875、常時攻撃は2.01（魔力は圧のみ）となる。最大HP+70%の新変種へ二つの守りを両方通し続ける最悪の有効HP相当は8.3125だが、分離・側面・攻撃後の隙という解除手段を持つ。新性質だけの悪夢はHP4.275、軽減上限を受け続けても有効HP7.125。ここへ追加の人数倍率・人口・新攻撃を足さない。

Eclipse Demonは同条件でHP4.0375、守り中の有効HP5.046875、フェーズ開放中は3.3646。ボスへ新たな攻撃力・魔力・速度を足さず、重いHPを追加攻撃ではなく二つの反撃機会と短い明滅で扱う。既存の強力な悪夢・本体の難度・Limbo補正はそのままであり、この数値はそれらの本体強度に対する上乗せの範囲を示す。実戦の秒数や全滅率を予測した値ではない。

調査対象は `D:/app/stm/steamapps/common/Shape of Dreams/Shape of Dreams_Data/Managed/` の `Dew.Core.dll` と `Dew.Contents.dll`。アセンブリは読み取り専用で利用し、出力先はゲーム外の `C:/Temp/v129-monster-api/`。

- 行動フック：`.ref/dump/Entity.txt`の被ダメージプロセッサ、攻撃発射、被ダメージイベント、同区画・関係判定。`.ref/dump/EntityControl.txt`の`ongoingChannels`。`Entity.ProcessReceivedDamage`からプロセッサが実行されること、`DamageData.ApplyRawMultiplier`が`originalAmount`を変えることは共有API調査で確認されている。
- 攻撃元の位置：共有調査で`Actor.firstEntity` / `FindFirstOfType`を`Actor.cs` 2246〜2263行と`.ref/dump/Actor.txt`で確認。弾の接触位置ではなく最初のEntity祖先を使い、取れなければ`damage.originPosition`へ退避、それも不明なら軽減なし。
- 回復・障壁：`.ref/dump/Actor.txt`と逆コンパイル`Actor.cs`の`Heal` / `GiveShield`。GiveShieldは初期量と時間を持つ。
- 状態表示：`.ref/dump/EntityVisual.txt`と逆コンパイル`EntityVisual.cs`。`SetShaderProperty(string, Color)`は全クライアント向けClientRpcで`includeOwner=true`、`_CMEmission`は静的初期化に存在する。金=障壁予告、琥珀=条件付きガード、シアン=攻撃後の隙・フェーズ開放・敵の減速、緑=回復。状態変化時と5秒再同期、解除時は黒へ戻す。`GetNew*Modifiers`はローカルAPIであり、それ自体を同期機構とは扱わない。

- 純粋ロジック：`src/SodRpg.Core/Game/MonsterBehavior.cs`の`PulseGuarded`、`IncomingMultiplier`、`MovementPct`、`HealingPct`、`ShouldWarnLastStand`、`CrossedHealthPhases`。データ/表示は`Nightmares.AffixDescription`、`Nightmares.HasBehavior`、`Variants.IsExpanded`。ホスト統合は`src/SodRpg.Mod/HostAuthority.Monsters.cs`と`HostAuthority.cs`のフック、性質説明と色の凡例は`DreamforgeUi.cs`。戦闘状態は出現単位で保持し、死亡・除去・切断で解除。保存フィールドは増やさず、撃破統計は既存codecで保存する。
