# PR #434 の融合と旧版取引の保護

PR #434 の融合（同名・同レア度の材料、最大5段、1段6%、保存・鍛冶表示）は、
現行mainの #444 と #447 に取り込み済み。この修正版はそれらを維持して、
旧版との交換で融合段階を失う経路を保護する。元PRに残っていた融合段階の
ハッシュ加算は、現行の段階を直接比較するキャッシュで既に置き換わっている。
空ファイル `3` は機能に関係しないため取り込まない。

## 交換の可否

- 旧ホスト、または対応が未確認のホスト・交換相手へ融合済み遺物を提示しない。
  提示・確認の送信と予約の前に、既存の画面の理由表示へ日英の説明を返す。
- 新ホストは双方の probe の `fusion` から対応を確認し、view の
  `partnerFusion` で相手の対応を通知する。欄がなければ未確認として扱う。
  旧版の送り手がこの保護を持たない場合も、ホストが提示時・予約時・成立直前に拒否する。
  対応広告が後退した場合も成立前の取引を取り消す。
- 融合していない遺物と素材は交換できる。交換対象外の融合済み遺物は保持する。
  ホスト・相手とも対応していれば融合段階を含めて交換する。
- 保存済みの予約・成立記録は書き換えない。過去の LegacyFusion 予約の精算、
  取消、再接続照会は残す。既に旧版へ渡して失われた融合段階の自動復元は行わない。
- 共通Protocol、Hello、取引versionと保存形式は変更しない。
  検証は取引操作やprobeを受けた時だけで、毎フレームの一覧・割り当てを追加しない。

## 審査懸念の確認

`WithoutFusionForLegacyTrade` はパース後のキーを再帰確認し、融合キーがない場合は
入力文字列の参照を返す。受領書の変換も変更がない場合は元の文字列を返す。
既存の `CoopTradeMigrationTests` で旧受領書のバイト列保持と未知の欄の保持を検証する。
この処理を無条件のJSON再出力へ戻さない。

`HostBuildValidation.Encode` の `R:` は `hero.Equipped` のみを列挙する。
未装備の融合済み遺物はビルド入力に含まれず、`WithoutFusion` が装備中だけを
段階0にする実装と整合する。既存ケースで未装備の段階5を残し、送信する装備は
14欄、未装備のUIDは入力に出ないことを確認する。
