# v1.14.1 仕様：分解の返事待ちに遠征が終わったときの扱い（issue #8）

担当：方針は Claude、実装は GPT（OMP 経由）、試験は Claude。

## 問題

分解の返事待ちの間に遠征が終わると、`Rules.EndRun` が対象の遺物を保管庫（勝利）か遺失物（敗北）へ移す。その後に成功の返事が来ても、鞄（`Run.Satchel`）しか探さないため遺物が消えず、ダストも付与されて二重取りになる。容量があふれて素材に変わった場合も、取り消せない。

## 方針：返事待ちの遺物は「預かり」に入れて、遠征の精算から外す

1. `Profile` に `PendingSalvage`（返事待ちの遺物の一覧。各要素は遺物と「失敗したときの戻し先」＝ Stash / LostAndFound）を足す。ProfileCodec で保存する（古い保存では空）。
2. `Rules.EndRun` の精算の**前に**、予約中の遺物（`TradeLedger.IsReserved` が true の物。`EndRun` に予約中の Uid の集合を渡せるようにする）を鞄から取り除き、`PendingSalvage` に入れる。戻し先は、勝利なら Stash、敗北なら LostAndFound。これで、確保・遺失物への移動・容量あふれの素材化の対象にならない。
3. 成功の返事：`Run.Satchel` か `PendingSalvage` から、その Uid の遺物を1つだけ取り除く（どちらにも無ければ何もしない）。
4. 失敗の返事・送信できなかったとき・30秒の期限切れ：
   - 遺物が `Run.Satchel` にあれば何もしない（予約が解けるだけ）。
   - `PendingSalvage` にあれば、戻し先へ戻す。Stash があふれる場合は Stash に入れられるだけ入れ、入らなければ LostAndFound へ（それもあふれたら既存の「あふれた遺失物は欠片に換える」処理に従う）。
5. ゲームを再起動したときなど、`PendingSalvage` に残っているのに対応する取引が無い場合（取引台帳は保存しない）：MOD の起動時に、`PendingSalvage` の遺物をすべて戻し先へ戻す。
6. 予約中の遺物と `PendingSalvage` の遺物は、装着・鍛冶・合成・分解・出来事の対象にしない（今の予約の扱いと同じ）。

## 守ること

- 試験は GPT が書かない（Claude が書く）。コアの処理（EndRun・預かり・戻し）は `Rules` に置き、試験できる形にする。
- 既存の動き（予約していない遺物の精算）は変えない。
