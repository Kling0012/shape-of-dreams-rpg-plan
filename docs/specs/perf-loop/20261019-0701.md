# perf-loop/20261019-0701

対象: mod src/SodRpg.Mod/ClientSession.CoopTrade.cs（と、そこから通信ごとに呼ばれる受信処理）。

直した内容: `OnCoopTradeState` の `view` 処理（ClientSession.CoopTrade.cs:564 付近）は、ホストから届く取引ビュー 1 件ごとに自分自身の提示内容の複製 `msg.ownOffer` を必ず JSON 展開していた。この展開結果が使われるのは `OwnOffer` を組み立てる 1 箇所だけで、自分の編集中の提示がまだホストの応答（ack）を待っている間（`_coopPendingOffer != null`）は、展開結果が捨てられ views には編集中の下書きが入る。そこで、`_coopPendingOffer` がある間は `msg.ownOffer` の展開を丸ごと省き、捨てられるはずだった解析と提示オブジェクト（遺物 UID のリストを含む）の確保をやめた。展開の省略は ack ブロック（`offerAck` の照合と `_coopPendingOffer` の確定）の後に評価する。最初の版が ack ブロックの前で `_coopPendingOffer` を読んでいたのをレビューで直したもので、これにより `_coopPendingOffer` を view 組立直前に読むという評価時点が変更前と完全に一致する。

結果が変わらない理由: 展開結果の参照は 1 箇所だけで、その箇所は `_coopPendingOffer != null` のときに限り元から `ownOffer` を使わない。省く条件（view 組立直前の時点で `_coopPendingOffer != null`）は「結果が捨てられる条件」と完全に一致するため、`CoopTradeView` に入る値・画面の表示・以降の ack 照合（`msg.ownOffer` との文字列比較）・送信処理は 1 文字も変わらない。ack が届いた view では ack ブロックが下書きを確定させるため、そこでは従来どおりホストの返送を展開して `OwnOffer` に入る（下書きオブジェクトではなく展開結果であることも含めて変更前と同じ。CoopTradeClientTests の新規 3 件で確認した）。ホストが異常な `ownOffer`（空・壊れた JSON）を送ってきた場合だけ挙動が変わり、従来は例外が `DisableCoopTrade` で取引全体を停止させていたところを、ack 待ちの間は展開しないため例外が起きなくなる。ホストは正常な view に必ず自分の提示を入れる（HostAuthority.CoopTrade.cs の `SendCoopView`）ため、正常な通信では違いが出ない。

効果の見込み（推定）: 提示の編集中・確認待ちの間に届く view 1 件ごとに、小さな JSON 解析と `CoopTradeOffer`（UID 文字列のリスト付き）1 個分の確保が省ける。view はイベント発生時（提示の更新・確認・取消など）にしか届かないので、頻度は毎フレームではなく編集中に毎秒数件の程度であり、削減は受信側の CPU と確保のごく一部と推定する（推定）。通信量・送信回数・判定・見た目は変わらない。
