# perf-loop/20261020-0714

対象は本体 `Dew.Core/ChatManager.cs`（703行）と、そこから通信ごと・発言ごとに呼ばれる処理である。実 DLL（2026-10-19 版）から ilspycmd で再取り出しし、空白正規化 diff で逆コンパイル物と照合した。差分は `base.` 修飾や `default(bool)` 表記など逆コンパイラの表現差のみで、ロジック差はなかった。

毎フレーム経路はゲスト側では `LogicUpdate` の `isServer` の1比較だけだった。ホスト側の残りは発言制限用のレート辞書の減衰で、通常は空の辞書への軽い処理である。送信系（Cmd・BroadcastMessage・TargetRpc）はすべて利用者の操作かゲーム内イベントの起点で、値が変わらないのに繰り返す送信はなかった。ゲストの受信処理に乗るのはチャット系メッセージの受信で、その中で毎回の確保をしている箇所はミュート判定の1つだけだった。ほかに見た `SafeAction.Invoke` と発言フィルタ（`DewSafety.FilterProfanityIfEnabled`）は、前者がハンドラ数による高速パス、後者がコンパイル済み正規表現のキャッシュをすでに持っていて、触る価値がなかった。

直した内容は、チャット受信ごとのミュート判定 `ChatManager.IsPlayerMutedByNetId(uint)` を Harmony Prefix で置き換え、本体の `DewPlayer.allHumanPlayers.Find(ラムダ)` がメッセージ受信ごとに確保するクロージャ（表示クラス＋デリゲートの2確保）を、確保なしの for ループに変えることである。`src/SodRpg.Mod/NativePerfPatches.cs` に `NativeChatMuteAllocPerf` として追加し、MOD 設定 `nativeChatMuteCheckAlloc`（既定は有効）で切れる。対象のメソッドが見つからない・引数名が変わっているときは警告を1回出してこの修正だけ外れる。このメソッドは Chat 型と UnlockedAchievement 型のメッセージを受信するたびに、ホスト・ゲストを問わず各クライアントで1回ずつ走る（本体の `UserCode_BroadcastMessage__Message` と `UserCode_TargetBroadcastMessage__...` のミュート判定）。プレイヤーのチャット、実績の解放、RPGItems の `[RPGDUST]` 通知（分解時にゲストからホストへコマンドで伝わり、本体が全員に再送する）などがここを通る。

結果が変わらない理由は次のとおりである。本体の `List<T>.Find` と置き換えた for ループは、同じ順序で同じ「最初に一致した要素」を探す走査で、判定結果（見つからなければミュート扱い、見つかれば `IsPlayerMuted` の結果）が同一になる。netId は実体ごとに一意で、一致の向きも本体と同じである。ミュート一覧の判断自体は本体の公開メソッド `IsPlayerMuted` をそのまま呼ぶため、その中身が将来更新されても引き継ぐ。`allHumanPlayers` が null になるような異常時は Prefix を外して本体に戻す（本体と同じ例外の伝わり方になる）と同時に、警告1回を出してこの修正を停止する。

効果の見込み（推定）は、受信したチャット系メッセージ1件につき、全クライアント（ゲストを含む）でクロージャとデリゲートの2確保（合計100バイト弱の推定）と、参加人数ぶんのデリゲート呼び出しがなくなることである。チャット系の受信は利用者操作の起点で頻度は低いため（数十件/分が上限の目安）、効果は小さい。ただし、このファイルのゲスト側受信経路に残っていた唯一の毎回の確保であり、結果が変わる箇所はない。数値は推定で、実機での計測は行っていない。

見送った候補は次の3つである。`LogicUpdate` はゲスト側1比較・ホスト側も通常は空の辞書の減衰で触る価値がなかった。送信系はすべてイベント起点で、間引けるものがなかった。発言の無害化（`SanitizeUserInput` の正規表現）と発言フィルタは、どちらも .NET の正規表現キャッシュを使っていて、発言制限（8件/12秒）で頻度も低かった。

検証は次のとおりである。`python3 tools/balance/gen_cs.py --check` を通した。`dotnet build src/SodRpg.Mod -c Release -p:GameDir=... -p:ModDeployDir=/tmp/perfloop-x` を通した（エラー0、警告は既存分のみ）。`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` は 561 件すべて通過した。`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release` は 225 件通過・1 件スキップで失敗はなかった（スキップは既存のもの）。実機（ゲーム内）での確認は未実行である。この環境ではゲームを動かせないためである。
