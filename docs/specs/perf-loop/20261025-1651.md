# perf-loop/20261025-1651

対象: `Dew.Core/ActorTransformSync.cs`（座標同期の毎フレーム補間）

## 直した内容

ActorTransformSync は、受信した座標サンプル（SyncVar の `_syncData`）を速度で外挿した
目標姿勢へ SmoothDamp で追わせる FrameUpdate を、ホストと参加者の全端末で
全アクター分毎フレーム走らせます。これまでの2件の軽量化
（perf-loop/20261018-1631 の静止時の再送省略、20261025-0353 の Transform 書き戻し省略）で
通信とネイティブ書き込みは止まりましたが、その後も補間が収束したアクターに対しては
毎フレーム、外挿の計算と SmoothDamp（内部で Time.deltaTime のネイティブ呼び出しを含む）
が「変わらない結果」を出し続けていました。

MOD 側に `NativeTransformSyncHoldPerf`（NativePerfPatches.cs）を追加し、
FrameUpdate への Harmony Prefix で、全チャンネルが「サンプル・描画状態
（`_renderPos` / `_renderRot` / `_renderScale`）・Transform の現在値の三者がビット一致し、
かつ三つの速度と SmoothDamp の速度項が厳密に 0」のときだけ本体を丸ごと省きます。
設定での切り替えは DreamforgeConfig の nativeTransformSyncHold（既定は有効）で、
パッチ先が見つからないときは警告1回でこの機能だけ外れます。
サーバは同じ呼び出しの中で `_serverTickPending` を消費して座標を確定するため、
その経路は常に本体へ流します（省略が効くのは参加者と、確定が済んだ後のホストです）。

## 結果が変わらない理由

- 判定を満たすとき、本体の計算はフィールドと Transform を1つも変えません。
  速度が厳密に 0 なので外挿項は符号を問わず ±0 になり、保存値に -0 成分がなければ
  目標姿勢はサンプルとビット一致します。現在値と目標がビット一致し速度項が ±0 のとき
  SmoothDamp は恒等式になり、速度項も ±0 のままです。Transform への書き込みは
  0353 のラッパーがビット一致で省いています。成分ごとの確認は NativePerfPatches.cs の
  コメントに書きました。
- 判定は状態を持たず、毎フレームの現在値だけでやり直します。動き出した・新しい
  サンプルが届いた・アニメーションなど外部が Transform を動かした、のいずれも
  次のフレームで判定が外れて本体に戻るので、本体と同じ更新が続きます。
- Unity の == は許容差つきなので、判定の一致は 0353 のラッパーと同じビット比較で
  行います。NaN は常に一致しないと扱い、本体どおり書かれます。
- -0 成分や、正規化で 1ULP でも動く回転（`Quaternion.Normalize` の一致を見る）は
  本体がまだ状態を変えるので省きません。位置・回転・拡大のどれか1つでも
  省けないチャンネルがあれば、そのアクター全体を本体に流します。
- 破壊済みアクターの読み出しで出る NullReferenceException /
  MissingReferenceException は、判定を本体へ流すことで本体と同じ例外として出ます。

## 効果の見込み（推定）

参加者端末では FrameUpdate が全アクター分走るため、静止して補間が収束した
アクター1体あたり、毎フレームの外挿と SmoothDamp が判定1回に置き換わります。
1回あたり百ナノ秒程度（推定）で、数十〜数百体のうち静止分の数だけ効く見込みです。
動いている間と、ホストの座標確定と同じ呼び出しの間は本体のままなので、
効果は静止分に出ます。リンクした NativePerfPatches.cs が参照する名前のぶんだけ、
テストの境界スタブ（ActorTransformSync・DreamforgeConfig・Quaternion.Normalize）を
合わせました。新しいテストは足していません。
