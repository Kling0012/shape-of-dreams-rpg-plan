# perf-loop/20261025-0644

## 対象

`mod src/SodRpg.Mod/HostAuthority.Waypoints.cs`（道標のホスト側。受信フックの登録・解除、道標に応じた回復・障壁・HP・召喚ダメージの係数、記憶のクールダウン軽減、悪夢化の抽選）。この partial の処理はすべて `HostAuthority` の tick とホスト側のイベントフックからだけ呼ばれ、参加者の PC を走る経路はない。利用者の指示どおり、毎フレーム・イベントごとの経路（探すもの 3・4）の観点で見た。

## 直した内容

毎フレームの tick 項目 `SyncWaypointHeroes` が呼ぶ `WaypointRoster.Diff`（`src/SodRpg.Core/Game/MpHostRules.cs`）に、追跡中のヒーローを `Dictionary.Keys`、現在の隊を `List<Hero>` として `IEnumerable<T>` の引数で渡していた。`IEnumerable` 経由の列挙は実装が構造体でもインターフェース呼び出しでボクシングされるため、毎フレーム 2 個（`List<T>.Enumerator` と `KeyCollection.Enumerator`）の小さな確保がホスト側で起きていた。`List<T>` を直接巡る index ループの `Diff` のオーバーロードを `MpHostRules.cs` に足し、呼び出し側では追跡辞書の鍵を既存の scratch と同じ要領の新しい scratch List（`_waypointTrackedScratch`）に写してから渡すようにした。空の隊の代わりに使う `Array.Empty<Hero>()` のキャストも、共有する空の `List<Hero>`（`EmptyHeroRoster`）に替えた。隊として渡す `_am.allHeroes` は本体 `Dew.Core.dll` の `ActorManager` で `public List<Hero>` と宣言されているため（検証欄の逆アセンブル確認）、`_am != null ? _am.allHeroes : EmptyHeroRoster` の型は `List<Hero>` になり、新しい `List<T>` 版が選ばれる。既存の `IEnumerable<T>` 版はそのまま残し、配列を渡している既存のテストとほかの呼び出しは変わらない。

## 結果が変わらない理由

scratch への写しは Diff より先の同じ tick の中で行われ、その間に辞書や隊の構成を変える処理はなく、列挙の順序は元の `Keys` と同じ順になる。`Diff` の `List<T>` 版は `IEnumerable<T>` 版と同じ比較を同じ順で行うので、`toAdd`／`toRemove` に入る要素と順序は同一で、追加・解除のフックの付け替えも同一になる。この出力の一致は、null 要素・不適格なヒーロー・追跡だけにいるヒーロー・隊だけにいるヒーローを含む同じ入力を両オーバーロードへ渡して `toAdd`／`toRemove` の要素と順序が一致することを確かめるテスト（`MpHostFixesV131Tests.WaypointRosterListDiffMatchesEnumerableDiff`）でも機械的に確認した。判定に使う `isEligible`（null・`isActive`・`Status` の確認）は値を読むだけの純粋な関数で、写しと実物のどちらを巡っても結果は替わらない。`EmptyHeroRoster` は空で不変であり、`Array.Empty<Hero>()` と同じ空の走査になる。

## 効果の見込み（推定）

ホストの tick から毎フレーム 2 個、60fps で毎秒約 120 個・1 分あたり約 7,000 個の小さな列挙子の確保がなくなり、GC のきっかけになるゴミが毎秒数 KB 減る。目に見るほどの差ではなく、GC の発生頻度をわずかに下げる程度の見込み。ホスト側だけの経路で、参加者への送信内容・回数・タイミングは替わらない。実測はしていない推定。

## 見送った候補

- `ApplyWaypointMemoryCooldown` が早抜けの guard より先に `WaypointTotalsForHero` を計算している点。スキル使用ごとの経路で、`Waypoints.Sum` は配列 1 回の参照返し（確保なし）なので、順序を替えても減らせる処理が小さすぎる。
- `SyncWaypointHeroes`・`RefreshRunModifiers` の毎フレーム処理の間引き。ヒーローの離脱検出や道標替わりの stats 再計算のタイミングが替わり、結果が替わりかねない。
- 回復・障壁・HP の各プロセッサの中身。`Waypoints.Sum` はキャッシュ済み `Totals` の参照を返すだけで、すでに確保のない最小の形。
