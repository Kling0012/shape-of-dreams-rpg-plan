# perf-loop/20261019-0542

対象: mod src/SodRpg.Mod/InfinityMode.cs（と、そこから毎フレーム・継続セーブごとに呼ばれる経路）。

直した内容: `WriteEnvelope`（InfinityMode.cs:448）はインフィニティの実行状態（グラフ、クリア済みノード、フェーズなど）を JSON 化して `GameSettingsManager.customData["dreamforge.infinity.runtime"]` に書き込む。この辞書は Mirror の SyncDictionary で、インデクサの set は同値の再設定でも必ず OP_SET を記録して全クライアントへ再送する（sod-decomp Mirror/SyncIDictionary.cs の実装で確認。同値比較は行われていない）。一方、本体は継続セーブ（`GameManager.SaveContinueData`）をノード移動のたびに、ボス戦などのロック中は20秒以上あくごとに（GameManager.cs:1033 の `_lastContinueSaveUnscaledTime > 20f` 判定）実行し、そのたびに MOD の `DewPersistence.SerializeGameData` へのパッチ（`InfinityNativeSave`）が `PrepareNativeInfinityContinue` → `WriteEnvelope` を呼ぶ。前回の書き込みから状態が変わっていないとき（同じ部屋の中での20秒ごとのロックセーブ、部屋開始時の `InfinityRoomIdentity` による書き込みと移動完了時のセーブの重複など）も、エンベロープ全文の serialize と全クライアントへの再送が毎回起こっていた。書き込む文字列を先に作り、現在の customData の値と完全一致するときは書き込みを省くようにした。

結果が変わらない理由: 省くのは「すでに全員が持っている値と同じ文字列の再送」だけである。ホストと参加者の辞書の中身は書き込み前後で同一なので、`TryReadEnvelope`・`NativeEnvelopePresent`（ContainsKey）・Continue への埋め込み・途中参加の同期（OnSerializeAll は現在値を全件送る）のどれも結果が変わらない。同値検出に失敗したとき（JSON のキー順が変わるなどの想定外）は書き込みが行われ、従来どおりの動作に戻る。変わった状態の書き込み（フェーズ遷移、RoomEpoch の更新、グラフ再生成）は、文字列が一致しないため必ず送られる。確定・撃破・報酬・ロック解除の送信には触れていない。

効果の見込み（推定）: 通信面では、ロック中のボス戦（Polaris のロックは StarlessPath_BossPolarisManager から LockMidRunSave）で20秒ごとに起きていたエンベロープ全文（状態の規模に応じて数百バイト〜、推定）の全クライアント再送がなくなり、ノード移動ごとの2回目の書き込みも省かれる。CPU 面では同値時の Mirror 側の OP_SET 記録がなくなるが、変化検出のための serialize 自体は残る。送る必要がある変更は従来どおり即時に送るため、参加者への状態の届き方は変わらない。
