# perf-loop/20261025-0136

## 対象

`src/SodRpg.Mod/ClientSession.GemSlotConflict.cs`（MOD 側。旧バージョン向けの互換メッセージの受信と、技ボタンの宝石枠 HUD の点検・修復を受け持つファイル）。

参加者側で走る経路から確認した。受信処理 `OnGemSlotConflict` は、ホストの `ClearGemSlotConflict`（`HostAuthority.GemSlotConflict.cs`）がビルドの適用時にだけ送る任意メッセージを受け取るだけで、中身は null 検査と `Protocol.WarnMismatch`（HashSet で全セッション 1 回に絞られている）のみで、無駄はない。残るプレイ中の経路は `TickGemSlotHudProbe` で、毎フレームの 24 ステップ tick の 1 つだが、実行は 1 秒に 1 回に間引かれている。記録用の最初の 1 回を過ぎれば移動（Movement）以外のボタンは飛ばす（20261024 の前の回で対応済み）のだが、移動ボタンについては `GetComponentInChildren<UI_InGame_SkillButton_GemGroup>(true)` で親の副木を毎秒走査し続けていた。非表示になった gem group を見つけて表示へ戻すのがこの点検の目的なので、走査は非表示のものも含める `true` 付きで、セッションの間ずっと毎秒走る。

## 直した内容

一度見つけた移動ボタンの gem group を字段 `_movementGemGroup` に覚え、次の点検からはその参照を使うようにした。副木の走査は、覚えた参照が壊れた（Unity の `== null` が真になった。HUD の作り直しで古い UI が破棄されたときに起きる）ときと、まだ見つかっていないときだけ行う。走査本体は `FindGemGroup` に取り出しただけで、中身は元のコードと同じ（親があれば `GetComponentInChildren(true)`、なければ null）。記録用の最初の 1 回は全ボタンの走査と名札への記録を従来どおり行い、そのとき移動ボタンの group を字段に覚える。

## 結果が変わらない理由

点検が group 参照に要求することは、`(1) 毎秒、その GameObject が非表示かどうかを確かめられること` と `(2) 非表示なら表示へ戻せること` で、どちらも破棄されていない Component 参照があれば足りる。非表示の group は参照が有効なままなので、キャッシュしていても検出も修復も毎秒の同じタイミングで起きる。参照が壊れるのは UI が破棄されたときだけで、そのときは Unity の `== null` で同じ周期の中で探し直すので、検出が遅れる周期はない。まだ見つかっていない間（group が存在しない構成のとき）は従来と同じく毎秒探し直す。この前提は本体自身と同じで、`UI_InGame_SkillButton.Awake`（本体の逆コンパイル `Dew.UI/UI_InGame_SkillButton.cs` の 192 行目）は同じ親子関係の gem group を Awake で一度見つけて寿命の間キャッシュし直しておらず、本体の `UI_InGame_SkillButton_GemGroup.Awake` も逆方向の参照を同じ方法で固定している。記録の 1 回で出すログの内容も、走査の結果が同じなので変わらない。

## 効果の見込み（推定）

定常状態で、移動ボタンの親の副木走査（全孫孫の Transform を巡って各々 GetComponent を試す。gem 枠の並びを含むので数十コンポーネント規模）が毎秒 1 回から 0 回になり、Unity の `== null` 比較 1 回と `activeSelf` の読み 1 回だけになる。1 秒 1 回の小さな経路なので 1 フレームあたりの負荷への寄与はもともと小さいが、点検のたびに必ず走っていた処理が常時 0 回になり、ホスト・参加者のどちらでも同じだけ減る。実測はしていない推定。

## 見送った候補

- `OnGemSlotConflict`（受信処理）。送信側がビルド適用時のイベント駆動だけで、警告も 1 回に絞られており、減らすものがない。
- 記録 1 回の後は点検自体を止める案。非表示への戻しはいつ起きてもおかしくない事象への保険なので、点検を止めると保険が消える（報告された症状の再発を見逃す）。
- `softInstance` の参照（毎秒 1 回）。`ManagerBase<T>.softInstance` は静的字段の参照返しで、`instance` のような `FindObjectOfType` は走らない。
