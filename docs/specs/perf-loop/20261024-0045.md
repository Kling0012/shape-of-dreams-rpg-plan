# perf-loop/20261024-0045

対象は `src/SodRpg.Mod/HostAuthority.BossNyx.cs` である。直した内容は、Nyx の印表示の配送で、`NyxPublishMarks` が `PublishBossVisual` に渡す `due` を毎回の現在時刻から印の蓄積開始時刻（`NyxState` に追加した `MarkDue`）に固定した点である。stage3 の命中で印が0から増えるときに開始時刻を記録し、状態の消去時に戻す。同じ規約は Skoll の印表示（`SkollPublishMarks`、`HostAuthority.BossSkoll.cs`、perf-loop/20261023-2325）で既に採用済みである。

送信が減るしくみは次のとおりである。`PublishBossVisual`（`HostAuthority.BossVisuals.cs`）には、前回と全フィールドが同じなら何も送らずに返る同一性判定がある。Nyx の印は持ち主（ヒーロー）の移動に合わせて位置を追従させるため、印を持っている間は0.25秒ごとに再発行していて、従来は `due` に毎回の現在時刻を渡していた。そのため、位置も数も変わっていない再発行でもこの判定が必ず失敗し、kind 9 の間引き（0.1秒の保留窓）は0.25秒ごとの発行間隔では働かないので、0.25秒ごとに revision を1つ進めて全員へ1通ずつ送っていた。クライアント側（`ClientSession.BossVisuals.cs`）でその差分が変えるものは何もない。`due` を固定すると、静止中で数が変わらない再発行は同一性判定で止まり、送信も revision の更新もなくなる。移動時・数の増減・削除は従来どおりの経路で即時に届く。

結果が変わらない理由は次のとおりである。クライアントで `due` を読むのは `pending = effect.due > now`（表示色の濃さとリングの太さ）だけで、Nyx の印のリングは `finalRadius` を送っていないので `due` からの進行度は半径に使われていない。従来の送信でも `due` は送信フレームの `Time.time` で、クライアントは受信時刻との差し引きのあと `pending` を false と判定する。蓄積開始時刻は必ずそれより過去なので、固定後も `pending` は false のままであり、線の太さと色は変わらない。印の数・位置の追従・削除のタイミングも、変更前と同じ経路で届く。

効果の見込みは推定だが、印が付いていて持ち主が静止している間、全員宛ての差分送信（従来は1つの印につき4通/秒）と、各参加者の `OnBossEffects`（全効果の検証付きの受信処理）がその分だけなくなる。Nyx の印は stage3 の命中のたびに寿命が12秒に延びるため、戦闘が続くあいだ付き続けることが多く、戦闘中に継続して流れていた無駄である。削減量は印が付いているヒーローの数と静止している割合に依存する。ホスト側も、0.25秒ごとの差分送信と revision の更新が同一性判定の早期 return になる。実機（ゲーム内）での確認は未実行である（この環境ではゲームを動かせないため）。

レビュー（PR #1071 の F1）を受けて、上の性質を印の経路そのもので確かめるテストを追加した（`tests/Issue73.Native.Tests/NyxMarkTests.cs`、境界は `NyxMarkBoundary.cs`、抽出は `NativePersistence.targets` の `CompileNyxMarks`）。`HostAuthority.BossNyx.cs` の印の経路（`NyxGet`・`DispatchNyxBoss`・`TickNyxBoss`・`NyxReconcileTokens`・`NyxPublishMarks`・星点の設置と消去・`NyxState`・`NyxChannelState`・持ち主ごとの状態一覧）を実ソースから抽出して動かし、(1) 位置も数も変わらない0.25秒ごとの再発行は差分も revision の更新も保留も生まないこと（間引き窓をまたいだ再発行と `NyxPublishMarks` の直接呼び出しの両方で）、対照として持ち主が動いた再発行は間引き窓（直前の送信から0.1秒）の外では即座に1通出て、窓の中では保留に入ること、(2) 印の増加は即時の差分になり、`due` は蓄積開始時刻のまま送信時刻以下で届き、クライアントの `pending = effect.due > now` が false のままであること。満ちた印（3つ）の再取得は数が変わらなくても期限（`MarksUntil`）の延長を送ること、(3) 期限切れで印が消えたあとに再び印が付くと `MarkDue` が新しい蓄積開始時刻に更新されること、を確かめる。敵の引き寄せ、種（kind 3）・領域（kind 4）・ダッシュ（表示なし）と星界の運命（stage6）の毎ティック処理、予約の帳簿、障壁と移動の実行は印表示の対象外として形だけの境界にする（`SkollMarkBoundary.cs` と同じ扱い）。これに伴い、`NativeBoundary.cs` の `EntityControl` に移動終了・中断の通知の形を、`SkollBurstBoundary.cs` の `BossCombatState` には `Build`・`Movement`・`Defense`（Nyx の経路が読む分）を部分宣言で足した。追加後の `DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` は728件通過（既存の Skoll の印とバースト表示のテストを含む）。
