# perf-loop/20261025-0448

対象は mod `src/SodRpg.Mod/HostAuthority.cs` である。ホスト側の権威処理の中核で、毎フレームのティック工程、被弾・撃破・通信ごとのフック、そしてゲストへの送信の出口を持つ。ゲスト側の負荷につながる出口を点検した。圧力の定期送信（`SendPressure`）は既に変更検知と5〜30秒の再送で絞られており、依頼カウント（`TickBountyReports`）は1秒間隔にまとめ済みで、モンスター分類は `HostAuthority.KillSync.cs` の過去のループで絞り済みだった。毎フレームの工程（`UpdateRuntime`、`UpdateReactions`、`TickGuard` の各ステップ）も確保はなく、要素数の小さい早期リターンばかりだった。残っていたのは仕掛け発動の報告である。

見えた構造は次のとおりである。仕掛けや組コンボが発動するたびに `QueueGimmickRequests` が `rt.PendingGimmickReports` に件数を積み、ティック工程「gimmick apply」（`StageGimmickApply`）が毎フレーム `FlushGimmickReports(rt)` を回して、未送信があれば `DreamforgeBountyReportMsg`（`GimmicksTriggered`、累計件数）を1通送る。#161 で「発動ごとに1通」から「ティックごとに1通」にまとめられたが、発動が続く戦闘ではティックごとに未送信が積まるので、1秒あたり最大でフレーム数と同じ回数（60fps で最大60通）がゲストへ届く。同じ「累計を送る」形の依頼カウントは、20261020-1522 で1秒間隔にまとめる変更が入れられ、受け入れられている。

直した内容は、`StageGimmickApply` のフラッシュを1秒に1回へ間引いたことである（`BountyFlushSeconds` = 1秒。`TickBountyReports` の `_nextBountyFlush` と同じ `_tickNow` による間引きの型）。キャラを外す直前のフラッシュ（`Unhook` の冒頭、#161 の「落とさない」）は間引かず即時のままである。`HostAuthority.cs` は `tests/Issue73.Native.Tests` にリンクできないため、原則 II（結果が変わらないことをテストで確かめる）のために、間引きの判定（`IsTickDue`）と累計の取り出し（`TakePending`）を新しい小さなクラス `GimmickReportThrottle`（`src/SodRpg.Mod/GimmickReportThrottle.cs`）に切り出し、`StageGimmickApply` と `FlushGimmickReports` はそれを使う形にした。このファイルをテストプロジェクトにリンクして、`Issue1171GimmickReportThrottleTests` で複数フレームにわたって発動を積んだときの1秒ごとの送信合計が毎フレーム送った場合の合計と一致することと、間引きを待たない境界の取り出し（Unhook と同じ）が残り全体を返すことを確かめている。

結果が変わらない理由は次のとおりである。送る値は「前回のフラッシュからの累計」なので、送信を1秒に束ねてもゲストが受け取る合計は同じである。ゲストの受信処理（`OnBountyReport` → `Rules.OnGimmicksTriggered` → `AdvanceBounty`）は件数をそのまま足すだけの加算で、到着の細かさに依存しない。最後の値は、キャラを外す直前の即時フラッシュが保証する。遠征の終わりではキャラの取り外しが先に起き、同じ信頼性のある順序付きチャネルで終了通知が後に続くので、締めの前に未送信が送り出される。変わるのは依頼「GimmickUser」の進捗の計上が最大1秒遅れることと、ゲストが突然切断されたときに未送信分として最大1秒ぶん（変更前は最大1フレームぶん）失われる可能性があることだけである。これは依頼カウントの集計報告（20261020-1522）で既に受け入れられているのと同じ性質である。スキル使用・連携・被弾系のほかの個別報告と、戦闘の状態を運ぶ電文は触っていない。

効果の見込み（推定）は、仕掛けや組コンボのビルドが戦闘中に発動を続けているときの、この報告のゲスト宛ての送信が毎ティック最大1通から毎秒1通になることである。ホストの直列化と送信、ゲストの受信・逆直列化・ハンドラ・`Emit` がその回数だけ減る。発動のないフレームの負荷は、間引きの判定1回だけでほぼ変わらない。
