# perf-loop/20261018-1541

対象: mod src/SodRpg.Mod/ClientSession.Continue.cs

## 直した内容

`ConfirmNativeContinue`（本体の再開保存が書き終わったあとの `DewSave.onSaveEnded` で呼ばれる）は、
確認のためだけに保存ファイルを2つの JObject DOM として読んでいた。1つ目はファイル全体
（root → continueData）、2つ目はその中の continueData で、本体のゲーム状態全体に加えて MOD 自身の
Continue.Profile / Continue.Trades の大きなスナップショット文字列を含む。実際に必要なのは
serverActorData の2つの短いキー（Continue.Id / Continue.Run）だけである。

この読み取りを JsonTextReader のストリーム読み取りに置き換えた。2つのキーが揃った時点で読み取りを
終え、それ以外の値（プロファイルのスナップショットを含む）は Skip() で読み飛ばして DOM に
保持しない。ただし、読み取り位置が文字列値を通る場合は、その文字列の一時確保が残る。
JObject の LINQ to JSON 依存はこのファイルから消えた。

## 保存の確認と読み取りの扱い

- 通常の保存では、読むタイミング・読み先・取り出す2つの値は同じで、変えたのは読み方だけである。
  確認の判断（ConfirmContinueCheckpoint への引き渡し、不一致時の警告）は変更していない。
- 読み取りで例外が起きた場合やチェックポイントが一致しない場合は、既存の catch が
  WarnUnconfirmedContinue で警告する。fail-soft のまま。
- 値は DateParseHandling.None で、ファイルに書かれたままの文字列として読む。
- 文字列・null 以外のキー値は例外にし、serverActorData が JSON null の場合は2つのキーを null のまま返す。
  旧実装は数値などのキー値を文字列に変換し、serverActorData の JSON null では例外になっていた。
- 重複キーは、最初の serverActorData を対象に先頭から読み、2つの非 null のキー値が揃った時点で終了する。
  揃う前に同じキーが現れれば後の値で上書きするが、揃ったあとの重複キーは読まない。
  旧実装の JObject は最後の値を採っていたため、この入力では結果が異なり得る。
  早期終了を維持する方針とし、重複キーの互換性は保証しない。MOD 自身は各キーを文字列として1回ずつ書く。
  これらの入力までの等価性は、既存テストでは確認していない。

## 効果の見込み（推定）

onSaveEnded は保存のたびにメインスレッドで走る。再開保存（部屋の到着・ボス撃破・20秒抑制のある
途中保存）のたびにチェックポイントの取得と確認が1回ずつ起こり、確認の側でこの読み取りが動く。これまでの実装は
ファイル全体と continueData の DOM を作り、Continue.Profile などの文字列も保持していた。ストリーム
読み取りでは continueData の文字列と2つのキーを取り出し、2つの DOM と不要な値の保持を省く。
読み飛ばす文字列の一時確保は残るため、削減できるメモリ量と GC 負荷は、保存サイズとキーの位置に
依存する。効果は推定で、実測していない。
