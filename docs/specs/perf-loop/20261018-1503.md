# perf-loop/20261018-1503

対象は本体 `Dew.Core/Accessory_AttachPoint.cs`。装飾品（帽子・腰の装飾など）を英雄のモデルへ毎フレーム追従させるコンポーネントで、`LateUpdate` が `UpdatePosition` を呼び、その中で `FindOffset` が走る。

## 直した内容

`FindOffset(entityOrSkinName)` は `customOffsets` のリストを名前の一致で線形探索する。`LateUpdate` はモデルが変わらない限り同じ文字列（`_cachedOriginalName`）を毎フレーム渡すため、リストが変わらなければ結果は毎フレーム同じになる。この照会を `NativePerfPatches.cs` に足した `NativeAccessoryOffsetPerf`（Harmony の Prefix/Postfix）でキャッシュし、名前・リストの参照・件数が前回と同じなら本体の走査を省いて前回の結果を返す。設定は `nativeAccessoryOffsetCache`（既定は有効）。

## 結果が変わらない理由

`FindOffset` は引数の文字列と `customOffsets` の中身だけから決まる純粋な検索で、本体のコードは実行時に `customOffsets` を書き換えない（逆コンパイルを grep で確認。参照は `Accessory_AttachPoint.cs` の内部のみ）。キャッシュの鍵は文字列とリストの参照一致に件数で、どれかが変われば作り直す。内容が同じでも別の文字列インスタンスなら照合に失敗し、本体の処理をそのまま通す。

キャッシュするのは見つかった `AttachOffset` の参照で、位置・回転・拡大率は毎フレーム `UpdatePosition` の本体の計算が読み直す。追従、HatHalo の浮遊と向き、拡縮の補正は本体のまま。パッチ先が見つからない・実行時に例外が出たときは警告1回で本体の動作に戻る（fail-soft）。設定で切れる。

## 効果の見込み（推定）

毎フレームの文字列比較の繰り返しがなくなる。装飾品1つにつき毎フレーム数十〜数百ナノ秒、実行中の装飾品は十数個程度なので、全体では毎フレーム数マイクロ秒程度の削減と推定する（微小）。`customOffsets` が空の装飾品はもともと比較が早く終わるため、削減はほぼなく、英雄ごとの調整を多く持つ装飾品ほど効く。

実機での確認はしていない（見た目・数値は変わらないため、コードとテストで確認した）。
