# perf-loop/20261020-0515

対象は MOD の `src/SodRpg.Mod/HostAuthority.KillSync.cs` である。このファイルはホスト側の撃破ストリームとモンスター分類の同期を担い、参加者（ゲスト）が受信するメッセージの送出口になっている。ゲスト側の負荷に関わる経路は、毎フレームの `TickKillReplay` が直す `FlushMonsterSync` と、権威世代の更新や観測セッションの再割り当てのあとに走る `SendNextKillReplay` のモンスター全件再送（`cursor.Monsters` の先頭から1件ずつ、分類1通と行動合図1通を対象ごとに送る）である。

直した内容は、その全件再送が行動合図 `DreamforgeMonsterCueMsg` の cue=0 を送っていたのをやめたことである。実装は `SendNextKillReplay` から毎フレーム・通信ごとに呼ばれる `src/SodRpg.Mod/HostAuthority.Monsters.cs` の `SendMonsterBehaviorCue` にあり、対象（`target != null`）を指定した呼び出しで、state を持たないモンスターへの cue=0 送信と、計算した cue が 0 になるときの送信を省いた。ブロードキャスト経路（`target == null`）と 0 以外の cue の再送は従来どおりである。

結果が変わらない理由は、ゲスト側の `OnMonsterCue`（`src/SodRpg.Mod/ClientSession.Monsters.cs`）では cue=0 は `RemoveMonsterCue`、つまり辞書のエントリ削除だけであり、エントリが無ければ何も起きないからである。ゲストの cue エントリは「受信した最新のブロードキャスト値が 0 でない」間だけ存在する。行動の着脱は必ずブロードキャストを伴い（`rt.Behavior` の代入は付与時の `SendMonsterBehaviorCue(rt, true)` と `RemoveMonsterBehavior` 内の `QueueMonsterCue(netId, 0)` だけ）、`TickKillReplay` は同じフレームの前の段 `StageMonsterBehaviors` で積まれたブロードキャストを先に drain する。通信は本体の `CustomRpc_SendMessageToClient` / `SendMessageToAllClients` が Mirror の TargetRpc / ClientRpc、つまり同一接続上の reliable ordered なので、再送の cue=0 がゲストに届くとき、同じ状態を伝えるブロードキャストは必ず先に処理済みで、エントリは存在しない。権威世代の更新でゲストが状態を消した直後も、再送が必要なのは 0 以外の cue だけで、0 は消すべきエントリを持たない。分類メッセージ（所有権の表示に必要）と 0 以外の cue は送り続けるので、ゲストで見えるものは変わらない。

効果の見込み（推定）は、権威世代の更新（部屋をまたぐホスト俳優の作り直し）や観測セッションの再割り当てのたびに、生きているモンスター1件につき1通の割合で届いていた cue=0 をなくすことである。悪夢化・変異のない通常モンスターがほとんどの部屋では、再送メッセージの約半分がこれに当たる。各1通はホスト側の `DewPersistence.ToJson` の文字列化と Mirror への書き込み、ゲスト側の JSON パースとハンドラ呼び出しを1回ずつ減らす。部屋をまたぐ頻度に依存するため秒あたりの数値は出せないが、移動直後のゲストの受信処理を確実に減らす。数値は推定で、実機での計測は行っていない。

検証は `python3 tools/balance/gen_cs.py --check`（変化なし）、`dotnet build src/SodRpg.Mod -c Release -p:GameDir=... -p:ModDeployDir=/tmp/perfloop-x`（0 エラー、警告 6 件は既存のもの）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release`（551 件全通）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release`（225 件通過・1 件スキップは既存のもの）を実行してすべて通した。この helper を使う既存テストはない（`tests/Issue73.Native.Tests/NativeBoundary.cs` のハーネスは `HostAuthority.Monsters.cs` をコンパイルせず、スタブで置き換えているため、テストの期待値は変わらない）。実機（ゲーム内）での確認は未実行であり、コードとテストで理論上正しいことを確かめた段階である。
