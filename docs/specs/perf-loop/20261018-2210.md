# perf-loop/20261018-2210

## 対象

mod src/SodRpg.Mod/ClientSession.cs（毎フレームの `Tick` → `SendBuildIfNeeded`）。

## 直した内容

`SendBuildIfNeeded` の中の `RefreshForbiddenGearNotice`（禁忌装備 #415 の警告の出力確認）の呼び出しを、送信スロットルの早期 return の前から後ろへ移した。この確認は装備15欄それぞれについて `Profile.FindStash`（倉庫の全走査）を呼ぶ。ホストが #415 の対応を宣言していない間（MOD なし・旧版のホスト）は早期 return に入らないため、これまでビルドを送らない tick でも毎フレーム走査が回っていた。移動後はビルドを実際に評価する tick（変更・強制再送・ハートビート。応答のないホストで5秒間隔）でのみ走る。

## 結果が変わらない理由

警告の内容・条件は同じで、確認する時期だけが送信の評価点に揃う。装備の変化は MarkDirty（`_buildDirty`）を、ホストの能力応答は `OnBuildInputCapability` が `_buildDirty = true` を通るため、警告はすぐに出る。遅れの上限は、応答のないホストでハートビート1回分（5秒、警告文が少し遅れて表示されるだけ）。ビルド本体の送信・抑制の条件は変えていない。現行版のホスト（`_hostForbiddenInput` が立つ）とソロプレイ（`NetworkServer.active`）は従来から最初の1行で return しており、挙動は完全に同じ。

## 効果の見込み（推定）

MOD なし・旧版のホストに参加している間、毎フレームの「装備15欄 × 倉庫の遺物数」の文字列比較がなくなる。倉庫500個・60fpsなら約4万5千回/秒の比較に当たる（推定。実際の削減量は倉庫の大きさとフレームレートに依存）。
