# perf-loop/20261018-1810

対象: native Dew.Core/CameraManager.cs（と、そこから毎フレーム呼ばれる経路）。

直した内容: `GetFollowOffsetTarget`（CameraManager.cs:278）は毎フレーム `FrameUpdateZoom` から呼ばれ、返り値の `Quaternion.Euler(0f, entityCamAngle, 0f)` を毎回計算し直している。この四元数は `entityCamAngle` のセッターが `entityCamAngleRotation` フィールドに同じ式で保持しており、本体側に使い回す仕組みがあっても使っていない。NativePerfPatches.cs に NativeCameraZoomRotationPerf を追加し、トランスポイラでこの1箇所の Euler 呼び出しだけを `FollowRotation` の呼び出しに置き換えた。角度が 0 以外なら `entityCamAngleRotation` を返し、0 なら実行時に元の式を計算する。ズームの補間、修飾子の走査、観戦中の分岐は本体のまま残す。MOD 設定は `nativeCameraZoomRotation`（既定で有効）。

結果が変わらない理由: セッターは `entityCamAngleRotation = Quaternion.Euler(0f, _entityCamAngle, 0f)` を代入し、`Euler` は入力だけで決まる純粋な呼び出しのため、角度が一度でも設定されれば保持値と再計算はビット単位で一致する。逆コンパイル全体で `_entityCamAngle`（バッキングフィールド）と `entityCamAngleRotation` を書く場所は CameraManager 自身だけ（Room.cs:344/349 はプロパティ経由）で、MOD にも書き込みはない。角度が 0 のとき（未設定の初期状態を含む）は `FollowRotation` が実行時に元の式 `Quaternion.Euler(0f, camera.entityCamAngle, 0f)` を計算する。-0f もそのまま渡すため、どの状態でも返り値は元の式と一致する。呼び出し箇所の形はゲーム DLL の IL で確認した（ldc.r4 0 / ldarg.0 / get_entityCamAngle / ldc.r4 0 / Euler の5命令）。

シリアライズの点検（レビュー F1 への回答）: `_entityCamAngle` は `[SerializeField]` の付かない private フィールドで、`entityCamAngleRotation` には `[NonSerialized]` が付く（CameraManager.cs:75/78）。継承は `ManagerBase<CameraManager>` → `LogicBehaviour` → `MonoBehaviour` で NetworkBehaviour ではなく、シーン・プレハブ・逆直列化のどの経路もセッターを飛ばして角度を入れられない。したがって「角度が 0 以外なのに保持値が初期値のまま」という状態は発生せず、FollowRotation が保持値を返す前提は成り立つ。

効果の見込み（推定）: カメラ角度が 0 でない部屋で、毎フレーム1回のネイティブ呼び出し（Internal_FromEulerRad）とその前後の演算が省ける。1回は数百ナノ秒程度と推定し、フレーム時間への影響はごく小さい。角度が 0 の部屋では変わらない。ゲーム内の数値・判定・見た目には影響しない。

テスト（レビュー F1 で追加）: Issue73.Native.Tests に CameraZoomRotationPerfTests を追加した。実ソースから抽出した Transpiler そのものを、本体 GetFollowOffsetTarget と同じ命令並びの見本（CameraZoomIlShapes、ゲーム DLL の IL_009e〜IL_00b3 と同じ5命令の窓）に当てる。警告が出ないこと、5命令の窓がちょうど1箇所だけ nop / ldarg.0 / FollowRotation / nop / nop に置き換わること、窓の外が変わらないこと、置き換え後のスタック収支が元と同じ（Quaternion を1つ残す）ことを確かめる。窓の形が壊れた見本（引数が定数でない・Euler が2箇所・Euler がない）では何も置き換えず警告を1回出すことも確かめた。FollowRotation は角度 0 で元の式・0 以外でセッターが保持した値・設定 OFF で毎回再計算を返すことを、境界のセッター（本体と同じ不変）に対して確かめる。
