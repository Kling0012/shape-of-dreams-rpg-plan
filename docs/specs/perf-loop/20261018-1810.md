# perf-loop/20261018-1810

対象: native Dew.Core/CameraManager.cs（と、そこから毎フレーム呼ばれる経路）。

直した内容: `GetFollowOffsetTarget`（CameraManager.cs:278）は毎フレーム `FrameUpdateZoom` から呼ばれ、返り値の `Quaternion.Euler(0f, entityCamAngle, 0f)` を毎回計算し直している。この四元数は `entityCamAngle` のセッターが `entityCamAngleRotation` フィールドに同じ式で保持しており、本体側に使い回す仕組みがあっても使っていない。NativePerfPatches.cs に NativeCameraZoomRotationPerf を追加し、トランスポイラでこの1箇所の Euler 呼び出しだけを `entityCamAngleRotation` の読み取りに置き換えた。ズームの補間、修飾子の走査、観戦中の分岐は本体のまま残す。MOD 設定は `nativeCameraZoomRotation`（既定で有効）。

結果が変わらない理由: セッターは `entityCamAngleRotation = Quaternion.Euler(0f, _entityCamAngle, 0f)` を代入し、`Euler` は入力だけで決まる純粋な呼び出しのため、角度が一度でも設定されれば保持値と再計算はビット単位で一致する。逆コンパイル全体で `_entityCamAngle`（バッキングフィールド）と `entityCamAngleRotation` を書く場所は CameraManager 自身だけ（Room.cs:344/349 はプロパティ経由）で、MOD にも書き込みはない。角度が 0 のとき（未設定の初期状態を含む）は置き換えず同じ式を計算するため、どの状態でも返り値は元の式と一致する。呼び出し箇所の形はゲーム DLL の IL で確認した（ldc.r4 0 / ldarg.0 / get_entityCamAngle / ldc.r4 0 / Euler の5命令）。形が変われば警告を1回出して本体のまま動く。

効果の見込み（推定）: カメラ角度が 0 でない部屋で、毎フレーム1回のネイティブ呼び出し（Internal_FromEulerRad）とその前後の演算が省ける。1回は数百ナノ秒程度と推定し、フレーム時間への影響はごく小さい。角度が 0 の部屋では変わらない。ゲーム内の数値・判定・見た目には影響しない。
