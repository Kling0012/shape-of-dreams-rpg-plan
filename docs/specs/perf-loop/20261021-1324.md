# perf-loop/20261021-1324

対象は `native Dew.Core/Se_MirageSkin_Delusion_Delusional.cs` である。ミラージュスキンのモンスターが英雄にダメージを与えるたびに付く「妄想」デバフで、スタックが回復量を削り、ホストは付与・スタック更新・回復イベントのたびに処理し、参加者はスタックの同期と表示を受け取る。

直した内容は、`ActiveLogicUpdate` の毎フレームのボリューム更新である。この本体コードは `delusionalVolume.targetStrength` を `Mathf.MoveTowards` で目標値へなめらかに動かし、その直後で無条件に `FxVolume.UpdateVolume()` を呼ぶ。MoveTowards は 0.3 秒で目標に収束するので、収束後は値が変わらないフレームでも `UpdateVolume()` を呼び続けていた。MOD 側に `NativeMirageVolumeIdle`（`src/SodRpg.Mod/NativePerfPatches.cs`）を追加し、トランスパイラでこの呼び出し1か所を `ApplyVolume(FxVolume)` に置き換えた。`ApplyVolume` は `currentValue`・`targetStrength`・`_contextMultiplier` の3値が前回書き込んだときと一致していて `_volume` が null でなければ呼び出しを省き、そうでなければ本体の `UpdateVolume()` をそのまま呼ぶ。設定 `nativeMirageVolumeIdle`（既定は有効）で切り替えられ、パッチ先が見つからない・形が違う場合は警告を1回出して従来どおりの動作に下りる。

結果が変わらない理由は、`UpdateVolume()` の書き込みが3つの入力だけの純関数だからである。`weight = currentValue * targetStrength * _contextMultiplier`、`enabled = currentValue > 0`（FxVolume.cs:59-63）なので、3値がビット単位で一致しているなら書き込む値は現状と同じになり、省いても画面の weight・enabled は動かない。入力が動く経路はどれも実書き込みを伴う。`currentValue` は基本クラス `FxInterpolatedEffectBase.Update` が値の変化ごとに `ValueSetter` を通して書き、`_contextMultiplier` は `Play()` が設定したあと `base.Play()` 内の `ValueSetter` で書く。`ValueSetter` は引数を無視して現状値から同じ式で書き直すので、`OnDisable` の `ValueSetter(0f)` も同じ形である。`targetStrength` を外から書くのはこの効果の `ActiveLogicUpdate` と `OnDisable`（効果の消滅時、実呼び出しが残る）と `FlavourManager`（演出強度の一括変更）だけだが、FlavourManager が違う値を書けば次のフレームで記録と一致しなくなり、実呼び出しで回収される。本体コード全体で `UpdateVolume()` を外から呼んでいるのはこの1か所だけで、あとは `FxVolume` 内部の `ValueSetter` から呼ばれるため、パッチの及ぶ範囲はこのデバフの表示に限られる。

効果の見込みは推定だが、デバフが付いている英雄1体ごと・毎フレームに、`Behaviour.enabled` へのネイティブ呼び出し1回と weight のフィールド書き込みが消える。1回は 0.1〜0.3μs 程度（60fps で1体あたり毎秒 10μs 前後）の小さな削減で、デバフはミラージュスキンの攻撃が当たっている間だけ存在する。この経路はホストでも参加者でも同じように走るので、参加者側にも同じだけ効く。付与・スタック・回復削減・RPC（0.35 秒間引き済み）の通信は一切変えていない。

検証は `python3 tools/balance/gen_cs.py --check`（通過）、`dotnet build src/SodRpg.Mod -c Release -p:GameDir="$HOME/dev/sod-gamedata/Shape of Dreams" -p:ModDeployDir=/tmp/perfloop-x`（0エラー、警告6件は既存のもの）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release`（655件通過）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release`（231件通過、1件スキップは既存のもの）を行った。加えて、実 DLL（Dew.Core.dll）から `ActiveLogicUpdate` の IL を取り出すドライランを /tmp のコンソールプログラムで行い、`UpdateVolume` の呼び出しが1か所だけあること、`Prepare()` が実 `FxVolume` の `_volume`・`_contextMultiplier` を解決すること、置換後の命令列が `ldfld delusionalVolume` → `call ApplyVolume(FxVolume)` になることを確認した。実機（ゲーム内）での表示確認は未実行（この環境ではゲームを動かせないため）。
