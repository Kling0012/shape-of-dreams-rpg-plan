# perf-loop/20261024-0635

対象は `src/SodRpg.Mod/HostAuthority.BossBeam.cs` である。直した内容は、本体の光線（Beam of Balance）が1体に命中するたびに、MOD 側の同じ検証（ビームと親・記憶・術者・部屋・Run が今も有効かを確かめる `InkBeamCurrent` と、`BossEnsure`・`InkReconcile`）を、1回の命中の中で繰り返していた点を1回にまとめたことである。ネイティブの `Hit` は呼び出しの先頭で必ず MOD の `PrepareInkBeamHit` を通る（`InkBeamNativeHit.Prefix`）ので、そこで出した判定を `InkBeamState.HitPrepared` に覚え、同じ命中の中で走る3つのコールバック（ダメージのプロセッサ `OnProcess`、イベント `OnDealDamage`・`OnDoHeal`）ではその判定を流用する。流用のあいだに同期に変わり得るのは親・ビーム・術者の消失だけなので、その3つだけを確かめ直す。覚えた判定がないときは、従来どおり全部を確かめ直す。

覚える判定の条件は従来のコールバックの条件と同じである。変更前の `InkBeamNative` が true を返すのは
`InkBeamCurrent` と `BossEnsure` の両方が通ったときだけなので、`HitPrepared` もその両方が通ったときだけ立つ
（`BossEnsure` が失敗した命中ではフラグは立たず、各コールバックは従来どおり全検証を自分で走らせる。
失敗が装備やゾーン遷移に由来するときは `ClearBossEffects` がビーム状態自体を破棄するため、以後のコールバックは
同一性の確認で止まる）。また `InkReconcile` は力の Build か光線の記憶スキルが変わったときだけ処理を行い、
dispatch のコールバックは計数・予算・クールダウンの刻印・演出しか書き換えないため、1回の `Hit` の中では
先頭の1回で全体を賄える。

結果が変わらない理由は次のとおりである。流用する判定が確かめるのは親・ビーム・スキル・術者・部屋・Run の同一性であり、1回の `Hit` の中のダメージと回復の dispatch のあいだでこれらは変わらない。dispatch の中で同時に起こり得る消失は、反撃などでビームか術者が倒れることなので、生存の再確認で同じ結果になる。覚えた判定は命中の先頭で必ず作り直す。先頭の最初の確認（MOD 由来の再帰でないか）で早抜けしたときは、同じ確認を各コールバックでも行うため、古い判定は使われない。`Hit` は `isServer` の gate でホスト専用であり、命中ごとの3つのコールバックはすべてこの `Hit` の中でしか発生しない（本体 `Hit` の dispatch は1ダメージ+1回復で、契約の確認で毎回数えている）。この変更は参加者側の処理と通信に触れない。もともとこのファイルの参加者側の経路は、4つのパッチが `NetworkServer.active` の確認だけで抜けるため負荷がほぼなく、観点3（被弾ごとの経路での重複した計算）に従ってこの箇所を選んだ。

効果の見込みは推定だが、命中ごとの検証が、敵への命中で3回から1回、味方への命中で2回から1回に減る。光線の範囲には敵のほかに味方と召喚物も入るので、範囲内のエンティティが多い部屋ほど減る割合が大きい。1回の検証は辞書引きと欄の読み取りが中心で軽いため、削れる量は1回の命中あたり数十〜百程度の単純な操作の推定である。実機（ゲーム内）での確認は未実行である（この環境ではゲームを動かせないため）。
