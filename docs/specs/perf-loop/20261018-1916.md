# perf-loop/20261018-1916

対象: native Dew.Core/CharacterModelDisplay.cs（と、そこから毎ロジックTick・毎フレーム呼ばれる経路）。

直した内容: `LogicUpdate`（30Hz）は毎Tick、体のレンダラー全員の `Renderer.bounds` を読み直して `_bounds` を作り直している（CharacterModelDisplay.cs:89-96）。この値を読むのは `GetCenterPosition` / `GetAbovePosition` の2つだけで、その唯一の呼び出し元はロビーの回転チュートリアル（PlayLobby_RotateCharacterTutorial、1回完了すれば以後非表示）のため、タイトル画面・スキンpreview・チュートリアル完了後のロビーでは、この全走査は誰にも観察されない。NativeCharacterModelDisplayBounds を追加し、`LogicUpdate` の Prefix で `_currentRenderers` を空のリストと差し替えて本体の走査を飛ばし、2つのゲッターの Postfix で前回の計算から1/30秒以上経っていたら同じ式で再計算して返す。MOD設定は `nativeCharacterModelDisplayBounds`（既定で有効）。設定を切ったときは次のTickでリストを本体へ返し、元の30Hz走査に戻す。

結果が変わらない理由: `_bounds` は private フィールドで、読む経路は上の2つのゲッターだけ（逆コンパイル全体で呼び出し元はチュートリアルのみ。MODにも参照なし）。読まれない間の再計算は観察されないため省いても結果は同じ。読みがある間は1/30秒ごとに再計算するため、読み値の鮮度は最長1/30秒という本体のロジックTickと同じ保証を保つ。再計算の中身は本体と同一（先頭のboundsを代入し残りをEncapsulate、対象がなければ `_bounds` を更新しない）。FrameUpdate（不透明度）・スキン差し替え・フォーカス通知は本体のまま。差し替え後も `Setup` は現在のリストを埋め直すため、スキン変更のたびに新しいリストを受け取って使い直す。

効果の見込み（推定）: ロビー（最大4体）・タイトル画面（最大4体）・スキンpreview（1体）の表示ぶん、毎ロジックTick×体のレンダラー数（推定6〜10）の `Renderer.bounds` ネイティブ呼び出しが消える。ロビー4体で推定700〜1200回/秒ほど。チュートリアル表示中の1体だけは読み駆動で同率の再計算が残る。ゲーム内の数値・判定・見た目には影響しない。
