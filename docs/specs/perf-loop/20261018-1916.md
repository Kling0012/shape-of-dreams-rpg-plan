# perf-loop/20261018-1916

対象: native Dew.Core/CharacterModelDisplay.cs（と、そこから毎ロジックTick・毎フレーム呼ばれる経路）。

直した内容: `LogicUpdate`（30Hz）は毎Tick、体のレンダラー全員の `Renderer.bounds` を読み直して `_bounds` を作り直している（CharacterModelDisplay.cs:89-96）。この値を読むのは `GetCenterPosition` / `GetAbovePosition` の2つだけで、その唯一の呼び出し元はロビーの回転チュートリアル（PlayLobby_RotateCharacterTutorial、1回完了すれば以後非表示）のため、タイトル画面・スキンpreview・チュートリアル完了後のロビーでは、この全走査は誰にも観察されない。NativeCharacterModelDisplayBounds を追加し、`LogicUpdate` の Prefix で `_currentRenderers` を空のリストと差し替えて本体の走査を飛ばし、2つのゲッターの Prefix で `_bounds` を読みの直前に作り直す。MOD設定は `nativeCharacterModelDisplayBounds`（既定で有効）。設定を切ったときは次のTickでリストを本体へ返し、元の30Hz走査に戻す。

結果が変わらない理由: `_bounds` は private フィールドで、読む経路は上の2つのゲッターだけ（逆コンパイル全体で呼び出し元はチュートリアルのみ。MODにも参照なし）。読まれない間の再計算は観察されないため省いても結果は同じ。読みがある間は1/30秒ごとに再計算するため、読み値の鮮度は最長1/30秒という本体のロジックTickと同じ保証を保つ。再計算の中身は本体と同一（先頭のboundsを代入し残りをEncapsulate、対象がなければ `_bounds` を更新しない）。ゲッターの Prefix は `_bounds` を更新するだけで返り値には触れないため、返る値は常に本体の式が計算したものになる（式の写しは持たない）。FrameUpdate（不透明度）・スキン差し替え・フォーカス通知は本体のまま。差し替え後も `Setup` は現在のリストを埋め直すため、スキン変更のたびに新しいリストを受け取って使い直す。`_currentRenderers` の読み手は逆コンパイル全体で LogicUpdate の走査だけで、ほかの処理（FrameUpdate は `_currentEffectRenderers`、フォーカスは `_focusHandlers` を使う）はこのリストを回していない。

効果の見込み（推定）: ロビー（最大4体）・タイトル画面（最大4体）・スキンpreview（1体）の表示ぶん、毎ロジックTick×体のレンダラー数（推定6〜10）の `Renderer.bounds` ネイティブ呼び出しが消える。ロビー4体で推定700〜1200回/秒ほど。チュートリアル表示中の1体だけは読み駆動で同率の再計算が残る。ゲーム内の数値・判定・見た目には影響しない。

修正ラウンド（レビュー所指摘、2026-10-18）: 2つのゲッターを Postfix での上書きから Prefix での `_bounds` 更新だけに変えた。本体の戻り値を捨てて自前の式で上書きしていたため、本体 `GetAbovePosition` の式と同じであることが差分から確かめられなかった。Prefix は `_bounds` を更新するだけで返り値は本体の式に計算させるため、設定OFF・間引き中・失敗後のどの状態でも返る値は本体と完全に一致する。間引きの時間基準は `Time.time` から `Time.timeAsDouble` と閾値 `0.03333333507180214` に変えた。本体 `LogicUpdateManager.DoLogicUpdates` の間引きが `(double)Time.time - _lastLogicUpdateTime < 0.03333333507180214`（スケール時間）であることを逆コンパイルで確認し、同じ時計と同じ閾値を使う。`Time.timeScale` が 0 の間は本体のロジックTickも止まるため、読み値が更新されない点は本体の動作と同じである。あわせて Issue73.Native.Tests に検証を8件追加した。境界の CharacterModelDisplay は本体の逆コンパイルと同じ式で LogicUpdate の走査・Setup のリスト埋め直し・2つのゲッターを書き、実ソースの NativeCharacterModelDisplayBounds をそのまま検証に使う。確かめたのは、再計算が本体の走査と同じ結果になること（先頭を代入して残りをEncapsulate、対象がなければ更新しない）、1/30秒の間引き、設定解除・失敗時にリストが本体へ戻ること、Setup で埋め直したリストを次のTickで取り込むこと、埋め直し済みなら古いスナップショットで上書きしないこと、ゲッターの Prefix が間引き中・設定OFFでも返り値を書き換えないこと。検証: Issue73.Native.Tests 302件（従来294件＋追加8件）合格、mod の Release ビルドを通した（警告は既存のもの）、Startup.Tests 149件合格・1件は既存のスキップ。実機での動作は引き続き未実行。
