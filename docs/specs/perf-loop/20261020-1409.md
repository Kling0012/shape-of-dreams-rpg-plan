# perf-loop/20261020-1409

## 対象

mod src/SodRpg.Mod/LevelEssencePatches.cs（混沌の祠 `Shrine_CorruptedChaos` のエッセンス枠まわりの Postfix 2本と、周辺の呼び出し先一式）。

## 直した内容

混沌の祠の編集UIが開いているあいだ、本体UIは毎ロジックフレームで `GetTargetInfo(DewPlayer, HeroSkillLocation, SkillTrigger)` を繰り返し呼ぶ（`UI_InGame_SkillButton_EditSkill.LogicUpdate` のコスト表示でスキルボタン4個ぶん、`EditSkillManager.IsSlotHighlighted` のハイライト判定で同じく最大2回ずつ。合計でおおむね4〜12回/フレーム）。表示中は `GetEditSkillIndicatorRawText` も1回/フレーム呼ばれる。MOD の Postfix 2本（`LevelEssenceChaosTargetInfo`・`LevelEssenceChaosIndicator`）はどちらも毎回 `string.Format` で新しい文字列を作っていて、エッセンス枠の報酬が選ばれているあいだフレームごとに小さな文字列確保が积み上がっていた。

そこで、書式結果をキャッシュして入力が同じなら作り直さないようにした。鍵は「ローカライズ文字列の参照一致」と「変わる int だけ」で、対象情報の側はツールチップ文（枠数 `current` と、そのとき使ったローカライズ文字列の参照）、インジケータの側は実効上限 `EffectiveCap` とローカライズ文字列の参照。`DewLocalization.GetUIValue` は辞書の値か定数（`DebugText`）を常に同じ参照で返すので、参照が変わったときだけ言語や辞書の差し替わりと判断して作り直す。鍵の比較と `string.Format` はゲームの型に依存しない `LevelEssenceTextCache.cs`（`AccessoryOffsetCacheKey.cs` と同じ形の切り出し）に置いて、Postfix はそれを呼ぶだけにした。

## 結果が変わらない理由

ツールチップ文 `"{0} {1}<sprite=0>{2}"` はローカライズ文字列と `current`・`current + 1` だけで決まり、インジケータ文はローカライズ文字列と上限だけで決まる。どちらも鍵が同じなら1文字も変わらない。この「結果が変わらないこと」は `LevelEssenceTextCacheTests`（SodRpg.Mod.Startup.Tests から `LevelEssenceTextCache.cs` を直接リンク）で確かめる: (a) 同じ入力ならキャッシュ導入前の `string.Format` と同じ結果を返し、2回目は前回と同じ参照を返す、(b) `current`・`EffectiveCap`・ロケール文字列の参照のいずれかが変われば作り直す（同じ内容でも別参照なら作り直す）。拒否側の `rejectReasonRawText` と `actionTypeRawText` は `GetUIValue` の戻りをそのまま入れていて変更していない（確保がなく、言語差し替えも次の呼び出しで映る）。上限の変わり方（設定変更・HUD 無効化での4への縮小）は `EffectiveCap` の鍵に、枠数の変化は `current` の鍵にそれぞれ現れるので、値が動けば次の呼び出しで作り直す。キャッシュは1組だけなので、ホストで別プレイヤーの操作を処理するときに `current` が入れ替わっても、外れれば作り直すだけで出力は常に正しい。Postfix 自体の動作（結果の上書き規則、拒否時の `tooltipRawText = null`、失敗時に1回警告して外れる）は変えていない。

## 効果の見込み（推定）

混沌の祠でエッセンス枠の報酬を選んだプレイヤー（ホスト・参加者とも、UI は各自の PC で走る）の画面で、編集UIを開いているあいだの MOD 由来の文字列確保が、枠数や上限が変わる瞬間を除いてゼロになる。最大12回/ロジックフレーム × 編集UIの表示時間ぶんの割り当てと GC 回収が減る（推定。60fps で毎秒数百回の小さな割り当て減。表示は秒単位の短い時間なので効果は場面限定）。本体側の `GetTargetInfo` が自分で作る文字列は対象外で、残る。
