# perf-loop/20261024-1341

対象: `src/SodRpg.Mod/HostAuthority.SkillLock.cs`（ゲストのスキル使用不可の安全装置を、ホストが受信ごとに応じる部分）

## 直した内容

このファイルの経路は、参加者から `DreamforgeSkillResyncMsg` を受け取ったときにだけ
ホストで動きます。応答では各スキル（最大6スロット）に対して `Resend` が
`NativeSkillLockRecovery.ResendSkill` と `NativeCooldownSafety.ResendAuthoritative` の
両方を呼び、同じ値を2つの経路で送っていました。

`ResendSkill` の中の `ResendArrays` は、本体の全配列 RPC
（`RpcSyncAfterFrameDelayStates_Imp`）でクールダウン・チャージ・最低待ちの3配列を
sanitize 済みの値でまとめて送ります。`ResendAuthoritative` は同じ sanitize 処理
（`SafeTime` と `Math.Max(charge, 0)` は本体の `RpcSetCooldownTime` 系の
`!(値 >= 0f) || IsInfinity → 0`、`charge < 0 → 0` と同じ結果）を経た同じ値を、
設定数ごとに `RpcSetCooldownTime` / `RpcSetMinimumDelay` / `RpcSetCharge` の
3 RPC で送ります。6スロット×設定数ぶんの RPC が、直前の全配列 RPC と同じ内容で
全オブザーバ（参加者を含む）に届いていました。

そこで `ResendSkill` が全配列 RPC を送れたかを返すようにして、`Resend` 側では
送れたときだけ `ResendAuthoritative` を省きます。全配列 RPC を送れなかったとき
（配列の長さが揃っていない、本体の RPC 参照が取れない、など）は従来どおり
要素ごとの再送に頼るので、安全装置としての動作は変わりません。

## 結果が変わらない理由

- 本体の受け手側の処理（逆コンパイルした `AbilityTrigger` の UserCode）は、
  `RpcSyncAfterFrameDelayStates_Imp` が3配列の参照を送られてきた配列で丸ごと置き換え、
  `RpcSetCooldownTime` / `RpcSetMinimumDelay` / `RpcSetCharge` が対応する要素に
  値を1つ書くだけです。イベントもコールバックもありません。
- 2つの RPC は同じ reliable チャネル（`SendRPCInternal` の channel 0、
  `includeOwner: true`）で、`Resend` は同期的に全配列を先に送るので、
  参加者には必ず全配列 → 要素ごとの順で届きます。要素ごとの書き込みが
  同じ値の上書きになるため、省いても各参加者の最終状態は同じです。
  ホスト自身は `NetworkServer.active` のガードでどちらも適用しないので無関係です。
- 送る値の sanitize は両経路で同じです（上に書いたとおり、非有限と負の扱いが一致する）。
- `ResendSkill` の他の副作用（`SetDirty`、設定同期の dirty、ロック2リストの
  同値 SET の積み直し）と `ResendHero`（SyncVar の dirty と ability 辞書の再送）は
  触っていません。`ResendAuthoritative` が要らなくなるのは全配列 RPC が
  実際に送れたときだけです。

## 回帰テスト（Issue73.Native.Tests）

`NativeSkillLockResendTests` が、この分岐そのものを境界スタブ
（`SkillLockResyncBoundary.cs`。RPC の送出を記録にする）で確かめます。

- 全配列 RPC が送れたとき: 要素ごとの3種 RPC は1件も出ない。副作用（設定同期の
  dirty・ロック2リストの同値 SET の積み直し）は従来どおり残る。
- 省いた要素ごとの再送が運ぶ値は、全配列 RPC の配列と要素ごとに一致する
  （ sanitize 込み。受け手の処理から、最終状態は旧動作と同じになる）。
- 全配列 RPC を送れなかった各経路（本体 RPC 参照なし・配列長不整合・送出時例外・
  直前の失敗で `_arraysFailed` 済み）では、要素ごとの再送に戻る。
- `ResendSkill` の戻り値は、設定0・配列 null のときも false を返す。

## 効果の見込み（推定）

再同期1回あたり、6スロット×設定数×3件（設定数2なら36件）の要素ごと RPC が
なくなります。RPC 1件ごとに Mirror の送信側の直列化と、全参加者での
受信・振り分け・引数の読み取りが1回ずつ減ります。この経路は1人の参加者につき
8秒以上の間隔、同じ停滞1回で最大3回に限られるので、日常の負荷は元から小さく、
削減も通信の断続的な山で効くものです（推定）。参加者が受け取るメッセージ数が
直接減るので、標的の参加者側の負荷に効きます。
