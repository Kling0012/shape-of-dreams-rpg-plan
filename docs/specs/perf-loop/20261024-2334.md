# perf-loop/20261024-2334

## 対象

`src/SodRpg.Mod/ClientSession.BossVisuals.cs`（MOD 側。ボスの予告表示の、ホストからの受信と IMGUI による描画を受け持つファイル）。

参加者側で走る経路を先に確認した。受信は `OnBossLite` と `OnBossEffects` で、ホストは差分を 0.1 秒間隔・スナップショットを 1 秒間隔で送っており、`HostAuthority.BossVisuals.cs` 側のまとめ送り（変わらない値の送信止め、NetLite の圧縮、同一スナップショットの 5 秒抑止）は実装済みだった。受信側は検査とプール済みインスタンスへのコピーだけで、メッセージごとの確保はない。`TickBossDisplay` は tick の 1 ステップだが、刈り取り本体は 0.25 秒間隔で、残りは部屋替えの確認のみ。残って毎フレーム走るのは `DrawBossEffects`（OnGUI の Repaint ごと）で、描画リストの作り直しは 0.1 秒間隔に間引かれているが、描画そのものは毎 Repaint に全セグメントを通る。

## 直した内容

全セグメントの共通の末尾 `DrawBossWorldSegment`（リング・扇・帯・スポーク・矢頭・線がここに集まる）で、`GUIUtility.RotateAroundPivot(angle, pivot)` を呼ぶ代わりに、回転行列を sincos から直接組み立てて `GUI.matrix` に 1 回設定するようにした。Unity のこのヘルパーは 1 本ごとに `GUI.matrix` の読み戻し（ネイティブ）と単位行列の設定、`GUIClip.Unclip` によるピボットの戻し、`Quaternion.Euler` を含む `Matrix4x4.TRS` 2 回と行列乗算 2 回、最終設定（ネイティブ）を行い、その後に呼び出し側が単位行列へ戻している。単位行列を基準にしたときのこのヘルパーの結果は `T(pivot)・R(angle)・T(-pivot)` の 1 つなので、それを直接書く。`Mathf.Sin` と `Mathf.Cos` の 2 回の呼び出しと算術だけになり、ネイティブへの出入りは設定の 1 回になる。

## 結果が変わらない理由

この末尾は単位行列を基準にすることをファイルの方針としていて、`DrawBossEffects` が描画の前に `GUI.matrix` を単位行列にし、各セグメントの描画後も戻している。基準が単位行列のとき `GUIUtility.RotateAroundPivot` の作る行列は `T(pivot)・R(angle)・T(-pivot)` であり、直接の構成と同じ値になる。ピボットの `GUIClip.Unclip` は、MOD の OnGUI の入口でクリップの根（全画面・原点）にいるため恒等で、`PerfMeter.Begin` は GUI に触れない Stopwatch だけなので入口の状態は変わらない。回転部分は `Quaternion.Euler(0, 0, angle)` から作る行列の成分（`1-2sin²(θ/2)` など）と sincos の値が数学的に等しく、浮動小数の最下位ビット程度の差は描画される四角形の位置・角度・幅に現れない。描画される矩形を決める `BossSegmentPlacement.TryPlace` は触っていないので、描かれる線の集合は元と同じである。

## 効果の見込み（推定）

セグメント 1 本ごとに、ネイティブな `GUI.matrix` の読み書き 3 回と `GUIClip.Unclip` 1 回がなくなり、`Quaternion.Euler` を含む `TRS` 2 回と行列乗算 2 回の計算も sincos 1 回に置き換わる。予告が多数並ぶボス戦では描画予算（高画質 2048 本・低画質 768 本）の範囲で毎 Repaint に数百から千本超のセグメントが通るので、IMGUI の描画経路でその分の呼び出しと計算が減る（実測はしていない推定）。描画はホストと参加者の両方で走るので、参加者側でも同じ数だけ減る。

## 見送った候補

- `OnBossEffects` の効果 id の重複確認（受信 1 回ごとに二重走査）。メッセージは最大でも差分 0.1 秒間隔で、件数は上限 64 と小さく、効果が見込めない。
- `Protocol.WarnContentMismatch` がメッセージごとに読む `ContentFingerprint.Value`。実装を確認したところ、ロック付きのキャッシュ済み文字列の参照比較 2 回だけで安い。
- `BossDisplayVisible` を描画リストの更新（0.1 秒間隔）だけにして Repaint ごとの再判定をやめる案。カメラは更新の合間にも動くので、判定を間引くと画面外の予告を描き続けたり、画面内の予告を消したりする（見た目が変わる）。
- `TickBossDisplay` の 0.25 秒ごとの `GetComponent<Hero>`。所有者上限 16 × 毎秒 4 回で小さい。
