# perf-loop/20261019-0957

対象: mod src/SodRpg.Mod/HostAuthority.BossNativeAdapters.cs。

直した内容: このファイルには、ボスやヒーローの「生の」移動・テレポート・キャストをホスト側で把握するための Harmony パッチが置かれ、各パッチはメソッドの前後で静的なスコープ変数（`BossNativeCastScope.Current`、`BossNativeMovementSource.Current`、テレポート前の位置）を退避・復元している。このうち `BossNativeMovementSource` は `Actor.LogicUpdate` と `Actor.FrameUpdate`（全 Actor が毎フレーム呼ぶ 2 系統）と各コンテンツの移動メソッドに Prefix/Finalizer を乗せるため、参加者（クライアント）側でも毎フレーム・全 Actor 分の退避・復元と、クロージャ経由の移動メソッドではリフレクションによる所有者の取り出しまで走っていた。`BossNativeTeleportCompletion.Prefix` は `EntityControl.Teleport` のたびに `Entity.position`（`transform.position` の Unity ネイティブ呼び出し）を読み、`BossNativeCastScope` はキャストのたびに退避・復元をしていた。ところがこれらのスコープを読む処理はどれも `NetworkServer.active` が true の経路（ホスト側の displacement・テレポート・被弾の公開処理）からしか呼ばれないため、参加者側で走るこれらの仕事は結果として誰にも読まれない。そこで 3 つのパッチクラスの Prefix/Finalizer に `NetworkServer.active` ガードを置き、参加者側ではスコープに一切触れないようにした。

結果が変わらない理由: スコープ変数の読み手（`BossNativeMovementBinding`、`PublishBossNativeTeleport`、`BindBossNativeDisplacement`、`BindBossNativeInstance`、`PublishBossNativeDamage`）はすべてホスト側の呼び出しチェーンにあり、参加者側では実行されない。ホスト側では Prefix/Finalizer の動作が 1 行も変わらない（ガードは true で通過するだけ）。したがってホストが把握する移動・テレポート・キャストの内容、それに基づく公開・送信・判定は、ホスト・参加者のどちらから見ても変わらない。テストが `BossNativeCastScope.Current` を直接設定している箇所は Harmony パッチを通らない直接呼び出しなので、この変更の影響を受けない。

効果の見込み（推定）: 参加者側で、全 Actor × 毎フレーム × 2 系統の静的フィールド退避・復元（戦闘中は Actor が数十〜数百）と、テレポートごとの `transform.position` 読み、キャストごとの退避・復元・解放チェックがなくなる。通信そのものは変わらない（送信はホストだけの仕事で、送信経路には触れていない）。規模は小さく、1 フレームあたりの削減はマイクロ秒オーダーの推定（推定）。
