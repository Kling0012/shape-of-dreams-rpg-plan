# perf-loop/20261024-0531

対象は `src/SodRpg.Mod/HostAuthority.CoopKeystones.cs` である。直した内容は、`CoopGuardTarget`（PackGuard のお供ガード）が 0.25 秒ごとのスキャンで、召喚物ごとに全エンティティを走り直していた点を、候補の収集を 1 回にまとめたことである。従来は召喚物の数だけ全エンティティの走査を繰り返し、そのたびに「敵関係か・生存しているか・最弱の味方を狙っているか」を確かめていた。この絞り込みは召喚物に依存しないので、先に候補の一覧（`_coopGuardCandidates`、呼び出しごとに使い回すリスト）を作り、召喚物ごとの内側の走査では距離の比較と `Summon.CanAggroTo` だけを行うようにした。

結果が変わらない理由は次のとおりである。候補の絞り込みに使う値（`CoopEnemy` の関係判定・`currentHealth`・`AI.context.targetEnemy`）は 1 回の `CoopGuardTarget` の呼び出しのあいだに変わらない。候補の一覧は `_am.allEntities` と同じ順で作るので、`distance < nearest` の同点のときに先に見つけた敵を選ぶ従来の扱いも同じである。`Summon.CanAggroTo` は味方の位置と関係だけを読む問い合わせで副作用がなく（本体 `Summon.CanAggroTo`、`Entity.CanAggroTo` で確認）、呼び出される（召喚物・敵）の組と順序も変わらないため、選ばれる敵も同じである。`RecordSummonGuardTarget` と `Aggro` の呼び出し条件は触っていない。

効果の見込みは推定だが、絞り込みの評価が召喚物 S・エンティティ E で S×E 回から E＋S×C 回（C は最弱の味方を狙っている敵の数）に減る。召喚物が多いビルドで敵の多い部屋ほど、関係判定（`GetRelation` のチーム計算）の重複が減る割合が大きい。なお、このファイルには参加者側の経路がない。7 つのパッチは `NetworkServer.active` の確認だけで参加者側は抜けるため、観点 3（定期スキャンの経路での重複した全走査）に従ってこの箇所を選んだ。この修正もホスト側だけで走り、参加者側の処理・通信は変わらない。実機（ゲーム内）での確認は未実行である（この環境ではゲームを動かせないため）。
