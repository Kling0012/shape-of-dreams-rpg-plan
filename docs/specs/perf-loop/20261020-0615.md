# perf-loop/20261020-0615

対象: `src/SodRpg.Mod/HostAuthority.cs`

## 直した内容

悪夢化「トゲ付き（Thorned）」の敵の反射処理が使う辞書 `_thornsNextReflect`（HostAuthority.cs）に、キー型 `KeyValuePair<Monster, Hero>` 専用の比較器（`ThornsKeyComparer`）を渡した。これまで既定の比較器が使われ、構造体キーに `ValueType.Equals` が落ちて、参照ごとにキーをボックス化し、リフレクションで欄を比べていた。ボックス化と欄比較は、トゲ付きの敵がダメージを受けるごとの `TryGetValue`（`OnMonsterDamageTaken`）と、256件を超えたときの掃除（`PruneThornsTimers` の全件走査）で発生する。

比較器は、同じ partial クラスの `HostAuthority.AutoCastTargets.cs` にある `EnemyContactComparer`（構造体キー `_enemyContacts` に同じ理由で既に導入済み）と同じ形で、`ReferenceEquals` と `RuntimeHelpers.GetHashCode` を使う。

## 結果が変わらない理由

- 等値の意味を変えない。キーは Unity のオブジェクト（Monster・Hero）で、マネージラッパとネイティブ実体は 1対1 なので、`ReferenceEquals` は既定の比較（`UnityEngine.Object.Equals` の実体ポインタ比較）と同じ結果になる。ハッシュ関数の選び方は辞書の動作に影響しない（同じ比較器の中で等値とハッシュが一貫していればよい）。
- 辞書の読み書きの呼び方（`TryGetValue`、インデクサ代入、`Remove`）と値の意味（次の反射までの時刻）は変えていない。掃除の条件（`kv.Key.Key == null` などの null 判定は Unity の `==` のまま）も変えていない。

## 効果の見込み（推定）

トゲ付きの敵がいる戦闘で、その敵がダメージを受けるごとに、キーのボックス化（1回あたり約50〜100バイトの Gen0 確保）とリフレクションによる欄比較がなくなる。発生頻度は、トゲ付きの悪夢が画面にいるときの被弾ごと（激しい戦闘で秒間数十回の見込み）と、掃除時の全件走査。1回あたりは数百ナノ秒程度の見込みで、削減量としては小さい。トゲ付きの敵がいない場面では効果ゼロ（推定。実測はしていない）。

## 見た範囲と見送った候補

ゲスト（参加者）側の経路として、このファイルから参加者へ送る3系統を確認した。いずれも重複送信を抑える仕組みがすでにあり、扱うべき無駄は見つからなかった。`SendPressure`（`DreamforgePressureMsg`）はプレイヤーごとのスナップショット比較と 5秒／30秒の間隔で重複を止めていて、`runChoices` の文字列は `EncodeRunChoices` 側でメモ化済み、送信のたびの `LinksSatisfied` の再錨打ちも送信1回につき1回だけだった。`SendBountyReport`（`DreamforgeBountyReportMsg`）は、シールド・回復・属性撃破が `BountyReportBatching.cs` でティックごとの1通に、仕掛け発動が #161 でティックごとの1通に、それぞれまとまっている。モンスターの分類・削除の送信がある `HostAuthority.Monsters.cs` と `HostAuthority.KillSync.cs` は、未マージの #904 が同じ場所を触るため避けた。

`GimmicksTriggered` の送信を0.25秒に間引く案も検討したが、見送った。報酬（Bounty）進行が参加者に届く時刻が変わることに加え、ラン終了時の境界フラッシュ（`BountyReportsBeforeBoundary` はシールド・回復・属性撃破を流すが、仕掛け分を流していない）と流し残しの前後関係を検証する必要がある。

ホスト側の毎フレーム・毎回の経路も一通り見た（`Tick` の37段階、`UpdateRuntime`、`ScanArea`、`UpdateLinks`、`ProcessSpawns`、`PruneAndApplyPending`、`RecordAutoCastContact`、`CollectPairMemories`、`ForgetNewPowerTarget` など）。いずれも実行間隔の制限・エポックによるキャッシュ・スクラッチコレクションの再利用が済んでいて、残る無駄はこの辞書の比較器だけだった。
