# perf-loop/20261024-0727

対象は `src/SodRpg.Mod/HostAuthority.MemoryNativeAdditionalAdapters.cs` である。直した内容は、4つのネイティブ追加分パケットのアダプター（Astrid's Masterpiece の En Garde と Priorite、Frozen Fists、Dangerous Theory）が被弾・攻撃のたびに走らせる検証の入り口 `BeginVerifiedStatusAddedPacket` で、検証に先立って行っていた2種類の毎回の処理を、通ったときだけ行うようにしたことである。1つ目は Frozen Fists だけが引数として渡していた `input.chain.New(source)` の構築で、これは `List<Actor>` を1つ確保して要素を写す処理であり、検証が不合格になってスコープを作らないときは捨てられていた。2つ目は記憶の一致を見る `FindMemory(hero, trigger.GetType().Name)` に渡す型名で、実行時の `GetType()` と型名の取り出しを、呼び出し側で `is` ですでに確定している型の `nameof` の定数に置き換えた。

結果が変わらない理由は次のとおりである。反応チェーンの構築は読み取りしかしない純粋な処理で（`ReactionChain.New` は元の鎖の要素を写して1つ足すだけ）、構築を検証の後に遅らせても、その間に入るのは副作用的でない確認だけなので、作られる鎖の中身は同一である。不合格のときは従来もスコープを返さないので、鎖を作らなくなっても外から見える違いはない。型名についても、呼び出し側の `is St_…` を通った時点で `trigger` の実行時の型はその型そのもの（本体の逆コンパイルで、対象の4つの記憶トリガーがどれも派生クラスのない内容型であることを確認済み）であり、`FindMemory` が装備スロットから探すときの鍵も同じ文字列なので、探す結果は変わらない。スコープに入れる各フィールド（`Chain` の既定値を含む）の値は従来と同じである。

効果の見込みは推定だが、Frozen Fists が有効な6秒間は主人公の攻撃のたびにこの検証が走り、記憶の発動に紐づかない通常攻撃では不合格になるため、攻撃ごとの `List` の確保がなくなる。Unity の GC は確保のたびに負担になるので、戦闘中のごみの量が減る。型名の定数化は検証を試みるたびの仮想呼び出し1回を除く。Wind Scar の `BeginWindScarAddedPacket` は別の経路であり、今回の変更には含まれない。なお、このファイルに参加者側の経路はない。4つのパッチ先の本体メソッド（En Garde と Priorite の `CheckExposed`、Frozen Fists の `OnCreate` のラムダ、Dangerous Theory の `EntityEventOnAttackFiredBeforePrepare` のラムダ）はどれも `isServer` のときだけ登録・実行されることを逆コンパイルで確認しており、参加者側では `NetworkServer.active` の確認で抜けるため、観点3（被弾・攻撃ごとの経路での無駄な確保）に従ってホスト側のこの箇所を選んだ。参加者側の処理・通信は変わらない。実機（ゲーム内）での確認は未実行である（この環境ではゲームを動かせないため）。
