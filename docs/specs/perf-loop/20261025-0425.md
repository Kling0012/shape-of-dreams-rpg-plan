# perf-loop/20261025-0425

## 対象

`native Dew.Core/EntityAnimation.cs`（ゲーム本体。歩行・死亡アニメの切替と、能力アニメの上半身レイヤーの重みの管理を受け持つクラス）。

見た範囲はファイル全体（891行）。実 DLL からの再取り出しは省略し、リポジトリの逆コンパイル（sod-decomp）をそのまま使った。毎フレームの経路（`LogicUpdate`・`FrameUpdate`・`FrameUpdateAnimations`・`LateUpdate`、1秒ごとの `ReanchorLoopingStates`）、被弾・スキル使用ごとの RPC の送受信、SyncVar（`isDeathAnimationForced`）の同期を点検した。呼び出し先の `walkStrength`・`movementSpeedMultiplier`・`hasRoot`・`hasStun`・`GetMovementSpeedMultiplierByAttack` もあわせて見て、どれもフィールド読み程度の O(1) であることを確かめた。

## 直した内容

点検の結果、値を書く処理はすでにすべて値キャッシュで絞られていた（`SetBool`・`SetFloat`・`SetLayerWeight` は変化のあったときだけ呼ぶ）。一方で `Animator.GetLayerWeight(1)` だけは値を覚えず、能力アニメを再生していない実体でも、寝ていない全実体で毎フレーム2回（`FrameUpdateAnimations` の遷移管理と `LateUpdate` の背骨補正の判定）ネイティブ呼び出しが走っていた。

修正は `NativePerfPatches.cs` に追加した `NativeEntityAnimationLayerWeightIdlePerf` である。その2か所の呼び出し（各メソッドにちょうど1か所）を、`GetWeight(Animator, int, EntityAnimation)` に差し替える Transpiler にした。`GetWeight` は目標値（`abilityAnimStatus.isPlaying ? 1 : 0`。本体の `FrameUpdateAnimations` が使うのと同じ式）を実体ごとに覚え、覚えた値と目標が等しい間はネイティブの取得を呼ばずに覚えた値を返す。等しくない間（遷移中）は本体と同じく毎フレーム実際の値を読み、読んだ値で覚え直す。MOD 設定の `nativeEntityAnimLayerWeightIdle`（既定は有効）で切れる。メソッドが見つからない・呼び出しがちょうど1か所でない・実行時に例外が出た、といったときは警告を1回出して、その実体以降は本体どおりの読み取りに戻す。

## 結果が変わらない理由

レイヤー1の重みを書くのは本体の `EntityAnimation` の中の2か所だけである（`FrameUpdateAnimations` の目標への漸近と、RPC 受信時の `SetLayerWeight(1, 1f)`。後者は必ず同じメソッド内で先に `isPlaying = true` を書く）。漸近は `MoveTowards` の不動点で目標にぴったり一致するので、「覚えた値 == 目標」の間は実際の値も目標で固定であり、覚えた値を返しても読み直しと同じ値になる。目標が変わる（再生が始まる・終わる）瞬間は必ず「覚えた値 != 目標」になり、そのあいだは本体と同じく実際の値を読むので、遷移の見た目と `LateUpdate` の背骨補正のタイミングは元どおりである。`LateUpdate` は同じフレームの `FrameUpdate` のあとに走るので、遷移中は更新済みの値を読む。 Animator が作り直されたときは覚え直しの初期値を NaN（目標と比較して常に不一致）にしてあるので、最初の1回で実際の値に同期する。

## 効果の見込み（推定）

寝ていない実体1つあたり毎フレーム2回の `Animator.GetLayerWeight` の外部呼び出しが、能力アニメの遷移が落ち着いている間はなくなる。戦闘中の実体はほとんどの時間この状態なので、実体数十人 × 60fps で毎秒数千回の呼び出しが減る見込みである（実測はしていない推定。1回あたりは数百ナノ秒程度の小さい節約で、効果は控えめ）。削れるのはホスト・参加者の両方の毎フレーム経路なので、標的のゲスト側にもその分効く。

## 見送った候補

- `LogicUpdate` の歩行速度の再計算。入力のプロパティはすべて O(1) で、`SetFloat` は値が変わらない限り呼ばないキャッシュ済み。
- `ReanchorLoopingStates`。1秒に1回、レイヤー2個の状態読みだけ。
- `RpcPlayStaggerAnimation` などの RPC と `WriteDewAnimationClip` の通信。アセットID参照の書き込みで、値が変わったときだけ送る同期であり、間引くと見た目・判定が変わる。
- `abilityAnimStatus` 終了フレームに残る `SetFloat` 2回。1フレーム1回だけの話で効果が小さい。
