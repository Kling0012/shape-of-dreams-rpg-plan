# perf-loop/20261024-2054

## 対象

`mod src/SodRpg.Mod/ClientSession.Infinity.cs`。このファイルで毎フレーム走る経路は `TickInfinity`（`TickRunChoices` の各フレームステップから呼ばれる）に集中する。ホスト・参加者の両方がここを毎フレーム通るので、順に追って確認した。

## 直した内容

`TickInfinity` の末尾（選択の確定チェック）で、ホストは `PartyAcknowledged`（参加者名簿の全走査と離脱者の ACK 清掃）→ `CanAdvance` → `HostInfinityBoundarySettled`（未確認の撃破ファクト全走査 × 受領状の線形走査 × ピアごとの参加レンジ走査）を毎フレーム評価していた。しかし、このチェックが門にしている処理は、その直後の「確保の結果表示」「境界の再生成」「遷移中の再生成」の 3 つだけで、いずれも `choice.Secure`・`choice.Boundary`・`state.Phase == InfinityPhase.Transitioning` が揃ったときにしか動かない。

`Rules.Delve` は潜行の選択を適用した直後に `Phase` を `Transitioning` へ進める。つまり適用直後の短い遷移窓が過ぎれば、残りの区間（次の選択がQueueされるまでの戦闘と選択待ちの全フレーム）では、3 つのチェックは毎フレーム「true を返して何もしない」ことが確定している。

そこで発火条件の判定を先に移し、確保でも境界でも遷移中でもない選択では 3 つのチェック自体をスキップするようにした。チェックの評価順序と内容は変えていない。

## 参加者側の経路について

参加者は毎フレーム `TickInfinity` を通るが、その経路は初期リターンの比較だけだった。保存待ち（`CompleteInfinityStateSave`）は保留が無ければ 1 回の比較で抜け、個人選択の再送（`TickInfinityPersonalChoice`）は未送信の選択が無ければ抜け、鏡像のコピーはスナップショット受信ごとに 1 回だけ走る。参加者が送るのは `AcknowledgeLocal` の再送（1 秒ごと）だけで、これはホストが ACK を待つ仕組みの一部なので触らない。参加者側で省ける処理は見つからなかったため、ホスト側の毎フレーム経路（探すもの 3）としてこの修正を行った。

## 結果が変わらない理由

スキップするフレームでは、元のコードも 3 つのチェックの結果にかかわらず何も実行していない。本体の 3 つの分岐は `choice.Secure`、`choice.Boundary`、`state?.Phase == InfinityPhase.Transitioning` をそれぞれの条件にするので、この 3 つがすべて偽のフレームでは本体が空だと構造上確定する。先に条件を見るだけなので、発火しうる窓（確保・境界・遷移中）ではチェックの評価順序と結果が元のまま残る。

`PartyAcknowledged`（`src/SodRpg.Mod/InfinityMode.cs`）は、`!ReferenceEquals(choice, _ackWaitingChoice)` のときだけ `_ackWaitStarted` に `Time.unscaledTime` を記録し、`_ackWaitReleased` を `false` に戻すため、待ちの起点は新しい選択の初回評価ごとに初期化される。`CurrentChoice` は設定の JSON が同じ間は同じオブジェクトを返すので、同じ選択の毎フレーム評価で起点は更新されない。

非境界の潜行では、`TickInfinity` が `Rules.Delve` を適用すると `Phase` が `Transitioning` になり、保存の完了後に早期 return を通過して最初の ACK 判定へ進む。確保と境界の選択も常にこの早期 return を通過する。遷移後に判定を省く区間では、次の選択が前の起点を引き継ぐことはない。離脱者の ACK の清掃は遅れるが、次の判定では現在の参加者名簿で清掃してから ACK を評価する。

ACK の猶予は 60 秒ではなく、`Math.Max(0f, Math.Min(ChoiceAckGraceSeconds, choice.PersonalAckGraceSeconds))` による最大 30 秒である。個人選択が無応答で 60 秒の期限を迎えた場合は `PersonalTimedOut` によりリモートの ACK 待ちを追加しないが、ホスト自身の ACK は省略しない。個人選択の待機と残り時間の計算は `TickPersonalChoicesNative`（`src/SodRpg.Mod/InfinityMode.PersonalChoices.cs`）が担当し、この早期 return より前の `InfinityMode.Tick` で呼ばれるため、今回の判定省略の影響を受けない。

## 効果の見込み（推定）

遠征中のほとんどの時間は区間の戦闘と選択待ちなので、ホストは走査をそこで丸ごと省ける。重いのは `HostInfinityBoundarySettled` で、未確認の撃破ファクト 1 件ごとに受領状の線形走査（1 〜 4 件）とピア数（上限 4）× 参加レンジの走査が回る。戦闘中に未確認が数十件に積もっていると、1 フレームあたり数百〜数千回の比較がなくなる計算になる（推定）。アロケーションは元から無いので GC への影響はない。区間が短く撃破が少ない遠征では効果は小さい。
