# perf-loop/20261025-0841

対象: `src/SodRpg.Mod/PressureEnemyNativeRewards.cs`（MOD。撃破ごとに呼ぶ共有ヘルパー `PressureCountRewards.ScaleFromActorData` の重複パースを1撃破1回にまとめる）

## 直した内容

このファイルのパッチは5系統あり、いずれも `NetworkServer.active` でガードされます。`PickupManager.HandleDeathDrop` への購読は本体の `OnStartServer` で行われるため、協力プレイの参加者（ゲスト）が走る経路は実質なく、ゲストが払うのはガードの字段読みだけです。そこで標的の切り替え（参加者側の経路がない場合の観点3）に従い、ホスト側の撃破ごとの経路を見ました。

圧迫モードのエキストラ1体の撃破では、同じ被害者の `persistentSyncedData` に入った同じスケール文字列を、次の6箇所で読み直します。`BeforeDeathDrop`・`AfterKillGold`・`AfterKillExp`（このファイル）と、`PressureEnemyCount.BeforeDeath`、`HostAuthority.PressureDividend` の死亡捕捉、`HostAuthority.KillSync` の撃破イベント刻印です。読むたびに、Mirror の SyncDictionary への `TryGetValue`（47文字の固定キーのハッシュ計算）と、`double.TryParse`（"R" 書式の往復文字列で、数値のパースの中でも遅い経路）をやり直していました。

そこで `ScaleFromActorData`（`src/SodRpg.Core/Game/PressureCountRewards.cs`）に、文字列の参照を鍵にした1件分のメモを追加しました。前回と同じ参照なら前回のパース結果を返し、それ以外は従来どおりパースします。変更はこの関数1つです。

## 結果が変わらない理由

- スケールの文字列は、ウェーブごとに1つの "R" 書式の不変文字列をスポーン時に書き込むだけで、以後の読み取りで書き変わらないため、同じ参照からは常に同じ値にパースされます。
- 鍵の判定は `ReferenceEquals` なので、内容が同じでも参照が違えば普通にパースします。値が null のときは鍵に一致させず、`double.TryParse(null)` が false を返す従来の経路どおり 1 を返します。
- メモは `[ThreadStatic]` なので、Harmony フック（メインスレッド）と並列で走るテストの間で値を受け渡しません。値を鍵より先に書き込むため、鍵が一致したときに違う値の組を読むこともありません。

## 効果の見込み（推定）

撃破1回あたり最大6回の `TryParse` が1回にまとまります（推定）。1回の節約は数百ナノ秒程度（推定）で、撃破が密集する圧迫モードの部屋ほど乗ります。1つのウェーブのエキストラは同じ文字列の参照を共有するため、同じ部屋の連続撃破ではほぼ毎回メモに当たります（推定）。このファイルにゲスト側の経路はないため、ゲストの負荷は変わらず、削減はホスト側に乗ります。
