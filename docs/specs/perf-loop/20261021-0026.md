# perf-loop/20261021-0026

対象は本体の `Dew.Core/PropEnt_Merchant_Base.cs`（逆コンパイル）である。商人（Jonas・Smoothie・Backpack・Unmanned の基底クラス）であり、商品の辞書 `merchandises`（SyncDictionary）の管理と売買のコマンド処理を持つ。ホストと参加者のどちらでも走る経路は、商品の入出荷のたびの辞書の同期（購入・更新という操作のたびに1回）と、毎ロジックティックの `ActiveLogicUpdate` である。操作のたびに走る経路はどれも軽く、毎フレームの経路はこの `ActiveLogicUpdate` の1つしかない。

見つけた無駄は、`ActiveLogicUpdate` の props の位置合わせである。`Awake` で装飾モデルの GameObject（`props` 配列）をシーンのルートに引き剥がして別レイヤーにしているため、本体は毎ティック、各 props に `SetPositionAndRotation` で商人本体の位置と向きを書き込む。商人は自分の力で動かず、逆コンパイルの範囲でこの変換に書き込む処理はこのループのほかにない。それでも Unity の `SetPositionAndRotation` は同じ値を受け取っても分解・保存・ダーティ化を行うため、商人が動いていない間は、毎ティック同じ値の書き込みが商人1体とその props の数だけ繰り返される。エンティティは近くに英雄がいる限り眠らない（ActorManager が半径40以内の実体を起こし続ける）ため、商人のいる部屋にいる間、ホストと参加者の両方でこの書き込みが毎ティック続く。

直した内容は、`NativePerfPatches.cs` に `PropEnt_Merchant_Base.ActiveLogicUpdate` への Transpiler を1本足したことである。メソッド全体を置き換えると基底クラス（`Entity.ActiveLogicUpdate`）の呼び出しを飛ばしてしまうため、本体 IL の中の唯一の `Transform.SetPositionAndRotation(Vector3, Quaternion)` の呼び出し箇所を、同じ引数の積み（transform・位置・回転）を持つ MOD 側のヘルパー `SetIfChanged` に置き換えた。ヘルパーはまず props 側の実物の変換を読み、位置を成分ごとの `float ==` で、回転を `Quaternion` の `==` で比べて、両方とも書こうとしている値と同じなら本体の書き込みを省く。呼び出し箇所が1つに数えられない形になっていれば警告を1回出してこの修正だけを外れる。MOD 設定 `nativeMerchantPropIdle`（既定ON）で切れる。テスト側は本体 API の境界として、`NativeBoundary.cs` に `PropEnt_Merchant_Base` の宣言だけの模倣を、`DashSweepStepPerfBoundary.cs` の `Transform` に `SetPositionAndRotation` の受け口を、`NativeEmbracePositionBoundary.cs` の `DreamforgeConfig` に同名の設定フィールドを足した（既存ファイルの修正のみで、新しいテストファイルはない）。

結果が変わらない理由は、省くのが「現在の値と同じ値の書き込み」だけだからである。位置の比較は成分ごとの完全一致で、props と商人はどちらも親を持たないルートの変換なので、getter は保存されている値をそのまま返す（+0 と -0 は等しく、数値の使い道では符号の違いは表に出ない。NaN はすべての比較に失敗して本体の書き込みに進む）。回転の比較は `Quaternion` の `==` で、実機の許容はおよそ0.1度であり、受け入れ済みの向きが止まった実体の省略（0.05度の凍結を許す）と同じ種類で少し緩い。ただしこの商人ではその許容は実際には効かない。最初の1回の本体の書き込みが商人の向きをそのまま保存し、以後の読み出しは同じビットを返すため、安定状態では props は本体が最後に書いた値をそのまま持つ。比較を相手の実物の変換に対して行うため、何かが props を動かした場合は次のティックで比較が外れて本体の書き込みに戻り、商人が実際に動く・向きが変わる場面（転移、再配置、移動）では毎ティック比較が外れて本体どおりに動く。`Transform.hasChanged` を読む本体の処理はない（逆コンパイル全体で grep して0件）。

効果の見込み（推定）は、商人1体あたり毎ティックの `SetPositionAndRotation` の呼び出し（props の数だけ。変換の分解・保存・ダーティ化と、それに続く子の行列の更新）をなくすことである。商人のいる部屋ではホストと参加者の両方で効き、props が子を持つほど差が広がる。商人は戦闘の中心にいる常時稼働の実体ではないので、全体の負荷への寄与は小さいと推定するが、数値は推定であり、実機での計測は行っていない。
