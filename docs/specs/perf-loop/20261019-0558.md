# perf-loop/20261019-0558

対象: native Dew.Core/CameraManager.cs。

直した内容: `LogicUpdateOcclusionTest`（CameraManager.cs:396）は、壁の向こうのキャラを見えやすくする遮蔽透過のために、ロジックティックごとに4つのグローバルシェーダー値を送り直す。キャラ位置配列 `_CharacterPositions`（16×Vector4）、件数 `_CharacterPositionsCount`、注視エンティティの位置 `_MainCharacterPosition`、ズーム距離の係数 `_DistanceFromCameraMultiplier` の4つで、透過判定が無効のときは件数と係数の2つを毎ティック送る。グローバルシェーダー値は描画のときに読まれるだけで、同じ値の送り直しは描画に対して何もしないのと同じである。NativePerfPatches.cs に NativeOcclusionShaderIdlePerf を追加し、トランスポイラでこの6箇所の `Shader.SetGlobal*` 呼び出しを MOD 側のガード（引数のプロパティIDごとに前回送った値を記録し、完全一致ならネイティブ呼び出しを省く）に差し替えた。配列は16要素すべてを成分一致で比べ、要素が1つでも変わっていれば送る。本体のオクルージョン判定・ループ・補間はそのまま残す。`CameraManager.OnDestroy` が件数0・係数1をガードの外へ直接書いたあともキャッシュを信用できないため、OnDestroy に Postfix を足してキャッシュを捨てている。MOD 設定は `nativeOcclusionIdle`（既定で有効）。OFF のときはガードが素通しし、本体と同じ呼び出しになる。素通しの分も GuardVectorArray と同じ扱いで各ガードが自分のキャッシュを捨てるため、実行中に OFF にした間に書いた値が、ON に戻った後の省略判定に使われることはない。

結果が変わらない理由: ガードが送信を省くのは、前回実際に送った値と新しく計算した値が完全一致したときだけである（スカラー・Vector4・配列は各 float の値を `==` で比べ、+0 と -0 は同一視する。NaN は自身とも一致しないため送り直す。ビット単位の一致を判定しているわけではない。Unity の `Vector4.operator==` は kEpsilon 相当の近似一致で、1e-5 未満の変化を同一視して GPU 側に残してしまうため、比較には使わない）。値が変わっていれば元どおりネイティブの setter を呼ぶ。この4つのプロパティを書く場所は、ゲームの逆コンパイル全体（sod-decomp と sod-contents、グローバル名で検索）では `LogicUpdateOcclusionTest`（6箇所）と `CameraManager.OnDestroy`（件数0・係数1を直接書く。パッチ対象外）だけで、MOD 側にも書き込みはない。ガードのキャッシュは「同じ CameraManager インスタンスが最後にガード経由で送った値」であり、Prefix がインスタンスの変化を検出してキャッシュを捨てる。ガードを経由しない書き込みは、設定 OFF 中の素通しと OnDestroy の直接書き込み（件数0・係数1）の2つで、素通しの分は各ガードが自分のキャッシュを捨て、OnDestroy には Postfix を足して破棄後にキャッシュを必ず捨てている。ティックを持たない重複インスタンスが OnDestroy で 0 と 1 を書いた場合も、生きているインスタンスの次のティック（Prefix が owner 不一致でキャッシュを捨てる）またはガード呼び出しで必ず送り直るため、キャッシュのせいで遮蔽透過が効かなくなることはない。配列は null か長さが16以外のときにキャッシュを使わず素通しして無効化する。

効果の見込み（推定）: ロジックティックごとのネイティブ呼び出し4回（無効時は2回）と、配列送信の256バイトのコピーが、値が動いていない間に省れる。値が動くのはプレイヤーの移動・周囲のオブジェクトの出入り・透過のフェード・ズーム補間の間で、静止している間（店・会話・拠点・部屋間のロード）は毎ティック4回が0回になる。ロジック更新の頻度は今回確認していないので、1回あたり数百ナノ秒程度という見込みと合わせて推定と書く。戦闘中の動きの多い場面では値が変わるため省けず、効果は静止時間の多い場面に偏る。ゲーム内の数値・判定・見た目には影響しない。
