# perf-loop/20261025-0353

対象: `Dew.Core/ActorTransformSync.cs`（座標同期のTransform書き戻し）

## 直した内容

ActorTransformSync は、ネットワークで受信した座標サンプル（SyncVar の `_syncData`）を
2つの経路で Transform へ書き戻します。サーバは LogicUpdate のたび（最大30Hz）に
受信済みサンプルを再適用し、それ以外の全端末（ホストと参加者）は FrameUpdate のたびに
SmoothDamp の補間値 `_renderPos` / `_renderRot` / `_renderScale` を書きます。
対象が止まって補間が収束した後は、この出力は毎フレーム同じ値になるため、
書き込みは全アクター×毎フレームの「同じ値の再書き込み」になっていました。
実機の Transform の setter は値を比較しないので、同じ値でも階層の
変更印の付け直し（dirty 化）というネイティブ呼び出しが毎回走ります。
参加者端末では遠くの静止した敵も含めて全アクター分がこの負担を払っています。

MOD 側に `NativeTransformSyncWriteSkipPerf`（FrameUpdate 用）と
`NativeTransformSyncWriteSkipLogic`（LogicUpdate 用）の2つのパッチ
（NativePerfPatches.cs）を追加し、Transpiler で3つの setter 呼び出しを
「読み戻した現在値と IEEE754 のビット単位で比べて、値が変わるときだけ書く」
ラッパーに差し替えました。チャンネルの有無（`SyncMovementData.Has`）の分岐は
本体に残るので、位置・向き・スケールの無効チャンネルの扱いには触れていません。
ラッパーは設定（DreamforgeConfig の nativeTransformSyncWriteSkip、既定は有効）で
切れます。本体の IL の形が違うとき（setter が各1・Has が3以外のとき）は
1回だけ警告を出して、この2つのパッチを外します。

## 結果が変わらない理由

- ラッパーは書く前に現在値を読んで比べるので、値が等しいときに省くのは
  「同じ値をもう1回書く」動作だけです。同じ値の書き込みは描画結果を変えません。
- 比較はビット一致で行います。+0 と -0 は float の == で等しいですが符号ビットが
  違うため「変わった」と扱い、本体が保持するのと同じ符号付きゼロを書きます。
- 動いているとき・ワープしたとき・初回サンプルのときは、現在値が書く値と
  異なるため、本体と同じタイミングで必ず上書きします。
  アニメーションなど MOD の外から Transform が動かされた場合も、
  毎回読み戻すことで次のフレームに書き直ります。
- 同じ値の書き込みが Transform.hasChanged を立てることだけが異なりますが、
  配布されているゲームコードには hasChanged を読む箇所がなく
  （逆コンパイル木の全検索で確認）、この前提は既存の付属エフェクト系 idle
  パッチ（NativeCastTelegraphIdlePerf など）と同じです。
- 値が NaN のときは != 比較が常に true になるため、本体どおり書き込まれます。

## 効果の見込み（推定）

書き戻しは全アクターが対象なので、戦闘中の数十体のうち動いていない
（または補間が収束した）分の数だけ、毎フレームあたり3回ずつのネイティブ
書き込みが読み出し1回と比較に置き換わります。Transform への同じ値の書き込みは
1回あたり百ナノ秒程度（推定）で、子を持つアクターでは dirty 化に伴う
階層の再計算も減ります。LogicUpdate 側はサーバ（ホスト）だけの経路ですが、
FrameUpdate 側は参加者端末でも全アクター分走るため、参加者の
毎フレーム負荷が下がる見込みです。止まっていないアクターでは
元の書き込みが残るので、効果はそこには出ません。親を持つ transform や
正規化されていない回転では、書き込んだ値を読み戻すと最下位ビットが
変わることがあり、その場合も省けずに毎フレームの書き込みが残ります
（本体と同じ動作で、結果は変わりません）。省けないときの
オーバーヘッドは読み出しと比較の1回ずつだけです。
