# perf-loop/20261024-0000

## 対象

mod src/SodRpg.Mod/HostAuthority.BossPrimus.cs（純白の夢＝Primus ボス装備のホスト側処理）。このファイルはホストだけで走り、参加者への通信はボス演出メッセージの送信側として only だが、被弾・攻撃・メモリ使用・移動完了の各アクティベーションごとに呼ばれる dispatch が主な処理なので、3（被弾ごとの経路の無駄）の観点で見た。

## 直した内容

`DispatchPrimusBoss` は、受理されたイベント1件ごとに `rt.Boss.Build.BossMoves`（最大64件。Primus 装備なら9件）の全走査を重複して繰り返していた。所有判定の走査、攻撃を並べる dispatch ループの走査に加え、`PrimusPhaseInput` と `PrimusCycleInput` が位相を切り替える共通アクション（stage2）と三連の締め（stage6）の在確認を、移動完了では glyph（stage3）の在確認を、それぞれ `BossFind` で全走査していた。つまり基本攻撃1ヒットごとに最大3〜4回の全走査が走る。また所有判定の走査は、受理されないイベント（ヒーローが与えたダメージのアクティベーションなど、戦闘中に最も頻繁な種類）でも必ず走ってから帰っていた。

そこで、`PrimusState` が状態の作成時と、`TickPrimusBoss` が装備エポックの変更時にすでに行っている9種一括の `BossFind` で、毎ヒット参照する3つの区分（stage2・stage3・stage6）の (entry, profile) を `PrimusCombat` に覚えるようにした。毎ヒットの `PrimusPhaseInput`・`PrimusCycleInput` は覚えた判定を流用し、`BossFind` を行わない。所有判定も `PrimusState` の装備走査に集約した（`PrimusSetId` を持つ move は `PrimusProfiles` の9種だけ）。作成側で装備走査を先に済ませ、どれか1つでも在れば状態を登録し、1つも無ければレンタルした状態をプールへ返して null を返す（`PolarisState` と同じ所有確認の形）。非 Primus のヒーローの状態は作られないので、dispatch 側での所有の再判定は不要になった。

## 結果が変わらない理由

`BossFind` の結果は `rt.Powers.Build.BossMoves` の内容と静的な `BossProfiles` だけで決まり、`BossMoves` は `Build` の生成後にどこからも変更されない。装備の付け替えは必ず別インスタンスの `Build` になり、`BossEnsure` は `Build` の差し替えと装備エポックの変更のたびに `ClearBossEffects` → `ClearPrimusBoss` で状態を一度捨てるので、`PrimusCombat` が生きている間は覚えた判定が古くなる窓がない。装備エポックだけが変わる経路でも、`TickPrimusBoss` の変更パスが9種を走査し直して覚えた判定を付け直す。消えた装備の区分は判定を null に戻し、`PrimusPhaseInput`・`PrimusCycleInput` は null のとき旧コードと同じく `BossFind` が失敗したのと同じ早期 return をする。

所有判定とイベント受理の順序は入れ替わる。旧コードの所有判定には副作用がなかったのに対し `PrimusState` は状態のレンタルと登録をするので、作成側で装備走査を先に済ませ、`PrimusSetId` の move を1つも持たない `Build` では登録せずにプールへ返して null を返す（`PolarisState` と同じ）。これで非 Primus のヒーローが64枠の辞書とプールを占めることがなく、`TickPrimusBoss` のエポック変更で最後の Primus move が消えたときも `ClearPrimusBoss` で即座に捨てられる。クールダウン・ダメージ・演出・通信の内容は何も変わらない。この処理はホストだけで走り、送信の量と回数は変わらない。

## 効果の見込み（推定）

被弾・攻撃・メモリ使用・移動完了の各アクティベーションごとに、最大64件（Primus 装備では9件）の `BossMoves` 全走査が1件あたり最大3回（移動完了は4回）から1回（dispatch ループのみ）に減る。全走査1回は最大64回の文字列比較と辞書引きで、1回あたり数百ナノ秒と見積もる。4人で Primus 装備を付けた協力プレイで各プレイヤーが秒間数回攻撃する状況を想定すると、毎秒数十回の全走査がなくなる（推定。1回は小さいが、戦闘中ずっと走る経路の固定費である）。参加者の PC には届かない処理だが、ホストのフレーム時間の裾を下げる。
