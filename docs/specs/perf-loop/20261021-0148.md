# perf-loop/20261021-0148

対象は native `Dew.Core/Se_GenericStealth.cs`（汎用ステルスのステータス効果）である。魔物がステルスで出現するときに付けられる効果で、出現直後の猶予期間を過ぎると、周囲に敵対エンティティ（英雄や召喚）が近づいたときにリビールする。実 DLL から `ilspycmd` で `Se_GenericStealth` を取り出し、空白正規化の diff でリポジトリの逆コンパイル一式と照合した。差分は `base.` 修飾など逆コンパイラの表現差だけで、ロジックは一致していた。

まず参加者（ゲスト）側の経路を確認した結果、このクラスにゲストの毎フレーム経路はなかった。`ActiveLogicUpdate` の本体は `isServer` ガードの直後に return し、ゲストでは何もしない。ゲストが受信するのは、スポーン時の SyncVar（`revealRange`、適用後はほぼ変わらない）、`FxPlayNetworked` の表示指示、被弾時のポップアップ用 ClientRpc（ペイロード 0 バイト、送り側で 0.15 秒間隔に絞られ、既存の `NativeStatsCalcRpcPerf` が統計再計算の通知も絞っている）だけで、受信ごとの処理も軽かった。`OnCreate`・`OnDestroyActor`・被弾・詠唱完了の各イベント処理はホストでのみ購読される。

見つかった無駄はホスト側の接近判定である。`ActiveLogicUpdate` は猶予期間（`revealOnProximityGracePeriod`、初期値 0.65 秒）を過ぎると、`DewPhysics.OverlapCircleAllEntities` で `revealRange`（初期値 1.5）内の敵対エンティティの存在を調べ、1体でも見つかれば `Reveal` する。コードには 0.25 秒間隔に絞る比較（`Time.time - _lastRevealCheckTime < 0.25f`）があるが、throttle 用のフィールド `_lastRevealCheckTime` は `OnDisable` で 0 に戻されるだけで、どこからも代入されない（実 DLL の逆コンパイルと IL ダンプの両方で確認。対照的にポップアップ側の `_lastPopupTextPrintTime` は正しく代入されている）。そのためこの判定は 0.25 秒間隔ではなく、効果が付いている間ずっと毎ロジックTick走る。ステルス魔物が複数体いる部屋では、ホストがTickごとに「ステルス数 × Physics2D の円クエリ + 周囲コライダー全件の走査」を繰り返していたことになる。ホストは権威者として全員の同期を送る側でもあるため、この負荷は協力プレイ全体の滑らかさに響く。

間隔そのものを本来の 0.25 秒に戻す修正は見送った。リビールの発生が最大 250ms 遅れ、敵がいつ操作可能になるかという判定・タイミングが変わるためである。代わりに、間隔を変えずに 1 回の判定を軽くした。呼び出し側は戻り値の `Count > 0` しか読まず、この呼び出しに渡される `CollisionCheckSettings` は `includeUncollidable` だけを立てた既定値（`sortComparer` が null で `SortList` は即座に return する）なので、見つかったエンティティを全件集める必要がない。そこで Transpiler で呼び出し先を「最初の1体で打ち切る」実装へ差し替えるパッチ（`NativeStealthRevealOverlapPerf`、新規ファイル `src/SodRpg.Mod/NativeStealthReveal.cs`）を追加した。差し替わるのは IL の呼び出し1箇所だけで、`base.ActiveLogicUpdate` の呼び出し、猶予期間の判定、表示の開始、`Reveal`、`handle.Return()` はすべて本体の IL のまま残る。差し替え先は同じ `Physics2D.OverlapCircle`（`EntityFilter` は private プロパティの getter をコンパイル済みデリゲートで読む）に同じ引数を渡し、同じ述語を同じ短絡の順序（`TryGetEntity` → `isActive` → `validator.Evaluate` → `hasUncollidable`）で評価し、最初の1体を見つけたら打ち切る。MOD 設定は `nativeStealthRevealOverlapScan`（既定は有効、`DreamforgeConfig.cs` と `ApplyNativePerfConfig` に追加）で切れる。設定を切ったとき、準備に失敗したとき、ヘルパー内で例外が出たときは、ネイティブの `OverlapCircleAllEntities` をそのまま呼ぶ。Transpiler は呼び出しが 6 引数の `IBinaryEntityValidator` オーバーロードちょうど1箇所でないときは差し替えを行わず1回だけ警告を出す（実 DLL の IL ダンプで、該当メソッド内のこのオーバーロードの呼び出しは 1 箇所であることを確認済み）。

結果が変わらない理由は次のとおりである。元の実装は「周囲に条件を満たすエンティティが 1 つでもあるか」の答えだけを呼び出し側に伝えており、集めた残りは捨てられる。打ち切り版は同じクエリで同じ答えを出し、リストの中身（1体目以降を集めないこと）は呼び出し側から観測できない。ソートも既定設定では元々何もしていない。ホスト・ゲストで見えるもの、判定、タイミングは何も変わらない。

効果の見込み（推定）は、ステルス魔物の近くに英雄や召喚がいる時間帯（リビール中を含む）に、各Tickの円クエリのうち「1体目より後のコライダー全件」の走査（プロキシ引き当て・関係判定・リスト追加）が消えることである。魔物の群れに囲まれた近接戦ほど消える分が大きく、静かな場面では差がない。 Physics2D のクエリ自体と 1Tick ごとの実行回数は変わらないので、削減量は 1 判定あたりの走査部分に限られ、量の見積りは推定のままにする。

見送った候補は次のとおりである。(1) `_lastRevealCheckTime` への代入を補って 0.25 秒間隔へ戻す案。効果は大きいが、リビールのタイミングが変わるため本ルールでは直せない。(2) `OnDestroyActor` が null を `-=` していてイベント購読の解除が一度も機能しない点。解除されないハンドラは `isActive` の早期 return で無害で、性能影響は被弾ごとのデリゲート呼び出し1回程度にとどまる。一方で効果をプールが再利用したときの二重購読の振る舞いに関わるため、遊び方を変え得るこの修正は今回の範囲外とした。(3) ポップアップ RPC の受信側確保（`WorldMessageSetting` とクロージャ）。送り側で絞られており効果が小さく、`ShowWorldPopMessage` の受け手が設定を保持し直すかを確かめないまま使い回すのは安全でない。

検証は次のとおりである。実 DLL からの再取り出しと空白正規化 diff（一致）、`Se_GenericStealth::ActiveLogicUpdate` の IL ダンプでの呼び出し形状確認（6 引数オーバーロード、1 箇所のみ、throttle フィールドへの代入なし）を済ませた。`python3 tools/balance/gen_cs.py --check` を通した。`dotnet build src/SodRpg.Mod -c Release -p:GameDir=... -p:ModDeployDir=/tmp/perfloop-x` を通した（エラー 0、警告 6 件は既存分）。`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` は 634 件すべて通過した。`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release` は 231 件通過・1 件スキップで失敗はなかった。テスト側の対応は、`NativePerfPatches.cs` をリンクする `tests/Issue73.Native.Tests/NativeEmbracePositionBoundary.cs` の `DreamforgeConfig` 境界へ同名フィールドを足すことだけである（ファイルのコメントの規約どおり）。実機（ゲーム内）での確認は未実行である（この環境ではゲームを動かせないため）。

レビュー指摘（F1）を受けて、打ち切り版の走査ループにも等価性の裏付けを足した。`NativeStealthReveal.cs` を `Issue73.Native.Tests` にリンクし、本体 API 境界（`tests/Issue73.Native.Tests/StealthRevealOverlapPerfBoundary.cs`）に `DewPhysics`（`EntityFilter`・`TryGetEntity`・`OverlapCircleAllEntities` の 6 引数版の転写）、`DewPool`・`ListReturnHandle<T>`・`IBinaryEntityValidator`・`CollisionCheckSettings`・`Se_GenericStealth`・`Physics2D.OverlapCircle`・`Collider2D` の模倣を置いた。`StealthRevealOverlapPerfTests` は、(a) 条件に合うエンティティが 0・1・複数体のいずれでも `Count > 0` の真偽が本体側の写しと一致し打ち切り版は1体目で止まること、(b) 非エンティティ・非アクティブ・述語不一致・`hasUncollidable` の除外が本体側と同じ `TryGetEntity` → `isActive` → `Evaluate` → `hasUncollidable` の短絡の順序で起きること（述語の呼ばれ方の並びで確認）、(c) 設定オフのとき本体実装へ委譲すること、(d) 例外が出たときその場で本体実装へフォールバックし以後も無効化が続くこと、を確かめる。あわせて、例外経路で借りたプールのリスト2本（コライダー用・エンティティ用）が返却されないままだった点を直した（`catch` で `needToReturn` を見てから `Return()` する。指摘の戻し確認では、直す前のコードで (d) のテストがプールの返し漏れ（リスト 2 本）を検出して失敗し、直した後は 7 件すべて通過した）。修正後の `DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` は 648 件すべて通過、`dotnet build src/SodRpg.Mod` はエラー 0・警告 6 件（既存分）である。
