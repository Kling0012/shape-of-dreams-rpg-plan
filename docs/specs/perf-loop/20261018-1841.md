# perf-loop/20261018-1841

対象: native Dew.Core/CastIndicatorManager.cs（と、そこから毎フレーム呼ばれる経路）。

直した内容: 照準インジケーターの円（`DTT.AreaOfEffectRegions.CircleRegion.UpdateProperties`）は、`CastIndicatorManager` の描画メソッドと領域自身の `Update` の両方から毎フレーム呼ばれ、子トランスフォームのスケール・オフセットとマテリアル float を `Radius`・`Offset`・`FillProgress` から毎回書き直している。`NativePerfPatches.cs` に Prefix を追加し、この3入力とレンダラーのマテリアル実体が前回から変わっていないときは本体の再書き込みを省く。MOD設定 `nativeCastIndicatorCircle`（既定は有効）で切り替えられる。本体側の IL 形状（`get_Radius` 1回、`get_Offset` 2回、`Material.SetFloat` 1回、`_fillProgress` 読み出し 1回）を `Prepare` で検証し、形が違えば警告1回だけでパッチを入れない。`SodRpg.Mod.csproj` は `DTT.AreaOfEffectRegions.Runtime` を参照に追加した。型名は完全修飾で書き、テストの抽出生成物（`NativePersistence.targets` が using 行ごと持ち込む）が DTT 参照のないテストプロジェクトで壊れないようにした。スキップ判定は DTT に依存しない純粋関数 `ShouldSkip` として切り出し、`Offset` は成分ごとの厳密な float 比較に揃えた（`Radius`・`Fill` と同じ。Unity の `Vector2==` が持つ約1e-5 の許容は使わない）。

結果が変わらない理由: このメソッドは入力から出力を決める書き直しで、入力が同じなら既に書き込んであるのと同じ値をもう一度格納するだけである。書き込み先の子トランスフォーム `_circle` とマテリアルの `_FillProgress` を書くのはこのメソッドだけで、射程超出時の縮小アニメ（DOTween）が動かすのは領域ルート側のトランスフォームである。円の位置追従（`playerOrigin` への書き込みと対象の位置の指定）はこのメソッドの外にあり、毎フレームそのまま動く。マテリアルは `CastIndicatorManager.Awake` がレンダラーごとに実体化したもので、実体が差し替えられた場合は比較で検知して必ず再実行する。入力が変化したフレームは必ず通すため、1フレームの遅れも生じない。ゲーム内でこの領域クラスを使うのは `CastIndicatorManager` だけである（逆コンパイル全体を検索して確認）。

効果の見込み（推定）: 照準円が表示されている間、円1つあたり毎フレーム2回の `UpdateProperties`（ローカルスケールとローカル位置の読み書き、`sharedMaterial` の取得と `SetFloat`、合わせて5回ほどのネイティブ呼び出し）を、半径・進行度が動かないフレームは省く。対象指定の照準では二重円で2つ、射程はめったにフレーム間で変わらないため、照準中のほぼ全フレームで省ける推定である。判定・数値・通信には関わりがない。

検証: `python3 tools/balance/gen_cs.py --check` 合格、`dotnet build src/SodRpg.Mod -c Release -p:GameDir=... -p:ModDeployDir=...` 合格（警告は既存のもの）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` 300件合格（`CastIndicatorPerfTests` 13件を含む。`ValidateBody` は本体と同じ読み出し回数の見本を受理し、`get_Radius`・`get_Offset`・`SetFloat`・`_fillProgress` のどれか1つでも回数が崩れた形を拒否する。`ShouldSkip` は全入力が同じときだけ true、Radius・Offset（成分ごと・1 ULP 差）・Fill・マテリアル実体のどれかが変われば false、スナップショットなし・material が null でも false を確認）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release` 149件合格・1件は既存のスキップ。加えて /tmp の一次ハーネスで、実ゲームの `DTT.AreaOfEffectRegions.Runtime.dll` から読んだ `UpdateProperties` の IL を、ビルド済み MOD の `ValidateBody` に通して受理（True）を確認した。IL 生バイトの手デコードでも `get_Radius` 1回・`get_Offset` 2回・`SetFloat` 1回・`_fillProgress` 1回を確認した。実機での動作確認は未実行。
