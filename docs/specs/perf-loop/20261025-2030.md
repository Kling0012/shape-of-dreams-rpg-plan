# perf-loop/20261025-2030

## 対象

`src/SodRpg.Mod/HostAuthority.Monsters.cs`（MOD 側・ホスト authority のモンスター挙動）。

## 直した内容

`TickMonsterBehaviors`（0.1秒ごとのホストティック）で、群れ（Packbound）の味方キャッシュの更新 `PackboundAllyNear` を呼ぶ位置を、睡眠・ゾーン遷移のスキップ branch の後ろへ移しました。以前は眠っているモンスター（戦闘が起きていない部屋のモンスター）やゾーン遷移中のモンスターに対しても、0.2秒ごと（キャッシュ窓 0.15秒 × ティック 0.1秒）に `_monsters` 辞書全体の走査（`FindBehaviorAlly`）を回していました。

## 結果が変わらない理由

眠っている間は更新結果を読む経路がありません。合図の送信（`SendMonsterBehaviorCue`）は睡眠 branch の `continue` で止まり、被弾処理は `isSleeping` で先に抜けます。キャッシュは時間ベース（0.15秒で無効化）なので、窓が切れた後の最初の読み、つまり起床後の最初の被弾・合図・リプレイが同じ計算をその場で行い、同じ値を返します。どの読みの時点でも、返る値は最大 0.15秒前の値という性質は変更前後で同じです。

## 効果の見込み

眠っている Packbound モンスター1体ごとに、0.2秒ごとの `_monsters` 全走査（対象はゾーン内の全モンスター）が止まります。ゾーン遷移中は全モンスターがこの対象になります。効果はホスト側の CPU で、辞書の規模 N と眠っている Packbound 数 P に対して毎秒 5×P×N 回だった候補チェックが減ります（推定: N=80・P=15 で毎秒約6,000回の候補チェック減。推定値です）。ゲスト側への通信は変更前後で変わりません。このファイルからゲストへ出る合図は値が変わったときだけで、今回の変更は送信に触れないためです。
