# perf-loop/20261020-0336

## 対象

mod src/SodRpg.Mod/ClientSession.GemSlotConflict.cs。ゲストを含む全クライアントの ClientSession の tick 配列の先頭で毎フレーム呼ばれ、内部で1秒に1回に間引かれている `TickGemSlotHudProbe` と、ゲストが受け取る `DreamforgeGemSlotConflictMsg` の受信処理 `OnGemSlotConflict`。

## 直した内容

`TickGemSlotHudProbe` は、HUD の技ボタン1個ごとに親の Transform から `GetComponentInChildren<UI_InGame_SkillButton_GemGroup>(true)`（非アクティブ込みの副木全走査）を毎秒行う。この走査の結果を使う先は2つだけで、1回目の Player.log への記録（`_gemSlotHudLogged` が偽の間だけ）と、移動（Movement）ボタンの枠並びを表示へ戻す保険（`HealMovementGroup`）。移動以外のボタンでは1回目を過ぎてからは結果をどこにも使っていないのに、親の副木の走査だけを毎秒続けていた。

そこで、記録用の1回を過ぎたら（`log` が偽になったら）移動以外のボタンを親の走査の前に飛ばすようにした。移動ボタンの走査と保険、1回目の記録は従来どおり行う。

あわせて見て変えなかったもの。ホスト側の `ClearGemSlotConflict` の送信は適用時と5秒ごとの通知だけで量は少なく、受信側の `OnGemSlotConflict` はガード1つと `Protocol.WarnMismatch`（HashSet で重複排除済み）だけなので、通信と受信の経路には手を付けていない。

## 結果が変わらない理由

飛ばすのは「`log` が偽（記録は済み）」かつ「`skillType` が Movement でない」ボタンだけである。この条件のボタンでは、元のコードも走査の結果を `if (log)` の記録にしか渡しておらず、記録済みなら結果は捨てられていた。`button.skillType` の読み取りを前へ動かしたが、副作用のないプロパティの読み取りで、処理の並び順・`movementButton` の意味・1回目のログの出力は変わらない。移動ボタンはこれまでどおり毎秒走査して `HealMovementGroup` に渡すので、枠が隠れたときの表示への復帰も同じタイミングで働く。

## 効果の見込み（推定）

技ボタンは通常5〜7個で、その大半が移動以外である。1個あたりの `GetComponentInChildren(true)` は親の副木の Transform 数に比例し、技ボタンの UI は各記憶の枠やアイコンを下に持つため、十数〜数十ノードの走査と GetComponent になると見込む（推定）。つまり全クライアント（ゲストを含む）で、プレイ中1秒ごとに4〜6回分の副木全走査がなくなる。無駄な走査の削除だけで、送信・受信・見た目・判定は変わらない。
