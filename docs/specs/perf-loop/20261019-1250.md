# perf-loop/20261019-1250

対象: mod src/SodRpg.Mod/ClientSession.KillSync.cs。参加者からホストへ撃破の受領（receipt）を報せる `DreamforgeKillReceiptMsg` の送信経路のうち、差分送信に対応しない旧ホスト（hello の能力応答で `killReceiptDelta == 0`、v3.7.0 より前のMOD）と接続しているときに選ばれるレガシー経路を見た。現行ホスト用の `TickKillReceiptDelta` は前回までのループで間引き済みで、今回の変更には入らない。

直した内容: レガシー経路は5秒ごとに受領リストの内容にかかわらず必ず1通送っていた（空のリストでも送る）。それを、前回送った受領限界との値比較で変化を検出し、変化があるとき・不足事実の要求があるとき・25秒ごとの生存心拍のときだけ送るようにした。送るメッセージの形は従来どおり全件の receipts を含み、欄の並びも同じ。変化の検出は現行の差分経路と同じ `_killSentReceipts`（送信済みの値を記録する辞書）を使い、接続先のアクタ・権限生成・実行IDの変化は `ResetKillReceiptSchedule` がこの辞書を空にするため、次の走査で直ちに全件を送る。5秒の走査間隔と不足事実の要求（32件上限、非空の間は5秒ごとに送り直し）は従来どおり。

結果が変わらない理由: 送る1通の内容は従来と同じなので、旧ホスト側の受信処理（限界の累積マージ・観察セッションの結合・不足要求の処理）は何も変えずに済む。受領メッセージは Mirror の Command（信頼性のある経路）で届くため、同じ値の再送をやめても取りこぼしによる限界の滞留は起きない。旧ホストの受信側（v3.6.0 で確認）はピアの生存を受信間隔で判断しない。退出イベントでピアを外すだけで、30秒の猶予は「まだ1通も受領のない仮ピア」にしか働かない。初回の受領（プレイ開始直後・権限の再生成後・接続の張り直し後）は従来より速い（5秒以内ではなく次の走査）ので、ホストが参加者への撃破リプレイを始めるタイミングは遅れない。不足事実の要求は空でなくなる限り5秒ごとに送り続けるので、復旧のタイミングも変わらない。

効果の見込み（推定）: 旧ホストと接続したとき、参加者1人あたりの受領メッセージが走査ごと12通/分から、変化がなければ心拍の約2.4通/分まで減る（1通は JSON 1個を信頼性経路で送る）。ホスト側では受信ごとの JSON の解析と `PruneAcknowledgedKills`（未承認の撃破全体とピア全員の走査）の回数が同じ分だけ減る。静止中の参加者では5秒ごとの受領リストと不足配列の確保もなくなる。現行ホスト（差分経路）の動作には影響しない。
