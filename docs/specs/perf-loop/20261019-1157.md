# perf-loop/20261019-1157

対象: mod src/SodRpg.Mod/HostAuthority.BossGlacialCore.cs。Skoll 報酬の GlacialCore（`Gem_U_GlacialCore`）を追跡するホスト側アダプタで、毎フレームの経路は2本ある。本体の `ActiveLogicUpdate` に差し込んだ Prefix（`BeginSkollCoreUpdate`）と、射撃間隔の曲線評価の直後にトランスパイルで差し込んだ `SkollCoreInterval` だ。通信はバースト表示（`PublishBossVisual` の kind 9）だけで、これは既存の同値送信を省く仕組みと0.1秒合成で間引かれているので、今回は毎フレーム経路を見た。

直した内容: Prefix の `SkollCoreRuntime` と `SkollCoreInterval` の `SkollCoreRuntime` は、同じ `ActiveLogicUpdate` 1回の呼び出しの中で連続して走り、同じ検証（ランタイム辞書、`BossEnsure`、装備 gem の一致、寿命、部屋と run の一貫性）を毎フレーム2回繰り返していた。そこで Prefix が検証に成功したとき、結果（`HeroRuntime` と `SkollCoreState`）を1更新分だけ静的な記録に置き、`SkollCoreInterval` はそれを流用して2回目の全検証を省く。報酬段階（`BossRewardStage`。記憶と精髄の走査を含む）も1更新で1回だけ計算して使い回す。従来はバースト中に1更新あたり3〜4回計算していた（検証の中で1回、段階の判定でもう1回、返す間隔の決定で `SkollCoreReward` がさらに1回）。Prefix の検証が効かなかったときは、`SkollCoreInterval` が従来どおり自前で全検証するので、この修正だけが外れても動作は保たれる。検証の記録は Finalizer で毎更新、捨てる。

結果が変わらない理由: 検証の入力（英雄の生存、装備、報酬段階、部屋と run、寿命）は `ActiveLogicUpdate` 1回の呼び出しの中では変わらない。その間に本体がするのは銀行の辞書の読みとリストの整理だけで、装備も報酬も変えない。間隔の決定は従来と同じ値を同じ順番で見る（残数、期限、段階、銀行の合計、物理判定）ので、返す間隔も `ApprovedThisUpdate` も発射のタイミングも従来と同一だ。段階は旧コードも同じ更新の中で2〜3回計算していて、毎回同じ値になっていたものを1回の計算にまとめただけでもある。

効果の見込み（推定）: gem 1個あたりの毎フレームの全検証が2回から1回になる。`BossRewardStage` は銀行に未回収のダメージがある間（戦闘中の大半）2回から1回、バースト中は3〜4回から2回になる。協力プレイではホストが全員の gem についてこの cost を払っているので、ホストの毎フレームの負担がその分減る。ネットワークの送信量と回数は変わらない。
