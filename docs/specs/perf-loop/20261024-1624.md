# perf-loop/20261024-1624

対象: `src/SodRpg.Mod/NativeProcSpawnSpread.cs`（重いフレームの反応弾の生成を次フレームへ
分散する処理）と、そこから被弾ごと・毎フレームに呼ばれる `NativeProcCoalesce.Offer`。

## 直した内容

`NativeProcSpawnSpread.Tick()` は MOD の `Update()` から毎フレーム呼ばれ、ホスト・参加者の
どちらでも同じ本体が走っていました。本体は重いフレームの判定（`GraphicsManager` の取得と
`perfPressureStrength`・`Time.unscaledDeltaTime` の読み）、部屋の追跡（`TickRoom`）、キューが
空のときの予算縮小の記録（`Time.unscaledTime` の読み）で、キューに何もなければ書き込みは
ありません。一方、生成を分散する `Defer()` も、弾をまとめる `NativeProcCoalesce.Offer` も、
どちらも `NetworkServer.active` を要求するため、参加者（ゲスト）ではキューが伸びることは
なく、Tick 本体は参加者の PC では結果のない固定費になっていました。

そこで `Tick()` の先頭に `NetworkServer.active` の判定を足し、参加者では診断と判定の
いずれも行わずに抜けるようにしました。ホストでは判定が真なので、本体は1行も変わって
いません。

## 結果が変わらない理由

- `Defer()` は `NetworkServer.active && _heavy && ...` の条件で、参加者では常に false です。
  そのため `Enqueue` は動かず、キューは常に空で、排水ループと `_roomSpawn*` の集計は
  参加者では一度も走りません。
- `NativeProcCoalesce.Offer` も `!NetworkServer.active` で即座に抜けるため、`RoomMerged` と
  `RoomPeakGroup` は参加者でゼロのままです。`_roomPower*` を書く `RecordPowerCarry` の
  呼び元は `HostAuthority`（ホストの Tick）だけです。
- このため参加者で `FlushRoomLog()` は必ず早期リターンし、部屋が変わってもログは
  出ません。`_heavy` の読み手は `Defer()` だけ、予算縮小は `_level > 0` が条件で、
  参加者で `_level` はゼロのままなので、いずれも参加者では不活性です。
- 見た目・判定・通信への影響はありません。分散もまとめも、もともと参加者では
  働いておらず、ホスト側の生成のタイミングは変えていません。
- 切り替え時の扱い: 参加者がホストに戻るような場合でも、次の Tick で `TickRoom` が部屋を
  追い直し、`_heavy` はそのフレームで再計算されます。持ち越しは通常 0.07 秒以内に
  捌けるため、切り替えの時点で残っていません。
- 既存テストの `NativeProcSpawnSpreadTests` は `NetworkServer.active = true` を明示して
  ホスト条件を作っているため、判定の追加で挙動は変わりません（3件とも成功を確認）。

## 効果の見込み（推定）

参加者側で毎フレーム走っていた次の読みをなくします。`GraphicsManager` の取得と
`perfPressureStrength` の読み、`Time.unscaledDeltaTime` と `Time.unscaledTime` の読み
（Unity の native 呼び出し）、`TickRoom` の `ZoneManager.currentRoom` の読みと比較。
1フレームあたり数十ナノ秒程度の固定費で、測定できる差にはほぼならない見込みです
（推定）。ホスト側の負荷は変わりません。

## 見送った候補

- 排水後の `Queue.RemoveRange(0, done)` は残り要素の詰め直し（最大で数百要素の複写）が
  毎重いフレームに走ります。先頭位置を持つ構造にすれば除けますが作り替えになり、
  削れる量も複写数マイクロ秒程度のため見送りました。
- 排水ループの経過時間の確認（`Stopwatch.GetTimestamp()`）は1件ごとに呼んでいますが、
  読む間隔を広げると予算で打ち切る位置が変わるため、結果が同じと確かめられません。
- `Offer` の `Counts` は取得と書き込みで辞書を2回引きます。Unity の .NET には1回に
  まとめる API（`CollectionsMarshal.GetValueRefOrAddDefault`）がないため見送りました。
