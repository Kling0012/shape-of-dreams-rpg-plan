# perf-loop/20261024-0544

## 対象

native Dew.Core/DewAudioManager.cs。効果音の発音を最大64のプール済み AudioSource（Voice）に割り当てて管理するクラスで、発音のたびに `Play` が、以後は `Update` がアクティブな Voice ごとに毎フレーム走る。ゲーム本体は直接変えられないので、MOD から Harmony のパッチで軽くする。`Play` が呼ぶ `AudioManager.SetupAudioSource` と、`TickVoice` が毎フレーム読む `TimescaleManager.effectTimescale`（単純な自動実装プロパティだった）を確認し、3（毎フレーム・被弾ごとの経路の無駄）の観点で見た。

## 直した内容

`AudioManager.NeedsSetupEverytime` は GameBoss・GameSelf・GameOtherPlayers・GameOthers の4型に対して真を返す。この4型は戦闘中の効果音がほぼすべて乗る型で、`DewAudioSource.SetOwnerContext` が演出の所有者に応じて効果音をこの4型へ振り分けるため、被弾・撃破・スキルの発音のたびに `DewAudioManager.Play` が `SetupAudioSource` を毎回呼び直す。`SetupAudioSource` が書き込む項目のうち、空間ブレンド・ミキサーグループ・ロールオフモード・カスタムロールオフ曲線・最小・最大距離は引数の (type, space, rolloff) だけから決まる定数で、優先度だけが意図的に発音ごとに私的メソッド `GetNextDynamicPriority` の輪で回している。逆コンパイル木の全走査で、これらのプロパティを書くのは `AudioManager` だけであることも確かめた。

そこで NativeAudioSetupIdlePerf を新設した。`AudioManager.SetupAudioSource` への Prefix で、同じ AudioSource に同じ (AudioManager インスタンス, type, space, rolloff) で呼び直されたときは、元の本体を実行せずに優先度の式だけを本体どおりに再計算して代入し、残りの定数の書き込みを省く。優先度は `forceCriticalPriority` が真なら 0、偽なら同じ私的メソッドを同じ引数で呼び戻すので、輪の進みと回り込み時の登録済み音源への再優先度設定も本体と同じ順序で起こる。初回や、型・空間・ロールオフ・マネージャーインスタンスのどれかが変わった呼び出しは本体に返して、その結果で欄を置き直す。Game* 以外の型（UI・Music・SFX・GameEnvironment。呼び出し元は一度きりの `DewAudioSourceSetup` と `MusicManager`）は最初から本体に返す。キャッシュは ConditionalWeakTable<AudioSource, …> なので、プールから外れた AudioSource といっしょに欄も消える。対象や私的メソッドが見つからない・形が違う・例外のときは警告を1回出してこの修正だけ外れる（fail-soft）。設定は DreamforgeConfig.nativeAudioSetupIdle（既定は有効）。

テスト側は、リンクされた NativePerfPatches.cs がコンパイルに必要とする本体 API の境界（NativeBoundary.cs・NativeEmbracePositionBoundary.cs）に、AudioType・AudioSpaceType・DewAudioRollOffType・AudioSource・AudioManager（本体と同じ署名の `NeedsSetupEverytime`・`SetupAudioSource`・私的 `GetNextDynamicPriority`）と DreamforgeConfig.nativeAudioSetupIdle を足した。新しいテストファイルは作っていない。

## 結果が変わらない理由

省く書き込みは、引数が同じなら本体が書き込むはずだった値と現在の値が一致する書き込みだけである。`AudioManager` がこれらのプロパティの唯一の書き手で、プールの音源は DontDestroyOnLoad の DewAudioManager の下に置かれてシーンの読み直しでも初期化されないため、同じ (マネージャー, 音源, type, space, rolloff) の2回目以降の呼び出しで本体が行うのは、同じ値の上書きと優先度の更新だけである。優先度は残してあり、その式・呼び出し回数・副作用の順序も本体どおりなので、発音ごとの優先度の回転（音が混んだときにどの音を切るかの決め方）も変わらない。Game* 以外の型と条件が変わった呼び出しは本体に返るので、`MusicManager` や `DewAudioSourceSetup` の経路は何も変わらない。`DewAudioManager` 側の `lastSetup*` による絞り込みはそのままで、この Prefix からは見えない。見た目・音量・ピッチ・発音のタイミングを読む値には触れていない。

## 効果の見込み（推定）

戦闘音1回の発音ごとに、ネイティブな書き込みが約6回（うち1回は AnimationCurve をオーディオシステムへ複製する SetCustomCurve）から、優先度の1回（動的優先度を使う設定なら加えて輪の1呼び出し）に減る。発音は被弾・撃破・スキルごとに全クライアントで起こるので、戦闘が激しい場面で1フレームに発音が固まるときの波が小さくなる（推定）。設定で動的優先度が無効のときは省える分がさらに小さい。追加の負荷は発音ごとの ConditionalWeakTable の参照1回だけである。
