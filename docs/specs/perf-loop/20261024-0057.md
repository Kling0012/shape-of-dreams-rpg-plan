# perf-loop/20261024-0057

対象は `src/SodRpg.Mod/HostAuthority.BossMechanisms.cs` である。直した内容は、弾（`BossProjectileExecutor`）の1ステップの進行（`TickShot`）で、経路に何も当たっていないステップでは敵の走査（`DewPhysics.SphereCastAllEntities`）を丸ごと省いた点である。条件に `collisionCount > 0` を足しただけで、変更は数行にとどまる。

無駄のしくみは次のとおりである。`TickShot` は飛行中の弾1つについてティックごとに、まず `Physics2D.CircleCast`（Entity と CollidableWithProjectile の両レイヤー）で当たり一覧（`_collisions`）を取り、その後 `SphereCastAllEntities` でもう一度同じ原点・半径・方向・距離の円キャストを行う。後者（本体 `DewPhysics` の中でさらに1回の `Physics2D.CircleCast` を実行し、結果の検証ループを回す）の結果が読まれるのは `_collisions` のループの中だけで、`collisionCount == 0` のステップではループが1度も回らず `nearest` が null のまま即 break する。つまり何も当たっていない飛行の大半のステップで、2回目の物理クエリは結果に影響しないまま毎回実行されていた。`StageBossEffects` はホストのティック段階の1つなので、ラジアル弾幕（最大64発）では最大でその数だけティックごとに繰り返っていた。

結果が変わらない理由は次のとおりである。省いたブロックの唯一の読み先は `_collisions` の走査であり、`collisionCount == 0` なら走査が実行されないので、`impact`・`ended`・`travelled`・以降の爆発と終端の処理はすべて変更前と同じ値になる。当たりがあったステップでは従来どおり走査を行い、`entities` による所属確認もそのまま残す。壁（地面・障害物）の判定は別の `Physics.Raycast` と `_collisions` 自身で行うので、当たりゼロのステップでも進行と停止の距離は変わらない。

効果の見込みは推定だが、飛行中の弾1つあたりティックごとの物理クエリが2回から、何かの近くを通るステップだけの最大2回になる。開けた空間を飛んでいる間は半分になる。ホスト側の負荷の削減であり、送信量は変わらない（この変更はメッセージを出さないため、参加者の受信処理には影響しない）。削減量は同時に飛んでいる弾の数と、経路上に敵や壁がいないステップの割合に依存する。

このファイルの参加者側の経路は `PublishBossVisual`（`HostAuthority.BossVisuals.cs`）経路のみで、そちらには同一性判定と種類ごとの間引きが既にあり、このファイル内の送信は出現・更新・削除の必須のものだけだったため、通信を減る変更は見つからなかった。
