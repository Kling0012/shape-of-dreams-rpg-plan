# perf-loop/20261021-1434

対象は本体の `Dew.Contents/Se_ObliviaxKidnap.cs` である。オブリヴィアクスの旅割り込みイベント（`Ge_Obliviax_InterruptTravelAndKidnap`）が全生存プレイヤーに付ける「連れ去り」の状態効果で、直した内容は、ホストが配る `RpcPlayAnimation` を各端末が受けて始まるアニメーションコルーチンの先頭に残っていた開発時のデバッグ出力 `Debug.Log("HELLO" + victim)` を、Harmony の Transpiler で MOD 設定付きの経路へ差し替えて省く点である。配布 DLL の IL（`<<RpcPlayAnimation>g__Routine|9_0>d.MoveNext`、リポジトリの逆コンパイル中間物では `UserCode_RpcPlayAnimation` 側に現れるが、実物のコルーチン内にある）の `ldstr "HELLO"` から `call Debug.Log(object)` までの11命令を1か所だけ照合し、末尾の `Debug.Log` の呼び出し先を、設定が有効なとき何もしない MOD 側の `MaybeLog(object)` へ替える。設定を無効にすると `MaybeLog` が同じ引数で本体の `Debug.Log` を呼ぶので、無効時は本体と同じ出力に戻る。

この経路は参加者側に毎回走る。`RpcPlayAnimation` は `includeOwner: true` の ClientRpc で全クライアントに届き、イベントは全生存プレイヤーを同時に連れ去るため、各端末は連れ去りの瞬間の同じフレームで人数分の `Debug.Log` を処理する。ログは状態の読み書きにも演出にも使われておらず、後続の文がそのまま本体の処理を続ける。削れるのは文字列の構築のうち Unity のログパイプラインに入る部分（マネージドスタックトレースの取得とプレイヤーログへの同期書き出し）で、呼び出しの前の短い文字列連結は残してある。連結ブロックごと消すにはコルーチン内部の分岐（`brtrue.s` と `br.s` が block 内に着地する）の張り替えが必要で、連れ去り1回につき1個の短命な文字列を削る価値はないと判断した。

結果が変わらない理由は、省く対象が何の意味も持たない1行のログ出力だからである。MOD の `MaybeLog` は `NativePerfOptions.ObliviaxKidnapLog`（設定 `nativeObliviaxKidnapLog`、既定は有効）が真のとき何もせず、偽のとき本体と同じ `Debug.Log(message)` を呼ぶので、差し替えは有効時に出力が消えるだけで、コルーチンの他の命令は1つも動かしていない。パッチは11命令の形（`"HELLO"` の文字列、`get_victim`、null 条件の `ToString`、`String.Concat(string,string)`、`Debug.Log(object)`）が1か所だけ完全一致したときのみ差し替え、形が違うか2回目以降は本体をそのまま残して1回だけ警告を出す。効果の見込みは推定だが、連れ去り1回につき各端末で人数分のログ処理（1回あたりスタックトレース取得と同期 I/O を含む）が消える。フレームごとの削減ではなく事象ごとの削減で、量としては小さいが、連れ去りの瞬間はエフェクトが重なる負荷の高いフレームなので、その瞬間のスパイクをわずかに下げる。数値の計測は行っていない。

レビュー指摘に従い、差し替えの照合に命令の種類の検査を加え、このパッチ自体の動作を確かめるテストを足した。`IsLeftoverLogBlock` は `"HELLO"` を載せる命令が `ldstr` であることと、`get_victim` を呼ぶ命令が `call` であることも見る（それまでの実装はオペランドの値だけを見ていて、直前のコメントの主張と食い違っていた。実害はほぼ無いが、照合の厳密さをコメントと一致させた）。`ObliviaxKidnapLogPerfTests`（Issue73.Native.Tests）は、本体の MoveNext が並べる11命令と同じ形を合成した CodeInstruction 列で Transpiler を直接呼び、(a) 形がちょうど1か所一致したときは末尾の呼び出し先だけが `MaybeLog` に替わり他の命令は1つも変わらないこと、(b) 形が1命令違うとき（文字列の中身・命令の種類・分岐の形式・引数の数を変える）、照合が2か所あるとき、差し替え済みの2回目のいずれも入力をそのまま返して警告を1回出すこと、(c) `MaybeLog` が設定の真偽で本体の `Debug.Log` を同じ引数で呼ぶ・呼ばないこと、を確かめる。模倣の `StatusEffect.victim` を本体と同じ形のプロパティ（`get_victim`）に揃え、模倣の `Debug.Log` が受け取った引数を記録するようにしたのは、このテストが getter の解決と引数の転送を見るためである。
