# perf-loop/20261025-0540

対象: `Dew.Core/EntityAbility.cs`（能力の追加・削除を配る `_synedAbilities.Callback` の再購読）

## 直した内容

EntityAbility は、能力の辞書（`_synedAbilities`）に変化があったことを
`OnAbilityChanged` で購読者に配ります。購読は `OnStartClient` の中で
`Callback += OnAbilityChanged` とするだけで、外す処理がどこにもありません
（OnStopClient の上書きはなく、プールに入るときの identity の Reset も
SyncObject のコールバックには触りません）。

このゲームは出現した端末（Actor）をクライアント側のプールで使い回します。
各アセットには despawn ハンドラが登録してあり、Mirror はその経路で identity を
Reset する（`clientStarted` を落とす）ので、同じ GameObject が再出現するたびに
`OnStartClient` がもう1回走り、そのたびに購読が1つずつ重なります。
重なった分は消えないので、プール再利用が K 回済んだインスタンスでは、
その後の能力の追加・削除1つごとに `OnAbilityChanged` が K 回走ります。
能力の追加・削除は出現時だけでなく実行中にも届きます。スキルの付け替え
（報酬の台などでの編成変更。`HeroSkill.EquipSkill` が `SetAbility` と
`UnequipSkill` を通るので、外して付けるの2操作）は、走っているあいだ
繰り返し起きるこのゲームの基本の操作です。ゲストではこの配信は受信経路
（SyncDictionary の差分デシリアライズ → `AddOperation` → Callback）で走り、
ホストでも自分のローカルクライアント経由で同じだけ走ります。
1回ごとに `ClientEvent_OnAbilityAdded` / `Removed`（本体の StatusEffect の
do-ability の後片付け）と `OnLocalHeroAbilityChanged`（スキルボタンの更新）が
同じ回数だけ呼ばれ、購読リスト自体もセッション中ずっと増え続けます。

MOD 側に `NativeEntityAbilitySubscribeDedup`（NativePerfPatches.cs）を追加しました。
`EntityAbility.OnStartClient` の Prefix で、本体が追加に回る前に、
「対象がそのインスタンス、メソッドが OnAbilityChanged」の購読だけを
すべて外します（辞書の Callback の裏フィールドを reflection で読み、
`Delegate.Remove` で1つずつ外す）。他の誰かが同じ辞書に入れた別の購読には
触れません。本体の元の処理（基底の OnStartClient と初期化の再現）は
そのまま走ります。設定（DreamforgeConfig の nativeEntityAbilitySubscribeDedup、
既定は有効）で切れます。本体の形が違うとき（OnStartClient・OnAbilityChanged・
`_synedAbilities`・Callback のどれかが見つからないとき）は、
この修正だけを外して1回警告を出します。

## 結果が変わらない理由

- 購読は必ず1つになります。これは出現から1回も再利用されていない
  新しいインスタンスで本体が動くときと同じ状態です。
- 辞書の操作1つごとのイベントは、回数が重複分から1回になるだけで、
  届く順序・鍵・渡される AbilityTrigger は変わりません。
  購読者は重複した呼び出しで同じ仕事をもう1回していたことになり、
  1回に戻しても結果は同じです。
- 送受信の仕組み（SyncVar・SyncDictionary の同期、RPC）には触れていません。
  出現時の初期化（初期状態は Callback を通らないため OnStartClient が
  直接再現する部分）も本体のままです。
- 外すのは「対象がそのインスタンス、メソッドが OnAbilityChanged」の
  購読だけなので、別の購読者（未来の本体コードや他の MOD）が
  いればその分は残ります。

## 効果の見込み（推定）

効果の大きさは、受け取る側のコピーの再利用回数 K と、実行中の能力の
追加・削除の回数で決まります。クライアント側のプールはプレハブごとに
共有されるので、英雄の予備インスタンスも部屋をまたぐ出現のたびに
使い回され、K は長いセッションで数十に達し得ます（推定）。
スキルの付け替え1回（外して付けるの2操作、複数枠ならそのぶん）は
全クライアントに差分として届くので、K 回の重複配信が1回になります。
ホスト側では出現時のプリセット能力1つごとの Callback も K 分から
1分になります（出現のたびに走る経路です）。1回のハンドラは軽い
（switch と比較1回ずつ）のですが、StatusEffect を付けた相手では
配信先がそのぶん増えるため、戦闘が長く続くほど差が開きます。
増え続けていた購読リストの分も止まります。実行中に能力が変わらない
相手の受信では効果は出ません（出現時の初期化は Callback を通らないため）。
