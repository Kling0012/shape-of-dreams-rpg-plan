# perf-loop/20261020-0106

対象は MOD の `src/SodRpg.Mod/ClientSession.RoomOmens.cs` と、そこから毎フレーム・通信ごとに呼ばれる処理である。部屋の兆し（Room Omen）のメッセージ `DreamforgeRoomOmenMsg` は、ホストが部屋の読み込み時と共鳴の盾が生きている間の 1 秒 1 回の維持送信でしか送らず（`HostAuthority.RoomOmens.cs` の `TickCoopOmen`。内容が変わらない再送はすでに省かれている）、ゲストの受信処理 `OnRoomOmen` は検証と表示の更新だけで低頻度であり、減らせる通信はなかった。代わりに、このファイルで定義する getter が毎フレーム経路になっていることが分かった。

直した内容は、`CoopWardId` が呼びのたびに表示条件の全体を再評価していたのを、1 フレーム 1 回の確定にまとめる変更である。表示条件は `CurrentRoomOmen == ResonantWard` と区域・部屋の一致と 4 秒の有効期限からなり、`CurrentRoomOmen` は内部で `RunActive` を呼ぶため、`List<string>.Contains`（`LobbyReturnedRunIds`）2 回と文字列比較を毎回行う。さらに区域・部屋番号は本体 `ZoneManager` のプロパティ、期限の比較は `Time.unscaledTime` で、どちらもネイティブ呼び出しである。呼び手の `DreamforgeUi.DrawNightmareLabels`（毎フレームの Repaint イベント）は、名札の掃除ループで敵キャッシュ 1 件ごとに 3 回、描画では名札候補の敵 1 体ごとに `CoopWardLabel` が 3 回呼ぶため、敵の多い戦闘部屋では 1 フレームに百数十回この評価が走る。変更後は最初の 1 回だけ条件を確定して 3 スロット分の値を配列に置き、以後の呼びは配列を読むだけになる。条件の入力はメッセージの受信（`ReceiveCoopOmen`）と部屋表示の更新（`SetRoomOmen` が変化時に呼ぶ同じ処理）でしか変わらないため、受信側で確定を無効化し、次の呼びで再確定する。

結果が変わらない理由は次のとおりである。フレーム番号（`Time.frameCount`）は同じフレーム内では変わらず、Unity の 1 フレーム内では `Time.unscaledTime` も区域・部屋番号も更新されない（Update で更新され、OnGUI はそのあとに走る）。したがってフレーム内の 2 回目以降の呼びで再評価した場合と、初回の確定を使う場合で返す値は同じである。メッセージの受信は確定を無効化するので、受信の前後で古い値を使うことはない。条件が偽のときは 3 スロットとも 0 を入れるのは元の式と同じで、`CoopResonanceRemaining` は触っていないため共鳴の残り秒の表示は元どおりである。送信も受信も改変していないため、ホストと参加者の見え方・判定・タイミングは変わらない。

効果の見込み（推定）は、敵の多い戦闘部屋の参加者で、名札描画ごとに百数十回走っていた表示条件の評価（文字列のリスト走査 2 回・文字列比較・ネイティブプロパティ 2 回・時刻のネイティブ呼び出し 1 回）が、1 フレーム 1 回の確定と配列読み 1 回の呼びに置き換わることである。1 回あたりの評価を 0.5～1μs とすると、60fps で毎秒 9 千回超が毎秒 60 回になり、参加者側で毎秒数ミリ秒程度の削減を見込む。数値は推定で、実機での計測は行っていない。

検証は `python3 tools/balance/gen_cs.py --check`、`dotnet build src/SodRpg.Mod -c Release -p:GameDir=... -p:ModDeployDir=/tmp/perfloop-x`（0 エラー）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release`（536 件全通。`CoopOmensWardTests` が `CoopWardId` の値の直接検証を含む）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release`（225 件通過・1 件スキップ）を実行してすべて通した。実機（ゲーム内）での確認は未実行であり、コードとテストで理論上正しいことを確かめた段階である。
