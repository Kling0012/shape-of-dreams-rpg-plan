# perf-loop/20261019-0106

## 対象

mod src/SodRpg.Mod/ClientSession.cs（毎フレームの `Tick` → `TickSalvageExpiry` → `SendLedgerProbe`）。

## 直した内容

ホストの取引台帳の識別子を尋ねる照会（`SendLedgerProbe`）を、これまでの固定2秒間隔から、最初の5回だけ2秒間隔で、答えがなければ15秒間隔に緩めるようにした。接続先が替わったとき（`Wire` の輸送の付け替え）は数えた回数を0に戻し、新しい接続では最初から2秒間隔で尋ね直す。MOD のあるホストは最初の照会に台帳の識別子を添えて答えるので、答えが届いた時点で照会は止まる。

この照会は、参加者が取引を始める前の下調べで、台帳に何も書かれず、ゲームの状態も変えない。MOD のないホスト（旧版を含む）には答えが永遠に届かないため、答えの出ない照会を1接続につき毎2秒、遠征の間ずっと繰り返していた。

## 結果が変わらない理由

照会の答えで決まる動作は、識別子が分かるまで新しい取引を始めさせないこと（`TradeUnavailable`）だけだ。MOD のあるホストでは最初の照会で識別子が確定するので、照会の間隔を変えても何も変わらない。識別子を0に戻す経路は接続の付け替えだけで、そこでは回数も0に戻すので、再接続後の待ち時間は従来と同じ。

挙動が変わるのは、接続から10秒以内に答えが返らなかった場合だけだ。この場合、次の照会までの間隔が2秒から15秒になる。該当するのは MOD のないホスト（識別子は永久に手に入らず、取引は従来どおり最初から使えない。案内文も同じ）か、ホストの読み込みが10秒以上掛かる一時的な場面で、後者では取引の開始が最長で約13秒遅れる。取引は確保地点での操作で、遠征開始直後の十数秒に使うことがないため、遊び方・判定・数値には触れない。

手動の取引の送信、結果不明の取引の照会（`SendDueTradeQueries`、台帳が独自の間隔で管理）、呪いの同期、ビルドの送信は変えていない。

## 効果の見込み（推定）

MOD のないホストに参加している間の照会の送信が、毎2秒から毎15秒になる。1時間の遠征で約1800回だった送信が約244回になり、送信のたびの Mirror の直列化・送受信双方のメッセージ処理も同じ割合で減る（回数は1接続あたりの推定。実際はセッションの長さに依存する）。MOD のあるホストでは最初の1回しか送らないので、削減効果はない。
