# perf-loop/20261025-1614

## 対象

mod src/SodRpg.Mod/AutocastPressure.cs。

## 直した内容

参加者がホストへ送る自動詠唱の負荷報告（1バイトの `DreamforgePerfPressureMsg`）のうち、圧力がゼロのときの毎秒の再送をやめた。ゼロでも最初の1回は送り、そのあとは値がゼロから動くまで送信しない。ゼロ以外の値は、ホストが報告を5秒で失効させる仕様のままであることを保つため、従来どおり毎秒再送する。失敗した送信の再試行と値の変化の報告は、従来どおり1秒間隔の送信制限が担う。

## 結果が変わらない理由

ホストがこの報告から読み取る値は3つあり、どれもゼロ報告の省略で変わらない。

- `RemoteOver`：`TickHost` の0.25秒ループだけが `Peers` を読み、鮮度条件（5秒以内）を満たすエントリの `Over / 255` を最大値に足すだけである。欠けているエントリと鮮度が切れたエントリの加算値は同じ 0 なので、ゼロの報告を新鮮に保つ必要がない。ゼロ以外は毎秒の再送が残るため、失効で見え落ちすることもない。
- `NetOver`：RTT と送信キューから計算され、圧力パケットとは無関係である。参加者→ホストのパケットはホストの送信キューに載らない。
- `AllPeersSupported`：`SupportsAutocastPressure` の判定材料は Hello の capability 交渉で決まる `_autocastPressurePeers` であり、圧力パケットの受信とは無関係である。

値がゼロから動いたときは、次の1秒間隔の送信タイミングで報告する。従来も変化は同じタイミングで送られるため、ホストが変化を知るまでの遅延は変わらない。切断とロスター変更の後始末は capability 側の集合に対して行われ、`Peers` にエントリがなくても `GetPlayer` 経由のフォールバックで同じプレイヤーを忘れる。`Receive` が減ることで `_nextRefresh = 0` による即時再計算も減るが、0.25秒ループが同じ値を再計算するため見え方は変わらない。

## 効果の見込み（推定）

参加者側（送信側）で、圧力がゼロの間（協力プレイ中の参加者の多くの時間にあたる）は、毎秒1回の Mirror 送信（シリアライズ、バッチ積み、UDP パケット1個）がなくなる。ホスト側では、参加者ごとに毎秒1回の受信処理（`GetPlayer` の `GetComponent`、辞書書き込み）がなくなる。1回あたりはµs規模・数バイト〜数十バイトの小さな削減で、体感できる規模ではない（推定）。
