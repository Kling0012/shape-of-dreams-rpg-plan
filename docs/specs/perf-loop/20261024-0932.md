# perf-loop/20261024-0932

対象: `Dew.Core/FxAttachToEntity.cs`（エンティティに付く演出の位置合わせ）

## 直した内容

`FxAttachToEntity.UpdatePosition` は、エンティティに付いた演出1つ1つについて、
1/160秒の間引き（60fps では実質毎フレーム）で位置・向き・サイズを計算し、
最後に Transform へ無条件に書き込んでいます。書き込みは `localScale`（サイズ4種）、
`position`（回転なしの場合）、`SetPositionAndRotation`（それ以外）の3系統です。

本体はホスト・参加者の両方で同じクラスを動かすので、参加者の PC でも
付いた演出の数だけ毎フレームこの書き込みが走ります。

MOD 側に `NativeFxAttachIdlePerf` パッチ（`NativePerfPatches.cs`）を追加し、
Transpiler でこの3系統の書き込みを「現在値と比べて、値が変わるときだけ書く」
ラッパーに差し替えました。付属先が止まっていてカメラ角も動いていなければ、
計算結果は Transform が既に持つ値と等しく、書き込みは階層の再計算マーク
（dirty 化）だけを繰り返していました。ラッパーは設定
（DreamforgeConfig の `nativeFxAttachIdle`、既定は有効）で切れます。
本体の IL の形が違うとき（書き込みの数が 4/1/1 以外のとき）は1回だけ警告を出して
何も置き換えません。
ラッパーの読み出しが null・破棄済みの Transform で例外
（NullReference / MissingReferenceException）を出したときは、本体どおりの
無条件書き込みに戻すだけで、パッチを無効化もし警告を出しもしません
（付属演出はフレームの途中で消えるのが通常のため、本体が同じ例外を出すのと
同じ挙動です）。それ以外の例外では、Prepare の指紋警告とは別枠の警告1回を
出してパッチ全体を無効化し、本体どおり書きます（fail-soft）。

## 結果が変わらない理由

- ラッパーは書く前に現在値を読んで比べるので、値が等しいときに省くのは
  「同じ値をもう1回書く」動作だけです。同じ値の書き込みは描画結果を変えません。
- 演出自体のアニメーションが位置やサイズを別の値に動かしているときは、
  現在値が計算結果と異なるため、本体と同じタイミングで必ず上書きします。
  外部の書き込みを尊重できなくなる経路はありません。
- 同じ値の書き込みが `Transform.hasChanged` を立てることだけが異なりますが、
  配布されているアセンブリにはゲームの Transform の `hasChanged` を読む箇所がなく、
  この前提は既存の hero-weapon idle パッチ（`NativeHeroWeaponIdlePerf`）で
  確認済みのものと同じです。
- 値が NaN のときは `!=` 比較が常に true になるため、本体どおり書き込まれます。

## 効果の見込み（推定）

付属演出は戦闘中に数十〜数百になるため、付属先が止まっている時間の比率次第ですが、
参加者を含む各端末で、毎フレームの Transform 書き込みとそれに伴う階層の dirty 化を
「現在値の読み出し1回＋比較」で済ませられます。Transform の同一値の書き込みは
1回あたり百ナノ秒程度（推定）に加えて子の階層の再計算が続くため、
演出が多い場面（状態異常が重なったボス戦など）で効く見込みです。
付属先が動き続ける演出では元の書き込みが残るので、効果はそこには出ません。
