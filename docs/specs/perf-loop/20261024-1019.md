# perf-loop/20261024-1019

対象は `native Dew.Core/FxGibs_Kinematic.cs` である。撃破・被弾などで飛び散るギブ（破片）エフェクトで、プレハブ経由で全端末がローカルに生成し、それぞれの端末でローカルに物理演算する。直した内容は、`Update` の毎フレーム物理ループが、着地して見た目上止まった破片に対しても爆発が終わるまでネイティブ呼び出しを繰り返していた点である。バウンド処理は y 速度をちょうど 0 にでき、その後も元のコードは毎フレーム「重力で沈めて、バウンド枝で同じ量だけ押し戻す」を繰り返すため、描画上は何も動かない。そこで Harmony の Prefix が前フレーム終了時の `_velocities`／`_spins`（管理配列の読み取りのみ）から破片ごとの静止フラグを算出し、Transpiler が破片の null・activeSelf 確認の直後に、フラグ付き破片をループ増分へ飛ばす分岐を挿入した。`DoBurst` の Postfix で再爆発時にフラグをすべて消す。MOD 設定は `nativeGibsRestSkip`（既定有効）。IL の形が変わっていたときは1回だけ警告して、元の処理のままにする。

結果が変わらない理由は次のとおりである。y 速度がフレーム境界でちょうど 0 になるのはバウンド規則（0.4 未満なら 0 にする）だけで、空中の破片が誤って静止扱いになることはない。静止とみなす閾値は水平速度 0.05（毎フレーム 0.9mm 弱）、回転 1°/秒（毎フレーム 0.02°）で、本体自身が `|vy| < 0.4`（毎フレーム 6.7mm）を「止まった」とみなす基準より1桁厳しい。スキップ後も残り期間の見た目の差はこの閾値未満に収まる。縮小しながら消える演出（`ValueSetter`）、`DoBurst`、`FinishBurst`、`HidePieces` は静止した破片にも従来どおり走り、`useGroundPlane = false` や地面に届かない破片は静止扱いにならない。形の確認は実 DLL（`Shape of Dreams_Data/Managed/Dew.Core.dll`）の `Update`（512バイト）を逆アセンブルして数え、activeSelf 確認1回・Rotate 1回・bounds 1回・position の取得と設定が各2回・`DoBurst` 呼び出し1回・`_pieces[i]` の読み取り1回という指紋がすべて一致したときだけ挿入する。

効果の見込みは推定だが、静止した破片1個あたり毎フレーム6回のネイティブ呼び出し（`gameObject`・`activeSelf`・`position` の取得と設定・`Rotate`・`bounds`）と構造体演算がなくなる。初期速度（impulse 7 前後）から摩擦で毎フレーム半減するため、着地から約8フレーム（0.13秒、推定）で閾値に達し、爆発期間（開始0.25秒＋減衰0.25秒が既定、推定）の後半の破片更新の大半が省略される。ギブは撃破・被弾のたびに全端末でローカルに走るため、ホストだけでなく参加者の PC も同じ削減を受ける。実機（ゲーム内）での確認は未実行である（この環境ではゲームを動かせないため）。
