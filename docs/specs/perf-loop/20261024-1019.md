# perf-loop/20261024-1019

対象は `native Dew.Core/FxGibs_Kinematic.cs` である。撃破・被弾などで飛び散るギブ（破片）エフェクトで、プレハブ経由で全端末がローカルに生成し、それぞれの端末でローカルに物理演算する。直した内容は、`Update` の毎フレーム物理ループが、着地して見た目上止まった破片に対しても爆発が終わるまでネイティブ呼び出しを繰り返していた点である。バウンド処理は y 速度をちょうど 0 にでき、その後も元のコードは毎フレーム「重力で沈めて、バウンド枝で同じ量だけ押し戻す」を繰り返すため、描画上は何も動かない。そこで Harmony の Prefix が前フレーム終了時の `_velocities`／`_spins`（管理配列の読み取りのみ）から破片ごとの静止フラグを算出し、Transpiler が破片の null・activeSelf 確認の直後に、フラグ付き破片をループ増分へ飛ばす分岐を挿入した。`DoBurst` の Postfix で再爆発時にフラグをすべて消す。MOD 設定は `nativeGibsRestSkip`（既定有効）。IL の形が変わっていたときは1回だけ警告して、元の処理のままにする。

結果が変わらない理由は次のとおりである。y 速度がフレーム境界でちょうど 0 になるのはバウンド規則（0.4 未満なら 0 にする）だけで、空中の破片が誤って静止扱いになることはない。静止とみなす閾値は水平速度 0.05（毎フレーム 0.9mm 弱）、回転 1°/秒（毎フレーム 0.02°）で、本体自身が `|vy| < 0.4`（毎フレーム 6.7mm）を「止まった」とみなす基準より1桁厳しい。さらに、静止は効果値（`FxInterpolatedEffectBase.currentValue`）が縮小を駆動していない期間、すなわち plateau（既定の easeInOutSine では 1.0、丸めの余地を残して 0.999 以上）に限る。縮小しながら消える演出（`ValueSetter`）は効果値が plateau を下回る全期間で破片の縮小を続け、元のコードは同じ重力と bounds 判定で縮んだ分だけ破片を沈めて着地面に戻す。スキップした破片はこの再着地を受けないため縮みながら浮いて見えるので、フェードイン・フェードアウト中（効果値が 1 未満の間）は全破片が元の物理演算を通り続け、`DoBurst`、`FinishBurst`、`HidePieces` も従来どおりすべての破片へ走る。`useGroundPlane = false` や地面に届かない破片は静止扱いにならない。Prefix が読む効果値は前フレームの値なので、減衰の最初のフレームだけは1フレーム遅れてフラグが外れるが、その間の縮小は初動の ease-out で 1% 強（破片寸法の約1%、1〜2mm 未満の寸法ではサブピクセル）に収まる。形の確認は実 DLL（`Shape of Dreams_Data/Managed/Dew.Core.dll`）の `Update`（512バイト）を逆アセンブルして数え、activeSelf 確認1回・Rotate 1回・bounds 1回・position の取得と設定が各2回・`DoBurst` 呼び出し1回・`_pieces[i]` の読み取り1回という指紋がすべて一致したときだけ挿入する。activeSelf 確認の分岐は brfalse に限定し、共有確認ではその分岐自身を除外して（自分自身は常に自分の飛び先と一致するため）null 確認の brtrue が同じ飛び先を共有することでループ増分であることを確かめる。ループ添字の ldloc の複製は opcode と operand だけを写し、ラベルの重複による IL 生成失敗を防ぐ。

効果の見込みは推定だが、静止した破片1個あたり毎フレーム6回のネイティブ呼び出し（`gameObject`・`activeSelf`・`position` の取得と設定・`Rotate`・`bounds`）と構造体演算がなくなる。初期速度（impulse 7 前後）から摩擦で毎フレーム半減するため、着地から約8フレーム（0.13秒、推定）で閾値に達する。静止が有効なのは効果値が plateau の間だけなので、削減が効くのは プレハブの sustain 期間（フィールド既定は sustainTime 0 なので、既定値どおりだと plateau は一瞬にすぎない。実際の削減量はプレハブ設定に依存する）。フェードイン・フェードアウト中は縮小の再着地のために元の物理演算が全破片で走り続ける。ギブは撃破・被弾のたびに全端末でローカルに走るため、削減が効く場面ではホストだけでなく参加者の PC も同じ削減を受ける。実機（ゲーム内）での確認は未実行である（この環境ではゲームを動かせないため）。

検証は次のとおりである。`python3 tools/balance/gen_cs.py --check` が通った。`dotnet build src/SodRpg.Mod -c Release -p:GameDir="$HOME/dev/sod-gamedata/Shape of Dreams" -p:ModDeployDir=/tmp/perfloop-x` が0エラーで通った（警告6件は既存のもの）。`tests/Issue73.Native.Tests/GibsRestSkipPerfTests.cs` に静止判定の単体テストを置いた: plateau で接地した破片だけが静止扱い、空中・水平速度か回転が閾値以上・`useGroundPlane=false`・縮小中は静止扱いにならない、縮小の開始で既存のフラグが外れる、`DoBurst` の Postfix がフラグを消す、配列の長度が揃わない再初期化で古いフラグを残さない、設定が無効なら常に false、添字の境界検査。`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` と `DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release` の全数実行はこの作業では行わず、gh-auto の確認段階に回す。Transpiler が実 DLL の IL に対して期待どおり分岐を挿入するかは、ゲーム内での警告ログの有無で確認するのが確実で、これは未実行として残す。
