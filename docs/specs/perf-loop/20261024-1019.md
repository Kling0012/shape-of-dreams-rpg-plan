# perf-loop/20261024-1019

対象は `native Dew.Core/FxGibs_Kinematic.cs` である。撃破・被弾などで飛び散るギブ（破片）エフェクトで、プレハブ経由で全端末がローカルに生成し、それぞれの端末でローカルに物理演算する。直した内容は、`Update` の毎フレーム物理ループが、着地して見た目上止まった破片に対しても爆発が終わるまでネイティブ呼び出しを繰り返していた点である。バウンド処理は y 速度をちょうど 0 にでき、その後も元のコードは毎フレーム「重力で沈めて、バウンド枝で同じ量だけ押し戻す」を繰り返すため、鉛直方向の移動は相殺される。そこで Harmony の Prefix が前フレーム終了時の `_velocities`／`_spins`（管理配列の読み取りのみ）から破片ごとの静止フラグを算出し、Transpiler が破片の null・activeSelf 確認の直後に、フラグ付き破片をループ増分へ飛ばす分岐を挿入した。`DoBurst` の Postfix で再爆発時にフラグをすべて消す。MOD 設定は `nativeGibsRestSkip`（既定有効）。IL の形が変わっていたときは1回だけ警告して、元の処理のままにする。

静止とみなす条件と許容差は次のとおりである。y 速度がフレーム境界でちょうど 0 になるのはバウンド規則（0.4 未満なら 0 にする）だけで、空中の破片が誤って静止扱いになることはない。静止とみなす閾値は水平速度 0.05（毎フレーム 0.9mm 弱）、回転 1°/秒（毎フレーム 0.02°）で、本体自身が `|vy| < 0.4`（毎フレーム 6.7mm）を「止まった」とみなす基準より1桁厳しい。さらに、静止は効果値（`FxInterpolatedEffectBase.currentValue`）が縮小を駆動していない期間、すなわち plateau（既定の easeInOutSine では 1.0、丸めの余地を残して 0.999 以上）に限る。縮小しながら消える演出（`ValueSetter`）は効果値が plateau を下回る全期間で破片の縮小を続け、元のコードは同じ重力と bounds 判定で縮んだ分だけ破片を沈めて着地面に戻す。スキップした破片はこの再着地を受けないため縮みながら浮いて見えるので、フェードイン・フェードアウト中（効果値が 1 未満の間）は全破片が元の物理演算を通り続け、`DoBurst`、`FinishBurst`、`HidePieces` も従来どおりすべての破片へ走る。`useGroundPlane = false` や地面に届かない破片は静止扱いにならない。Prefix が読む効果値は前フレームの値なので、減衰の最初のフレームだけは1フレーム遅れてフラグが外れるが、その間の縮小は初動の ease-out で 1% 強（破片寸法の約1%、1〜2mm 未満の寸法ではサブピクセル）に収まる。形の確認は実 DLL（`Shape of Dreams_Data/Managed/Dew.Core.dll`）の `Update`（512バイト）を逆アセンブルして数え、activeSelf 確認1回・Rotate 1回・bounds 1回・position の取得と設定が各2回・`DoBurst` 呼び出し1回・`_pieces[i]` の読み取り1回という指紋がすべて一致したときだけ挿入する。activeSelf 確認の分岐は brfalse に限定し、共有確認ではその分岐自身を除外して（自分自身は常に自分の飛び先に届くため）null 確認の分岐が同じ飛び先に届くことでループ増分であることを確かめる。このとき Harmony は分岐ごとに独立した Label 値を読んで飛び先の命令へ付けるため、同じ飛び先への2つの分岐も Label 同士の値比較では決して一致しない。そのため共有確認は値比較ではなく着地命令の解決（IndexOfLabel）で行う（初期実装が値比較だったため、実 DLL に対しても常に警告1回の非適用になる状態だったのを修正ラウンドで直した）。着地命令は命令列としても検証する: 同一ローカルの ldloc・ldc.i4.1・add・stloc（ループ増分）であることと、挿入時に複製する添字 ldloc がその増分のローカルを指すこと（実 DLL の着地 IL_01d2 は ldloc.1・ldc.i4.1・add・stloc.1 の増分で、`_pieces[i]` の添字読み取りも同じローカルの ldloc.1。逆アセンブルで確認）。while(true) の再条件評価への着地や、増分と異なるローカルからの添字読み取りは不適用とする。ループ添字の ldloc の複製は opcode と operand だけを写し、ラベルの重複による IL 生成失敗を防ぐ。

F1-a の残留速度・回転は許容差として残す。静止スキップは `_velocities[i]` の更新と `Rotate` だけでなく摩擦減衰も通らないため、閾値未満の水平速度と回転は plateau の間そのまま残り、フラグが外れたあとに元の摩擦減衰を再開する。元のコードとの軌跡・時刻の厳密な一致は保証しない。60fps・既定の `groundFriction = 0.5`・毎フレーム接地という条件で、水平速度 0.0499m/秒・回転 0.999°/秒から残りの半減列を合計すると、元のコードが追加で動く量は約1.663mm・0.0333°となる。これはその条件での計算値であり、異なる dt・摩擦・接地条件の上限ではない。同じ dt・摩擦・接地条件で十分なフレーム数を処理すれば再開後の合計量は同じになるが、消えるまでの残り時間や dt が異なれば最終位置・姿勢にも差が残り得る。裁定で重大な不具合ではないとされた範囲として、静止閾値とスキップ処理は変更しない。
