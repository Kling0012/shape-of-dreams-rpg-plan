# perf-loop/20261021-0958

対象は `src/SodRpg.Mod/HostAuthority.MemoryNativeProjectileAdapters.cs` である。直した内容は、ダブルタップのコルーチンを受け取る接辞（`NativeDoubleTapCoroutineCapture.Postfix`）が反射で読んでいた、ローカル関数の状態を保持するコンパイラ生成クラスのフィールド2つを、起動時に作ったコンパイル済みアクセサ（`AccessTools.FieldRef`）に置き換えた点である。変更は契約クラスへのアクセサ2フィールドの追加と Postfix の2行だけにとどめた。

本体 `Se_D_DoubleTap` は `isServer` のときだけ通常攻撃の発射イベントを購読し、スタックがある間は発射ごとに `Routine()` ローカル関数を呼んでコルーチンを作る。MOD の Postfix はこのファクトリの戻り値ごとに、その状態クラスの `<>4__this`（`Se_D_DoubleTap`）と `obj`（`EventInfoAttackFired`）を `FieldInfo.GetValue` で読んでいた。後者は構造体なので、呼び出しごとに戻り値を `object` へボクシングしており、1回の発射につき確保が1件発生していた。前者も参照型ゆえ確保はないが、反射の実行時検査を毎回通っていた。

結果が変わらない理由は、コンパイル済みアクセサが同じフィールドを同じ型で読むためである。`FieldRef` は `ldarg`・`castclass`・`ldfld`・`ret` だけの動的メソッドで、`ref` 返しなので構造体をボクシングせずそのまま複製する。読み取る値は反射と同一で、取得後の流れ（`CaptureDoubleTapCoroutine` への値渡し、拒否時の `Rejected` 付き `PendingDoubleTap`）は何も変えていない。契約の検証（フィールドの存在・非静的・型一致）は従来どおり先に行い、通ってからアクセサを作る。作成に失敗した場合は既存の `Available = false` の経路で警告を1回出してダブルタップの帰属追跡だけが外れる。起動時プレフライト（`NativePatchPreflight.ValidateDoubleTapCapturedFields`）が使う `Source`・`Fired` の `FieldInfo` は残したので、事前検証の内容も変わらない。

効果の見込みは推定だが、ダブルタップ装備中の英雄の攻撃1回につき構造体ボクシング1件（数十バイト）と反射呼び出し2回が消える。攻撃は戦闘中に毎秒数回起きるので、確保の削減は毎秒数件の規模である。参加者側の負荷は変わらない。購読自体が `isServer` だけなのでゲストではこの接辞が走らず、ファイル内の他のパッチも `NetworkServer.active` で保護されている。参加者側の経路がないため、規則3（攻撃ごとの経路での boxing の除去）の観点で選んだ。
