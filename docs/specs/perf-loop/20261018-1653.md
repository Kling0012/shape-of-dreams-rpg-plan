# perf-loop/20261018-1653

対象: native Dew.Core/Ai_EmbraceNewIdentity.cs（アイデンティティの取り込み。`ActiveFrameUpdate` から毎フレーム呼ばれる `UpdatePositions` と、その周辺）。

直した内容: MOD 側 src/SodRpg.Mod/NativePerfPatches.cs に `NativeEmbracePositionPerf` を追加した（設定 `nativeEmbracePositionReuse`、既定はON）。取り込みの詠唱中、`UpdatePositions` は `NetworktargetSkill` プロパティを null 判定・書き込み・ループ内の読み出しの3箇所で呼ぶ。この getter（Mirror の `GetSyncVarNetworkBehaviour`）はクライアントではキャッシュを返さず、呼ぶたびに `NetworkClient.spawned` の辞書引きと `NetworkBehaviours` 配列からの取り出し＋キャストをする。さらに `onSkillTransform` の要素ごとに `NetworktargetSkill.position`（`transform` を経由するネイティブ読み出し）を読み直す。Harmony の Prefix で本体と同じ計算をしながら、この参照・座標・イージングデリゲートの各読み出しを毎フレーム1回にまとめた。パッチ先が見つからない・非公開フィールドの形が違うときは警告1回でこの機能だけ外れる（ほかの native パッチと同じ）。

結果が変わらない理由: 同じ同期メソッドの中で解決結果は変わらず、毎回同じ `SkillTrigger` インスタンスが返るため、最初に1回読んだ参照をそのまま使う。ループ内の全要素は本体でも毎回同じ値（書き込み直後の `transform.position`）を受け取るため、書き込み後に1回だけ読んだ値を全要素へ渡す結果と一致する。補間元・補間先・`Mathf.Clamp01`・`Time.time` と `creationTime` の除算・イージングの呼び出しは本体と同一の式をそのまま使い、位置・回転・見た目に手を加えない。

効果の見込み（推定）: 取り込みの詠唱中（チャンネル時間の数秒間）、クライアントで毎フレームあった (2+要素数) 回の辞書引きと (1+要素数) 回の `Transform.position` ネイティブ読み出しが、それぞれ1回になる。この経路は詠唱中しか走らないため効果はその間に限られ、フレーム全体への寄与は小さい。

検証: `python3 tools/balance/gen_cs.py --check` 合格、`dotnet build src/SodRpg.Mod -c Release` 合格（警告は既存）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` 278件合格、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release` 149件合格・1件スキップ（既存の環境によるスキップ）。実機での動作確認は未実行。

## 修正ラウンド2（レビュー所指摘 F1・F2）

指摘 F1（構成原則 C-I）: `GuardNativeBody` が `Prepare` の try の外で `GetMethodBody()` を呼んでいた。ゲーム更新で `UpdatePositions` が extern・抽象メソッドになって body が null を返すとき、IL を読めない環境で例外が出るときに例外が `Prepare` から漏れ、ほかの native パッチの適用まで巻き込むおそれがあった。

対応（src/SodRpg.Mod/NativePerfPatches.cs）: `GuardNativeBody` の中で body が null なら警告して false を返し、IL の取得と指紋の照合全体を try/catch で包んだ。どちらの失敗も警告1回でこの機能だけが外れる（fail-soft）。

指摘 F2（構成原則 C-II）: Prefix の配布値を `skill.transform.position` から読んでいたのに対し、本体のループは各要素へ `NetworktargetSkill.position`（Actor.position）を配る。両者の等価性は「Actor.position は transform.position を返す」という、IL 指紋ガードも契約テストも固定していない前提に依存していた。ゲーム更新が Actor.position の getter（例: 補間オフセットの追加）だけを変え、UpdatePositions の本文をバイト同一のまま残すと、指紋ガードは一致と判定してパッチを生かし続け、詠唱中の onSkillTransform 配布座標だけが本体と黙ってずれるおそれがあった。

対応（src/SodRpg.Mod/NativePerfPatches.cs、tests/Issue73.Native.Tests/NativeEmbracePositionBoundary.cs）: Prefix の配布値を、書き込みの後に `skill.position`（本体ループと同じ Actor.position）から1回だけ読む形に変えた。参照読み出しの削減効果は変わらず、等価性は Actor.position の getter の定義に依存しなくなった。記録として、出荷済み Dew.Core r1.4.0.13 の Actor.position は `get { return transform.position; }`（set は transform.position への書き込み）であることを ilspycmd で確認し、境界ファイルのコメントに転写の元（逆コンパイルと IL の同じ分岐であること）と併せて残した。
