# perf-loop/20261018-1653

対象: native Dew.Core/Ai_EmbraceNewIdentity.cs（アイデンティティの取り込み。`ActiveFrameUpdate` から毎フレーム呼ばれる `UpdatePositions` と、その周辺）。

直した内容: MOD 側 src/SodRpg.Mod/NativePerfPatches.cs に `NativeEmbracePositionPerf` を追加した（設定 `nativeEmbracePositionReuse`、既定はON）。取り込みの詠唱中、`UpdatePositions` は `NetworktargetSkill` プロパティを null 判定・書き込み・ループ内の読み出しの3箇所で呼ぶ。この getter（Mirror の `GetSyncVarNetworkBehaviour`）はクライアントではキャッシュを返さず、呼ぶたびに `NetworkClient.spawned` の辞書引きと `NetworkBehaviours` 配列からの取り出し＋キャストをする。さらに `onSkillTransform` の要素ごとに `NetworktargetSkill.position`（`transform` を経由するネイティブ読み出し）を読み直す。Harmony の Prefix で本体と同じ計算をしながら、この参照・座標・イージングデリゲートの各読み出しを毎フレーム1回にまとめた。パッチ先が見つからない・非公開フィールドの形が違うときは警告1回でこの機能だけ外れる（ほかの native パッチと同じ）。

結果が変わらない理由: 同じ同期メソッドの中で解決結果は変わらず、毎回同じ `SkillTrigger` インスタンスが返るため、最初に1回読んだ参照をそのまま使う。`skill.transform` はローカル変数で保持し、位置の書き込みと祖先判定に使う。配布値は書き込み後の `skill.position`（本体と同じ `Actor.position`）から1回だけ読む。`onSkillTransform` の要素が `skill.transform` 自身かその祖先なら、要素への書き込みで後続要素の配布値が変わり得るため、一括配布せず本体経路へ戻る。それ以外の要素には同じ座標を配布できる。補間元・補間先・`Mathf.Clamp01`・`Time.time` と `creationTime` の除算・イージングの呼び出しは本体と同一の式を使う。祖先がある場合の制限と検証は下の「修正ラウンド3」に記録している。

効果の見込み（推定）: 取り込みの詠唱中（チャンネル時間の数秒間）、祖先の要素がない場合は、クライアントで毎フレームあった (2+要素数) 回の辞書引きと、要素数分の `skill.position`（`Actor.position`）の読み出しが、それぞれ1回になる。補間先の `caster.position` は本体も Prefix も1回読む。祖先判定には毎フレーム階層の深さ分の `Transform.parent` のネイティブ読み出しと Unity の null 比較、要素数×階層の深さ分の参照比較が加わる。深い階層では、この追加コストが削減効果を一部打ち消し得る。祖先の要素がある場合は本体も実行するため、削減効果はない。この経路は詠唱中しか走らないため効果はその間に限られ、フレーム全体への寄与は小さい。実測はしていない。

祖先判定の結果はキャッシュしない。`onSkillTransform` の要素や skill の親子関係が途中で変わる場合も本体経路へ戻せるよう、毎フレーム確かめる。初回だけ判定する案はこの不変条件を保証できないため採用しない。

## 修正ラウンド3（レビュー所指摘 F1）

指摘: 本体のループは要素ごとに `NetworktargetSkill.position` を読み直すのに対し、Prefix は配る値をループの前に1回だけ読む。`onSkillTransform` の要素が `skill.transform` 自身かその祖先のとき、その要素への書き込みが skill のワールド座標を動かすため、本体では後の要素が移動後の別の値を受け取るが、Prefix では全要素が同じ値になる。この前提（どの要素も skill の祖先ではない）は IL 指紋にも等価性テストにも固定されておらず、テストの Transform 模倣に親子関係がなかったためこの経路を確かめられなかった。

対応（src/SodRpg.Mod/NativePerfPatches.cs、tests/Issue73.Native.Tests/）:

- 前提を仮定せず実行時に確かめる形にした。`HasAncestorElement`（`skill.transform` から親の連鎖を1回たどり、各要素との参照一致を見る。連鎖は自身から始めるため skill.transform 自身も検出する）を追加し、Prefix は skill への書き込みの後にこれを確かめて、祖先の要素があれば配布せず本体経路へ戻る（Harmony の Prefix が true を返す）。この場面では毎フレーム本体の計算がそのまま走るため、性能の削減効果は祖先がある間だけ消え、配布結果は常に本体と一致する。連鎖の探索は書き込みに成功した直後（skill.transform とその祖先が生きている）だけなので、参照比較で足りる。
- 模倣 UnityEngine.Transform に `parent` を足し、(1) `HasAncestorElement` が自身・親・祖先を検出し、子・無関係・null 要素を対象外にすること、(2) 要素が親のとき Prefix が本体経路への合図を出し自身は配布しないこと、(3) 要素が子孫のときは従来どおり一括配布して本体と同じ結果になること、のテストを3件追加した。
- 模倣の `position` は親子の座標の連鎖を模かないため、「祖先があると本体と配布がずれる」こと自体は再現できない。この前提と Prefix の戻り方の対応は境界 NativeEmbracePositionBoundary.cs のコメントにも記録した。
- あわせて、境界の DreamforgeConfig 模倣に「ApplyNativePerfConfig（NativePerfPatches.cs）に設定を足したら同じ名前のフィールドを模倣にも足す。足し忘れるとテストプロジェクトのコンパイルが壊れる」注記を入れ、NativeCastIndicatorCirclePerf の「テストハーネスがこのファイルからクラスを抽出する」という実態と合わなくなったコメントを、ファイル全体をテストプロジェクトへコンパイルする現状に合わせて直した。
