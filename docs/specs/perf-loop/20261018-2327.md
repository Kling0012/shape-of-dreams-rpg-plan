# perf-loop/20261018-2327

対象は本体 `Dew.Core/CurseStatusEffect.cs`。呪いそのものに毎フレームの処理はない（`StatusEffect.FrameUpdate` は残り時間なしでは数個のフラグ検査のみ）が、`OnCreate` が `TrackKills(8f, OnKill)` で作る `KillTracker` が、呪いを受けた英雄がダメージを与えるたびに重い処理を回していた。

## 直した内容

`KillTracker.TrackDamagedVictims`（`ActorEvent_OnDealDamage` への登録。被弾ごと＝英雄が与えるダメージごとに呼ばれる）は、末尾で `CullExpiredEntities` を呼ぶ。これは追跡辞書 `Dictionary<Entity, float>` の全走査で、期限切れ（猶予8秒。`Hero.OnStartServer` が全英雄に作るアシスト判定用の追跡は30秒）か破壊済みの項目を掃除する。大群との戦闘では、1回のダメージごとに数十〜数百項目の走査が走る（英雄ごとに常に1個、呪いごとにもう1個）。

`NativePerfPatches.cs` に `NativeKillTrackerCullPerf` を足し、`CullExpiredEntities` の Prefix でこの掃除走査を1秒に1回に間引いた（`DreamforgeConfig` の `nativeKillTrackerCullThrottle`、既定は有効）。最終走査時刻は `ConditionalWeakTable` で追跡器ごとに持つ。`Prepare` で本体メソッドの形（`_trackingDict` 読み出しと辞書の `Remove` 呼び出しを含むか）を確かめ、崩れていれば警告1回で無効になる。

## 結果が変わらない理由

- `CullExpiredEntities` がするのは期限切れ・破壊済み項目の辞書からの削除だけ。`OnDeath` の登録解除は `_cachedReportKill`（未代入のため null）を引くもので、もともと何も外していない。
- 撃破の報告側 `ReportKill` が自分で `Time.time - value > _gracePeriod` を再判定するため、期限切れの項目が辞書に残っていても報告は起きない。猶予内の項目は本来も削除されないので、報告の有無は変わらない。
- 間引いた区間で期限切れ項目に再ダメージが当たると、本体では削除後の再追加（`OnDeath` への重複登録。2回目以降の発火は辞書に項目がなく何もしない）だったのが、時刻の更新だけになる。どちらも撃破時の報告は1回きりで同じ。

## 効果の見込み（推定）

被ダメージイベントごとの O(追跡項目数) 走査が、追跡器ごとに毎秒1回に減る（推定。ホスト側のみ。項目数は直近8〜30秒にダメージを与えた敵の種類数に比例）。割り当ての増減はなく、辞書は最大で猶予＋1秒分の項目を保つ。削減量は実測していない。
