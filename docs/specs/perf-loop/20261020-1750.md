# perf-loop/20261020-1750

対象は本体の `Dew.Core/Mon_RedGiant.cs`（逆コンパイル）である。このモンスターは被弾の計測用の特殊モンスターで、SyncVar を3本（`_totalDamage`・`_dps`・`_maxSingleDmg`）持ち、その値を頭上の `dpsText`（TextMeshPro）に表示する。ホスト側では被弾イベントごとに合計と最大値を進め、`ActiveLogicUpdate` の中で3秒以内の被弾を数えて DPS を出す。参加者側の出口はこの3本の SyncVar の差分受信であり、毎フレームの経路は `ActiveLogicUpdate` の表示更新である。

見つけた無駄は、その表示更新である。`ActiveLogicUpdate` の最後で、ホストと参加者の区別なく、生きている実体ごとに毎フレーム `dpsText.text = string.Format("Total: {0:#,##0}\r\nDPS: {1:#,##0}\r\nMax Single Dmg: {2:#,##0}", (object)_totalDamage, (object)_dps, (object)_maxSingleDmg)` を実行する。3つの入力は表示対象の SyncVar の float そのものなので、被弾と受信が起きていないフレームでは、組み立てられる文字列は前のフレームと完全に同じになる。TextMeshPro の `text` セッターは同じ文字列を受け取ると処理をやめるため、画面には何も起きず、残るのは文字列の確保と float のボックス化3回だけである。それが実体が存在する間ずっと毎フレーム続き、ホストと参加者の両方で同じ余分な確保が起きる。

直した内容は、`NativePerfPatches.cs` に `Mon_RedGiant.ActiveLogicUpdate` への Transpiler を1本足したことである。本体 IL の末尾の、各 ldfld の前に ldarg.0 が入る3つの ldfld と box、`String.Format`、`TMP_Text.set_text` という決まった並びを検証した上で、box だけを外し、`Format` と `set_text` の組を同じ引積み（text・書式・float3つ）の MOD 側ヘルパーに置き換える。ヘルパーは TextMeshPro の実体ごとに最後に組み立てた3つの値を覚えておき、3つとも変わっていなければ TextMeshPro に触れずに帰る。変わっていれば、本体と同じ文字列定数で同じ `string.Format` を実行する。設定が OFF の間はヘルパーが毎回組み立てるので本体どおりである。本体の名前や IL の並びが変わっていれば警告を1回出してこの修正だけを外れる。MOD 設定 `nativeRedGiantDamageText`（既定ON）で切れる。テスト側の置き換えとして、`NativeBoundary.cs` に `Mon_RedGiant` と `TMPro.TMP_Text` の境界を、`NativeEmbracePositionBoundary.cs` の `DreamforgeConfig` に同名の設定フィールドを足した。

結果が変わらない理由は、省くのが「前のフレームと同じ文字列の組み立て」だけだからである。値が変わったフレームでは、ヘルパーは本体と同じ定数で同じ `string.Format` を行い、同じフレームで同じ文字列を `text` に入れる。TextMeshPro 自身が同じ文字列を捨てていることを考えれば、参加者が見る表示はどのフレームでも本体と同じである。被弾の計測（合計・最大・DPS の算出）、SyncVar の送信のタイミング、3秒と5秒のリセットの動きには触れていないので、数値・判定・通信の中身は変わらない。ホストと参加者で見えるものも変わらない。

効果の見込み（推定）は、実体1体あたり毎フレームの文字列1つ（およそ100〜150バイト）とボックス化3つ（各24バイト）の確保をなくすことである。秒間60フレームなら1体で毎秒およそ7〜10KBの確保がなくなり、参加者側では被弾と受信が続く戦闘中と、計測が0に戻って以降の静かな期間の両方で効く。GC の確保の総量が減ることで、長い戦闘での GC の起き方と停止の間隔が伸びる見込みだが、数値は推定であり、実機での計測は行っていない。

## 修正ラウンド（2026-10-20、PR レビュー F1・F2）

前ラウンドのレビューで CRITICAL を2件受け、両方を直した。

F2（Transpiler の照合）。本体のインスタンス欄の読み出しは、各 ldfld の前に ldarg.0 が入る。前ラウンドの照合は ldfld と box が直接連なる形を想定していたため、実際の本体では一度も一致せず、警告を1回出したまま本体の処理に戻り、この軽量化が効かなかった。Dew.Core.dll r1.4.0.13 と r1.4.1.2 の両方を ilspycmd で確かめ、末尾が ldarg.0 / ldfld _totalDamage / box / ldarg.0 / ldfld _dps / box / ldarg.0 / ldfld _maxSingleDmg / box / call Format / callvirt TMP_Text::set_text であることを確認した。欄の読み出しは weaver による get_Network_* への置き換えを受けず ldfld のままであった（置き換わるのは書き込み側の set_Network_* だけ）。照合をこの命令列に合わせ、box だけを外して（ldarg.0 と ldfld は残して生の float を積む）ヘルパーに置き換えるように改めた。
