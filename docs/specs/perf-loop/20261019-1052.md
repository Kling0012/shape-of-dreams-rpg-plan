# perf-loop/20261019-1052

対象: mod src/SodRpg.Mod/HostAuthority.BossHerWorld.cs（Nyx の `Se_U_HerWorld_Blackhole` と爆発 `Ai_U_HerWorld_Explosion` を追跡するホスト側アダプタ）。黒穴が生きている間、`NyxWorldNativeTick` の毎フレームの Prefix が `RefreshNyxWorld` を通って 0.25 秒ごとに `NyxWorldPublish` → `PublishBossVisual`（HostAuthority.BossVisuals.cs）で参加者へ表示を配信する。その通信ごとの下流を一緒に見て、そちらに1か所だけ手を入れた。

直した内容: `PublishBossVisual` は `removed=true` で呼ばれると、効果一覧にその ID が無いとき（`state.Find` が -1 のとき）でも削除メッセージを組み立てて全員に送り、`state.Revision` を進めていた。削除メッセージに意味があるのは効果がホスト側に存在するときだけで、存在しない ID の削除は受け手の `ClientSession.BossVisuals.OnBossEffects` で `index < 0` のため何もしない。そこで removed のときに `index < 0` なら送信も Revision 加算もせずに return するガードを足した。修正は BossVisuals.cs の1か所で、削除が一度だけ送られる既存の経路（`index >= 0` の `RemoveAt` と送信）は変わらない。

効果がなかった経路: `NyxWorldPublish` は BossRewardStage が 0 のとき（Nyx 報酬の段階が未到達、または `BossEnsure` が偽のとき）リング効果を `removed=true` で公開する。このときリングは一度も追加されていないか削除済みなので index は必ず -1 で、黒穴1個につき毎秒4回の不要な削除メッセージと Revision 加算が黒穴の寿命の間続く。Revision が進むと `TickBossVisualSnapshots` の1秒ごとの全量スナップショットが `SkipUnchanged` で省かれなくなり、効果が空でも毎秒1通の再送が上乗せされる。同じ形の無駄は `NyxWorldClearTargets`（`Used` 済みの行に `row.Target != null` だけで再削除を送る）と、BossBeam・BossMechanisms・BossInk など他のアダプタが後片付けで存在しない可能性のある ID を削除する呼び出しにもある。

結果が変わらない理由: ホストの状態に無い効果 ID を参加者が持っていることはない。効果が存在したときの削除は `index >= 0` で必ず送られ、伝送は Mirror の TargetRpc で信頼性がある。部屋移動やあとから入った参加者は epoch 付きの全量スナップショットで置き換わり、ホストで期限切れになった効果は参加者側も同じ `expires` で `TickBossDisplay` が自前で消す。そのため無い ID の削除メッセージは受信側で何も変えず、送らないことで見た目・判定・タイミングの差は生じない。ガードは Revision を進めないだけで、進めるべき変更（追加・更新・実在する効果の削除）の通し番号は従来どおり連続に見え、クライアントの `revision < state.Revision` の廃棄判定と矛盾しない。

効果の見込み（推定）: Nyx 報酬の段階が 0 のプレイヤーが `St_U_HerWorld` を使うと、黒穴1個あたり毎秒4通の削除メッセージと毎秒1通の全量スナップショット再送が参加者ごとに消える（メッセージ1通は JSON 1個の送信）。段階が 1 以上のときも、撃破済みの目印への再削除と後片付け時の二重削除が消える。ほかのボスアダプタの後片付けで存在しない ID の削除を送っていた分も、同じガードで消える。戦闘中の経路だけの変更で、黒穴が無い通常の戦闘には影響しない。
