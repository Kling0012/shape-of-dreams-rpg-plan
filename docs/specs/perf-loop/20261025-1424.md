# perf-loop/20261025-1424

対象: `src/SodRpg.Mod/PressureEnemyCount.cs`（MOD。撃破ごとに走る `Entity.Kill` のフック `BeforeDeath` から、結果に使われないスケール読み出しを外す）

## 直した内容

このファイルのパッチは、ホストのスポーン希望・人口管理・撃破の3系統に分かれます。ウェーブの包み込みと人口の許可は `NetworkServer.active` や `_native == null` のガードで参加者を弾き、撃破系の `BeforeDeath`（`Entity.Kill` の Prefix）も `NetworkServer.active` で帰るため、参加者が払うのは字段読み1つです。そこで観点3（撃破ごとの経路の無駄）に従い、ホスト側の撃破ごとの経路を見ました。

`BeforeDeath` は毎撃破で `PressureCountRewards.ScaleFromActorData`（`persistentSyncedData` からの `TryGetValue`。47文字の固定キーのハッシュ計算つき）を呼び、その結果で `RoomMonsters.disableMiniBossRewards` を書き換えていました。本体でこのフラグを同期的に読むのは、ミニボスの `EntityEvent_OnDeath` が `StartCoroutine` で即時実行する chaos 報酬コルーチンの最初の区間だけです。つまり書き換えに意味があるのは「ネイティブの報酬が生きたままのミニボスの撃破」だけで、それ以外の撃破では、読み出したスケールは結果式に効かず（`mini` の短絡で落ちる）、書き込む値も元の値と同じになります。

そこで `BeforeDeath` を、次の2条件のどちらかが当てはまるときは早期リターンする形に直しました（数行の変更）。フラグがすでに true のとき（`RoomMod_CorruptedChaos_AuraOfPain` が true を入れるだけで、false へ戻す経路はないため、以後の撃破では書き換えが常に無操作になる）と、死者がミニボスでないときです。ミニボスの撃破では、条件式と `Random.NextDouble()` の評価順を保ったまま従来どおり動きます。

## 結果が変わらない理由

省かれる経路の代入値は `_deathBaseline || (mini && …)` ですが、`_deathBaseline` が true のときは常に true、`mini` が偽のときは常に false になり、いずれも `AfterDeath` が `Previous` として書き戻す値と同じです。また、ネイティブがこのフラグを同期に読む場所は、ミニボスの chaos コルーチンの最初の区間のみです（逆コンパイルの全体検索で確認）。ミニボス以外の死体処理の間にフラグを読む本体コードはなく、省いた書き換えが誰かに観測される隙間はありません。

ネストした撃破（ミニボスの死亡処理中に別の撃破が起きる場合）でも、深さと `Previous` の退避・復元は従来どおり行うため、外側の値は守られます。この省略の対象は、内側がミニボスでない撃破だけです。`ScaleFromActorData` のメモは参照鍵で、書き込まなくても後の読み取りが従来どおりパースして同じ値になるため、結果は一致します。`Random.NextDouble()` を消費するのは「ミニボス かつ scale < 1」のときだけで、これは元の短絡と同じ順序なので乱数の流れも変わりません。

## 効果の見込み（推定）

撃破1回ごとに、辞書1回分（47文字キーのハッシュ計算とインターフェース経由の `TryGetValue`、数百ナノ秒程度・推定）がなくなります。ミニボスの撃破は部屋に数体程度なので、ほぼ全ての撃破が省かれる側に乗ります（推定）。圧迫モードではエキストラ分だけ撃破数が増えるため、この MOD が追加した撃破ごとの経路ほど効きます。このファイルに参加者側の経路はないため、ゲストの負荷は変わらず、削減はホスト側に乗ります。
