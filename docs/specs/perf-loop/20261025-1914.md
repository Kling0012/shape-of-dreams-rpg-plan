# perf-loop/20261025-1914

## 対象

`src/SodRpg.Mod/HostAuthority.BossObliviax.cs`（Obliviax ボス装備のホスト側処理）。ファイル内に参加者（ゲスト）側で毎フレーム走る経路はない（移動パッチも Boss ティックも `NetworkServer.active` を最初に見る。参加者へ送る視覚は出撃・設置のイベント時だけ）。そのためゲストではなく、毎フレームの無駄（探すものの3）を減らした。

## 直した内容

ホストで毎フレーム繰り返していた9区分の在確認（`BossFind` の全走査）を、装備エポックが進んだ最初の1回だけに減らした。

`TickObliviaxBoss` は、毎フレーム9回の `BossFind`（`rt.Powers.Build.BossMoves` の線形走査、1件あたり約25文字の文字列比較）をやめ、状態に覚えた `EquippedMask` を読む。装備エポック（`rt.ShieldEquipmentEpoch`）が進んだ最初の1回だけ9区分を付け直し、区分が消えたときの予約取消しをそこで行う。

`ObserveObliviaxVoluntaryMovement` は、移動フレームごとに走る頭区分（`boss_obliviax.head`）の在確認を、状態があれば作成時の走査結果（`EquippedMask` の bit 8）で済ませる。エポックが進んでいる間だけは旧実装と同じく現在の装備で確かめる。

## 結果が変わらない理由

`BossMoves` は Build の生成後にどこからも変更されない（生成は `Build.cs` と `BossBuildCodec.Read` の構築時だけ）。装備が変わると `rt.Powers.Build` が新しい Build に差し替わり、毎ティック最初の `BossEnsure` が参照の不一致かエポックの前進で検出して `ClearBossEffects` → `ClearObliviaxBoss` で状態を一度捨てる（`HostAuthority.BossRuntime.cs` の changed 判定）。そのため状態が存在する間は、毎フレームの再走査は作成時の走査と同じ結果になるはずで、覚えた値を読むだけでは結果が変わらない。

装備が変わった直後から次のティックまでの窓では、旧実装と同じく現在の装備での在確認を残した（`ObserveObliviaxVoluntaryMovement` のエポック分岐と `TickObliviaxBoss` の付け直し）。エポックが進まない Build の差し替えも `BossEnsure` が参照比較で検出して状態を捨てる。この方式は、同じ理由で9区分の走査を装備エポックの変更時にだけ行う `PolarisState`（`HostAuthority.BossPolaris.cs`）・`HostAuthority.BossLight.cs`・`HostAuthority.BossPrimus.cs` の既存のやり方と同じである。

## 効果の見込み（推定）

Obliviax 装備の英雄がいるとき、ホストの毎フレーム9走査（`TickObliviaxBoss`）がなくなる。60fps で毎秒約540回の線形走査の削減になる（推定）。ボス装備一般の英雄についても、移動フレームごとの頭区分の走査（`ObserveObliviaxVoluntaryMovement`）がなくなり、移動中の英雄1体あたり毎フレーム1走査が減る（推定）。走査1回は小さいが、フレームレートが下がりにくいホスト側の定常費として効く。参加者側の負荷への直接の効果はない。
