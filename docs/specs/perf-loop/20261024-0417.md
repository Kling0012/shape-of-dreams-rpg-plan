# perf-loop/20261024-0417

対象: native Dew.Core/CastIndicatorManager.cs

## 直した内容

CastIndicatorManager は矢印タイプの照準（Arrow キャスト）を表示している間、毎フレーム `LineRegion.UpdateProperties()` を呼ぶ。LineRegion 自身の Update も毎フレーム同じ呼び出しをするため、表示中は1フレームに2回、本体（DTT.AreaOfEffectRegions）が body・head の transform 5か所と material の float 2か所を書き直していた。

Harmony の Prefix で、書き直しの入力（Angle・Length・Width・FillProgress、body のワールド回転・ワールド位置・ローカルスケール、head のスケールとワールド回転、2つの material）が前回と全部同じなら本体を呼ばずに抜けるパッチ（NativeCastIndicatorLineRegionPerf）を足した。20261023 に circle（照準円）で入れた NativeCastIndicatorCirclePerf と同じ形で、NativePerfPatches.cs に追加し、MOD 設定 nativeCastIndicatorLine（既定有効）で切れる。

## 結果が変わらない理由

本体の書き直しは上に挙げた入力だけから決まり、時刻や乱数など他の要素には依存しない（実 DLL から UpdateProperties の IL を取り出し、参照するメンバー一式を列挙して、それと一致することを Prepare で確かめる）。入力が全部同じなら書き直しはすでに書いてある値をもう一度書くだけなので、呼ばなくても描画結果は同じ。入力が1つでも変われば（マウスを動かす、キャラが動く・回る、material が差し替わる）普通に本体を呼ぶ。LineRegion の Update からの呼び出しにも同じ Prefix が効くので、見た目は変わらない。パッチ先が見つからない・IL の形が変わっているときは、そのパッチだけ外れて警告を1回出す。

メンバー一式の照合は命令が参照するメンバー名の文字列で行うため、get_eulerAngles の3回・get_localScale の4回が body と head のどちらのインスタンスに対する読み取りかは区別できない。そこでスナップショットは安全側として、現形状の書き換えが読むのは body 側の回転だけでも、head のワールド回転（eulerAngles）も入力に加えて比較する。仮に本体が head 側の回転を追加入力として読む形であっても、head が外部から回されたフレームは入力が変わったと判定して本体を呼ぶため、描画が更新されない経路は残らない。

このパッチ専用の境界テストを CastIndicatorPerfTests.cs に足した。ValidateBody は本体と同じメンバー一式（54件）を同じ回数参照する見本（LineSameShape）を受理し、Angle の読み出しを1つ足した形・Length の読み出しを1つ減らした形・マテリアル float の書き込みを1つ減らした形・追跡していない入力（_opacity）を読み足した形を拒否する。ShouldSkip は入力全部同一で true、初回（スナップショットなし）・null material・スカラー4種・transform 15成分（1 ULP 差）・material 実体の差し替えの各1つ変化で false を確かめる。

このテストを作る過程で、初版の実装に入っていた誤りが1つ見つかり、直した。ValidateBody が呼ぶメンバー一式の照合（MatchesExpectedMembers）は照準円のパッチから共有した静的メソッドで、比較先の ExpectedMembers が囲んでいる照準円のクラスに閉じた配列だった。そのため照準矢印側の54件は常に21件（照準円の配列）と比較されて一致せず、Prepare が常に本体を拒否して警告を1回出すだけ（fail-soft で描画は従来どおり、省略だけが効かない状態）になっていた。照合メソッドは期待値の配列を引数に取る形に変え、両方のパッチが自分の ExpectedMembers と比較するようにした。

## 効果の見込み（推定）

矢印の照準を出している間（攻撃移動・キャスト中）に、フレームごとに走る transform の書き込み5回と material への float 書き込み2回が、入力が変わらないフレームでは0回になる（変わるフレームではネイティブと同じく1回）。照準は画面に1個なので絶対量は小さいが、ゲストも含めて全プレイヤーで毎フレーム動く経路。推定: 軽い改善。
