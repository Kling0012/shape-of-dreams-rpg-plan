# perf-loop/20261024-0417

対象: native Dew.Core/CastIndicatorManager.cs

## 直した内容

CastIndicatorManager は矢印タイプの照準（Arrow キャスト）を表示している間、毎フレーム `LineRegion.UpdateProperties()` を呼ぶ。LineRegion 自身の Update も毎フレーム同じ呼び出しをするため、表示中は1フレームに2回、本体（DTT.AreaOfEffectRegions）が body・head の transform 5か所と material の float 2か所を書き直していた。

Harmony の Prefix で、書き直しの入力（Angle・Length・Width・FillProgress、body のワールド回転・ワールド位置・ローカルスケール、head のスケール、2つの material）が前回と全部同じなら本体を呼ばずに抜けるパッチ（NativeCastIndicatorLineRegionPerf）を足した。20261023 に circle（照準円）で入れた NativeCastIndicatorCirclePerf と同じ形で、NativePerfPatches.cs に追加し、MOD 設定 nativeCastIndicatorLine（既定有効）で切れる。

## 結果が変わらない理由

本体の書き直しは上に挙げた入力だけから決まり、時刻や乱数など他の要素には依存しない（実 DLL から UpdateProperties の IL を取り出し、参照するメンバー一式を列挙して、それと一致することを Prepare で確かめる）。入力が全部同じなら書き直しはすでに書いてある値をもう一度書くだけなので、呼ばなくても描画結果は同じ。入力が1つでも変われば（マウスを動かす、キャラが動く・回る、material が差し替わる）普通に本体を呼ぶ。LineRegion の Update からの呼び出しにも同じ Prefix が効くので、見た目は変わらない。パッチ先が見つからない・IL の形が変わっているときは、そのパッチだけ外れて警告を1回出す。

## 効果の見込み（推定）

矢印の照準を出している間（攻撃移動・キャスト中）に、フレームごとに走る transform の書き込み5回と material への float 書き込み2回が、入力が変わらないフレームでは0回になる（変わるフレームではネイティブと同じく1回）。照準は画面に1個なので絶対量は小さいが、ゲストも含めて全プレイヤーで毎フレーム動く経路。推定: 軽い改善。
