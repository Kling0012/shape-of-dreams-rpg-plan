# perf-loop/20261024-1456

対象: `src/SodRpg.Mod/DynamicDifficultyNative.cs`（動的難易度の部屋読み込みとスポーン完了の
ふたつの Harmony パッチ）と、そこから呼ばれる `HostAuthority.OnDynamicRoomLoading`・
`HostAuthority.CompleteDynamicSpawn` の周辺。

## 直した内容

対象ファイル自体は、ゲスト側では `NetworkServer.active` の1判定で抜ける経路しかなく、
手を入れられる箇所がありませんでした。そのため呼び先の
`HostAuthority.DynamicDifficulty.cs` の `DynamicRunning()` を見たところ、接続プレイヤー数を
数える `foreach (var player in DewPlayer.gamePlayers)` の各要素で `OwnershipConnected(player)`
を呼び、その中の `DewPlayer.gamePlayers.Contains(player)`（1人につきリスト全体の O(n) 走査）が
毎回走っていました。数えている相手は列挙元の `gamePlayers` 自身の要素なので、この所属確認は
常に真で、結果に寄与しません。

そこで `OwnershipConnected` から所属確認（`Contains`）だけを除いた条件を `IsCountableConnected`
として切り出し、`DynamicRunning()` の人数ループではこちらで数えるようにしました。
null 判定・`isHumanPlayer`・ローカルまたは接続ありの条件は `OwnershipConnected` と同じものを
共有し、`OwnershipConnected` 側は「`IsCountableConnected` && `Contains`」の形にしています。
条件が1か所にまとまったため、今後 `OwnershipConnected` に条件が足されたり変わったりしても、
人数の数え方が古い条件のまま残ることはありません。`OwnershipConnected` 自体は、プレイヤー一覧
以外の相手（`_dynamicPlayers` の再利用スロットなど、一覧から外れたプレイヤーを確かめる
呼び出し元）では意味があるので、`Contains` の役割はそのまま残しています。

`DynamicRunning()` は対象ファイルの spawn Postfix → `CompleteDynamicSpawn` の経路のほか、
被弾ごとの `RecordDynamicDamage`、撃破ごとの `ApplyDynamicKillReward`、周期走査
`ScanEnemyOwnership` → `CompleteDynamicSpawn`、0.25秒ごとの表示同期
（`ScanMonsterOwnershipSync` → `SendDynamicLegendPeer` → `DynamicSnapshot` → `DynamicFactor`）
からも呼ばれるため、これら全部の呼び出しが軽くなります。

## 結果が変わらない理由

- `DewPlayer.gamePlayers` は静的コンストラクタで1度だけ代入される `List<DewPlayer>` で、
  以後は Add・Remove・Clear のみです。実 DLL の逆コンパイル
  （`Dew.Core/DewPlayer.cs` の静的コンストラクタ）で確認しました。プレイ中は列挙と
  `Contains` が同じインスタンスを見るため、列挙して取り出した要素の `Contains` は常に真です。
- `DewPlayer` に `Equals` のオーバーライドはなく、`Contains` は参照一致です。
  列挙で取り出した要素との参照一致は必ず成立します。
- 数える条件は `IsCountableConnected` として `OwnershipConnected` から切り出したもので、
  `Contains` を除く条件と評価の順番（null → `isHumanPlayer` → 接続確認）は元のままです。
  `count` の値は同じになり、`DynamicRunning()` の戻り値も変わりません。
- この等価性はテストで確かめています（`DynamicDifficultyTests`。
  変更前と同じ式（`OwnershipConnected` で数える）で数え直した結果と `DynamicRunning()` を、
  ローカル1人・ゲスト接続あり・`connectionToClient` が null の非ローカル・`isHumanPlayer=false`・
  null 要素の各場合で突き合わせ）。一覧から外れた相手では `IsCountableConnected` だけ真に
  なる境界も固定しています。

## 効果の見込み（推定）

1回の呼び出しで、プレイヤー数 n（最大4）のとき、削れるのは n² − n 回（4人で12回）の
参照比較です。呼び出し頻度は被弾・撃破・周期走査・0.25秒ごとの表示同期に及ぶため、
戦闘中は秒間数百回のオーダーになり得ますが、1回あたりの削減が小さく、合計でも
毎秒数千〜数万回の参照比較を減らす程度の見込みです（推定）。ホスト側のみの削減で、
参加者（ゲスト）の PC の負荷は変わりません。対象ファイルにゲスト側の経路が
なかったため、指示の観点3（毎回の全走査の省略）として扱いました。

## 見送った候補

- `DynamicSoloRunning()`（同ファイル）も `DynamicRunning()` の後に同じ形で
  `gamePlayers` を再列挙して数え直すため、同じ冗長さがあります。対象ファイルの
  呼び先ではないため今回は触らず、次の機会の候補として残します。
