# perf-loop/20261024-0339

## 対象

native Dew.Core/AttachToFace.cs。装飾品などの付属物を SkinnedMeshRenderer の面に追従させるコンポーネントで、Update がインスタンスごとに毎フレーム走る。プレイ中の Update は、焼きメッシュの頂点3つから付け先の位置と向きを求め、SmoothDamp で追従させる。ゲーム本体は直接変えられないので、既存の MOD パッチ（NativeAttachFaceIdlePerf・NativeAttachFaceBakeRecord、#760）がベイクとベイクの間の照会を省いた残りの部分、すなわち再焼き込みが起きたフレーム（isNew フレーム）の経路を、3（毎フレーム・被弾ごとの経路の無駄）の観点で見た。

## 直した内容

Dew.GetBakedMeshOptimized は、照会されたスキンのメッシュを最大10回/秒（Dew.BakeMeshInterval は 0.1 秒）で焼き直し、焼き直したフレームだけ isNew を真にする。本体の AttachToFace.TryPopulateVertices は isNew フレームで mesh.GetVertices を呼び、メッシュの全頂点を呼び出し元ごとのリストへコピーする。同じスキンに付けた AttachToFace が N 個あると、同じ内容の全頂点コピーが最大10回/秒 × N 回走る。このコピーは参加者を含む全クライアントで起こる（装飾品は全クライアントで描画される）。

そこで NativeAttachFaceSharedVerts を新設した。同じメソッドへの Prefix で、isNew フレームだけ本体に代わって位置と向きを計算し、頂点リストをスキンごとに1回だけ共有する。最初の呼び出しが Mesh.GetVertices でキャッシュを埋め、以後の呼び出しは同じリストから自分の頂点3つを読む。数式は本体の TryGetWorldPositionAndRotation・GetFaceRotation・TransformPointUnscaled の転写そのままで、3メソッドの出荷済み IL の指紋（長さ・FNV-1a ハッシュ・ローカル数・例外句数）を Prepare で確かめ、ゲーム更新で本体が変わっていたら警告を1回出してこの修正だけ外れる。isNew でないフレームと、ベイク記録のないスキンは従来どおり本体の経路に任せる。設定は DreamforgeConfig.nativeAttachFaceSharedVerts（既定は有効）。ベイクの記録は既存の NativeAttachFaceBakeRecord が行い、記録条件を「2つの機能のどちらかが有効」に広げた。キャッシュは埋めたのと同じフレームしか読まず、件数がしきい値（16）を超えたときにベイク間隔を過ぎた項目だけを掃除する（NativeAttachFaceIdlePerf.PruneStale と同じ方式）。

テスト側は、リンクされた NativePerfPatches.cs がコンパイルに必要とする本体 API の境界（AttachFaceIdlePerfBoundary.cs など）に、Prefix が読むフィールドと Quaternion・Vector3 の演算、Dew.BakedMeshHandle.Return、Mesh.GetVertices を足した。既存テストの期待値は、記録条件の拡張に合わせて AttachFaceIdlePerfTests.PostfixRecordsTheBakeOnlyWhenTheMeshIsNew の1箇所を直した。新しいテストは作っていない。

## 結果が変わらない理由

isNew フレームの数式は本体の転写そのもので、演算の順序も同じである。入力も同じで、頂点は本体と同じ Mesh.GetVertices の結果、残りは同じ公開フィールド（vertexIndex0..2・relPosition・relRotation・targetRenderer）から読む。したがって設定する位置と向きは、本体が設定する値と一致する。更新のタイミングも同じである。本体の TryPopulateVertices は isNew でないフレームではコピーせず false を返すので、位置の更新は isNew フレームだけで起きる。この前提は MOD 側も同じで、Prefix は isNew のフレームにしか割り込まず、それ以外では本体に返す。キャッシュを古い頂点で読む窓もない。ベイクは GetBakedMeshOptimized の内部でしか起きないので、この Prefix が isNew を見たフレームで埋めたキャッシュは、そのフレームに本体がコピーするはずだった頂点と同じである。対象が見つからない・形が違う・例外のときは警告を1回出してこの修正だけ外れる（fail-soft）。

## 効果の見込み（推定）

同じスキンに付いた AttachToFace の数を N とすると、isNew フレーム（最大10回/秒）ごとの N 回の全頂点コピーが 1 回になる。キャラクターのメッシュは数千〜数万頂点なので、1 回のコピーは数十KB〜数百KB の転送とリストの成長に当たる。削れるのは (N−1) × 最大10回/秒 分で、面に付ける装飾品を複数付けた英雄がいる部屋ほど効果が大きい（推定）。N = 1 のスキンでは効果がほぼなく、追加の負荷は isNew フレームの辞書参照1回だけである。参加者の PC でも走る経路なので、ホストと参加者の両方でこの分の確保とコピーが減る。
