# perf-loop/20261024-0837

対象は `src/SodRpg.Mod/HostAuthority.BossDemon.cs` である。直した内容は、夢魔の報酬（Hysteria の爪）の処理 `BossHysteriaClaw` で、爪が1回の呼び出しの中で `BossRewardStage` を2回計算していたのを1回にまとめたことである。1回目は入り口のガード（報酬段階が0なら抜ける）で、2回目は爪の命中が決まった直後に `stage` という名前で再計算しており、段階2以上での植え付けと、段階3以上での集めと行軍の判定に使っていた。変更後はガードで計算した値を `stage` に受けて、命中側ではその値をそのまま使う。この確認は爪の作成・命中・消滅のたびに走り、TryGetReward の辞書引き、装備記憶の一致確認（装備エポックの比較と辞書引きを含む）、Build の報酬一覧の走査からできている。

結果が変わらない理由は次のとおりである。2回目の計算と1回目の計算の間にあるのは `ClawPairs`（爪のペア記録）の読み書きだけで、装備・Build・英雄の生存状態・エッセンスは何も変わらない。同じ呼び出しスタックの中で `Time.time` も進まないので、2回とも同じ値になる。元のコードでも `stage` は命中直後に1回計算してその値を使い回していたので、使う値が変わった箇所はない。ガードの評価順については、元は `BossEnsure` → `BossRewardStage` → `stateLife` と `clawLife` の確認の順だったのを、`BossRewardStage` を `stateLife` と `clawLife` の確認の後ろに移した。`BossRewardStage` は読み取りだけの処理で、副作用は `FindMemory` が内側で行う記憶名辞書の遅延更新だけである。この辞書を読むすべての箇所（`ApplyKillAssist` など）が読む直前に自分で更新を呼んでいるため、この経路で更新を省いてもほかの箇所が古い辞書を読むことはない。`stateLife` か `clawLife` が0のときは元から `return` するので、見える動作は変わらない。

効果の見込みは推定である。Hysteria は主人公の攻撃ごとに左右の爪を出すので、この処理は戦闘中に毎秒数回から十数回走る。爪の命中1回につき、報酬段階の確認（辞書引き数回と Build の走査）が2回から1回になり、作成と消滅の呼び出しでは `stateLife`・`clawLife` が有効な間だけ計算するようになるため、無駄な1回分の辞書引きと走査が減る。GC への負担は元から割り当てのない経路なので変わらず、減るのは CPU の数命令から数百命令程度の規模である。このファイルに参加者側の経路はなく、参加者への見た目の送信は `PublishBossVisual` の重複排除と間引きに任せており、今回の変更は通信に触れない。実機（ゲーム内）での確認は未実行である（この環境ではゲームを動かせないため）。
