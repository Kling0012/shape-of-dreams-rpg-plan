# perf-loop/20261024-1649

## 対象

`native Dew.Core/TransitionManager.cs`。

## 見た範囲

ファイル全体（272行）。実 DLL（`Shape of Dreams_Data/Managed/Dew.Core.dll`）から ilspycmd で再取り出しし、空白正規化 diff で照合した。差分は enum 表記（`0` ↔ `StateType.Normal`）の1箇所だけでロジックは同一。reflection-dump の `_alltypes.txt`（5627行目）にも型を確認した。実 DLL の IL も取り出し、`FrameUpdate` が呼ぶ15個のメソッドを数えて確かめた。

プレイ中に走る経路は `FrameUpdate` の1本だけ。このクラスは `ManagerBase<TransitionManager>` として `LogicUpdateManager` に登録され、ロビーでも戦闘中でも、ホストでも参加者でも、毎レンダーフレームに1回呼ばれる。ほかのメンバーは場面転換と読み込みのときにしか走らない（`FadeOut`／`FadeIn`／`LoadScene`／`UpdateLoadingStatus`／`SetBusy`／`ResetWhiteFade`／`TryGetNewTip` 群）。通信は流していない。

## 直した内容

`FrameUpdate` が、フェードが完全に静まっている定常状態（`state == Normal` かつ `screenFadeCg.alpha == 0f`）のときだけ何もしないようにした。MOD 側 `NativePerfPatches.cs` に `NativeTransitionIdlePerf` を追加する。Harmony の Prefix が毎フレーム同じ2つの値を読み、定常状態なら本体を丸ごと省く（return false）。本体 IL の形は `Prepare` で検査し、呼び出しの組み合わせ（15個の multiset）が実 DLL と違うときは警告を1回出してその修正だけを外す。MOD 設定 `nativeTransitionIdle`（既定は有効）で切れる。あわせてテストプロジェクトの境界（`NativeBoundary.cs`、`NativeEmbracePositionBoundary.cs`）に、設定フィールドと本体型の模倣を足した。

## 結果が変わらない理由

定常状態で本体が行うのは、(1) `MoveTowards(0, 0, dt)` の結果 0 の再設定、(2) `blocksRaycasts = false` の再設定、(3) すでに非アクティブなフェード用オーバーレイへの `SetActive(false)`、(4) 空の `base.FrameUpdate()`（`LogicBehaviour.FrameUpdate` は IL で `ret` 1個だけ）の4つで、どれも値も見た目も変えない。`screenFadeCg` に書くのはゲーム全体で `TransitionManager` だけなので（逆コンパイルと IL で確認）、省いた書き込みがほかの書き手と食い違うことはない。フェードが動いている間（`state == Loading`、または起動直後に `Start` が `alpha = 1` にしてから 0 へ減衰している間）は本体をそのまま走らせるので、見えるフレームは1つも変わらない。スキップの条件は本体が読むのと同じ `state` と `alpha` の生の値から毎フレーム決めるので、状態がずれて誤って省く余地もない。チップの入力待ち（`GetKeyDown`）は本体自身が `state == Loading` のときしか実行しない。

## 効果の見込み

推定: プレイ中の定常状態（フェードが出ていない時間、実質すべてのプレイ時間）で、全クライアント（ホストと各参加者）の毎フレームあたり Unity へのネイティブ呼び出し6回（`get_alpha`×2、`set_alpha`、`set_blocksRaycasts`、`get_gameObject`、`SetActive`）と `Mathf.MoveTowards`、自動プロパティ `get_state`×3 を省く。1回あたりは数百ナノ秒以下の規模だが、60fps なら毎秒約360回の不要なネイティブ呼び出しが減る。通信は変わらないので参加者の受信処理は増えず、参加者を含む全員の毎フレーム定常コストが少し下がる。体感できる規模ではない。

## 見送った候補

`TryGetNewTip_Hero`／`TryGetNewTip_General` の LINQ（`tips.Keys.Where(...)` で毎回列挙と確保）は、読み込み画面のチップ更新時にしか走らず、冷却1秒の間は呼ばれない。プレイ中の経路ではないため見送った。`UpdateLoadingStatus(LoadingStatus)` の `"Loading_" + status` の文字列連結も読み込み中だけなので見送った。
