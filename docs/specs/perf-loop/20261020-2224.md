# perf-loop/20261020-2224

対象は native `Dew.Core/Shrine_BossSoul.cs`（ボスソウルの神殿）である。ボスを倒したあとに出る、全員が1回ずつスキルやジェムを強化できる神殿であり、参加者（ゲスト）側の毎フレーム経路として、神殿の前に立ったときのインタラクト判定と、強化画面を開いている間の有効判定を持つ。

見えた構造は次のとおりである。`Shrine_BossSoul.CanInteract` は、神殿が使えるかどうかを判定するメソッドで、ゲストを含む各クライアントで走る。呼び出し元は、`ControlManager.GetNearbyInteractable`（6ユニット以内のインタラクト可能物を毎フレーム照会する）、`EditSkillManager.LogicUpdate`（この神殿の強化画面を開いている間、ロジック更新ごとに有効性を再確認する）、`FloatingWindowManager`（フォーカス中の対象を再確認する）であり、いずれも各端末の毎フレーム経路である。このメソッドの最後は `!ActorManager.instance.allEntities.Any(e => e is BossMonster)`、つまり「ボスが生きていないときだけ使える」の判定である。`allEntities` は `HashSet<Entity>` で、実体（英雄・魔物・召喚・弾など）がすべて入る。.NET 標準の `Any` は呼び出しごとに `HashSet` の列挙子を boxing して確保し、要素ごとにデリゲートを1回呼ぶ。ゲーム内（Mono の BCL）には .NET 8 にあるような `HashSet` 向けの高速経路はない。そのため、神殿の近くにいる間、各端末が毎フレーム「全実体の走査 + 呼び出しごとの確保」をしていた。ほかのメンバー（`OnUse`・`ActiveLogicUpdate` の全体強化チェック・`Explode`・名称やUI文字列）は、走る頻度がイベント単位かホストのみで軽く、対象にしなかった。

直した内容は、`Any` の呼び出し1箇所を、同じ意味の手書きループへ差し替える Transpiler（`NativeBossSoulShrineScanPerf`。`src/SodRpg.Mod/NativePerfPatches.cs` に追加）である。MOD 設定 `nativeBossSoulShrineScan`（既定は有効）で切れる。入れ替わるのは `Any(source, predicate)` の呼び出しだけで、`base.CanInteract`・使用済みプレイヤーの確認・否定の形など、メソッドのほかの部分は本体の IL のまま残る。本体の型（`Shrine_BossSoul`・`BossMonster`）は名前で解決し、MOD 側からは参照しない。解決できないときは、その修正だけが外れて1回警告を出す（既存の `NativeChaosShrineHitScanPerf` と同じ形）。Prefix/Postfix ではなく Transpiler を選んだのは、親クラスの仮想メソッド `Shrine.CanInteract` を Prefix から呼ぶ確実な方法がなく、本体の判定を MOD 側で写すと将来のゲーム更新で静かに食い違う恐れがあるためである。

結果が変わらない理由は次のとおりである。置き換えたループは、同じ `HashSet<Entity>` を同じ順序で列挙し（呼び出しの間に集合を変えないのは元の `Any` も同じ）、同じ `is BossMonster` の判定（`Type.IsInstanceOfType` は `is` 演算子と同じで、null は一致しない、派生クラスは一致する）を、同じ短絡の形で行う。返る値は常に元の `Any` と同じである。設定を切ったときと、ループ内で例外が出たときは、ネイティブの `Any` をそのまま呼ぶので、元の動作に戻る。

効果の見込み（推定）は、神殿の近くにいる・強化画面を開いている各端末で、毎フレームの全実体走査から列挙子の boxing（呼び出しごとのGC確保）と、要素ごとのデリゲート呼び出しが消えることである。実体が多い部屋（圧迫モードの魔物の波など）ほど差が開く。計測はゲーム内でできないので、量の見積りは推定のままにする。

検証は次のとおりである。実 DLL から `ilspycmd` で `Shrine_BossSoul` を取り出し、空白正規化の diff で逆コンパイル一式と照合した（差分は逆コンパイラの表現差のみで、`CanInteract` の行は一致）。`/tmp` の検証ハーネス（リポジトリに入れない）で、本物の `TryPrepare` と Transpiler をコンパイル済みの模倣クラスに通し、パッチ前後で結果が一致すること（集合が空・雑魚のみ・ボスの派生クラス・ボス除去後・null）、設定OFFで同じ結果になること、型名が解決しないときに1回警告して無効になることを確かめた。`python3 tools/balance/gen_cs.py --check` を通した。`dotnet build src/SodRpg.Mod -c Release -p:GameDir=... -p:ModDeployDir=/tmp/perfloop-x` を通した（エラー0、警告6件は既存分）。`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` は 621 件すべて通過した。`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release` は 231 件通過・1件スキップで失敗はなかった。実機（ゲーム内）での確認は未実行である。この環境ではゲームを動かせないためである。
