# perf-loop/20261025-0048

## 対象

`src/SodRpg.Mod/ClientSession.RunGrowth.cs`（MOD 側。ホストから届く遠征の鍛錬（RunGrowth）のスタックを受け取り、HUD と取得した効果の一覧用の表示状態を保つファイル）。

参加者側で走る経路を先に確認した。受信は `OnRunGrowth` の1つで、ホスト（`HostAuthority.RunGrowth.cs`）は同じ内容を30秒間隔（`netSkipUnchanged` を止めた設定では5秒間隔）で定期再送するが、受信側は生のペイロードの文字列比較で同一再送を早期 return しており、確保なしで抜ける（perf-loop/20261020-0249 で実装済み）。表示状態を読む `GrowthStacks` と `RunGrowthVersion` は HUD から差分の目印として読まれるだけで、辞書の参照1回か整数の読み取りで済む。登録・解除は接続の張り替え時の1回物で、このファイルに毎フレームで走る処理はない。残って確保のあるのは、スタックが実際に変わったときに届くメッセージの解析だけだった。

## 直した内容

`OnRunGrowth` の解析部分で、`msg.stacks.Split(',')` による文字列配列と要素ごとの確保、`part.Substring(eq + 1)` による数値解析用の文字列、解析結果の `Dictionary` をメッセージごとに new する3つの確保をやめた。生の文字列を `IndexOf` の位置で切りながら `ReadOnlySpan<char>` で要素ごとに処理し、数値は `int.TryParse(ReadOnlySpan<char>, ...)` で文字列を作らずに解析する。星IDの文字列だけは辞書のキーとして保持するために作る。解析結果の辞書は字段 `_growthParseScratch` を使い回し、入口で `Clear()` する。

## 結果が変わらない理由

切り出しの規則を `Split(',')` と同じにした。要素の区切りはコンマで、末尾のコンマは空の要素になる（`"a=1,"` は2要素目が空になり、`=` がないとして従来どおり拒否する）。要素の中の `=` の位置判定（`eq > 0` でIDを切り出し、`eq <= 0` で拒否）、削除済みの星の読み飛ばし、`NumberStyles.Integer` と不変カルチャでの数値解析、負の数の拒否は、元の文と同じ順序で行う。解析に失敗したときは警告を1回出して適用せず、`_growthRawStacks` を更新しないので、壊れた再送は従来どおり届くたびに警告になる。`eq <= 0` の判定が先にあるため、`=` がない要素で `Slice(eq + 1)` を評価することはない。解析結果の比較（件数と各キーの値）と、`changed` のときの `_growthStacks` へのコピーも触っていない。使い回す辞書は入口で必ず `Clear()` するため、壊れた形式で途中 return しても次回の解析に残らない。

`OnRunGrowth`・`ResetRunGrowthDisplay`・`GrowthStacks` の動きは、このファイルから抽出した本物のコードで確かめる既存のテスト（`RunGrowthResendTests`、同一再送・runId の切り替え・Reset 後の再適用・壊れた形式の再送・並び順違いの再送の5件）がそのまま通ることで固定する。レビュー（指摘 F1）で既存の5件が切り出しの境界を直接は確かめていないとされたため、境界の3件（末尾のコンマ・連続したコンマは空の要素として拒否、末尾の要素が削除済みの星なら読み飛ばして残りを適用）を同じテストファイルに加えた。テストの抽出対象の字段に `_growthParseScratch` を加えた（`tests/Issue73.Native.Tests/NativePersistence.targets`）。

## 効果の見込み（推定）

スタックが増え続ける遠征では、ホストが0.5秒間隔の上限で変更後のメッセージを送るので、変更1回ごとに文字列配列1個・数値用の部分文字列を星の数ぶん・辞書1個の確保がなくなる（星6個のビルドで10数個、数百バイト規模。実測はしていない推定）。変更後のメッセージはスタックが変わったときしか届かないため効果は小さいが、参加者側の受信経路のGC確保を減らす。

## 見送った候補

- 星IDの文字列の確保もやめる案。辞書のキーとして `_growthStacks` に保持するため文字列が要り、既にあるキーを再利用するには解析と比較の流れを組み替える必要がある。確保は星の数ぶんで小さい。
- 同一内容で並び順だけ違う再送を、生の文字列でなく解析結果の比較で早期 return する案。並び順が替わるのはビルドが替わったときだけで、頻度の根拠がない。
- ホスト側の `SendRunGrowth`（`HostAuthority.RunGrowth.cs`）の再送の間隔。対象のファイルから呼ばれる経路ではなく、0.5秒の上限と30秒の再送抑止がすでにある。
