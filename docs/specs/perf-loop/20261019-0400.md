# perf-loop/20261019-0400

## 対象

native Dew.Core/EntityControl.cs（位置同期 `PositionSyncData` を送るかどうかの判定 `HasMeaningfulSyncDataChange` と、その呼び出し元3箇所）。

## 直した内容

エンティティの位置・速度・向きを同期する値（`PositionSyncData`）には、送るかどうかを決める判定式がある。本体の式は「タイムスタンプが前回から1秒以上新しい」「位置が動いた」「速度が変わった」「向きが0.1度以上変わった」のどれか一つでも当てはまれば送る。このうち「1秒以上新しい」は心拍として働いていて、動いていないエンティティでも1秒に1回、中身（位置・速度・向き）が前回と1バイトも変わらない更新を送り続ける。参加者の操作する英雄では送信（Cmd）→サーバー受信→全オブザバーへの再配信という1往復、モンスターなどサーバー管理のエンティティでは SyncVar の dirty 化→全オブザバーへの配信が、動いていない間ずっと1秒に1回続く。

MOD では、この判定の呼び出し元3箇所（`UpdatePositionSyncData` 内2箇所＝所有クライアントが送るかどうかの判定と、サーバー管理エンティティの SyncVar を dirty にするかどうかの判定、`UserCode_CmdPositionSyncData` 内1箇所＝サーバーが所有クライアントのCmdを受け入れるかどうかの判定）を Harmony の Transpiler で書き換え、判定の計算を「タイムスタンプの条件を除いた同じ式」に置き換える。本体の閾値（1秒・0.0001平方・0.1度）とフィールド読み出しの形は IL の指紋で固定して確かめ、形が変わっていればこの修正だけが外れて警告を1回出す。MOD 設定の「動いていない実体の位置同期の同じ再送を省く」（`nativePositionSyncIdle`、既定ON）で切れる。

## 結果が変わらない理由

除いたのは「中身が全部前回と同じ」ときの再送だけだから、どのクライアントが持つどの値も変わらない。動き出したとき・止まるとき（速度の変化は全て条件に当てはまるので最後の静止状態も必ず送られる）・向きを変えるとき・1cm以上動くときは、今までどおり即座に送る。60Hzの送信上限も変えていない。テレポートは `EntityControl.Teleport` が新しいタイムスタンプ付きの同期をこの判定を通さず直接配信するので、参加者に遅れて届くことはない。変位・転移の終了時に参加者側で立てられるタイムスタンプの下限は、テレポートの直接配信か次の実際の移動で必ず上回られる。

動いていないエンティティでは、参加者側の「最終受信時刻」が更新されなくなる。受信側の実装（本体 EntityControl の SyncVar フック `OnMovementSyncDataReceived` と毎フレームの `DoMovementObserverFrameUpdate`、r1.4.1.2 の逆コンパイルで確認。定数は同 static コンストラクタによる）は、最終受信から0.5秒（`SyncFixSnapshotLifetime`）の間だけ最終位置へ速度を外挿した目標（外挿は `SyncExtrapolateMaxTime` 0.15秒で上限）へ SmoothDamp で寄せ、0.5秒を過ぎると補正を打ち切って速度ぶんの単純移動だけを続け、1秒（`SyncAgentVelocityLifetime`）を過ぎると保持している速度を0に落とし、停止判定の早期リターンで表示を凍結する。速度が0の静止実体では外挿も単純移動も動かないため、表示は変わらない。

速度が0でないのに位置が止まっている実体（行き先が壁やほかの実体で塞がっている場合など）では、表示の移り方が変わる。素の心拍は毎秒この受信時計をリセットしていたため、表示は毎秒最終位置へ引き戻される振動を続けていた。再送を省くと最終受信から速度×1秒程度まで一度進み、その位置で凍結する。このずれは速度×1秒で上限が切られ、時間とともに増えることはなく、実体が本当に動いた最初の更新（位置・速度の変化は必ず送られる）で再び寄せ直される。この状況の見た目の確認は実機では行っていない（本体コードと定数からの確認のみ）。

メッセージの形式は1バイトも変えていないので、MOD が片側だけ（ホストか参加者かどちらか）でも今までどおり動く。

## 効果の見込み（推定）

動いていないエンティティ1つあたり1秒に1回の同期が消える。数が大きく出るのは敵で、画面内に待機しているモンスターが30体いる場合、各参加者への配信で毎秒30回分のメッセージ処理と直列化がなくなる（1メッセージ約24〜28バイトの推定。人数分のオブザバーに同じだけの受信処理が掛かる）。立ち止まって動いていないプレイヤーの英雄も同様に1秒に1回のCmdと再配信がなくなる。戦闘で動いているエンティティの通信は一切減らないので、効果は静止しているエンティティの数に比例する（回数は推定）。
