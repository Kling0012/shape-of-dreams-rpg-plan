# perf-loop/20261019-1224

対象: native Dew.Core/Projectile.cs。

直した内容: Projectile は、飛行中に敵に当たるたびに `OnEntity` から weaver 生成の ClientRpc `RpcPlayOnEntityEffect` を全員へ送り、消散・完了・飛行停止のたびに `RpcPlayOnDissipateEffect`・`RpcPlayOnCompleteEffect`・`RpcStopOnFlyEffect` を送る。4つの受信側（`UserCode_*`）はどれも、対応する演出プレハブの字段（`effectOnEntity`・`effectOnDissipate`・`effectOnComplete`・`effectOnFly`）が null なら最初の if で抜けるだけで、メッセージを受け取って何もしない。そこで Prefix パッチ `NativeProjectileIdleRpcPerf`（src/SodRpg.Mod/NativePerfPatches.cs）を追加し、対象の字段が null の弾については対応する RPC の送信自体を省くようにした。字段に演出がある間は前置条件に当てはまらず、元の送信処理が1行も変わらず走る。MOD 設定 `nativeProjectileIdleRpc`（既定は有効）で切れる。

結果が変わらない理由: 送信を省くのは「受信側が何もしないことを実 DLL 逆コンパイルで確認できた場合」だけなので、届く情報は減らない。字段が全員で同じ値になることも確かめた。`effectOnEntity`・`effectOnComplete`・`effectOnDissipate` を実行中に代入するコードは、Dew.Contents.dll 全体の逆コンパイル（2458型）を探しても無く、プレハブの既定値だけが入る。`effectOnFly` を代入するのは DarkBolt・Scattershot・ShadowOverdrive の保存と差し替え（`Awake`・`OnCreate`・`OnDisable`）と、`AddEffect` の唯一の呼び出し元である Ai_Q_IncendiaryRounds_Attack（`OnCreate` 内）だけで、どれも全員の環境で同じ順に走る経路なので、送る側と受ける側で省く・送るの判定が食い違わない。4つの送信メソッドはどれも「プールから writer を取る・中身を書く・SendRPCInternal を呼ぶ・返す」だけで、送信以外の作用がないため、省いて消えるのは届いても捨てられるメッセージだけである。判定には `Adaptive_ShouldPlayEffects`（呼ぶたびに乱数で変わる）を使わず、受信側でそのまま判定させた。他の MOD がこれらの送信メソッドに Harmony で自分の演出を足している場合、呼び出し回数が減って見えるが、設定で戻せる。

効果の見込み（推定）: 演出プレハブを持たない弾の、被弾・完了・消散ごとの全員宛て RPC がなくなる。1件あたり `EntityHit`（エンティティ参照と座標）で十数バイトに Mirror の RPC ヘッダが付き、ホスト側では writer の取得・直列化・送信キューへの積み込み、各クライアントでは受信とディスパッチが省ける。この MOD の Infinity モードのような弾の多い戦闘で、毎秒数十件の被弾がそのまま減に変わる見込みだが、どのくらいの割合の弾が演出を持たないかはアセット側の値で決まり、実測はできていない（推定）。

検証: `python3 tools/balance/gen_cs.py --check` 合格、`dotnet build src/SodRpg.Mod -c Release -p:GameDir=… -p:ModDeployDir=/tmp/perfloop-x` 合格（警告6件は既存のもの）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` 441件合格、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release` 225件合格・1件は既存のスキップ。テストプロジェクトは NativePerfPatches.cs を本体APIの模倣とともにコンパイルするため、NativeEmbracePositionBoundary.cs の模倣に `Projectile`（4字段・`EntityHit`・送信メソッドの名前と引数）と `GameObject` の境界と設定フィールド `nativeProjectileIdleRpc` を足した。パッチ対象は実 DLL から ilspycmd で取り出したクラスで確認し、受信側の早期 return も同じもので確認した。実機での動作確認は未実行。見つからなければ `NativePerfPatch.Find` の fail-soft に従い、警告1回でこの修正だけが外れる。
