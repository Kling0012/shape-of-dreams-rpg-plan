直した内容: ホスト側の通常攻撃の命中ごとに走る `Actor.DoBasicAttackHit` の接頭処理（`BasicAttackContext.Prefix`）が、命中ごとに2つの前計算を必ず行っていた。1つ目は `IsGuaranteedBasicV129` で、攻撃者の `parentActor` 連鎖を最大128段階たどりながら、段階ごとに `ConditionalWeakTable` のキャスト表を引いて「保証された会心」の値を取るもの。2つ目は `from is Hero` のときに呼ぶ `TryWeakspotBasic` の中で、付与率（Weakspot のボーナス）が0かどうかに関わらず `BasicCritChanceV129` を計算するもの（こちらも同じ Actor 連鎖の走査とキャスト表の参照に加え、ステータスと辞書の参照をする）。この2つを、値を読む経路があるときだけにした。`Hit.Guaranteed` を読むのは `OnNewPowerDamage` の1か所だけで、そこには `basic.From != hero`（MOD のランタイムがあるヒーロー）の早期リターンが先にあるため、英雄以外（魔物・召喚・null）の攻撃では計算した値が誰にも読まれない。`BasicCritChanceV129` は純粋な読み取りで、付与率が0のときはその値を使う分岐も成立しない。

結果が変わらない理由: `Hit.Guaranteed` の読み手を src 全体で確かめ、`HostAuthority.NewPowers.cs` の `OnNewPowerDamage`（488行目）だけであることを確認した。この読み手は `basic.From == hero` のときしか届かないので、英雄攻撃では前と同じ値が入り、それ以外では読まれないため値を false にしても結果が変わる場所がない。`PairCombos`・`RunGrowth`・`GimmicksV129`・`MemoryActivationAttribution` の他の読み手は `From`・`Target`・`Actor`・`Primary`・`Serial` だけを見る。`TryWeakspotBasic` の並べ替えでは、乱数を引く条件を「付与率が0より大きい」のまま同じ位置に保ったので、乱数の出目の並びと会心の判定は前と同じになる。`BasicCritChanceV129`（`ConditionalWeakTable`・`Status.critChance`・`_runtimes` の辞書・`PilingLuckCriticalChance` の参照のみ）は副作用を持たない。通信は変更していない。これらの前計算はホスト側のローカルな値で、送受信には現れない。

効果の見込み（推定）: `DoBasicAttackHit` は近接（`MeleeAttackInstance` の主対象と副対象の2回）と投射物（`AttackProjectile`）の両方から呼ばれ、英雄・召喚・魔物が同じ経路を使う（本体の逆コンパイルで確認）。群れとの戦闘では魔物の攻撃が中心になるため、命中は1秒あたり数十〜百数十回になりうる。1回あたり、Actor 連鎖の走査（多くの場合1〜2段階）と `ConditionalWeakTable` の参照1〜2回と、英雄攻撃ではさらに辞書とステータスの参照を省く。1参照は数十〜数百ナノ秒程度なので、合計では1秒あたり十数マイクロ秒から数十マイクロ秒の削減の見込みで、小さい（推定）。確保は減らしていない（元から確保のない経路）。実測はできていない。
