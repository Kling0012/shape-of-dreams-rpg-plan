# perf-loop/20261020-0542

## 対象

mod src/SodRpg.Mod/NativePerfPatches.cs（本体 `DewPhysics.UpdateProxyPosition` への新しいパッチ）。

## 直した内容

`DewPhysics.UpdateProxyPosition(ProxyCollider, Vector3)` に Prefix パッチ（`NativeProxyPositionIdlePerf`）を足し、書き込む値がすでにプロキシの transform に入っているときはメソッド全体を飛ばすようにした。このメソッドは本体では `proxy.transform.position = (position.x, position.z, 0f)` の1行だけの代入で、`EntityControl.LogicUpdate` の最後で、眠っていない全実体に対して実行される（協力プレイの参加者では、ホストが処理するモンスター・召喚体・ほかのプレイヤーの英雄のすべてを含む。ロジック更新は最大30Hz）。実体が止まっている間は渡す位置が変わらず、同じ3つの float を毎回書き直している。Unity の `Transform.position` の setter は値が同じでも分解・保存・dirty 状態への変更を行うため、止まっている実体ほど無駄が大きい。スキップの条件は「現在のプロキシ位置の x が引数の x と等しい」「y が 0」「z が引数の z と等しい」の3つで、呼び出しごとに実際の transform から読み直す。

設定は `nativeProxyPositionIdle`（既定有効）で切れる。パッチ先のメソッドが見つからないときは、その修正だけ外れて1回警告を出す。テスト側では、リンクされる `NativePerfPatches.cs` が参照する本体 API の受け口として、既存の境界ファイルに `ProxyCollider` と `DewPhysics.UpdateProxyPosition` の模倣（NativeBoundary.cs）と、設定の受け口に `nativeProxyPositionIdle`（NativeEmbracePositionBoundary.cs）を足した。

## 結果が変わらない理由

ネイティブの本体は「プロキシの transform への (x, z, 0) の代入」だけで、ほかには何もしない。スキップは「今から書く値がすでにそこのビットと一致するときだけ」行い、スキップしても状態は1ビットも変わらない。比較相手を記憶した値ではなく毎回実物の transform にしているので、間に何かがプロキシを動かしても次の比較は外れて本体の書き込みが走る。NaN はどの比較も成立しないので本体の書き込みに流れる（NaN からの回復も元のままである）。+0 と -0 は等しいと扱うが、y は 2D プロキシで捨てられる成分で、x と z はどちらも同じ物理姿勢に入るため差が出ない。書き込みを飛ばしたことで `Transform.hasChanged` が立たなくなる点だけが動きと違うが、出荷されているゲームのコードには hasChanged を読む箇所がない（逆コンパイル物全体を grep して確認）。Physics2D は Collider の姿勢をシミュレーションの段階で transform から写すので、同じ値の書き込みの有無で姿勢が変わることはない。

## 効果の見込み（推定）

参加者の PC では、止まっている実体1つごとに毎ロジック tick（最大30Hz）の transform への書き込みと dirty 化がなくなる。60fps・止まっている実体40体の場面で毎秒約1200回の書き込み減（推定。実体数は場面による）。ホスト側でも同じ効果がある。動いている実体では、現在位置を読む `transform.position` の getter が元の本体に加えて1回増える（増分は小さい）。テレポートは位置が変わるため本体の書き込みが走る。
