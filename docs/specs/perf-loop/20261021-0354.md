# perf-loop/20261021-0354

対象は native Dew.Core/GenericTransformSync.cs（プレハブに付けられる汎用の位置・向き同期）。改善あり。

直した箇所: MOD 側 src/SodRpg.Mod/NativePerfPatches.cs に NativeGenericTransformIdlePerf を追加した（設定 nativeGenericTransformIdle、既定はON、ラベルは参加者のみを示す）。このコンポーネントの FrameUpdate は、サーバーでない端末で毎フレーム、同期変数 _pos と _rot を transform.position と transform.rotation に書き込む。Unity の位置・回転の代入は値が同じでも変換を分解して保存し、親子関係と子の描画・物理へ変更を配るため、止まっている同期オブジェクトは毎フレーム同じ7つの float を書き直す。そこで Harmony Prefix で本体の FrameUpdate の前に値を見て、位置（_pos が NaN でないとき）と回転（_rot が NaN でないとき）を実機の transform が持っている値と成分ごとの float == で比べ、両方の書き込みが同じビットになる場合に限って本体の処理を省く。同期変数が NaN のときは本体もその書き込みを飛ばすので、比較も飛ばす。ホスト（isServer）では Prefix は比較の前に本体へ流す（isServer の読み取りだけを足す。本体はホストではもともと何もしないため、ホストで transform の読み取りが増えない）。クラスは名前で解決し（MOD はこの型を参照しない）、型やメンバーが見つからないときは警告1回でこの機能だけ外れる。設定は DreamforgeConfig.cs に足し、Issue73.Native.Tests が設定を読むための既存のスタブ（NativeEmbracePositionBoundary.cs）にも同じ名前のフィールドを足した（スタブの注記の指示どおり）。

結果が変わらない理由: 省くのは、本体が書き込んでもビットが1つも変わらない場合（または本体自身が飛ばす NaN の場合）だけである。比較を実機の transform に対して行うので、同期以外の何かがオブジェクトを動かした次のフレームは必ず比較が外れて本体の経路に戻る。動いた同期オブジェクトも、本体が書き込んだ翌フレームからだけ省く。Unity の Quaternion ==（約0.1度の誤差を等価とみなす）は使わず成分ごとの float == で比べるので、回転がわずかに変わった更新は省かない。+0 と -0 は等価に比べられるが、符号の違いが数値に影響する場所はない。ゲットした値に NaN が混ざると比較がすべて外れて本体に流れるので、本体と同じように回復する。ホストでは Prefix が isServer を読んで比較の前に本体へ流す。本体の FrameUpdate はホストではもともと何もしない（書き込みは両方 !isServer 条件で、基底 DewNetworkBehaviour.FrameUpdate は空）ため、実行するのはパッチなしと同じで、transform の読み取りも増えない。通信は一切触れていない。ホストの送信側（LogicUpdate の Network_pos 代入）と Mirror の同期・逆シリアル化はそのままで、ホストと参加者で見えるもの・判定・タイミングは変わらない。省いたときだけ Transform.hasChanged が立たなくなるが、出荷ゲームの C#/Mirror のコードは hasChanged を読まない（逆コンパイル全体の grep で確認。ヒーロー武器の待機パッチでも同じ根拠を使った）。

効果の見込み（推定）: このコンポーネントはプレハブに付けられていてコードからは生成されないため、実インスタンス数はこの環境では測れていない（推定）。1インスタンスあたり、止まっている間は毎フレーム2回の transform への書き込み（変換の分解・保存・親子への変更配布・付属コライダーの姿勢更新）が2回の読み取り（保存済みの値の参照）に置き換わる。子やコライダーを持つオブジェクトほど書き込み側の配布が重く、参加者側の毎フレームの負荷が下がる見込み（推定）。動いているオブジェクトは比較が外れて従来どおり本体の経路で動く。

テスト: 既存の待機系パッチのテストと同じ形式で、ProxyPositionIdlePerfTests.cs に GenericTransformIdlePerfTests を足した。模倣の GenericTransformSync（NetworkBehaviour の子孫）を NativeBoundary.cs に置き、Prepare・Prefix をリンクされた NativePerfPatches.cs から直接動かす。位置・回転の1成分だけの不一致（回転は0.0001の差も）で本体経路に戻すこと、完全一致のときだけ省いて書き込みが増えないこと、同期変数の NaN でその比較を飛ばすこと（transform 側の NaN は本体経路で回復）、ホストで比較の前に本体へ流すこと、存在しない型名で TryPrepare が警告1回で false を返すことを確かめる。
