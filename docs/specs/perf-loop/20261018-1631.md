# perf-loop/20261018-1631

対象は native Dew.Core/ActorTransformSync.cs（アクターの座標同期）。改善あり。

直した箇所: MOD 側 src/SodRpg.Mod/NativePerfPatches.cs に NativeTransformSyncIdlePerf を追加した（設定 nativeTransformSyncIdle、既定はON）。サーバーはロジック tick ごとに CaptureServerAuthority で Network_syncData へ書き込むが、timestamp が毎回新しくなるため SyncVar は常に dirty になり、動いていないアクターも同期間隔のたびに全オブザーバーへ SyncMovementData を送り続ける。そこで、位置・回転・拡大・チャンネル・テレポートフラグが前回の保存値と同一で、かつ三つの速度（velocity・angularVelocity・scaleVelocity）が保存値・新しい標本の両方とも成分ごとに厳密に 0 のとき（timestamp 以外が同じ＝動いていない）だけ、プロパティ setter への Harmony Prefix で書き込みを省く。速度に近似を使わないのは、Unity の == は 1e-5 未満の差を等価と見なすため、微小な残り速度のまま省略が続くと外挿のずれが静止時間に比例して積もるからである（修正ラウンド F1）。パッチ先が見つからないときは警告1回でこの機能だけ外れる（ほかの native パッチと同じ）。省略判定は src/SodRpg.Mod/NativeTransformSyncIdle.cs の純粋 static 関数 IsIdleRefresh(in current, in next) として切り出して Prefix から呼び、SodRpg.Mod.Startup.Tests から実ソースを直接リンクして単体テストで確かめる。

結果が変わらない理由: 省くのは timestamp 以外が同一の更新だけである。クライアント側の描画（FrameUpdate の外挿と SmoothDamp）で timestamp は外挿時間の計算に使われるが、外挿の移動量は保存された速度に掛かるため、速度が厳密に 0 なら timestamp が古くても外挿項は 0 のまま目標の姿勢は同じになる。動きが止まった直後の標本（速度が非0から0へ変わる更新）とテレポート（isTeleport が立つ更新）は必ず値が変わるため省かれない。速度が近似上の 0（1e-5 未満の微小値）にしか収束していなかった場合も省略せず送り直すため、保存標本の速度が厳密に 0 になってから省略が始まる。動きの再開時の速度は、本体が毎 tick 更新する _serverLastCaptureTime と保存位置との差分から計算され、省いても同じ1 tick 分から同じ速度が出る。サーバー自身の LogicUpdate での姿勢の復元も、同一の値の再設定を省くだけである。

効果の見込み（推定）: 動いていないアクター（待機中の敵、静止した英雄など）ごとに、同期間隔のたびの SyncMovementData のシリアライズと送信がオブザーバー人数ぶん消える。位置のみを同期する標本は33バイト（フラグ1＋timestamp 8＋位置12＋速度12）に Mirror の枠が付く。ソロでもホスト内のシリアライズとローカル送信が減り、協力プレイでは観測するプレイヤーの数だけ送信が減る（推定。実際の送信間隔は NetworkIdentity 側の設定による）。

テスト: SodRpg.Mod.Startup.Tests の NativeTransformSyncIdleTests（11件）で判定を確かめた。timestamp だけが違う標本は省く（true）、isTeleport・channels・位置・速度・回転・角速度・拡大・拡大速度のどれか1つでも違う標本は通す（false、8件）、停止直後に速度が非0から0へ変わる標本は通す（false）、三つの速度のどれかに近似上は 0 と等価な微小値（1e-6）が残る標本は通す（false、保存側・新しい標本側の両方向）。境界スタブ（NativeTransformSyncIdleApi.cs）には本体 Dew.Core の SyncMovementData と SyncTransformChannel を置き、Vector3・Quaternion のスタブには Unity と同じ近似の == 演算子を足して、リンクした判定が本体と同じ比較意味で動くようにした。
