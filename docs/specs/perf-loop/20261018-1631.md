# perf-loop/20261018-1631

対象は native Dew.Core/ActorTransformSync.cs（アクターの座標同期）。改善あり。

直した箇所: MOD 側 src/SodRpg.Mod/NativePerfPatches.cs に NativeTransformSyncIdlePerf を追加した（設定 nativeTransformSyncIdle、既定はON）。サーバーはロジック tick ごとに CaptureServerAuthority で Network_syncData へ書き込むが、timestamp が毎回新しくなるため SyncVar は常に dirty になり、動いていないアクターも同期間隔のたびに全オブザーバーへ SyncMovementData を送り続ける。そこで、位置・回転・拡大・それぞれの速度・チャンネル・テレポートフラグのすべてが前回の保存値と同一のとき（timestamp 以外が同じ＝動いていない）だけ、プロパティ setter への Harmony Prefix で書き込みを省く。パッチ先が見つからないときは警告1回でこの機能だけ外れる（ほかの native パッチと同じ）。

結果が変わらない理由: 省くのは timestamp 以外が同一の更新だけである。クライアント側の描画（FrameUpdate の外挿と SmoothDamp）で timestamp は外挿時間の計算に使われるが、外挿の移動量は保存された速度に掛かるため、速度が0のままなら timestamp が古くても目標の姿勢は同じになる。動きが止まった直後の標本（速度が0へ変わる更新）とテレポート（isTeleport が立つ更新）は必ず値が変わるため省かれない。動きの再開時の速度は、本体が毎 tick 更新する _serverLastCaptureTime と保存位置との差分から計算され、省いても同じ1 tick 分から同じ速度が出る。サーバー自身の LogicUpdate での姿勢の復元も、同一の値の再設定を省くだけである。

効果の見込み（推定）: 動いていないアクター（待機中の敵、静止した英雄など）ごとに、同期間隔のたびの SyncMovementData のシリアライズと送信がオブザーバー人数ぶん消える。位置のみを同期する標本は33バイト（フラグ1＋timestamp 8＋位置12＋速度12）に Mirror の枠が付く。ソロでもホスト内のシリアライズとローカル送信が減り、協力プレイでは観測するプレイヤーの数だけ送信が減る（推定。実際の送信間隔は NetworkIdentity 側の設定による）。
