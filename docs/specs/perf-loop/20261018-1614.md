# perf-loop/20261018-1614

対象: mod src/SodRpg.Mod/ClientSession.CoopTrade.cs（と、そこから毎フレーム・通信ごとに呼ばれる経路）。

直した内容: `CoopLocalBlockReason` の件数付きの待ちメッセージ3種（分解の応答・取引結果の照会・遠征報酬の精算）を、種別・件数・表示言語が同じなら組み立て直さずにキャッシュした文字列を返すようにした。交換タブを開いている間、`CanCoopTrade` と `CoopTradeUnavailableReason` は1回の OnGUI イベントでボタンや相手ごとに何度も評価され（IMGUI はフレームごとに最低2回イベントが来る）、ブロック中はそのたびに補間文字列を2つ作り直していた。判定や走査そのものは毎回実行したまま、文字列の確保だけ省く。

結果が変わらない理由: 同じ種別・件数・言語から作られる文字列は値として常に同じ。キャッシュした同一のインスタンスを返すが、この文字列は比較も描画も値で行われる（`!=`、`string.IsNullOrEmpty`、`GUILayout.Label`、`CoopWaitText` の`!=`）。待ち状態の判定、件数の数え方、60秒接尾辞の付け方は一切変えていない。

効果の見込み（推定）: 交換タブを開いたまま待ち状態が続いている間、フレームあたり数個〜十数個の小さな文字列確保（数十〜百数バイトずつ）がなくなり、GC の負担が減る。待ちメッセージが出ていない通常時の割り当ては元からないため、効果はこの状態に限られる。判定の再計算は残すので CPU の節約はない。

検証: `python3 tools/balance/gen_cs.py --check` 合格、`dotnet build src/SodRpg.Mod -c Release` 合格（警告は既存）、`dotnet test tests/Issue73.Native.Tests -c Release` 278件合格、`dotnet test tests/SodRpg.Mod.Startup.Tests -c Release` 149件合格・1件スキップ（既存のスキップ）。実機での動作確認は未実行。
