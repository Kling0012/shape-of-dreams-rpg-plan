# perf-loop/20261020-1006

対象は native `Dew.Core/PickupInstance.cs`（439行）である。これはドロップ品の宝珠（ゴールド・経験値・夢のダスト・回復・マナ・リジェネの各オーブ）の基底クラスで、派生クラスは `ActiveFrameUpdate` を上書きしないため、全種類の宝珠がこの1本の毎フレーム更新に乗る。

見えた構造は次のとおりである。`ActiveFrameUpdate` はホスト・ゲストを問わず全クライアントで、生きている宝珠1個ごとに毎フレーム走る。その本体は、吸い寄せ先があれば追跡の速度制御、なければ水平速度の減速であり、どちらでも最後に地面の高さを得るための 3D `Physics.Raycast`（Ground レイヤー、真下6単位）を撃ち、transform へ位置を書き込む。宝珠の寿命の大半は地面に止まって動かない時間なので、このレイキャストは「同じ場所に同じ答えを取りに行く」毎フレームの繰り返しになる。ゲスト側の経路はこの `ActiveFrameUpdate` と、受信時の `RpcSyncPosition`・SyncVar の同期（いずれも送り側が間引くものではない）であり、ホストだけの `ActiveLogicUpdate`（目標探索・拾い判定・破壊）は今回触っていない。

直した内容は、Harmony の Prefix（`NativePickupIdlePerf`、`src/SodRpg.Mod/NativePerfPatches.cs`）で、宝珠が厳密に静止しているときだけ本体メソッドを丸ごと1フレーム飛ばすことである。静止の条件は、吸い寄せ先なし（`Network_target == null`）、水平速度が成分ごとに `== 0f`、垂直速度が `== 0f` の3つで、Unity の `Vector2` 同士の近似比較ではなく成分ごとの厳密な比較を使う。条件を満たしている間は 0.5 秒に1回（`Time.time` 基準）本体を走らせて再確認し、それ以外のフレームを飛ばす。最初に静止した1フレームは本体を走らせてから計測を始めるので、飛んでいる・滑っている宝珠は何も確保せず本体どおりに動く。設定 `nativePickupIdle`（既定有効）で切り替えられ、本体メソッドが見つからない・フィールドの形が違うときはこの軽量化だけが外れて警告を1回出す。

結果が変わらない理由は次のとおりである。静止の条件になるのは本体の地面クランプ（`vector.y = num4; _currentYVelocity = 0f`）の通過後だけで、その時点で宝珠は `groundHeight + yPosFromGround` にぴったり止まり、水平速度は `MoveTowards` がちょうどゼロに丸めた値だ。この状態で本体が毎フレーム行うのは、ゼロへの `MoveTowards`（結果はゼロのまま）、正確なゼロの加算（位置はビット単位で不変）、レイキャスト、どの書き込み節にも当てはまらず落ちた先の `-18.8 * dt` を垂直速度へ足す処理、そして読んだばかりの値での transform への再代入だけである。足した `-18.8 * dt` は、本体固有の2フレーム周期の「沈んで戻る」揺れ（18.8×dt²、60fps で約0.005単位、30fps で約0.02）を生む元だけで、飛ばすことでこの目に見えない揺れがなくなるほかの差はない。ホストが `SyncPosition` で送る位置・拾い判定の距離・描画される transform は、同一の値またはその揺れの振幅以内に収まる。止まった宝珠が動き出す経路（目標の SyncVar 到着、`RpcSyncPosition` による速度の上書き）はすべて条件を壊すので、動きは自然に再開する。ここから見えない唯一の状態は「止まった宝珠の下の地面が変わる」ことだが、0.5 秒ごとの再確認で本体に戻るため、ずれは最大0.5秒で直る。

効果の見込み（推定）は、静止している宝珠の地面レイキャストが毎フレーム（60fps で毎秒60回）から 0.5 秒に1回へ減ることである（約97%減の推定）。宝珠は `PickupManager` の上限（ゴール7・経験値7・夢のダスト5）と回復系を合わせて同時十数〜数十個になりうるので、戦利品が多い場面ではゲストを含む全クライアントの毎フレーム負荷を数0.1ms 単位で下げる見込みである（推定）。宝珠が飛んでいる間・吸い寄せられている間は従来どおり本体が走る。

検証は次のとおりである。`python3 tools/balance/gen_cs.py --check` を通した。`dotnet build src/SodRpg.Mod -c Release -p:GameDir=... -p:ModDeployDir=/tmp/perfloop-x` を通した（エラー0、警告6件は既存分）。`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release` は 573 件すべて通過した。`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release` は 225 件通過・1 件スキップで失敗はなかった。テストには、リンクされた `NativePerfPatches.cs` が新しい設定フィールドを参照するための境界（`NativeBoundary.cs` に `PickupInstance` の模倣、`NativeEmbracePositionBoundary.cs` に設定モックのフィールド）を既存ファイルへ足しただけで、新しいテストファイルは作っていない。実機（ゲーム内）での確認は未実行である。この環境ではゲームを動かせないためである。
