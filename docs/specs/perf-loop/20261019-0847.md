# perf-loop/20261019-0847

対象: mod src/SodRpg.Mod/InfinityMode.PersonalChoices.cs（と、そこから毎フレーム・通信ごとに呼ばれる処理）。

直した内容: `PublishPersonalWait` は、個人選択のバリアが存在する間 1 秒ごとに `GameSettingsManager.customData` へ待ち要求の JSON を書き込む。`customData` は Mirror の `SyncDictionary<string, string>` で参加者全員に同期されるが、このゲームに同梱の Mirror は書き込み時に値の等値比較をしない（`SyncIDictionary.AddOperation` が常に `changes` に積んで `OnDirty` を出す）ため、前回と同じ内容の書き込みでも値全体を参加者全員へ再送する。選択開始前（誰も「選択完了」を押していない間）は JSON が毎秒まったく同一なので、この間の再送は全部むだだった。そこで前回発行した JSON 文字列と設定先の `GameSettingsManager` インスタンスを static フィールドに覚え、両者が変わらなければ辞書への書き込みを省くことにした。辞書からの削除のあとは必ず書き直すよう、`ResetPersonalChoices` がキャッシュを消す。開始後は残り秒が 1 秒ごとに変わるため、値が変わった秒だけ書き込んで送る。

結果が変わらない理由: クライアントが `customData` で見る値の列が同じだから。同じ文字列の再書き込みは同期されてもクライアント側の値を変えず、省いても変わらない。開始後の「残り N 秒」表示は値が変わった秒だけ届くが、届く値とタイミングは従来と同じ（変わらない値の再送は表示に影響しない）。選択の確定・タイムアウト時の `Remove` は従来どおり必ず実行され、`ResetPersonalChoices` がキャッシュを消すので削除後の次の発行も必ず書かれる。途中参加のプレイヤーは初期状態同期で `customData` 全体を受け取るため、再送を省いても同じ値を受け取る。`GameSettingsManager` が作り直された場合はインスタンス参照が変わるので必ず書き直す。

効果の見込み（推定）: 選択開始前の待ちの間、1 秒ごとに参加者全員へ送っていた同一メッセージ（キー文字列と JSON 全体）の送信と、クライアント側の受信処理とコールバック発火が省ける。ホスト側の JSON 生成と前回文字列との比較は毎秒実行される（比較の判定に使うため、生成は省けない）。省けるのは辞書への書き込みと、書き込みに伴う同期の処理である。待ちが長いほど効果が伸びる（選択ノードごとに最大 60 秒、開始しないまま取られる待ちではさらに長くなる）。開始後の必要な残り秒の送信は残るので、確定・撃破・報酬のような必須の通信には触れていない。削減量は通信量と送信回数の一部で、待ち 30 秒・参加者 3 人のとき 1 ノードあたり約 30 通の重複送信が減る見込み（推定）。

見た範囲と見送った候補: ファイル全体と、そこから毎フレーム（`InfinityMode.Tick` → `TickPersonalChoices`）、バリアの確定・被弾・撃破ごと（`BeginPersonalChoice`・`QueuePersonalIntent`・`ReceivePersonalChoice`・ack）、設定の読み取りごと（`PersonalWait` プロパティ、テキストが変わったときだけ解析を繰り返す既存のキャッシュ付き）に呼ばれる処理を見た。本体側は `GameSettingsManager`（`customData` の同期と Callback）、Mirror の `SyncIDictionary`・`NetworkBehaviour.InitSyncObject`、`InfinityPersonalChoiceBarrier` を確認した。見送った候補は次のとおり。（1）`RegisterPersonalChoices` の毎フレーム呼び出しの間引き。アクターの変更後にハンドラ登録を維持するための既存の仕組みで、参照比較の早期リターンだけで確保がなく、間引くと再登録が遅れるため見送った。（2）バリア存在中の毎フレームの `TryRelease` とプレイヤー名簿の組み立て。名簿は静的スクラッチへの再利用で確保がなく、走査対象は 4 人以下のため見送った。（3）`TickPersonalChoicesNative` でバリアが無いときも走る `RegisterPersonalChoices` をバリアありのときだけにする案。クライアントはバリアなしのときに ack を受ける必要があるため見送った。
