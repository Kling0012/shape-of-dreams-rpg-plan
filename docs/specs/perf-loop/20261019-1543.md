# perf-loop/20261019-1543

## 対象

`native Dew.Core/Actor.cs`（2698行全体）。毎フレームの `LogicUpdate`・`FrameUpdate`、被弾ごとの `DealDamage`・`DoHeal`・`DoBasicAttackHit`、撃破後の破棄まわり、そして協力プレイの MOD 間通信の受け口 `HandleRpc_Imp` とその下流（`SafeAction`、`DewPersistence.ToJson/FromJson`、`DamageData.HasAttr`）を呼び出す側と一緒に読んだ。

## 直した内容

MOD 間通信を1通受けるたびに走る `Actor.HandleRpc_Imp` の型探しを、Harmony の Prefix（`NativeCustomRpcDispatchPerf`、`src/SodRpg.Mod/NativePerfPatches.cs`）で辞書引きに置き換えた。

本体の実装は、登録済みハンドラの辞書を最初から最後まで列挙し、各エントリで `Type.Name` と電文の型名を文字列比較して、一致した型で JSON を復元する。MOD はセッション用の Actor に数十種類のメッセージ型を登録するため、ホストも参加者も、撃破・モンスター・取引・選択肢など通信1通ごとに同じ全走査を払っていた。この Prefix は型名から型への対応を Actor ごとに一度だけ決めて覚え、以後は辞書の `TryGetValue` で1回引きする。JSON の復元は本体と同じ `DewPersistence.FromJson` を同じ型で呼び、設定は `DreamforgeConfig.nativeCustomRpcDispatch`（既定は有効）で切れる。

## 結果が変わらない理由

電文の内容も配達の結果も変えない。覚えた対応は、毎通その Actor の辞書で `TryGetValue` し直して確かめる。型の登録が解除されていれば引きが外れるので、その通は本体の全走査に戻る。リストの中身（ハンドラの追加・解除）は辞書が持っている生の List 参照越しに見える。対応を覚えるのは server 用と client 用の辞書で別々にする（両方に同名の型が別の組み合わせで登録され得るため、一方で覚えた対応が他方の配達を歪めないようにする）。

同じ単純名を持つ別々の型が同じ Actor に2つ以上登録されていた場合は覚えず、本体の列挙に任せる。この同名の判定は最初にその名前を解決した時点だけ行い、覚えた後に同じ名前の別の型が登録されても検知しない（毎通の再走査はこの軽量化の目的と両立しない）。既知の登録は Dew.Core・Dew.Contents・MOD を合わせても名前一意で、この場面は起こらない。後から登録される同名の別型も検知対象にするには、登録 API（`CustomRpc_RegisterClientMessageHandler` など）の側に Hook を足して、登録・解除のたびにその Actor のキャッシュを捨てる必要がある。本体の private な登録経路への追加パッチが要るため、この PR では改善案として記録するだけに留める。本体は一致する型が複数あると順に復元を試し、復元に失敗した型は飛ばして次へ進むが、この挙動ごと本体側に残る。復元は本体と同じ `DewPersistence.FromJson` で、復元に失敗した電文を捨てるのも本体と同じだ。

ハンドラは辞書が返す生のリストを、本体と同じ foreach の列挙（r1.4.1.2 逆コンパイル確認）で呼び、例外は1個ずつ `Debug.LogException` する。したがって、ハンドラが自分の登録を列挙の途中で解除した場合も本体と同じ `InvalidOperationException` で残りの配達を止める（添字走査で次のハンドラを黙って飛ばすことはない）。既知の差として、Prefix は本体が保持する外側の辞書列挙を保持しないため、配達中に辞書そのものが書き換えられた場合（自分の型の解除・別の型の解除・Clear など）、本体の外側 foreach が列挙の続行時に出す `InvalidOperationException`（とそのログ）だけが出ない。その型の配達はどちらの経路でも最後まで終わり、結果は同じだ。本体が先に代入している `_serverRpcCaller` も同じ位置で代入する。

送信側は一切触らないので、電文の形式は変わらず、古いバージョンや MOD なしの相手との組み合わせも今のままで動く。

本体側の形が違って更新で壊れたときは、`Prepare` が対象メソッドや private メンバー（`_serverRpcCaller`・2つの辞書・`RpcHandler.wrappedAction`）の有無に加えて `wrappedAction` の宣言型が `Action<object>` であることまで確かめて、そのパッチだけ外れて1回警告を出す。実行中の想定外の例外でも同じく1回警告して本体の処理に戻す。ハンドラを1件も呼ぶ前に委譲先の形を確かめ、壊れていれば誰も呼んでいない時点で本体へ戻すため、同じ電文が二重に配達される経路はない。

## 効果の見込み

通信1通あたり、登録済みメッセージ型の数（MOD だけで36か所の登録がある）に比例していた文字列比較と辞書列挙が、1回の辞書引きになる。支配的なコストは JSON の復元なので全体としての縮みは数パーセント程度の推定だが、協力プレイで最も頻繁に走る受信経路の1つなので、通信が増える終盤の戦闘ほど効く。毎フレームではないため GC への影響はない（本体も Prefix も電文ごとの確保を増やさない）。
