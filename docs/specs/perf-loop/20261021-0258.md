# perf-loop/20261021-0258

対象は `src/SodRpg.Mod/HostAuthority.SupportOverheal.cs` の `Actor.DoHeal` パッチ（NativeSupportHealScope）が持つ、呼び出しごとの状態である。

当初は、Harmony 2 が `__state` を object 型の局所変数として受け渡すため、値型の状態は呼び出しごとにボックス化されてヒープに確保されると考え、退避先を深さを添え字にした静的配列2本へ変える変更を作った。レビューで「Harmony 2 の MethodPatcher は `__state` をパラメータの実際の型のローカル変数として宣言して ref で渡すため、値型はボックス化されないはず」と指摘された。そこでゲーム同梱と同じ版の Harmony 2.3.6（同梱 dll は 0Harmony.dll、アセンブリ版 2.3.6.0）のソースと公式ビルドで確かめ直した。

ソース（タグ v2.3.6.0）では `__state` を持つパッチごとに `DeclareLocalVariable(patchParam.ParameterType)` でローカル変数を宣言する。`DeclareLocalVariable` は ByRef を `GetElementType()` で外すため、ローカルは構造体そのものの型になる。パッチの呼び出し側は `Ldloca` か `Ldloc` でこのローカルを直接渡し、この経路に box 命令はない。

実測も行った。公式 Lib.Harmony 2.3.6（net6.0 ビルド）を .NET 6.0.36 で動かし、元の実装と同じ形状のパッチ（`Prefix(out State __state)` と `Finalizer(Exception __exception, State __state)`。State は 72 バイトの構造体）を当てた静的メソッドを 100万回呼んで、`GC.GetAllocatedBytesForCurrentThread` の増分を測った。未パッチが 0.000 バイト/呼び出し、パッチありも 0.000 バイト/呼び出しで、同じ構造体を毎回ボックス化した対照は 88 バイト/呼び出しだった。つまり値型の `__state` はボックス化されず、呼び出しごとのヒープ確保を生まない。ゲーム同梱の dll は公式ビルドとは別のリパックで、.NET のコンソールでは同梱 MonoMod の初期化に失敗してパッチを当てられなかったため、実測には公式ビルドを使った。IL を生成する上記の箇所は対象ランタイムを問わず共通のソースで、ゲーム同梱 dll のメタデータにも同じメンバ（MethodPatcher・EmitCallParameter・DeclareLocalVariable）がある。

結論として、当初の予想は誤りで、静的スロットへ変えても減るヒープ確保はない。変更を取り下げ、コードは元の `__state` 実装へ戻した（`git diff 416e41d3^ -- src/SodRpg.Mod/HostAuthority.SupportOverheal.cs` が空であることで確認した）。軽量化の変更自体がなくなったため、等価性を確かめるテストは作っていない。この記録は同じ調査をもう一度行わないために残す。

検証は `dotnet build src/SodRpg.Mod -c Release -p:GameDir="$HOME/dev/sod-gamedata/Shape of Dreams" -p:ModDeployDir=/tmp/perfloop-x`（0 エラー）と `DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release`（231件通過、1件スキップは既存のもの）を行った。実機（ゲーム内）での確認は行っていない。
