# perf-loop/20261024-0752

対象: `src/SodRpg.Mod/FrostFxLifetime.cs`（霜の演出の寿命管理）

## 直した内容

`FrostFxLifetimePatch.Postfix` は、ゲーム内のすべてのプール演出の再生（`DewEffect.PlayIntoPool`）の後に走ります。
親には再生元の振る舞いの NetworkIdentity が渡るので、霜以外のほぼすべての再生でも
`parent.GetComponent<Gem_R_Frost>()` が毎回呼ばれ、そのほとんどが null で返るだけでした。

親の Gem_R_Frost の探索結果を `ConditionalWeakTable` で親ごとに1回だけ覚え、2回目以降の再生では
辞書引きとフラグ確認だけで済むようにしました。覚えた値は親の NetworkIdentity が消えると一緒に捨てられます。

## 結果が変わらない理由

- 判定の条件は変えていません。取得した frost が null、テンプレートが `activateEffect` と違う、の2点は従来どおりです。
- 本体コード（`Dew.Core` 逆コンパイル全体）には実行時に Gem 系コンポーネントを AddComponent する箇所がなく、
  ゲームオブジェクトのコンポーネント構成は出現時に固定です。そのため「親に霜がない」という一度目の判定が
  後から変わることはなく、覚えた値が古びる経路はありません。
  もし外部の別 MOD が後から Gem を AddComponent する唯一の例外ですが、その場合も起きるのは
  霜の演出が本体の標準寿命で消えることだけです。
- ゲスト側でも受け取った演出メッセージは同じ `PlayIntoPool` を通るため、ホストと同じ判定がそのまま働きます。

## 効果の見込み（推定）

演出の再生は戦闘中に毎秒数百回になりうるため、ホストと参加者の両方で、再生ごとのネイティブ
GetComponent 呼び出し（エンティティはコンポーネントが多いため1回あたりマイクロ秒程度、推定）を
マネージドな辞書引き（数十ナノ秒、推定）に置き換えられます。特に演出が多くなるボス戦や
Cold デッキの周回で、参加者側の毎フレームの固定コストが減る見込みです。
