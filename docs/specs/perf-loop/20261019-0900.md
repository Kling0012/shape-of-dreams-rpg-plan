# perf-loop/20261019-0900

対象: native Dew.Core/CharacterModelDisplay.cs（と、それを30HzのロジックTickごとに駆動する入口 PlayLobby_Character.LogicUpdate）。20261018-1916 と同じクラスを再訪し、前回が直した `LogicUpdate` 内の範囲計算の走査以外の、入口側の毎Tick処理を見た。

直した内容: `PlayLobby_Character.LogicUpdate`（ロビーのプレイヤー枠ごとに存在する本体クラス）は、毎Tick `p.selectedAccessories.Where(p.IsAllowedToUseItem).ToListNonAlloc` でフィルタ済みリストを作り直し、`model.accessories.SequenceEqual(list)` で比較している。装備が変わっていないTickでも、この式はラムダのクロージャとdelegate、`Where` の列挙子、`SequenceEqual` 内でボックス化される列挙子2個を毎Tick確保し、アクセサリごとに `IsAllowedToUseItem`（`StartsWith` の連鎖、`DewResources` の辞書引き、`ownedItems` のO(n)走査）を呼ぶ。`NativeLobbyAccessoryIdle.cs` を新しく足し、本体がこのTickで読む入力が、本体が最後に走ったTickから1つも変わっていなければ、Prefix で本体 `LogicUpdate` の1Tickだけを飛ばす。変わっていたときは本体にそのまま実行させ、Postfix で入力を撮り直す。撮る入力は、`forceSetup` の値、`playerIndex`、`DewPlayer.lobbyPlayers` の件数と枠の `DewPlayer` 参照、その `isEveryInfoSet`・`selectedSkin`・`selectedHeroType` の値、`selectedAccessories` と `ownedItems` のリスト参照と全要素の参照、`DewNetworkManager.startSettings` 参照と `continueData` 参照、`model.skinType` の値、`model.accessories` のリスト参照。MOD設定は `nativeLobbyAccessoryIdle`（既定で有効）。

結果が変わらない理由: 本体 `LogicUpdate` が書き換えるのは「`model.skinType` と初期向き（スキン名が変わったTickだけ）」と「`model.accessories` と `UpdateAccessories()`（フィルタ結果が変わったTickだけ）」だけで、その式の入力は上の鍵にすべて含まれる。鍵が一致しているなら本体が作るスキン名とフィルタ結果は前Tickと同じなので、本体を走らせても何も書き換わらない。文字列はイミュータブルなので要素の参照一致は値一致を保証し、不一致のときは本体に戻るだけで、逆に本体が走るべきときを飛ぶことはない。`IsAllowedToUseItem` が読む状態は、`DewResources` の名前辞書とリソースの `generatedFromServer`（両方とも、逆コンパイル全体に起動後の書き込みが無く、このMODもリソースを登録しない）と `ownedItems` の中身だけで、いずれも鍵に入れた。`Skin.GetDefaultSkin` は `heroType` から決定的な文字列を作る。鍵に `model.skinType` と `model.accessories` を入れたため、万一の外部からの書き換えでも次のTickで本体に戻って追従する。設定を切ったとき・パッチの例外のときは、Prefix と Postfix が何もせず本体の毎Tick処理に戻る（警告は1回）。

効果の見込み（推定）: ロビーのプレイヤー枠ごとに、変化のないTickからクロージャ1個・delegate1個・列挙子1個・ボックス化2個の毎Tick確保と、アクセサリ数×（`StartsWith` 数回＋`DewResources` の辞書引き2回＋`ownedItems` のO(n)走査）の呼び出しが消える。ロビー4人なら推定で毎秒数千回の確保と辞書引きが消える見込み。タイトル画面と戦闘中は `PlayLobby_Character` が存在しないため影響しない。実機での動作は未実行。
