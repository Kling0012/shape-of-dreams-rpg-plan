# perf-loop/20261020-0249

対象は MOD の `src/SodRpg.Mod/ClientSession.RunGrowth.cs` と、そこから通信ごとに呼ばれる処理である。このファイルに毎フレームの経路はない。ホスト側の送信（`HostAuthority.RunGrowth.cs` の `SendRunGrowth`）は 0.5 秒に 1 回しか判定を行わず、スタックが変わっていない再送は 30 秒に 1 回に抑えられている（`NetworkTrafficOptions.SkipUnchanged` を無効にしている環境では 5 秒に 1 回）。ただし 5 秒の再送は遠征の鍛錬の台帳（`RunGrowthLedger`）の版を共用しているため、ほかの旅人がスタックを溜めるたびに、スタックが変わっていない参加者にも同じ内容が届く。

直した内容は、ゲストの受信処理 `OnRunGrowth` が同じ内容の再送を解析し直していたのを省く変更である。従来はメッセージを受けるたびにスタック用の辞書を新しく確保し、`stacks` の文字列をコンマで分割し、各要素ごとに `Substring(0, eq)` を最大 3 回呼んでから、既存の辞書と比較して「変化なし」で捨てていた。変更後は最後に適用した生のペイロード（`runId` と `stacks` の文字列）をフィールドに覚えておき、両方が前回と同じなら 2 回の文字列比較だけで抜ける。あわせて、検証の済んだ要素で `Substring(0, eq)` を繰り返し呼んでいた箇所を 1 回にまとめた。

結果が変わらない理由は次のとおりである。`runId` と `stacks` の生の文字列が前回の適用と完全に一致するなら、解析結果は決定的に同じになり、従来の比較（`changed` の判定）も必ず偽を返して状態を何も変えずに return していた。新版の早期 return も状態を何も変えないので、外から見える振る舞いは同じである。キャッシュは適用に成功したときだけ更新するため、壊れた形式のメッセージが同じ内容で続いた場合も、従来どおり毎回警告が出る。接続の張り直しや遠征のやり直しで呼ばれる `ResetRunGrowthDisplay` はキャッシュも一緒に消すので、再接続後に同じ内容が届いたときも表示は作り直される。

効果の見込み（推定）は、スタックが変わらない参加者で、30 秒ごと（`SkipUnchanged` 無効時は 5 秒ごと、しかもほかの旅人の成長でも発生する）に走っていた解析一式（辞書 1 個、分割文字列の配列と要素、要素あたり最大 4 回の部分文字列の確保）が、文字列比較 2 回に置き換わることである。発生は最大で 1 人あたり 5 秒に 1 回程度と低頻度で、削減量は小さいと見る。数値は推定で、実機での計測は行っていない。

検証は `python3 tools/balance/gen_cs.py --check`（変化なし）、`dotnet build src/SodRpg.Mod -c Release -p:GameDir=... -p:ModDeployDir=/tmp/perfloop-x`（0 エラー、警告 6 件は既存のもの）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/Issue73.Native.Tests -c Release`（546 件全通）、`DOTNET_ROLL_FORWARD=LatestMajor dotnet test tests/SodRpg.Mod.Startup.Tests -c Release`（225 件通過・1 件スキップは既存のもの）を実行してすべて通した。実機（ゲーム内）での確認は未実行であり、コードとテストで理論上正しいことを確かめた段階である。
