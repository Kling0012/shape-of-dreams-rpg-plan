# perf-loop/20261025-1216

## 対象

mod src/SodRpg.Mod/LevelEssencePatches.cs（混沌の祠 `Shrine_CorruptedChaos` のエッセンス枠まわりの Harmony パッチ4本と、そこから呼ばれる `LevelEssenceRuntime`・書式キャッシュ・ホスト側の台帳処理）。

## 直した内容

混沌の祠の編集UIが開いているあいだ、本体UIは毎ロジックフレームで `GetTargetInfo(DewPlayer, HeroSkillLocation, SkillTrigger)` を12回呼ぶ（`UI_InGame_SkillButton_EditSkill.LogicUpdate` のコスト表示でスキルボタン4個ぶん、`EditSkillManager.IsSlotHighlighted` のハイライト判定でスキルが入っているボタンから2回ずつ）。MOD の Postfix（`LevelEssenceChaosTargetInfo`）はこの12回のそれぞれで、ツールチップ文の書式キャッシュを引く。キャッシュの鍵は「ローカライズ文字列の参照」と「枠数 `current`」だが、この `current` は場所ごとに違う。エッセンス枠の報酬は場所を選んで取るので、Q だけ上限が4で E は3、という状態が普通に起きる。前回（perf-loop/20261020-1409）で作った鍵1組のキャッシュは、UI が Q・W・E・R の順でボタンを順送りに処理するたびに外れて、1フレームに最大4回 `string.Format` を作り直していた。

そこで書式キャッシュ（src/SodRpg.Mod/LevelEssenceTextCache.cs）を、参照と int の組を5組覚えられる複数枠に変えた。5枠は Q・W・E・R の4通り＋入れ替わりの1枠ぶんで、鍵が4通りに違う場所を順送りに聞かれても、2周目からは外れない。配列1個の struct だけを使い、初期化後の確保はゼロで、探すのは最大5個の参照比較と int 比較。鍵の決め方（ローカライズ文字列は参照比較で言語差し替えを検出）と作る文字列は前回から1文字も変えていない。表示文の側（`LevelEssenceChaosIndicator`）の鍵は実効上限の1通りなので、複数枠になっても使うのは先頭1枠のままで、動きは変わらない。

## 結果が変わらない理由

鍵が同じなら返す文字列は、鍵1組のときと同じ `string.Format` の結果そのもの。複数枠にしても「外れたら作り直す」規則は同じで、枠が増えた分だけ前の結果がもう少し長く残るだけ。表示の受け手（TMPro の text セッター、ツールチップのUI）は文字列の内容を見るので、参照の残り方が変わっても表示は1文字も変わらない。枠数・実効上限・言語のどれかが変われば鍵が外れて、次の呼び出しで作り直す点も前回と同じ。この「前回までのコードと同じ結果」は既存の `LevelEssenceTextCacheTests`（同じ `string.Format` の結果との比較、2回目に同じ参照を返すこと、鍵が変われば作り直すこと）がそのまま通ることで確かめた。Postfix 自体の動作（結果の上書き規則、拒否時の `tooltipRawText = null`、失敗時に1回警告して外れる）は変えていない。

## 効果の見込み（推定）

混沌の祠でエッセンス枠の報酬を選んだプレイヤー（ホスト・参加者とも、編集UIは各自の PC で走る）が編集UIを開いているあいだ、場所ごとに枠数が違う状態での MOD 由来の `string.Format` が、鍵が変わる瞬間を除いてゼロになる。従来は1ロジックフレームに最大4回、60fps で毎秒240回ほどの小さな文字列確保が起きていた（推定。1回の文字列は百バイト前後なので毎秒数十KBの確保と GC 回収が減る）。表示は秒単位の短い時間なので効果は場面限定。本体側の `GetTargetInfo` が自分で作る文字列（毎フレーム12回）は対象外で、残る。
