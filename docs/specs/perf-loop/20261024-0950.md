# perf-loop/20261024-0950

対象: `Dew.Core/FxCastTelegraph.cs`（詠唱中のテレグラフ表示）

## 直した内容

FxCastTelegraph は、スキルの詠唱中に表示されるテレグラフ（円や矢印の予告表示）を
位置と向きで追従させるコンポーネントで、DewEffect.PlayCastEffect が詠唱エフェクトの
プレハブから見つけて Setup します。詠唱エフェクトはホストと参加者の両方で
出るので、テレグラフが生きている間、各端末で FrameUpdate（実質毎フレーム）が
UpdatePosition を呼び、最後に transform.position と transform.rotation を
無条件に書き込みます。

MOD 側に `NativeCastTelegraphIdlePerf` パッチ（NativePerfPatches.cs）を追加し、
Transpiler でこの2つの書き込みを「現在値と比べて、値が変わるときだけ書く」
ラッパーに差し替えました。位置が固定の点対象テレグラフや、詠唱中に動かない
キャスターのテレグラフでは、計算結果は前のフレームと同じで、書き込みは
階層の再計算マーク（dirty 化）を繰り返すだけでした。ラッパーは設定
（DreamforgeConfig の nativeCastTelegraphIdle、既定は有効）で切れます。
本体の IL の形が違うとき（書き込みの数が 1/1 以外のとき）は1回だけ警告を出して
何も置き換えません。

## 結果が変わらない理由

- ラッパーは書く前に現在値を読んで比べるので、値が等しいときに省くのは
  「同じ値をもう1回書く」動作だけです。同じ値の書き込みは描画結果を変えません。
- 位置元が動いているとき（キャスターが動いた、対象が動いた）は現在値が
  計算結果と異なるため、本体と同じタイミングで必ず上書きします。
  テレグラフの表示が遅れる経路はありません。
- 同じ値の書き込みが Transform.hasChanged を立てることだけが異なりますが、
  配布されているゲームコードには Transform の hasChanged を読む箇所がなく
  （逆コンパイル木の全検索で確認）、この前提は既存の付属エフェクト系 idle
  パッチと同じです。
- 値が NaN のときは != 比較が常に true になるため、本体どおり書き込まれます。

## 効果の見込み（推定）

詠唱テレグラフは戦闘中にこまめに出て、出ている間（数百ミリ秒〜数秒）毎フレーム
更新されます。Transform の同じ値の書き込みは1回あたり百ナノ秒程度（推定）に
加えて子の階層の dirty 化が続くため、範囲攻撃の詠唱が重なる場面で、参加者を
含む各端末の毎フレーム負荷が下がる見込みです。動き続けるキャスターの
テレグラフでは元の書き込みが残るので、効果はそこには出ません。省けないときの
オーバーヘッドは現在値の読み出しと比較の1回ずつだけで、書き込み1回より
小さい（推定）です。

ラッパーと Transpiler の書き込み数チェックは、tests/Issue73.Native.Tests の
CastTelegraphIdlePerfTests（修正ラウンドで追加）で直接確かめます:
WritePosition / WriteRotation が（a）値が等しいときは書かない、（b）値が違うときと
NaN のときは書く、（c）設定が無効のときは常に書く、外部から動かされた transform は
計算値で上書きする、の各ケースと、Transpiler が呼び出し箇所1つずつの形では
2つの書き込みだけを差し替え、位置の書き込みが2つ並んだ形では命令を変えず警告1回で
下りること、差し替え後の更新が本体（パッチなし）と同じ最終値になること。

対象メソッドの IL の形は、実 DLL（`Dew.Core.dll`）から ilspycmd で
FxCastTelegraph を取り出して確認しました（Transform への set_position 1、
set_rotation 1。get_transform は Component 宣言なので置き換え対象外。
逆コンパイル木との差は表記のみ）。

実機での見た目の確認は未実施（この環境ではゲームを動かせないため）。
