# perf-loop/20261019-1908

## 対象

mod src/SodRpg.Mod/ClientSession.cs（毎フレームの `Tick` → `SendBuildIfNeeded`）。

## 直した内容

`SendBuildIfNeeded` の中の `string heroKey = HeroKeyOf(hero);` を、送信スロットルの早期 return の前から後ろへ移した。`HeroKeyOf`（ClientSession.cs:173）は Unity のオーバーロードされた null チェック（ネイティブ呼び出し）と `GetType().Name` を行う。Mono では `Type.Name` は呼び出しごとに新しい文字列を確保する（CoreCLR と違い、結果をキャッシュしない）。heroKey を使う処理はすべて早期 return の後にあるため、ビルドを評価しない tick（前回の送信から30秒以内で、変更も強制再送もない通常のフレーム）でも、この2つが毎フレーム走っていた。移動後は、ビルドを評価する tick（変更・強制再送・ハートビート。確認応答のあるホストで30秒、無いホストで5秒間隔）でのみ呼ぶ。

20261018-2210 で `RefreshForbiddenGearNotice` を同じ位置へ移したのに続く、同じ早期 return の前に残っていた呼び出し。

## 結果が変わらない理由

heroKey は2つの早期 return の条件に使わず、この先の処理（禁忌装備の警告、能力の照会、互換プロファイルの作成、Build の計算と符号化）だけで使う。移動で heroKey の値も、この先の処理の順序も変わらない。早期 return に入る間は、heroKey を使う処理がどれも走らないので、呼ばなくても結果は同じ。

## 効果の見込み（推定）

プレイ中の全セッション（ホスト・参加者とも）で、ビルドを評価しないフレームでの文字列確保1件とネイティブ呼び出し1件がなくなる。60fps で毎秒60回のアロケーション削減（1件20バイト前後として毎秒1〜2KB、推定）と、GC への負荷の軽減。ゲームの判定・通信量・見た目は変わらない。
