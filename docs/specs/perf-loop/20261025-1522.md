# perf-loop/20261025-1522

## 対象

mod src/SodRpg.Mod/HostAuthority.DynamicDifficulty.cs。

## 直した内容

`DewPlayer.gamePlayers` を列挙するループのうち、2026-10-24 に `DynamicRunning` で直っていなかった残り5箇所を、同じく `IsCountableConnected` の判定に置き換えた。動くのは `DynamicSoloRunning`（1行目の数え直し）、`PrepareDynamicEnemy`（ソロの所有者決め）、`DynamicSnapshot`（比較パスと再構築パス）、`DynamicStatusSnapshot`（接続人数の数え直し）の5箇所で、変更は条件式の置き換えだけである。

`OwnershipConnected` は `IsCountableConnected` に加えて `DewPlayer.gamePlayers.Contains(player)`（1人につき O(n) の走査）を重ねるが、列挙元が `gamePlayers` 自身ならその結果は常に真なので、判定は変わらず走査だけが余計だった。この恒真チェックは接続プレイヤーごとに O(n) の `List.Contains` を足すため、ループ全体では O(n²) になっていた。

## 結果が変わらない理由

`gamePlayers` は `static List<DewPlayer>` で、列挙で取り出した要素は同じリストの要素であるから `Contains` が偽になることはない（同一参照に対する等価判定は常に真。`DewPlayer` は UnityEngine.Object 派生で等価判定が演算子に沿った実装になっていても、同一参照の比較は真を返す）。これは 2026-10-24 に `DynamicRunning` を直したときと同じ根拠である。触っていない3箇所（`DynamicState` の引数と `_dynamicPlayers` スロット、`OnDynamicRoomLoading` のループ内）は列挙元が `gamePlayers` ではないため、抜けたプレイヤーの所属確認として `Contains` が本来必要で、そのまま残した。

## 効果の見込み（推定）

削減はホスト側で走る経路に限られる（このファイルの実行経路は `NetworkServer.active` でゲストでは早期リターンする）。減るのは、`DynamicSnapshot` と `DynamicStatusSnapshot` の呼び出しごとの比較パスで、接続人数 n ごとに (n−1)×2 回程度の参照比較とリスト走査である。`DynamicSnapshot` は 0.25 秒ごとの表示同期で接続プレイヤー人数分（最大4回）に加え、モンスター分類の送信（キル同期のスポーン経路）からも呼ばれるため、4人協力のスポーンが続く場面で1フレームあたり数十回の呼び出しになる。1呼び出しあたりの削減は数十演算程度の小さいもので、体感できる規模ではない（推定）。
