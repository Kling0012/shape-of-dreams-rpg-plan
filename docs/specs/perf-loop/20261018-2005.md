# perf-loop/20261018-2005

対象: mod src/SodRpg.Mod/ClientSession.RunChoices.cs（と、そこから毎フレーム呼ばれる経路）。

直した内容: `ClientSession.Tick` → `TickRunChoices`（ClientSession.RunChoices.cs:195）は毎フレーム `EnsurePureWhiteChoice`（同:270）と `FlushPendingRunRewards`（同:219）を呼び、ホストでは本体の純白の入口かどうかの検査（同:202）でも `InPureWhiteRoute`（同:75）を評価する。インフィニティ以外の遠征中は参加者で毎フレーム2回、ホストで3回 `_zone.currentZone.name == "Zone_Primus"` を計算していた。`Zone` は MonoBehaviour で、`.name` は Unity のネイティブ呼び出しであり、呼ぶたびに新しいマネージド文字列を確保する。判定結果を Zone の参照でキャッシュする `IsPureWhiteZone` を設け、同じ Zone では参照比較だけにした。

結果が変わらない理由: 本編で Zone の GameObject 名は変わらず、判定結果は Zone ごとに不変であるため、キャッシュの値は従来各フレームで計算していた値と同じになる。`_zone.currentZone` が null（破棄済みの偽 null を含む）のときは従来どおり false を返す。キャッシュは Zone への強参照を保持するため、破棄済み Zone のマネージドのラッパーが回収されて別の Zone が同じアドレスに割り当てられ、参照比較が誤って一致することもない。撃破ごとの `OnDeath`（ClientSession.cs:832）など他の呼び出し先も同じ判定を使うため、挙動は全体で変わらない。

効果の見込み（推定）: 遠征中の全セッションで、毎フレーム2〜3回の `.name` 取得（ネイティブ呼び出しと毎回の文字列確保）と文字列比較が、Zone の切り替わりのときだけに減る。ゾーン名1件あたり数十バイトとして、60fpsで毎秒数百バイト程度のアロケーション削減と Native↔Managed の行き来の削減（推定）。判定・数値・通信量・見た目は変わらない。
