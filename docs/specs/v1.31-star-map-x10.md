# v1.31 星図を10倍に（PoE 型の大きなスキルツリー）

利用者の指示（2026-10-03）：「数がこれだとすごく少ないので、PoE などを参考にして、最低でも10倍くらい豊富なスキルツリーにしてほしい。その分長く遊べることでもあるから」「フォールバックしないように気をつけて」。

## 1. いまの数と目標

| | v1.30 | v1.31 の目標 |
| --- | --- | --- |
| 1人の旅人の星 | 約70（核13・記憶の幹 7×7・橋8） | **700以上** |
| 9人の合計 | 約630 | **6,300以上** |
| 振れるポイント | 最大150 | 最大300（星の経験の曲線を伸ばし、長く遊べるようにする） |
| 1回で取れる割合 | 星のおよそ半分 | 星のおよそ1〜2割（PoE と同じく「どこを取るか」を選ぶ） |

## 2. 守ること（これまでの決まり＋今回）

1. **フォールバックしない**。数合わせの汎用ノード、効果のない仮置き、「実装できないので抽選しない／表示だけ」の星を入れない。すべての星は実際に働き、Core の試験で値と条件を確かめる。本体の経路が確かめられない効果は、星の設計の段階で別の効果に差し替える（実装時に黙って弱い代替へ落とさない）。未知の旅人（他MODのキャラ）だけは従来の汎用ツリーのまま。
2. **横に広げる**。全体の能力値だけの星（攻撃力%・最大HP% など）は**2割以下**。残りは、特定の記憶に反応する星（その記憶のダメージ・加速・仕掛けの強化）、仕掛け、合わせ技、選択式の星、刻印。
3. **旅人の戦い方を邪魔しない**。アイデンティティの星団はそのアイデンティティを前提にしてよい。Q・R・移動の星団は、その旅人の遠征前に選べるすべてのアイデンティティで成り立つこと（travelers.json の loadout。Bismuth は1つ、ほかは2つ。必ずデータで確認）。同じ枠の Q/R 候補は同時に装着できない。
4. **回避で発動する効果は入れない**（Husk の刻印「瞬歩の刃」だけは回避・ダッシュ・瞬間移動を受け付ける）。移動の記憶は「受け手」（クールダウンが戻る等）だけ。
5. 属性の上限（闇5・光5・冷気1・火なし）、スタックを消費しない、仕掛け・反応のダメージは連鎖しない・属性なし、回復と障壁は serverActor の経路、の決まりはそのまま。
6. 記憶の連打は仕様。「X秒に1回」は本当に必要な場合だけ。重なる効果は上限を必ず書く。%表記。
7. 本体の星座・エッセンスで簡単に手に入る効果の上位互換を作らない（汎用の会心・スキル加速・CDR・吸血・移動速度）。

## 3. 木の形（PoE を参考に）

中心の「始まりの星」と核（手前・奥・刻印）はいまの位置のまま。外へ3つの層を足す。

```
        外縁の星団（汎用・役割） ── 6〜8 星団
              │
   記憶の領域（幹＋4星団）×7 ── 橋の領域（合わせ技の星団）×8
              │
        核（いまの13）＋始まり
```

- **記憶の領域**（7つ、各約65星）：いまの幹（7星）に、**星団を4つ**ぶら下げる。星団は「入口の小さな星3〜6 → 中心の大きな星（仕掛け・ふるまいの変化）1〜2 → 選択の星（2つの効果から1つを選ぶ）」の形。星団ごとに、その記憶の使い方のテーマを1つ持つ（例：連打で回す／溜めて大きく撃つ／当てた敵に印を残す／味方を守る）。
- **橋の領域**（8つ、各約15星）：いまの橋の星を中心に、合わせ技を強める・別の形にする小さな星団。
- **外縁の星団**（6〜8、各約20星）：守り、回復とシールド、召喚、属性の反応、支援（味方）、夢の圧・報酬など。全体の能力値はここに集め、2割の枠に収める。
- **刻印**：各旅人に2つ→**8〜10**。外縁と記憶の領域の奥に置き、PoE のキーストーンのように「大きな利点と、はっきりした代償」を持たせる（例：仕掛けの値が2倍、ただし記憶の冴えが無効）。代償つきの刻印は1つだけ選べる、の決まりは残す。

小さな星の中身（全体の能力値にならないもの）：
- その記憶のダメージ +X%（既存の「記憶の冴え」）
- その記憶の加速（既存の「記憶加速」）
- **新**：その記憶の仕掛けの値 +X%（星団の仕掛けを強める）
- **新**：その記憶の仕掛けの確率・対象数・効果時間（仕掛けごとに意味のある1つ）
- 星団のテーマに合う既存の固有効果を少し伸ばす

## 4. 作り方（データの持ち方）

- 星は手書きの C# の羅列ではなく、**星団の型（テンプレート）＋旅人ごとの設定表**から生成する。表は `src/SodRpg.Core/Game/StarClusters/*.cs`（旅人ごと1ファイル）。
- 星の id は「旅人.領域.星団.番号」で固定し、表を直しても既存の振りが別の星へずれないようにする。保存の互換：v1.30 の星の id はそのまま残す（幹・核・橋）。
- 配置は HeroTreeLayout が星団の型から計算する（星団は扇形・輪形の小さな塊。重ならないことを試験する）。
- 通信：Build は「有効な効果の合計」を送るので星の数が増えても大きくならないことを確かめる（必要なら符号化を見直す）。
- 画面：700星でも重くならないように、線は1回だけ計算して画面外を描かない、名前は拡大したときだけ、検索（名前で光らせる）を付ける。

## 5. 進め方（並列）

1. **調査と星団の設計**（Claude＋Sonnet の調査）：9人それぞれ、アイデンティティ・旅人の記憶・旅人固有の星座と、コミュニティで強いとされる戦い方を確認し、記憶ごとの星団テーマ4つと中心の星（仕掛け）を表にする（`docs/specs/v1.31-clusters-<旅人>.md`）。別の見方でレビューしてから実装へ渡す。
2. **仕組み**（GPT 6.1 Sol）：星団の型・生成・配置・接続の判定・選択の星・新しい小さな星の効果（仕掛けの強化）・保存の互換・試験。
3. **重い本体連動**（GPT 6 Astra）：刻印8〜10×9人の新しいふるまい、新しい仕掛けの効果。
4. **データ入力**（GLM）：設計表を小分けにして星団ファイルへ入力し、表と生成結果を自動照合。
5. **画面**（Claude）：大きな木の描画の軽さ、検索、星団の名前、凡例。実機で確認。
6. 最後にバランス（BalanceSim と夢の圧の係数）を見直す。ポイントが倍になる分、夢の圧の「振った星の数」の係数を合わせる。

## 6. 完了の条件

- 9人すべてで星が700以上、全体の能力値だけの星が2割以下（試験で数える）。
- すべての星の効果が Core の試験で確かめられている（説明文と実際の値が一致）。
- 未実装・仮置きの星が0。
- 実機で星図を開き、全体表示・拡大・振る・外す・刻印の選択ができ、重くない（perf の計測で確認）。
