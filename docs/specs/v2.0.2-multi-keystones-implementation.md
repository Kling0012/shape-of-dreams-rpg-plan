# 検証メモ（実装時の内部メモ。設計は v2.0.2-multi-keystones.md を参照）

実装の対応表。設計の各行がどこに入るか。

| 設計 | 実装 |
| --- | --- |
| 枠の閾値（200/400）を1つの定数表に | `StarProgression.KeystoneSlots`（`UnlockLevels = { 200, 400 }`、`CountFor`/`NextUnlockLevel`/`Max = 3`） |
| HeroState の枠 | `HeroState.Keystones`（前詰めの3枠）。`HeroState.Keystone` は1つ目（Keystones[0]）のまま残す |
| 選ぶ・外す | `Rules.SetKeystone`（最初の空き枠へ追加。null で全て外す）と `Rules.RemoveKeystone`（1つだけ外す）。重複は `RuleMessages.KeystoneDuplicate`、枠超過は `KeystoneSlotsFull` で拒否 |
| 条件と費用は各刻印のまま | `EffectiveAllocationValidation.KeystoneUnlocked` を各枠の刻印ごとに適用。費用は `KeystoneDefinition.Cost` を各枠で加算（`SpentPoints`・`Build.ComputeTree`・`HostBuildValidation.TryValidateAllocation`） |
| C15 の承認（2つ目・3つ目も同じ） | `EffectiveAllocationValidation.Preview`/`Commit` が枠単位で機能判定・払い戻しを作る。候補の有効性は「その刻印を外した状態」と比較 |
| 枠が減った場合 | `AuthoredStarMigration.Apply` の最後で `KeystoneSlotCount` まで後ろの枠から外し、費用を払い戻す（保存の読み込み時に通る経路） |
| 保存 | `keystone`（1つ目）＋任意キー `keystones`（2つ目以降。無い場合は書かないのと同じ扱い）。版は上げない |
| 通信 | `Build.Encode`/`Decode` の `k:` に最大3レコード。`HostBuildValidation.Encode` は `K:`（全刻印）と `S:`（星のレベル）を送り、ホストは `TryValidateAllocation` で枠数（`keystone-slots`）を検証。`Protocol.Version` を 13→14 |
| 画面 | `StarMapPresentation.KeystoneSlotStatus`（「刻印 n/枠数」）と `NextSlotText`（「次の枠は星のレベル200で開きます。」）、`KeystoneRequirement` に枠の文を追加。`DreamforgeUi.DrawKeystoneBar` が帯に表示し、選択済みは右クリックで外す |
