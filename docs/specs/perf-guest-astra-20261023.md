# ゲストPCの軽量化記録（2026-10-23）

対象は `perf/guest-astra-20261023`。開始コミットは `9b5e7411`。
協力プレイのゲスト側でも実行する処理について、反射による読み取りと一時的なメモリ確保を減らした。
ゲームはこの環境で起動できないため、実機の負荷とプレイ結果は未確認。

## RPC受信の読み取り

コミット: `2c7b142`（軽量化（ゲスト）: RPC受信の反射読み取りを省く）

`NativeCustomRpcDispatchPerf` の辞書と `wrappedAction` の読み取りを、`FieldInfo.GetValue` から起動時にコンパイルするデリゲートに置き換えた。
辞書やハンドラの値は受信のたびに読み、値そのものはキャッシュしない。

変更前の結果を保つため、次の条件と処理を維持した。

- クライアント用とサーバ用の辞書を選ぶ条件は同じ。
- JSONの復元、ハンドラの順序、例外の記録と後続処理は変更していない。
- ハンドラを呼ぶ直前に現在のデリゲートを読む。処理中の登録解除も従来どおり列挙に反映される。
- 読み取り処理の構築に失敗した場合は、既存の警告処理を通してこのパッチだけを外す。
- 既存の `DreamforgeConfig.nativeCustomRpcDispatch`（既定は有効）で無効にできる。
- 送信内容・送信頻度・通信形式は変更していない。相手側の変更は不要。

受信1件につき辞書の反射読み取り1回、ハンドラ1件につき反射読み取り2回を省く。
CPU負荷の低下が見込まれるが、効果の大きさは推定であり、実測値はない。
起動時には3個の読み取り用デリゲートを生成する。

既存テストの不正なハンドラを注入する箇所だけを、新しい読み取り方法に合わせた。期待値とテスト件数は変えていない。
同名の別型をキャッシュ成立後に登録した場合の既存の制約も変更していない。

## 霜の演出回収

コミット: `9304386`（軽量化（ゲスト）: 霜の演出回収で構造体の確保を省く）

`FrostFxLifetimePatch.Release` が本体の管理リストを走査する際の読み取りを変更した。
本体の `EffectAutoDestroy.Entry` は構造体で、従来の `IList[index]` は走査した各要素をボックス化していた。
リストの型付きインデクサと `gameObject` フィールドを読むデリゲートを起動時に作り、このボックス化と反射読み取りを省いた。

変更前の結果を保つため、次の条件と処理を維持した。

- 回収のたびに現在の管理リストを取得する。各要素もその時点のリストから読む。
- 末尾からの走査、`ReferenceEquals` による一致判定、本体の `DestroyEntry` 呼び出しを保った。
- 本体による削除や末尾要素との入れ替え後も、従来と同じ順序で次の添字へ進む。
- 回収条件、監視間隔、寿命上限、イベント購読、粒子の停止処理は変更していない。
- 型やメソッドが合わない場合、またはデリゲートの生成に失敗した場合は、既存の無効化処理で警告を1回出す。MOD全体は止めない。
- 既存の本体パッチ内の読み取りだけを変更した。新しい本体パッチは追加していない。

回収1回でN要素を走査する場合、N回のボックス化とN+1回の反射読み取りを省く。
霜が多数の敵に付着し、他の演出も多い場面でCPUとGCの負荷低下が見込まれる。効果は推定であり、実機での時間や確保量は未測定。
走査量は引き続きO(N)。起動時には2個の読み取り用デリゲートを生成する。

既存のテスト用 `EffectAutoDestroyEntry` をクラスから構造体へ替え、本体の値型を読む経路で既存テストを実行した。新しいテストやテストファイルは追加していない。
