# v1.31 authored integration contract

Step1 connects authored definitions to allocation, Build transport, mutual content admission and host runtime. This document is the generator contract; it does not claim that the ten content manifests have already been generated or registered as shipped content.

## One production registration API

Call `StarClusters.RegisterAuthored(heroKey, definitions)` once with the complete authored definition set for that hero. It atomically validates and publishes the merged tree, layout and C15 allocation engine; returns `AuthoredStarRegistry`, whose `TreeFor(heroKey)` is the published tree. Existing baseline nodes remain unless explicitly replaced. Do not separately mutate `Content`, install an alternate tree, or register a second validation convention. Empty definitions restore that hero's baseline; production generators should not clear a registered tree between purchases.

Registration checks ownership, graph references, choices, scoped targets, pair endpoints, executable payloads and producer bounds before publication. Content and cap registry identities are cached, invalidated on mutation and used by both peers. Profile purchases use `Rules.AddTalentRank`, choices use the same method with an explicit option index, and keys use `Rules.SetKeystone`. Allocation dictionaries are persisted state, not a generator purchase API.

Minimal complete definitions, using a verified identity source and a movement *recipient*:

```csharp
const string hero = "Hero_Vesper";
const string root = "outer.generated.s1", effect = "outer.generated.n1";
var source = MemorySelector.Parse("St_D_Resolve");
var receiver = MemorySelector.Parse("@M(St_M_Charge)");
StarClusters.RegisterAuthored(hero, new[] {
    new AuthoredStarDef {
        HeroKey = hero, LocalStarId = root, ClusterId = "outer.generated",
        Region = ClusterRegion.Outer, AnchorId = root, Shape = ClusterShape.Fan,
        Edges = new[] { new AuthoredStarEdge(root, effect) },
        Effect = new ClusterStarDef {
            Kind = ClusterStarKind.Stat, Stat = Stat.Armor, Amount = 1,
            Name = new Txt("入口", "Entry"), MaxRank = 1, RankCost = 1
        }
    },
    new AuthoredStarDef {
        HeroKey = hero, LocalStarId = effect, ClusterId = "outer.generated",
        Region = ClusterRegion.Outer, AnchorId = root, Shape = ClusterShape.Fan,
        RequiredStarIds = new[] { root },
        MemoryOwnership = new MemoryOwnership {
            TargetMemory = "St_M_Charge", SourceMemories = new[] { "St_D_Resolve" }
        },
        Effect = new ClusterStarDef {
            Kind = ClusterStarKind.Notable, Name = new Txt("受信", "Receiver"),
            MaxRank = 1, RankCost = 1
        },
        Mechanism = new AuthoredMechanismSpec {
            Kind = AuthoredMechanismKind.DirectedRecharge, ChannelId = effect,
            Source = source, Trigger = MemoryEventKind.ConfirmedUse,
            Budget = AttributionBudget.PerActivation,
            Recharge = new DirectedRechargeChannel(effect, source,
                MemoryEventKind.ConfirmedUse, receiver, new[] { 500 }, everyN: 2)
        }
    }
});
// After legal, funded purchases through Rules:
// Build transported = Build.Decode(Build.Compute(profile, hero, dailyId).Encode());
```

`ChannelId` is a stable authored effect identity, not a random runtime identifier. IDs are hero-qualified by `AuthoredStarKey`; expand shared outer content separately for each hero without renaming its saved local IDs.

| `stars` | one saved node per `AuthoredStarDef`; options are not extra nodes |

| `cluster`, `shape` | `ClusterId`, per-star `ClusterShape.Fan/Ring/Chain`; a cluster may mix shapes (compound geometry: consecutive same-shape runs are placed as rigid segments), with `StarClusterDef.Shape` being its entry star's segment |
| `anchor` | `AnchorId`; retain null where authored edges provide the access path |
| `edges` | explicit `AuthoredStarEdge(thisId, otherId)`; deduplicate undirected edges |

| `gimmick` | concrete `AuthoredMechanismSpec` or retained `GimmickDef`, according to the effect table below |
| `power` | existing typed `Power` plus its actual value; retain existing key powers such as ShadowStep |
| `stat` | existing `Stat` and amount, not a new string-dispatched runtime |
| `options` | exactly two `ClusterStarDef.Options`; `RequiresExplicitSelection = true`, one saved option for every rank, no silent default |
| `keystone` | `KeystoneDefinition` on definition and effect, compiled from both sides; prose-only rows require explicit generator translation |
| `mechanisms` | `MechanismIds` provenance; tags never substitute for an executable payload |
| `maxRank`, `rankCost` | effect `MaxRank`, `RankCost`; preserve original saved costs/ranks for retained nodes |
| `nameJa`, `nameEn` | `Txt` effect name; descriptions include actual mechanisms and both key sides |
| `notes` | `Notes`; translate behavioral clauses into typed fields as well, never runtime prose parsing |

Retained rows set `RetainedLegacy = true`. Migration records are not a replacement graph: their missing graph/rank/cost data comes from the original node, not invented defaults. Key refunds and point totals use `KeystoneDefinition.Cost`, falling back to the existing cost only for untyped legacy keys.

Outer placement orders dependent groups before their dependents. A root with an explicit external authored edge receives no invented nearest-trunk edge. Missing anchors and cycles reject registration. Outer ownership follows the real entrance: a same-hero native route star (the per-hero outer clusters attach to their route terminus), a star of this hero's authored memory region, the cluster's own effectful Stat root (`outer.<slug>.s1`), or a registered outer anchor stat; `NormalizeAuthored` inherits the cluster entry anchor, so an outer star with no resolvable entrance is ownerless and a foreign-hero anchor rejects registration. `ReceiverOnlyBridge = true` allows an explicitly owned receiver extra at an existing real bridge anchor; it creates no fake pair.

### Modifier and channel metadata

A 0.5% receiver boost is `new ScopedModifierDef { ScopeKind = ScopeKind.Receiver, ScopeMemory = "St_M_Charge", TargetEffectIds = new[] { effect }, Amount = ModifierUnits.FromPercent(.5m) }`. Native memory damage/haste use `NativeMemoryModifierDef { Memory, Kind, Value, CapProfileId }`; retain the appropriate declared cap profile.

Equivalent additive rows use `EffectChannelDef` with **all** identity fields: `OwnerId`, `SourceMemory`, `ReceiverMemory`, `ChannelId`, `EquipmentRequirements`, `PairSuccessId`, `ActivationBudget`, `ClockPolicy`, `ScopeKind`. Owner is `self`; canonical clock policy is `channel`. A notification channel and a per-activation channel are not equivalent. Independent legacy stars do not gain a shared channel identity automatically. Unsupported identities or clock policies reject instead of silently collapsing.

## Executable effect mapping

| Manifest effect | Typed payload / semantics |
|---|---|
| Element, ElementEdge, Echo, Burst, Sap, Wound, Shield, Rampart, Heal, PackMend, Expose, Ricochet, Crescendo, Daze | `Kind = Gimmick`, concrete `GimmickDef`, exact source/trigger/budget; existing real native effect handlers consume the result |
| Primed | `Kind = MemoryPrimed`, `MemoryPrimedDefinition`; source-specific successful-next-main-attack ledger, not a global stat |
| RelayWindow | `Kind = RelayWindow`, `RelayWindowDefinition`; actual relay source and named target Q, not all Q/R damage |
| Recharge | directed channel with the manifest's explicit target; retained bridge base becomes `BridgePayloadKind.Recharge` |
| RechargeTarget | `Kind = DirectedRecharge`, exact recipient selector, source, trigger and cadence |
| RechargeOther | directed channel, `@OTHER`, excluding triggering source, identity, movement and ultimate categories |
| ReceiverRecharge | directed channel with the canonical condition corresponding to that row's Arg, not generic recharge inferred from Arg alone |
| AlliedWard | `AlliedWardDefinition`, allied-traveler recipients; preserve basis, pool and owner inclusion |
| SummonWard | `AlliedWardDefinition`, owned-summon recipients; preserve recipient HP basis when specified |
| PressureDividend | `PressureDividendChannel`, verified native CoinExplosion/Shout source, per-kill quota and pressure provenance |
| Calm source filter | `StunSourceFilter` grant only on selected `h.cetus.key2`; actual native successful Q/R stun provenance |
| Sacrifice conversion | concrete `SacrificeShield` grant plus matching `SacrificeShield` payload kind on selected `h.aurena.key2`; verified native HP-payment callsite plus matching downside. A payload-kind flag alone does not install an effect |

Percent-valued typed constructors use hundredths: 5% is 500 units; `ValuesByRank = new[] { 3000, 4000, 5000 }` represents 30/40/50%. `GimmickDef.Value` remains a decimal percentage. Seconds/metres are absolute values in the shared C07 payload, never mislabelled as percent units.

`GimmickDef` keeps the ordinary/profile-clamped baseline and exact pre-final-cap metadata: `UncappedValue`, `UncappedDurationUnits`, `UncappedRadiusUnits`, `UncappedExtraTargets`, `UncappedChanceUnits`. Runtime-only `EffectiveValue`, `EffectiveChanceProbabilityUnits`, effective seconds/radius/count are derived results, not a second authored input. Typed specs carry `UncappedValueUnits`, `UncappedProbabilityUnits`, `UncappedDurationSeconds`, `UncappedRadiusMetres`, `UncappedTargetCount`. Do not discard these before key downsides.

### Trigger, budget and manifest extras

| Input | Concrete representation |
|---|---|
| `OnUse` | confirmed native use / `ConfirmedUse`, not cast-start or canceled cast |
| `OnHit`, `OnKill`, `OnCrit` | corresponding admitted native notification; independent budget below |
| `OnBasicAttack` identity override | `OwnedBasicAttackFired`; authentic owner main attack, empty native source, and actual live owned summon predicate where required |
| `once` | `Once = true`; one accepted effect per activation |
| `everyN` | one channel-owned counter, `EveryN`; do not multiply outer and inner cadence |
| `valuesByRank` | `ValuesByRank` exact unit array, selected by real paid rank |
| `triggerByIdentity` | ordinal `Dictionary<string, MemoryEventKind>`; preserve each identity branch |
| `replaces` | `Replaces` explicit authored ID array; selected replacement suppresses only those predecessor effects |
| `condition` | `Condition = BridgeSuccess/BridgeMark/BridgeWindow`, resolved real `PairId` |
| `basis` | `WardAmountBasis.CasterMaxOffense/RecipientMaxHP` |
| `pool` | `ModShieldPoolKind.Ordinary/Allied/Rampart` |

Budgets are `PerActivation`, `PerActivationVictim`, `PerKill`, `PerOwnedBasicAttack`; quota identity includes owner, equipment epoch and logical channel. Victim quotas count admitted targets from that cast, not every projectile. Per-hit notifications do not invent an unsupported PerHit enum; seconds gates are not activation quotas. Generated damage, gem/elemental/reaction origins cannot feedback into ordinary native notification channels. Equal Build retransmission preserves counters; actual equipment/key/channel changes revoke the relevant pending work and state.

Examples requiring explicit extras:

* Vesper vessel: rank array 30/40/50, receiver `@M(St_M_Charge)`.
* Nachia movement receivers: HeartOfThePack hit branch versus CircleOfLife owned-basic-fired branch, every four; the key's every-two applies only to `OwnedBasicAttack`, not identity hits.
* Cetus insight: real bridge mark, once, rank array 15/25/35.
* Bismuth renewal: retained five ranks remain 1/2/3/4/5; do not apply the three-rank mark limit to direct receiver base.
* Yubar ward: recipient max HP and ordinary pool remain explicit.

A retained bridge extra resolves `PairCombos.ForBridge(bridgeAnchor).Id`; ownership comes from the registered pair's `HeroKey`. It requires an explicit typed base definition and actual allocated endpoint ranks. A newly authored pair has exactly two distinct, owned route endpoints and rank requirements. Opening and payoff selectors/triggers, mark/window/direct-receiver gate, activation quota and extra payoffs are distinct fields. A generic success flag is not a replacement for this predicate chain.

## Selectors and verified native categories

`MemorySelector.Parse` accepts exact memories, `@ID`, `@Q`, `@R`, `@M`, filters such as `@Q(St_Q_EtherealInfluence|St_Q_SuperNova)`, and unions such as `@Q|@R`. Null source means all admitted nonmovement sources. Deprecated `equippedQ`, `Q*` and `@ALLSRC` are not authoring syntax.

Q/R mean **actual equipped physical slots**, not the `St_Q_`/`St_R_` spelling. Readonly native metadata and native swap code show both Normal and Ultimate memories can occupy Q/W/E/R; only identity/movement are fixed. `VerifiedMechanismSlots` stores explicit ownership/category facts and feasible slots. Unknown, foreign and unknown-hero memories gain no hypothetical positions. Its semantic fingerprint participates in negotiation. Actual equipment wins over projection.

`@OTHER` includes actual Normal memories only, excluding the triggering memory, identity, movement and Ultimate. Movement is a recipient or native movement event, never an ordinary C01 sender. The sole named C07 movement-event exception is **`h.husk.key2`**, the existing ShadowStep key; no alias for the old specification typo.

## Keystone compiler: all field families

`AuthoredKeystoneCompiler.Compile(id, requiredMemories, upside, downside, prerequisites, cost, payloads)` produces one selected key. Both sides have to bind simultaneously. Each `AuthoredKeystoneSpec` has explicit `Layer`, `Field`, `Scope`, exactly one operation (`Percent`, `To`, `Delta`, `Disable`, `Grant`), optional `From` only with `To`, optional `Maximum` only with `Delta`. `WoundLifetimePercent` couples total and lifetime into one Wound operation.

```csharp
var key = AuthoredKeystoneCompiler.Compile("generated.echo.key",
    new[] { "St_Q_CruelSun" },
    new[] { new AuthoredKeystoneSpec {
        Percent = 60m, Scope = new KeystoneScope(
            targetEffectSet: new[] { GimmickEffect.Echo, GimmickEffect.Burst })
    } },
    new[] { new AuthoredKeystoneSpec {
        Layer = KeystoneLayer.NativeDamage, Percent = -25m,
        Scope = new KeystoneScope(targetMemorySet: new[] { "St_Q_CruelSun" })
    } });
```

Register it as a `ClusterStarKind.Keystone`, assign the same `KeystoneDefinition` to definition/effect, use the actual cost and prerequisite graph, and purchase with `Rules.SetKeystone`.

## Ordering, caps and lifecycle

C03 ordering is authored base × ranks → equivalent additive merge → ordinary GB once → ordinary parameter/profile ceilings → C07 upside and downside → native effect caps once → float conversion at the native API. Negative key transforms must see pre-final-cap value/probability/time/radius/count. Native count intermediates are wide; cast to final int only after both sides and final caps.

* C06 ordinary/rampart/allied pools cap at 15/10/3% recipient HP, replace by maximum remaining, and are independent. A sacrifice award's 10% creation cap does not reduce an existing 13% ordinary pool. Bridge ordinary shields preserve their original `DurationCapSeconds`; there is no blanket eight-second bridge cap.
* C09 new source preparations: base 5s, final cap 10s, strongest one consumed by successful own main hit. A rearming hit cannot consume its newly created slot. Retained legacy global Primed keeps its older lifetime contract; key/equipment changes clear only that cached preparation, not unrelated next-basic powers. Equal retransmits preserve it.
* C10 native named normal Q: base 4s, ordinary cap 8s, quiet-window cap 16s, magnitude cap 40%.
* C12 normal wards: base 10m/4s/3 targets, cap 15m/8s/4 heroes or 5 summons. Summon recipient-HP variant preserves 3s/1 target and its explicit lifetime contract. Do not synchronize fixed manifest lifetimes to an unspecified native window.
* Crescendo: actual source cooldown determines base `max(8s, 1.5 × current native max cooldown)`; initial and deferred legacy, typed and bridge dispatch pass that context and cap at four times the contextual base.
* C13: actual native room spawn, applied HP multiplier at least 1.25, verified owner/source kill, one host roll per enemy lifetime/owner, probability cap 40%, authenticated unsecured-shard receipt with deduplication.
* C08/C11: removal, missing equipment or failed native-hook verification disables both key halves and removes pending grants/pools atomically. Native HP payment remains native when conversion is disabled.

## C15 transactions and shared admission

The shared effective-allocation engine evaluates real final fields, scoped targets, channels, conditions and verified attainable equipment positions. Permanent capped, disabled or dominated paid allocations cannot survive a change silently. `Preview` captures profile/allocation, registry/cap identities, engine and exact refund rows; `Commit` requires precisely approved IDs and rejects stale captured plans. Point refunds use original paid ranks × original cost. UI cancel has no mutation; approval performs the entire intended relic/star/choice/key change and refund atomically. Run, trade reservation, ownership and edit gates still apply.

Each Build takes one graph-reachability snapshot while retaining individual authored prerequisite checks. C15 reuses exact full-rank captures and indexes comparable channels; it does not skip marginal validation for independent recharge rows. Composition copies mutable payloads directly, compares canonical signatures only for channels that actually merge, and visits only scoped modifier rows. Removing a bridge endpoint also removes its currently unavailable base and conditioned extras from the emitted Build; malformed transported orphan conditions still reject, and a legal permanent allocation change still needs the C15 refund transaction.

Native skill unequip/re-equip is a **temporary availability predicate**, not a permanent paid-allocation rewrite: advance equipment epoch, disable affected effects and both key sides, clear related counters/pending/pools, retain paid ranks, and restore eligible effects on re-equip. Full cooldown/full HP are likewise temporary. Do not silently refund native equipment changes after they happen.

Mutual Hello accepts protocol plus the full content identity. Host build admission and client build/Applied application require the currently accepted identity; authored/cap/category mutation revokes admission and Hello renegotiates. OnBuild allocation validation remains the separate host-validation slice; reconnect run-choice sequencing remains unchanged.

## Protocol 13 and fixed envelope

Protocol changed **once: 12 → 13**. Existing sections remain; `f` carries fractional parameters, `n` native cap profiles, `v` fine values, `j` the complete eleven-field channel context, `m` typed mechanism binary version 1, `e` real allocated endpoint ranks, `k` selected typed keystone, and `r` retained pre-key/finer ordinary raw metadata. `u` remains conditional powers, not raw metadata.

Legacy `r` has a strict bitmask and bounded binary representation (maximum 49 bytes / 68 base64 characters per payload); duplicate, unknown, contradictory, negative and trailing data reject the entire Build. Keyless raw rows are limited to meaningful finer coefficients. Unknown/malformed typed payloads fail closed.

The unchanged observed serialized envelope is **195820 ASCII bytes**; the old 131072 figure is not this wire's actual prior envelope. Effective channels are bounded at 512, including nested bridge payoffs, intrinsic marks and key grants. Registration computes a conservative legal-300-point maximum, including at most one selected key and its grants, and rejects producers that could exceed the existing envelope. No chunk-size expansion or silent dropping of paid effects.
