# v1.13.1 仕様：取引と同期の不具合修正（issue #5・#6・#7）

担当：方針は Claude、実装は GPT（OMP 経由）、試験と確認は Claude。

## #5 取引の返事より先に確保・潜行すると、通貨だけ減る

方針：**支払いが確定したら、その後の状態に関係なく対価は必ず渡す**。あわせて、返事待ちの間は確保・潜行を止める。

1. 返事待ちの間は確保・潜行・契約を選べないようにする。
   - `ClientSession.Secure` / `Delve` の先頭で `_trades.PendingCount > 0` なら何もせず、理由（「取引の応答を待っています。」/ "Waiting for the trade to complete."）を返す（今の戻り値が void なら string を返すようにし、画面で `SetStatus` に出す）。
   - 画面（`DreamforgeUi.DrawSecurePrompt`）の「確保する」「深く潜る」「契約」ボタンと、確保・潜行のキー操作も、返事待ちの間は押せないようにする（GUI.enabled = false）。
2. 成功の返事を受けたら、状態に関係なく対価を渡す（本体のラン終了など、ボタンを止めても状態が変わる場合への備え）。
   - ダスト交換：確保地点が終わっていても、欠片を保管庫側の素材に足す。`Rules` に「支払い済みのダストを欠片に換える」関数を足し、`AwaitingChoice` を条件にしない。
   - 夢の商人：出来事が終わっていても、遺物を渡す。遠征中なら鞄（未確保）、遠征が終わっていれば保管庫へ。`Rules` に「支払い済みの商人の遺物を渡す」関数を足し、`OfferedEvent` を条件にしない。
3. 同じ取引の返事が2回届いても、付与は1回だけ（今の `TradeLedger` の token による一度きりの処理を保つ）。

## #6 分解が失敗しても遺物が消える

方針：**遺物は、成功の返事が来たときに初めて鞄から取り除く**。

1. `ClientSession.SalvageUnsecured`：鞄から取り除かずに取引を送り、遺物の Uid を「予約中」にする（`TradeLedger` の保留中の取引から分かればよい）。
   - 送れなかった（未接続など）場合は、予約を解除して遺物はそのまま。エラー文を返す。
2. 成功の返事：その遺物を鞄から取り除く（すでに無ければ何もしない）。
3. 失敗の返事：予約を解除するだけ（遺物は残る）。`TradeLedger.Complete` は失敗のときも取引の内容（種類・Uid）を返すようにし、呼び出し側で予約を解除できるようにする。
4. 予約中の遺物は、分解・装着・合成など別の操作の対象にしない（画面の分解ボタンも押せないようにする）。
5. 返事が来ないまま 30 秒たった予約は解除する（切断などで返事が失われた場合。まれに二重取りになりうるが、遺物を失うより安全と判断）。

## #7 ホストだけMODを読み直すと、参加者の能力補正が戻らない

方針：**参加者は、確認済みでも定期的に Build を送り直し、ホストは同じ内容なら付け直さずに確認だけ返す**。

1. `ClientSession.SendBuildIfNeeded`：`HostConfirmed` でも 30 秒ごとに今の Build を送り直す（今は 20 秒ごとに送らずに延長しているのを、実際に送るように変える）。
2. ホスト（`HostAuthority`）：受け取った Build の文字列が、そのヒーローに今付けている物と同じなら、補正や固有効果の状態を作り直さず、確認（Applied）の返事だけを送る。違う、または持っていなければ、今まで通り付ける。
3. これで、ホストを読み直しても 30 秒以内に全員の補正が戻る。同じ Build を何度受け取っても StatBonus は重ならない（今の `Apply` は付け直す前に外しているが、同じ内容なら触らない）。
