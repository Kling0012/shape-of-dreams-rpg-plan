# v1.31 multiplayer fixes (host authority, batch B)

Source reviews: `docs/reviews/mp-host.md` findings 3, 4, 5, 7, 8, 9, 10, 11 and `docs/reviews/mp-sync.md` finding 5.
Decision logic lives in `src/SodRpg.Core/Game/MpHostRules.cs`; Mod wiring is in the new partial
`src/SodRpg.Mod/HostAuthority.MpFixes.cs` plus small edits to the existing partials. Tests:
`tests/SodRpg.Core.Tests/MpHostFixesV131Tests.cs`.

## host #3 - stale pooled shield handle (confirmed)
- Root cause: `_powerShields` stored the raw `Se_GenericShield_OneShot`; the class is `reuseInRoom`, so an expired
  handle can be recycled for another hero's shield. `PowerShield` then refreshed/destroyed the recycled object, or
  destroyed the new shield when `GiveShield` returned the cached object.
- Fix: `PowerShieldLedger` stores handle plus the exact inner `ShieldEffect` of the activation. An entry is live only
  when the handle is active and still holds that effect (same identity rule as `NativeModShieldAdapter`). Recycled or
  stale entries are forgotten, never refreshed or destroyed. `PowerShield` calls `PowerShields.Offer`.
- Tests: cross-hero recycle, same-handle reuse with equal amount, strongest-only keep/replace unchanged.

## host #4 - shared depth counter suppresses teammate defenses (confirmed)
- Root cause: `OnNewPowerTaken` rejected on the global `_gimmickDamageDepth`, which another hero's queued power damage
  keeps positive while a death explosion hits a teammate.
- Fix: `ScopedDepth<Hero>` records which hero opened each generated scope (`EnterGenerated/ExitGenerated`, used at the
  power, gimmick, pair, memory-relay and reaction damage scopes). `OnNewPowerTaken` uses `GeneratedDepthFor(hero)` =
  global depth minus depth owned by other heroes, so a hero's own recursion is still suppressed while a teammate's
  genuine incoming hit is processed. The legacy global counter and all other guards are unchanged.
- Tests: A's scope suppresses A but not B; nesting and exit bookkeeping.

## host #5 - waypoint rules omit heroes without a Build (confirmed)
- Root cause: `SyncWaypointHeroes` enumerated `_runtimes`, summon multiplier and memory-cooldown rules lived only on
  the runtime.
- Fix: recipients come from `ActorManager.allHeroes` (`WaypointRoster.Diff`). Heal/shield/max-health receivers apply to
  every active hero. Heroes with no runtime also get a waypoint-only skill-use hook (memory cooldown) and a summon
  damage processor; both skip heroes that have a runtime so nothing is applied twice once a Build is accepted.
  Equipment powers still require a validated Build.
- Tests: roster diff (build-less hero added, inactive removed). Native hooks are Mod-only and not unit-testable.

## host #7 - MirageSkin survives cleanup (confirmed)
- Root cause: `AttachMirageSkin` discarded the effect; the native skin also adds max health directly, which destroying
  the skin does not undo.
- Fix: the skin is created with `customAmount` (so the native untracked health addition is skipped) and the equivalent
  health is a tracked `StatBonus`. `OwnedEffectRegistry` remembers only skins created here; `Unhook(MonsterRuntime)`
  destroys the owned skin and removes the bonus. Naturally occurring skins are never touched; re-attach releases the
  previous owned bonus first.
- Tests: registry releases owned effects only, isolates failures.

## host #8 - pact curses lost on reload (confirmed)
- Root cause: `_pactCurses` was cleared in `Detach` without destroying the curses, so a later `OnCurseClear` found
  nothing.
- Fix: `_pactCurses` is an `OwnedEffectRegistry`; `Detach` calls `ReleasePactCurses` (destroys every still-live owned
  curse, each isolated). Unrelated native curses are not touched. Decision: reload lifts owned pact curses rather than
  persisting a marker, since the mod unload cannot keep ownership state.
- Tests: release isolates failures; post-release clear is a no-op.

## host #9 - reload abandons power shields (confirmed)
- Root cause: `Detach` and zone clear cleared the ledger without destroying shields.
- Fix: `Detach` calls `ReleasePowerShields` (`PowerShieldLedger.DestroyAll`, identity-checked and failure-isolated).
  Zone clear now only `Prune`s dead entries (live shields keep their record, so same-power stacking cannot reappear).
- Tests: DestroyAll releases only live own activations, continues after a failure; Prune.

## host #10 - summon kills do not reach the owner (confirmed)
- Root cause: `RuntimeOf` took the nearest entity (the summon) and rejected non-heroes.
- Fix: `OwnerRuntimeOf` (via `ActorOwnership.ResolveHero`) resolves a summon to its owning hero; used by `OnDeath` and
  `OnApplyElemental` (same policy). The global death event fires once per kill, so the owner is processed once; the
  generated-damage guards are unchanged. `RuntimeOf` is left as is for its other callers.
- Tests: hero, summon-with-owner, orphan summon, monster, null.

## host #11 - serverActor support never credits bounties (confirmed)
- Root cause: bounty reports came only from the hero's own actor events; serverActor support is not in that chain.
- Fix: `CreditHealRestored` (health delta > 0, other allied hero) after TriumphSong, pair-heal ally and siphon-ally heals;
  `CreditShieldGranted` for accepted power shields (not the kept-existing/rejected path), reaction shields and
  accepted MOD shield awards. Decision in `SupportBountyCredit`. Hero-actor heals still report through the existing
  hooks, so no award is counted twice.
- Tests: overheal, self, negative, NaN, rejected shield, non-friendly target.

## sync #5 - host's Secure/Delve rejects remote Dream Omen (confirmed)
- Root cause: `OnPersonalDreamEvent` required the host's personal `run.AwaitingChoice`.
- Fix: removed that gate; `DreamOmenGate.Accept` validates run id, current generation, event id and per-player
  deduplication only.
- Tests: matching/mismatched run, generation, invalid event, dedupe, newer generation.
