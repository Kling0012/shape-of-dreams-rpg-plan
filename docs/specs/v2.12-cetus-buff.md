# v2.12 ケトゥスの強化（「下がれ！」を軸に、火力と耐久）

利用者の依頼（2026-10-09）：「ケトゥス 強化依頼」。背景の補足：ミストや空殻は、速くて強い攻撃とドレインでタンク以上の耐久が出せてしまうため、タンクのケトゥスは火力も耐久も弱く見える。
夢の圧の引き上げ（v2.11：敵HP最大×16.5・敵の数×5・与ダメージ×3.4）の後で、ケトゥスが耐えて倒しきれる水準にそろえる。

方針の追加（2026-10-09）：「下がれ！」を軸に、長く続く大きな障壁・大きなHP成長・強いHP回復で強くする。星図全体を見直し、「タンク」と名付けられていてもソロで戦える水準にする。星の依存関係と座標は変えない（別スレッドで調整中なので衝突を避ける）。数値原本 `tools/balance/stars.json` のセルだけを変え、`python tools/balance/gen_cs.py` で生成した。星のID・段数・費用・保存形式・Protocol は変えない。

## 1. 比較で見えた弱点

| 守りの仕掛け | 盾・回復・防壁は1〜3%の小粒 | 速く殴るミスト・空殻は命中・撃破ごとの回数で稼ぎ、装備のドレインも乗る |
| 能力値 | v1.31で防御系の能力値の星が仕掛けの強化に置き換わり、ケトゥス固有で残るのは外周の「深海の殻」「殻の厚み」だけ（HP＋2%・防御＋2） | 防御を能力値の星で補う手段がほぼない（装備のドレインで補うミスト・空殻との差） |

ミスト・空殻は1回ごとの回復量が小さくても、攻撃の回数で耐久を出せる。回数で勝てないケトゥスは、1回あたりの盾・回復と、技（スタン）で張り直す盾を厚くして差を埋める。

### 「下がれ！」を軸にした強化（第2弾）

「下がれ！」は味方と自分に盾を張る技で、星図の守りの星団（`back-off.c2`）と回復の星団（`back-off.c4`）が受け皿になる。ここを厚くして、ソロでも自分の盾とHPで耐えながら殴り続けられるようにした。

| 項目 | 旧 | 新 |
| --- | ---: | ---: |
| 守りの星団（c2）・回復の星団（c4）の強化星（各10個。仕掛けの値を伸ばす） | +1% | +1.5% |
| 同・障壁と効果の持続を伸ばす星（各2個） | +4% | **+10%** |
| 同・選択星「厚い氷の幕」「強まる氷盾」 | +3% | +4.5% |
| 「盾の恩返し」（撃破時に自分と近くの味方を回復、最大HPの%） | 2（第1弾で3） | **5** |
| 「巻き込みの防壁」（防壁、1回あたり） | 1（第1弾で1.5） | 2（上限） |
| 「氷盾の補強」（下がれ！の使用時に自分へ盾、最大HPの%） | 2 | **8** |
| 刻印「返礼の庇護」（下がれ！の盾・防壁の値） | +100% | **+150%** |
| 刻印「静かな氷壁」（全技の盾・防壁の値） | +80% | +100% |
| 同・伸びる能力値 | 与える障壁量 +0.5 | 与える障壁量 +0.5 と **最大HP（固定値）+5**（上限600、上限増分の星2つで最大100段。段の間隔9%と、深度0でゾーン4・深度1でゾーン3に上限へ届く設計目標は変えない） |

最大HPの固定値は、ヴェスパーの「傷を糧にする」（防御+1と最大HP+4、11%ごと）に合わせた形。

### ソロで戦えるかの確認

- ケトゥスの星図に、味方がいないと働かない星（味方への盾・共有の盾・召喚獣など）はない。味方に効く回復・盾は自分も対象で、ソロでも全額が自分に入る。
- 技（スタン）で張り直す盾（凪）、撃破ごとの回復、「下がれ！」自身の盾（自分は50%増し）、遠征中に伸びる最大HPで、ソロでも耐久を作れる。

## 3. 「下がれ！」のチャージ中の継続ダメージ（追加）

利用者の案（相性が良い）を実装した。星ではなく、「下がれ！」を装備している間の固有の動きとして入れてある。

| 項目 | 値 |
| --- | --- |
| 脈動の間隔 | 0.5秒（押してすぐ離す場合は何も出ない） |
| 1回の量 | 高い方の攻撃力・魔力の40%（星の消費による伸び率が掛かる。「割れる深海」などの仕掛け強化も掛かる） |
| 範囲 | ケトゥスを中心に半径4.5m、1回の脈動で最大8体 |
| 最長 | チャージ開始から2.5秒（終了通知が届かない場合の安全弁） |
| 全体の目安 | 2.5秒フルでも200%。振り抜きの最大（魔力の450%）の半分以下 |

- 開始は本体の詠唱開始通知、終了は詠唱完了と中断の通知。スタン・死亡・「下がれ！」を外した場合も止まる。
- 継続ダメージ属性の生成ダメージとして出すので、ここから反響・爆発などの仕掛けは連鎖しない。
- 実装: 時間管理と計算は `Mechanisms/BackOffChargeDot.cs`（単体テストあり）、本体との接続は `HostAuthority.BackOffCharge.cs`。接続は存在しない通知名があっても例外にせず、何も出さずに終わる。
- **実機未確認**: 本体の詠唱開始通知がチャージ（長押し）の始まりで発火するか、中断通知が存在するかは、このクラウド環境の本体DLLなしでは確かめられない。通知が合っていなければ何も出ないだけで、他の動きには影響しない。実機でチャージ中に周囲の敵が削れるか、振り抜きと二重に感じないかの確認が必要。
- 値を変えるときは `BackOffChargeRuntime` の定数を直す。星の仕掛けとして値や範囲を伸ばせるようにする案は、星図の構造に触れるので今回は見送った。

## 4. 変えないもの

- 星の依存関係・座標・費用・段数・ID。
- 他の旅人の値。夢の圧、装備、セット。
- 実行時の上限（盾は最大HPの15%まで、防壁は1回2%・合計10%、Echo/Burstは1000%など）。上限に当たった分は増えない。

## 5. 確認

- 計算とテストで確認した。チャージ中の継続ダメージは、時間管理と計算を単体テストで確認し、MOD側の接続は本体の代わりの模擬型でコンパイルを確認した。実機での手応え（ミスト・空殻との比較、敵が5倍に並んだときの耐久）は未確認。
- やりすぎの場合は `stars.json` のセルを戻し、`python tools/balance/gen_cs.py` で再生成するだけで戻せる。
- 内容の指紋が変わる。協力プレイでは全員が更新する。
