## 2. 見つけたAPI（ダンプの要点）

### イベント
Entity/Actor系（`EntityEvent_*` `ActorEvent_*`）は同期イベントでサーバー（ホスト）で発火。MODは既にホストで購読している。
`ClientEvent_*` / `Client*Event_*` は全ピアへRPC配信（ホスト自身も受け取る前提。要実機確認）。型は `SafeAction<…>`。

| 種別 | イベント | 引数の中身（使える項目） |
| --- | --- | --- |
| 命中 | `Entity.EntityEvent_OnAttackHit` / `OnAttackTaken` / `OnAttackMissed` / `OnAttackDodged` | `EventInfoAttackHit{actor,attacker,victim,isCrit,strength}` |
| 攻撃発射 | `Entity.EntityEvent_OnAttackFired(+BeforePrepare)` | `isCrit, isThisAttackFourthAttack, isNextAttackFourthAttack` |

### 加工用プロセッサ（`DataProcessorGroup<T,Actor,Entity>`、MODは takenDamageProcessor で実績あり）
`Actor.dealtDamageProcessor(DamageData)`、`dealtHealProcessor`、`dealtShieldProcessor`、`dealtCooldownReductionProcessor`、`Entity.takenHealProcessor/takenShieldProcessor`。
`DamageData`：`ApplyAmplification(x)`（倍率加算）、`ApplyStrength`、`AddFlatAmount`、`SetElemental`、`HasAttr(DamageAttribute.IsCrit…)`、`elemental`。

### 状態の参照
- `Entity.Status.hasStun / hasSlow / totalSlow / hasCold / fireStack / lightStack / darkStack / hasCrowdControlImmunity`、`Entity.HasElemental / GetElementalStack / GetElementalAmp`、`Entity.currentMana/maxMana/SetMana`。
- `Hero.Skill.GetSkill(Q/W/E/R/Movement)`（`SkillTrigger.level`、`skillType`、`type=Normal/Ultimate`）、`Hero.Skill.gems`（`IReadOnlyDictionary<GemLocation,Gem>`、`Gem.quality`(Int, %)、`qualityType`、`rarity`）、`maxGemCountQ…`。
- `AbilityTrigger.currentCharges / SetCharge / SetChargeAll / ApplyCooldownReduction(ByRatio) / ResetCooldown`。`SkillTrigger.Ult_OnKill* / Ult_PerDealt*` は静的な倍率（アルティメットは「時間以外の行動でCDを縮める」形）。
- 本体の属性ルール（RawData と synergy-review）：火＝DoT、冷気＝スロウ、光＝与光ダメ増・3スタックで確定クリティカル、闇＝与闇ダメ増・3スタック以上が薄明/深淵の条件。
- 本体のスタン付与源（Memory）：後退・氷河ストンプ・氷の爪・プレッシャーリリース・反重力・Essence の余震/静止/霜。スロウ付与：制御・出血。Essence「荒涼」は冷気/スロウ/バインド/スタンへの与ダメ+50%（足枷は同じ思想を遺物側で実現）。
- 複数チャージのMemoryは17種だが大半が回避（St_M_*）。→ チャージ系は回避系効果に寄るため今回は見送り（予備案）。

### 注意（実機未確認）
- `ClientHeroEvent_*` / `ClientEvent_*` はホストでも発火する前提（既に OnSkillUse で使用）。祭壇・通貨・Gem系もこの前提。最初の実機確認で `Player.log` に一行出して確かめる。
- 状態異常の付与者は `StatusEffect.info`（CastInfo）経由。`caster` がヒーローか要確認。
- 死亡イベント時点で victim の属性スタックが残っているかは未確認（収穫案のリスク）。

## 3. 提案：新・固有効果 12案

数値の見方：X は遺物の固有効果値（既存と同じく品質で変動する想定）。「ホスト/クライアント」はフックの発火側。難度は実装全体の見積もり。

### 1. 終曲（Finale）
- 効果：Q・W・E の3つを**異なるスロットで**8秒以内にすべて使うと、R（Ultimate）のクールダウンを現在の残りの X% 短縮する（10秒に1回）。
- 土台：Memory のスロット別運用＋Ultimate のチャージ設計（`SkillTrigger.Ult_*`、星「究極の悪意」）。
- フック：`Hero.ClientHeroEvent_OnSkillUse`（info.type が Q/W/E を記録）→ `Actor.ApplyCooldownReductionByRatio(hero.Skill.R, X/100)`。ホスト（既存の OnSkill に追記）。
- 新規性：Overload は「R・回避以外ならどれでも」魔力＋、EchoingDodge/Whirlwind は回避起点。**スロット3種の組み合わせ**と**R の充填**を絡めるのは既存になし。
- 難度：低。リスク：ratio API の挙動（残りに対する割合）要確認。X は 10〜25。

### 2. 会心の余韻（Critical Echo）
- 効果：基本攻撃がクリティカルで命中すると、Q/W/E のクールダウンを X/10 秒短縮（0.5秒に1回）。
- 土台：4発目確定クリティカルの Memory/Essence（牙・決意・エルの慈悲・サラマンダー）、光3スタックの確定会心、クリット率ステータス。
- フック：`Hero.EntityEvent_OnAttackHit`（`info.isCrit`）→ `ApplyCooldownReduction`。ホスト（既存の _onAttackHit に追記）。
- 新規性：既存はクリットを一切参照しない（ステ加算の CritChance のみ）。クリット率を上げる装備・星と相乗。
- 難度：低。リスク：クリット連発ビルドでCD過短縮 → 内部CDと上限。X は 2〜6。

### 3. 足枷（Fetters）
- 効果：スタン・スロウ・冷気のいずれかが乗った敵への与ダメージ +X%（Memory・基本攻撃とも）。
- 土台：本体に豊富なCC（上記スタン/スロウMemory、冷気）と Essence「荒涼」と同じ思想の重ね掛け。
- フック：`hero.dealtDamageProcessor.Add((ref DamageData d, Actor a, Entity t) => …)` で `t.Status.hasStun || hasSlow || hasCold` なら `d.ApplyAmplification(X/100)`。ホスト（takenDamageProcessor と同形で実績あり）。
- 新規性：既存の条件付きダメージは敵HP閾値（Executioner/OpeningStrike）。**敵の状態異常**で増減するのは新規。追加ダメージ生成ではなく本体と同じ「増幅」方式。
- 難度：低〜中。リスク：Remove 忘れ（Unhook必須）、荒涼との乗算の暴れ。X は 8〜20。

### 4. 止水（Still Water）
- 効果：自分の技で敵をスタンさせると、最大HPの X% の障壁（3秒、2秒に1回）。
- 土台：スタン付与Memory/Essence（後退・氷河ストンプ・反重力・余震・静止）。
- フック：`Entity.ClientEntityEvent_OnStatusEffectAdded`（敵側。`ActorManager.ClientEvent_OnEntityAdd` で Monster に購読）→ `effect.basicEffects` に StunEffect かつ `effect.info` の付与者が自分（要確認）→ `hero.GiveShield`。ホスト。
- 新規性：既存の障壁は時間（Barrier）、被弾（Aegis）、Ultimate（StarShield）起点。**自分が与えたCC**起点は新規。
- 難度：中。リスク：全モンスターへの購読/解除管理、付与者判定、スタン多用構成でのスパム（内部CD2秒）。X は 3〜8。

### 5. 散財の護り（Spender's Ward）
- 効果：ゴールドを 100 使うごとに、最大HPの X% の障壁（10秒、最大3回分まで加算）。
- 土台：ゴールド経済（ジョナスの商人、祭壇の費用、Chaos、Essence 購入）。
- フック：`DewPlayer.ClientEvent_OnSpendGold(int)`（ホストが各 DewPlayer に購読、`player.hero` から runtime を引く）→ `hero.GiveShield`。ホスト。
- 新規性：MOD は現在ゴールドを「支払うだけ」。**使った瞬間に報いる**効果は初。貯めるか使うかのトレードを生む。
- 難度：低〜中。リスク：MOD内取引（SpendGold 経由の欠片購入）でも発火する→意図通りか仕様化する。X は 4〜10。

### 6. 結晶共鳴（Crystal Resonance）
- 効果：装備中の Essence の品質合計 100% ごとに、攻撃力・魔力 +X%（最大8段）。
- 土台：Essence の品質（`Gem.quality`）、合成（`Gem.GetMergedQuality`、OnGemMergeUpgraded）、品質アップを狙うビルドの強化。
- フック：`hero.Skill.gems` を 0.25 秒の既存スキャン（ScanArea）で合算（または `HeroSkill.ClientHeroEvent_OnGemQualityChanged/OnGemEquip/OnGemUnequip` で再計算）→ `rt.DynBonus` へ反映。ホスト。
- 新規性：既存は Memory/Essence の中身を一切見ない。**合成・品質上げの行動に直接報いる**。
- 難度：中。リスク：品質の単位（%）と上限（Transcendent）を要確認、複数旅人。X は 1〜3。

### 7. 獲物の誇り（Prey's Pride）
- 効果：ハンターの追跡度（currentHuntLevel）1 につき、攻撃力・魔力 +X%（最大3）。
- 土台：ハンターの追跡（`ZoneManager.currentHuntLevel`、Hunter Level1〜3、Limbo の `hunterSpreadMultiplier`）。追われるほど強くなるリスク＆リターン。
- フック：`ZoneManager.ClientEvent_OnCurrentHuntLevelChanged`（既に ClientSession で購読）と `currentHuntLevel` を読んで DynBonus に反映。ホスト（ZoneManager は両側にある）。
- 新規性：MODの潜行/エリートは別機構。**ハンター追跡度そのものを能力値に結びつける**のは新規。
- 難度：低。リスク：追跡度が 0〜3 の整数か実機確認、追跡が無効なゾーンでは効果ゼロ（説明に明記）。X は 3〜6。

### 8. 溢れる命（Overflowing Life）
- 効果：回復が最大HPを超えた分（超過回復）の X% を、3秒の障壁に変える。
- 土台：本体の回復源（回復オーブ、Nachia/Aurena の味方回復、Essence 導き/再生）。Essence「導き」は特定Memoryの超過のみ→全体版として補う。
- フック：`Hero.EntityEvent_OnTakeHeal`（`EventInfoHeal.discardedAmount`）→ `hero.GiveShield(hero, discarded*X/100, 3f)`。ホスト。
- 新規性：既存の回復/障壁は別系統で、**回復の無駄を再利用**する発想はなし。Lifesteal/SoulSiphon と組むと満タン時の回復が障壁になる。
- 難度：低。リスク：障壁は回復ではないので自己ループはしないが、1回あたりの上限（最大HP10%）を設ける。X は 20〜50。

### 9. 祈願（Devotion）
- 効果：祭壇を使うたび、そのゾーンの間、攻撃力・魔力 +X%（最大5重）。
- 土台：祭壇（Luck・Paradox・Maw of Doom・Chaos など `Shrine_*` 約60種）。
- フック：`ActorManager.ClientEvent_OnActorAdd` で Shrine を購読 → `Shrine.ClientEvent_OnSuccessfulUse(Entity user)`（user が Hero）。Chaos だけなら `ClientEventManager.OnChaosUsed(DewPlayer)`。解除は `ZoneManager.ClientEvent_OnZoneLoaded`。ホスト。
- 新規性：v1.0 の依頼で祭壇行動は数えるが、**戦闘の強さに結びつける固有効果は未実装**。寄り道（探索）を促す。
- 難度：中。リスク：祭壇の購読/解除、`OnSuccessfulUse` の引数の信頼性、複数人時の使用者特定。X は 2〜5。

### 10. 見切り（Perfect Read）
- 効果：回避などの無敵で被弾を**実際に無効化した**とき、攻撃速度 +X%（3秒）。1.5秒に1回。
- 土台：回避（Movement）の無敵時間と、`DamageNegatedByImmunity`。
- フック：`Hero.EntityEvent_OnDamageNegatedByImmunity`（`effect` が Invulnerable か確認）→ DynBonus に時限バフ（既存の Momentum 型タイマーを流用）。ホスト。
- 新規性：既存の回避系3種（EchoingDodge/Whirlwind/Sprint）は**使った**瞬間に発動。これは**成功した**ときだけで、腕前に報いる。
- 難度：中。リスク：Invulnerable 以外の免疫（アンストッパブル等）の除外、多段ヒットの重複。X は 8〜20。

### 11. 飛び火（Wildfire）
- 効果：敵の火スタックが 3 以上のとき、火を付与するたびに X% で近くの敵1体へ火を1スタック移す（同一敵から2秒に1回）。
- 土台：火（DoT）。Essence「熱病」「太陽の眼」「エンバーテイル」と同じ「燃えている敵」の文脈。
- フック：`ClientEventManager.OnApplyElemental`（既に購読済み、`info.type == Fire`、`victim.Status.fireStack`）→ `DewPhysics.OverlapCircleAllEntities` で最寄りの敵 → `hero.ApplyElemental(Fire, other, 1)`。ホスト。
- 新規性：Ember は命中で火を付ける、Convergence は4属性揃いで爆発、Shatter は撃破で範囲ダメ。**属性スタックを他の敵へ伝播**するのは初（review の「爆砕＝属性スタックを広げる」案とも合致）。
- 難度：中。リスク：ApplyElemental が OnApplyElemental を再発火するため再入ガード必須（内部CD、1回あたりの上限）。X は 15〜35。

### 12. 明晰（Lucid Boon）
- 効果：有効な Evil の明晰夢 1 つにつき、攻撃力・魔力 +X%（最大6）。
- 土台：明晰夢（Good/Evil/Chaotic）と Limbo 深度（Evil の数＝深度）。難しくするほど遺物が応える。
- フック：`GameSettingsManager.activeLucidDreams`（`ClientEvent_OnActiveLucidDreamsChanged`）の各文字列を `DewResources` から `LucidDream` 型に解決し `type == Evil` を数える。ホスト。フォールバックは既に読んでいる `GameMod_Limbo.depth`。
- 新規性：Limbo はドロップ率の倍率にだけ使用。**戦闘能力へ直接反映**は新規。高難度ほど報われる。
- 難度：中。リスク：文字列→型の解決方法が未確認（失敗時は depth で代替）、ロビー設定のタイミング。X は 2〜4。

### 予備案（今回は見送り）
- 研鑽：Q/W/E/R の Memory レベル合計 1 につき記憶加速 +X（`SkillTrigger.level`、`ClientHeroEvent_OnSkillLevelChanged`）。結晶共鳴と同系統。低難度。
- 収穫：属性が乗った敵の撃破で、乗っていた属性の種類 1 につき Q/W/E のCDを X/10 秒短縮（OnDeath 時点でスタックが残っているか要確認、中リスク）。
- 予備弾：Memory詠唱でチャージを X% 返す（複数チャージは主に回避系のため重複気味、中難度）。

## 4. 優先度（私見）

1. 実装が軽く効果が分かりやすい：**会心の余韻（2）、足枷（3）、獲物の誇り（7）、溢れる命（8）**。
2. 本体の仕組みに深く乗る：**終曲（1）、飛び火（11）、結晶共鳴（6）、祈願（9）**。
3. 実機確認が必要：**止水（4）、見切り（10）、明晰（12）、散財の護り（5）**。

## 5. 実装メモ
