## Engine mismatch and canonical decisions

The current seven kinds are MemoryDamage, MemoryHaste, GimmickBoost, GimmickParam, Notable, Choice, Stat. `Amount`/Value are integers; star order generates numeric ID; Choice rank1; params memory-wide; graph is undirected reachability; Outer anchor must be a real Stat. These facts cannot express authored suffix IDs, rank3/5 migrated Choices, exact predecessor ownership, cross-memory receiver source, scoped/channel values or new effects by simply entering more rows.

Adopt [C01–C15](v1.31-new-mechanisms.md), in its dependency order. Each section defines fields, units, trigger/provenance, targets, caps, stacking/lifecycle, consumer-ID families, actual decompile hooks and acceptance cases. Local labels are aliases only; do not create duplicate recharge/ward enums or an assumed existing OnBasicAttack alias. Numeric wire units are hundredths of a percent; typed fields/protocol must distinguish them from existing authored percent integers.

## Human design decisions still open

1. **Topology, without changing counts silently.** Vesper/Lacerta have15 private+shared Outer groups; Husk/Mist/Yubar16; Cetus16 including installed Outer sample. Aurena/Nachia/Bismuth have8 shared. Decide spatial grouping/layers and attachment/search names while preserving IDs. Cetus historical fan/bridge regions also need deliberate placement with the four new memory themes. No overlap/performance approval exists.
2. **300-point coverage versus10–20% goal.** Unit-cost ceilings300/final are33.63–40.82%, not10–20%. Multiple-rank/slot/prerequisite costs reduce nodes actually taken, but concrete illustrative paths still do not prove the target. Decide point costs/breadth or explicitly revise the coverage goal; do not secretly add filler or remove valid stars.
3. **300-point balance and native high-frequency cases.** Measure offensive/receiver/support paths for each raw loadout, against one boss and multiple enemies. Include native charge resets, Tranquility flat reduction, Annihilation conversion, Golden Burst sacrifice exemption/0.25s CD, owned summon lifetime/recovery and native constellation penalties. Whole-tree mutually exclusive upper bounds are not balance results. DreamPressure's per-point coefficient must be decided with actual points, not total available node count.
4. **Capped-branch UX.** C15 canonical rejection/refund is decided, but the UI flow showing saturated IDs, exact returned costs and prerequisite-dependent refunds must be designed/exercised. A nonzero partial gain and a completely inert gain must be shown differently. No automatic alternative option/effect.
5. **Release gate ownership/integration.** Every C01–C15 handler, source adapter, codec/migration and consumer must have real Core/host/live proof before data is registered. Cases are specified, not waived. Unknown-source behaviour is rejection with no purchase of unsupported stars, not a substitute implementation.
