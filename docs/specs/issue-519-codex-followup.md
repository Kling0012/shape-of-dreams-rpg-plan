# #519 図鑑更新・表示キャッシュの追補

対象は [#519](https://github.com/Kling0012/shape-of-dreams-rpg-plan/issues/519)（#499 のレビュー追補）。確認日：2026-10-16。

## 鍛冶操作の点検結果

図鑑は `CodexView.Sync` で図鑑登録数・保管庫・遺失物・鞄の個数と言語を比較する。同数のまま固有効果の種類が変わる操作は、別途 `Invalidate` が必要になる。

| 操作 | 固有効果への影響 | 図鑑更新 |
| --- | --- | --- |
| 通常強化 | 節目で固有効果を追加し得る。最後の節目は倍率だけを変える | 既存の `affectsCodex: true` を維持 |
| 禁忌化・断ち切り（現行の表記は「断絶」） | `Rules.Forbid` が `ForbiddenMark` に追加効果を保存する。元の `Relic.Powers` は変更しない | `Forbid` の `Act` に `affectsCodex: true` を追加。`CodexQuery.KnownPowers` も `Forbidden.SourcePowers` を参照し、追加効果を含める |
| 禁忌化の過剰・契約・破滅の誓い | 倍率・能力値を変更する。図鑑で数える固有効果の種類は変えない | 禁忌化の共通 `Act` で更新する |
| 覚醒 | 鍛冶で押す独立した `Act` はない。`Rules.OnKill` で覚醒段階が上がり、既存の固有効果・特性の倍率が変わる | 固有効果の発見集合は変わらず、追加の図鑑失効は不要 |
| 再調律・特性の洗い直し | 特性だけを変更する | 追加の図鑑失効は不要 |
| 融合・限界突破 | 融合は能力値、限界突破は強化上限を変更。固有効果の種類は変えず、素材を1個消費する | 既存の個数検知で更新 |
| 分解・合成・製作 | 所持個数が変わる | 既存の個数検知で更新 |
| 夢の出来事（鍛冶の祭壇・記憶の井戸・固有効果のるつぼ） | 同数のまま固有効果を追加・交換し得る | 既存の明示的な `Invalidate` を維持 |

`KnownPowers` は効果の種類だけを集計するため、強化・覚醒の数値計算が不要な `Forbidden.SourcePowers` を使う。所持品を列挙する既存の図鑑再構築時だけの変更で、毎フレームの再構築は追加しない。保管庫・遺失物・鞄のすべてに同じ処理を使う。

## DisplayBuild の前提

`DisplayBuild` は表示専用で、実計算時刻から0.25秒未満の間は同じ旅人の Build を再利用する。`MarkDirty` を通らない Profile の Heat・Pacts などの変更は、表示への反映が最大0.25秒遅れる。この前提をメソッドのコメントに明記した。ホスト送信用は既存の `CurrentBuild` のままとする。

## 重複したテスト提案の扱い（R3・R5・R9）

本工程には新規テストの作成禁止があり、直接のユニットテストは追加していない。制限解除後の確認対象を次の2件にまとめる。

- `DisplayBuild` の0.25秒の期限境界、連続アクセス、変更直後の再計算。
- `RelicComparison.Compare` と新設 API（`StatDeltas`・`GainedPowers`・`LostPowers`）。断絶による追加効果を含む比較。

今回修正した禁忌化後の図鑑失効と断絶の発見数を直接再現する既存テストは見つかっていない。図鑑集計の修正を一時的に戻した状態でも対象の既存39件は成功し、復元後も39件が成功した。これは既存テストに直接の再現がないことを示し、更新漏れの動的な再現・修正前失敗の証明にはならない。制限解除後の回帰確認ではこの点も扱う。

## 性能テスト2件（R4・R10・R11）

対象：`PerformanceTests.A_kill_takes_well_under_a_tenth_of_a_millisecond` と `Build_and_encode_are_fast`。

Issue の報告では、ベース版 `ce5c854` でも既存の閾値（撃破0.1 ms／Build計算＋Encode 0.2 ms）を超え、観測時の load average は約62だった。これは過去の報告であり、今回の再測定値ではない。`ce5c854` のテスト定義を読み、同じ閾値と測定ループであることを確認した。

現行ブランチには既に `d74dec93` の対処が入っており、これらは `SlowFact`・`Speed=Slow` へ分類されている。通常検証での負荷由来の失敗を避け、main の低速 CI で実行する扱いになっている。今回、通常設定で対象2件が skip になることと、CI の低速テスト matrix が検出結果に一致することを実行確認した。

今回のホストは8論理CPU、確認時の load average は約11〜19で、低負荷条件ではなかった。また、本工程は `SODRPG_SLOW=1` と低速テストの実行を禁止している。このため低負荷環境での性能再測定・ベース版との動的比較は未実行。測定方式・閾値は変更しない。

見直し判断は、低速検証を許可された工程で、低負荷の同一ホスト・Release・同一ランタイムを揃えてベース版と現行版を比較してから行う。ウォームアップ後の複数回の中央値または最小値による判定は、一時的なスケジューリング待ちの影響を減らす候補とする。両方とも閾値を超えるのか、現行版だけが遅いのかを切り分ける前に、閾値だけを緩めない。既存の低速枠への分離は維持する。

## リリース後の確認（R6・R12）

実ゲームの確認とリリース後の利用者の反応は未確認。[#500 の「#499 の実機確認」](https://github.com/Kling0012/shape-of-dreams-rpg-plan/issues/500) を追跡先とし、本変更を含む次リリース後に次の反応を確認する。ここで確認済み扱いにはしない。

- 強化・禁忌化（断絶）の直後に、記録タブの図鑑要約と「固有効果」の発見数が更新されるか。
- 断絶の追加効果が装備比較の「＋」に表示されるか。
- 言語切替時に悪夢・変異の名札とロビーの旅人選択ラベルが切り替わるか。
- 装備や星の割り振り変更が強さの表示へ直ちに反映されるか。

この工程ではリリース・Issue コメント・Issue の変更は行わない。実機未確認を理由にコード修正を止めず、コードと既存テストで担保できる範囲とリリース後の確認を区別する。
