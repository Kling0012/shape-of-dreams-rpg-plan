# #519 図鑑更新・表示キャッシュの追補

対象は [#519](https://github.com/Kling0012/shape-of-dreams-rpg-plan/issues/519)（#499 のレビュー追補）。[元 PR #540](https://github.com/Kling0012/shape-of-dreams-rpg-plan/pull/540) の修正意図と点検結果を取り込み、集計の変更範囲と検証の不足を見直した。確認日：2026-10-17。

## 鍛冶操作の点検結果

図鑑は `CodexView.Sync` で図鑑登録数・保管庫・遺失物・鞄の個数と言語を比較する。同数のまま固有効果の種類が変わる操作は、別途 `Invalidate` が必要になる。

| 操作 | 固有効果への影響 | 図鑑更新 |
| --- | --- | --- |
| 通常強化 | 節目で固有効果を追加し得る。最後の節目は倍率だけを変える | 既存の `affectsCodex: true` を維持 |
| 禁忌化・断ち切り（現行の表記は「断絶」） | `Rules.Forbid` が `ForbiddenMark` に追加効果を保存する。元の `Relic.Powers` は変更しない | `Forbid` の `Act` に `affectsCodex: true` を追加。`KnownPowers` は断絶の遺物だけ `Forbidden.SourcePowers` を参照 |
| 禁忌の契約・過剰・破滅の誓い | 倍率・能力値を変更する。固有効果の種類は変えない | 禁忌化の共通 `Act` で更新する。集計は従来の `Relic.Powers` を使用 |
| 覚醒 | 独立した鍛冶の `Act` はない。`Rules.OnKill` で段階が上がり、固有効果・特性の倍率が変わる | 発見集合は変わらず、追加の失効は不要 |
| 再調律・特性の洗い直し | 特性だけを変更する | 追加の失効は不要 |
| 融合・限界突破 | 融合は能力値、限界突破は強化上限を変更。固有効果の種類は変えず、素材を1個消費する | 既存の個数検知で更新 |
| 分解・合成・製作 | 所持個数が変わる | 既存の個数検知で更新 |
| 夢の出来事（鍛冶の祭壇・記憶の井戸・固有効果のるつぼ） | 同数のまま固有効果を追加・交換し得る | 既存の明示的な `Invalidate` を維持 |

`KnownPowers` が必要とするのは効果の種類だけなので、強化・覚醒の数値計算は不要。元 PR は全遺物を `SourcePowers` に切り替えていたが、本変更では断絶だけに限定する。通常品と倍率だけを変える禁忌化は元の一覧を直接列挙し、過剰の倍率計算と一時リストも増やさない。保管庫・遺失物・鞄は既存の共通関数を使う。処理は図鑑再構築時だけで、毎フレームの所持品走査やメモリ確保は追加しない。

## 受け付け審査の懸念への対応

新規テスト・テストケースは追加していない。既存テストだけでは直接の証明にならないため、一時コンソールで本番ソースの処理を実行し、変更前後を観測した。保存先は `/tmp/pr540-codex-observation-Ec6nD3oD/`。実行コマンドは `python3 /tmp/pr540-codex-observation-Ec6nD3oD/observe.py <mode>`（`original` / `no-invalidation` / `no-discovery` / `current`）。ここには一時ソースと各モードのログを残したが、恒久的な回帰テストではない。上の `/tmp` のパスは作業時だけの一時領域で、後から再現することはできない。観測の内容は、この文書の表と本文の記録がすべてである。

既存の `tests/repro/issue522/extract.py` と同じブロック抽出で、鍛冶の `if (fbConfirm)`、`Act`、`CodexView` の `Summary`・`Sync`・文字列再構築を本番から取り出した。`CodexPresenter` と Core のソースも実行した。セッションの通知・保存・MarkDirty、色の解析は境界代替で、ボタン描画・入力処理は含まない。元実装と片側を外す比較は一時ソースだけで行い、作業ツリーは戻していない。

プロフィール乱数 seed 1、`Loot.RollUnique(new Rng(540), unique.endless_dance, 20)`、禁忌の職人と必要素材を用意し、図鑑の要約・追加効果の行・詳細を先に作った。確認済みの禁忌化処理で断絶が選ばれ、`SpilloverStrike` を得る。保管庫数1・図鑑登録数1は変わらない。

| 実行した処理 | 追加効果の直接集計 | 日本語・英語の表示結果 |
| --- | --- | --- |
| 修正前（`original`） | 発見されない | 固有効果 `2/90` のまま、一覧・詳細は「？？？」 |
| 集計のみ修正（`no-invalidation`） | 発見される | `2/90` のまま、一覧・詳細は「？？？」 |
| 失効のみ修正（`no-discovery`） | 発見されない | `2/90` のまま、一覧・詳細は「？？？」 |
| 両方修正（`current`） | 発見される | `3/90`、一覧・詳細に「溢れる一撃 / Spillover Strike」と効果説明 |

この比較で集計と失効の両方が必要であることを直接観測した。断絶した同じ遺物を保管庫・遺失物・鞄へそれぞれ置いた場合も、変更前は追加効果なし、変更後は追加効果ありだった。

通常品の直接保証も観測した。`Loot.RollRelic(new Rng(540), Rarity.Epic, 20, slot: Slot.Weapon)` の元の効果は `CoStar`・`ChainLightning`。保管庫・遺失物・鞄のそれぞれで、未禁忌化の `KnownPowers` はこの集合と一致し、`ReferenceEquals(r.Powers, Forbidden.SourcePowers(r))` も true だった。契約・過剰・破滅の誓いでも発見集合は同じだった。過剰の `SourcePowers` が別リストを返すのは既存の倍率計算の仕様で、今回の集計はこの経路を通らない。

これらは本番メソッドと代替境界による動的な観測であり、Unity の実描画・実ボタン操作・保存の実行確認ではない。既存テストが修正前に失敗したという主張もしない。修正前の既存部分テスト42件はすべて成功した。

## DisplayBuild の前提と条件付きのテスト提案（R2・R3・R5・R8・R9）

`DisplayBuild` は表示専用で、実計算時刻から0.25秒未満の間は同じ旅人の Build を再利用する。`MarkDirty` を通らない Profile の Heat・Pacts などは、表示への反映が最大0.25秒遅れる。この前提をメソッドのコメントに明記した。ホスト送信用は既存の `CurrentBuild` を使う。

新規テスト作成の制限が継続しているので、重複する条件付き提案を次の対象にまとめる。今回は追加・実行していない。

- `DisplayBuild` の0.25秒境界、連続アクセス、変更直後の再計算。
- `RelicComparison.Compare` と `StatDeltas`・`GainedPowers`・`LostPowers`。断絶の追加効果を含む比較。
- 上記の禁忌化から図鑑要約・一覧・詳細更新、通常品の直接集計を恒久的な回帰テストにすること。

## 性能テスト2件（R4・R10・R11）

対象は `PerformanceTests.A_kill_takes_well_under_a_tenth_of_a_millisecond` と `Build_and_encode_are_fast`。Issue にはベース版 `ce5c854` でも閾値超過が再現し、その際の load average は約62だったとある。今回読んだベース版と現行版の測定ループ・閾値（撃破0.1 ms、Build計算＋Encode 0.2 ms）は同じだった。

現行では既に `SlowFact`・`Speed=Slow` に分類されている。今回、通常設定で対象2件が skip されることと、`python3 tools/test_changed.py --check-ci-matrix` が低速3クラスに一致することを確認した。これは分離の検証であり、性能測定の合格ではない。

今回のホストは8論理CPU、観測時の load average は12.55 / 8.39 / 5.17。低負荷とは扱わず、この工程で禁止された低速テスト・`SODRPG_SLOW=1` は実行しない。閾値・測定方式は変更していない。低速検証を許可された工程で、低負荷の同一ホスト・Release・同一ランタイムでベース版と比較してから見直す。ウォームアップ後の複数回の中央値または最小値は一時的な待ちの影響を減らす候補とし、原因の切り分け前に閾値だけを緩めない。
