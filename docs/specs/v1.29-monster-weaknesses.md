# v1.29 wave 2 — 変種の弱点と耐性 / Monster weaknesses

`docs/specs/v1.30-horizontal-ideas.md` の D1「弱点と耐性を持つ変種」を v1.29 の敵側（26変種）に組み込む。
目的は、特定の型（属性・障壁・召喚・通常攻撃・記憶）に活躍の場を与え、ゾーンごとに装備を持ち替える理由を作ること。
弱点は「追加で効く」、耐性は「少し効きにくい」までで、型を否定しない。

## 性質の一覧

`VariantTag`（`src/SodRpg.Core/Game/Variants.cs`）。倍率の定数と純粋計算は `MonsterBehavior` の
`WeaknessIncomingMultiplier` / `WeaknessDealtMultiplier`（`src/SodRpg.Core/Game/MonsterBehavior.cs`）。

| Tag | 日本語 / English | 効果 / Effect |
|---|---|---|
| `WeakFire` | 火に弱い / weak to fire | 火のダメージ、または燃えている間は被ダメージ+30% |
| `WeakCold` | 冷気に弱い / weak to cold | 冷気のダメージ、または凍ている間は被ダメージ+30% |
| `WeakLight` | 光に弱い / weak to light | 光のダメージ、または光を浴びている間は被ダメージ+30% |
| `WeakDark` | 闇に弱い / weak to dark | 闇のダメージ、または闇を浴びている間は被ダメージ+30% |
| `ShieldBreaker` | 障壁を割る / breaks shields | 障壁を持つ相手へのダメージ+50%。攻撃者が障壁を持っている間は被ダメージ+30% |
| `SummonHunter` | 召喚獣を狩る / hunts summons | 召喚獣へのダメージ+50%、召喚獣からの被ダメージ+30% |
| `LightEater` | 光3以上で脆い / frail at 3+ light | 光のダメージで被ダメージ+30%（3スタック以上時のみ）。スタックは決して消費しない |
| `Armored` | 通常攻撃に堅い / armored against basics | 通常攻撃（記憶でない攻撃）の被ダメージ −30%。記憶は通常どおり |
| `Spellward` | 記憶を弾く / warded against memories | 記憶のダメージの被ダメージ −30%。通常攻撃は通常どおり |

- 弱点は加算（複数なら重なる）。耐性は1ヒットあたり **−30% で打ち止め**（Armored + Spellward の重複も 0.7 倍を下回らない）。
- 弱点と耐性が同時に効くヒットでは互いに打ち消し合う（+30% − 30% = 等倍）。
- `LightEater` の光スタックは `EntityStatus.lightStack` を**読むだけ**で、氷の血脈などの基本スタックを壊さない。

## 検出方法の決定（どちらの条件を採用したか）

元素弱点は「その元素のダメージ」と「その元素がかかっている間」の**両方**を検出できる。どちらか一方で起きる:
- ダメージの元素: `DamageData.elemental`（`Nullable<ElementalType>`、Fire/Cold/Light/Dark）。`.ref/dump/DamageData.txt` 3行目・`ElementalType.txt`。
- 付与状態: `EntityStatus` の `fireStack` / `hasCold` / `lightStack` / `darkStack`。`.ref/dump/EntityStatus.txt` 88〜91行目。`src/SodRpg.Mod/HostAuthority.cs` の既存コード（四元の共鳴）でも同じ読み方を使う。

これにより、元素ダメージを出す型も、元素を付与してから別のダメージで押す型も同じ弱点で報われる。
`DamageAttribute` には元素のビットがない（`.ref/dump/DamageAttribute.txt`）ため、属性フラグでの判定は使わない。

- 障壁の有無: `EntityStatus.currentShield`（`.ref/dump/EntityStatus.txt` 31行目）。攻撃者側は `parentActor` 鎖で `Hero` を探して `currentShield > 0` を見る（`Actor.parentActor` は `.ref/dump/Actor.txt` 41行目）。
- 召喚獣判定: 攻撃者・対象とも `FindFirstOfType<Summon>()` / `FindFirstAncestorOfType<Summon>()`（`.ref/dump/Actor.txt` 152〜153行目）。既存の召喚強化（`HookSummon`）と同じ辿り方。
- 記憶かどうか: 仕掛けの系と同じ `MemorySource`（作成元の `SkillTrigger` 型名と `Links.IsMemory`）を使う。記憶でなければ Armored 側（通常攻撃側）として扱う。

## 適用と実装

- 26 → **30変種**。既存10体に性質を付け、弱点を主役にした新4体を足す（後述の一覧）。
- 新4体は `Variants.IsWeaknessBuilt`（性質・悪夢の性質・Trait を持たず Tags のみ）。`IsExpanded` に含めるので、
  wave 1 と同じくランダムMirageSkin・悪夢共通HP +40%・常時攻撃力を重ねない。全て ShardBonusPct=100、HP +50〜60% のみ。
- ホスト: `MakeVariant` から `ApplyVariantTags`（`src/SodRpg.Mod/HostAuthority.Monsters.cs`）。
  被ダメージは `takenDamageProcessor`、ShieldBreaker/SummonHunter の与ダメージは `dealtDamageProcessor` へ。
  どちらも `DamageData.ApplyRawMultiplier`（`.ref/dump/DamageData.txt` 33行目）で、既存の HitCap・悪夢の守りと同じ経路。
  除去は `Unhook` → `RemoveVariantTags`。戦闘状態は出現単位で持ち、保存フィールドは増やさない。
- UI: 既存の変種通知（`DreamforgeVariantMsg` → `ClientSession.Variant`）から、同じ区画（`Entity.section`、
  `.ref/dump/Entity.txt` 50行目）にいる変種の性質を集め、HUD に一行（例：「この区画：火に弱い敵がいる」）を出す
  （`DreamforgeUi.SectionTagNotice`）。新しい通信・保存は不要。変種の説明文にも同じ内容を明文で書く。
