# 料理のエッセンス：食材の吸い寄せと所持上限の撤廃

## 本体の実体と根拠

ゲーム r1.4.0.13 の実 DLL を確認した。料理関連の未収録ソースは `ilspycmd -t <型> -o /tmp/sod-culinary-native <DLL>` で抽出した。以下の `*.decompiled.cs` はそのディレクトリ内の調査用ファイルで、ゲームデータはリポジトリへ含めない。

| 実体 | 根拠 |
| --- | --- |
| エッセンス `Gem_L_Culinary`：倒した敵から食材を生成 | `Gem_L_Culinary.decompiled.cs:32-37` |
| 食材 `Ai_Culinary_Pickup : PickupInstance`：拾うと食材スタックを追加／生成 | `Ai_Culinary_Pickup.decompiled.cs:4,30-42` |

`maxStack` のコード上の初期値は5だが、食材プレハブのシリアライズ値は提供された管理DLLだけでは確定できない。実装は作成時の実インスタンスから元の値を取得し、5などの推測定数を使わない。

## 吸い寄せ

- `src/SodRpg.Mod/CulinaryMagnet.cs` は実在する `Ai_Culinary_Pickup.OnCreate` だけにpostfixを適用する。`Pickup_` と食材らしい文字列の部分一致判定、型一覧／メンバー一覧ログは削除。
- 作成後の本体パラメーターを調整：吸引距離9m、拾得待ち最低0.6秒、最高速度24m/秒、接近距離に応じた加速度7～30m/秒²。
- 本体の `PickupInstance` の吸引・拾得・落下演出・タイムアウト吸引を維持する。タイムアウト吸引は従来どおり距離外からも動く場合がある。
- 食材は持ち主専用。他の最寄り旅人へ動かす旧PRの処理は、本体がその人の拾得を拒むため削除した。倒れている持ち主へは拾得させない。
- 本体がホストで対象を決め、`Network_target` と初期速度を同期し、各端末で本体の移動を実行する。ホストの `transform.position` だけを書き換える処理は廃止。
- 根拠：`PickupInstance.decompiled.cs:87-123,133-171,191-268,298-325`。追加の毎ティック処理・リスト構築・割り当てはない。本体の探索は `OverlapCircleNonAlloc`。

## 食材数・保存・同期・表示

- `src/SodRpg.Mod/CulinaryIngredientCap.cs` は実際の食材スタック型だけを対象とする。作成・変更前に `maxStack = int.MaxValue` とし、正の加算値は残り容量までに制限してから本体の `AddStack` を実行する。安全上限は2,147,483,647個。
- 他のスタック効果、負の追加の警告、減衰タイマー、0個になった際の破棄、本体の `Network_stack` setterを変更しない。
- 保存フィールド・型・Mirrorの通信形式は変更しない。保存後は実プレハブを生成→作成→`ApplyAfterCreation` の `_stack` 復元という本体順序を使う（提供ソース `Dew.Core/DewPersistence.cs:1351-1378`）。
- `src/SodRpg.Mod/CulinaryIngredientDisplay.cs` は食材アイコンだけ999表示を解除する。最大10桁の再利用バッファで正確な個数を表示し、3桁幅を超える分は文字を縮小する。値が同じなら表示更新せず、他の効果／プール再利用／停止時は元の文字サイズへ戻す。
- MODを外した後の本体は元の加算・上限制限に戻る。拡張在庫を継続して扱うには本機能が必要。

## 料理の強さ

本体の `Shrine_CookingPot.GetAmount` は食材数 `n` に比例する：攻撃力・魔力・防御力は `ceil(0.5n)`、会心率は `n` ポイント、最大HPは `2n`、金は `3n`（`Shrine_CookingPot.decompiled.cs:117-128,161-198`）。所持上限だけを上げると、1回で極端な恒久強化を得る。

そこで1回の調理量は実インスタンスから取得した元の `maxStack` までに維持する。`GetIngredientCount` が提示・効果へ渡す個数を制限し、`ConsumeIngredients` はその個数だけ本体の `RemoveStack` で消費する。余りは失わない。元の上限が5の例なら13個を5、5、3個に分けて調理できる。取得済み食材が捨てられない分、総獲得効果は以前より増え得るが、1回の強さは従来どおり。

根拠：`Shrine_CookingPot.decompiled.cs:63-75,100-114,205-222,257-266`。協力相手にも本体RPCで実際の調理量を送り、表示と消費を合わせる。元の調理上限が不正／`3n` の数値範囲を超える場合は推測値へ代替せず、この上限解除だけを無効にする。

## Fail-softと確認状況

- 吸い寄せ・在庫上限解除・表示は別ownerの任意Harmonyパッチ。対象不在／適用失敗／実行時の不一致では該当機能だけ停止し、警告は1回。上限解除のパッチ群は途中失敗時に自分のownerだけ戻す。他MOD・他機能・MOD全体は停止しない。厳密IL／Harmony非公開API／ハッシュ検証を起動条件にしない。
- 指定Releaseビルド成功：警告5、エラー0。
- 指定 `DOTNET=/usr/bin/dotnet DOTNET_ROLL_FORWARD=LatestMajor python tools/test_changed.py --all` 完走：成功2,727、失敗0、既存スキップ4（Native 116、Core 2,521、Startup 90）。最初の実行は180秒の外部時間枠で打ち切られ、時間枠を延長して完走した。
- 実DLL＋本番パッチのスモーク：元の上限と加算overflowを再現し、上限超え・`int.MaxValue`飽和・減算・無関係な効果・本体Mirror writer/reader・本体保存JSONと継承private `_stack` の復元を確認。
- 本番コードをリンクした管理境界スモーク：調理量と残量、負の追加／タイマー、再インストール、10桁表示／同桁数更新／プール再利用、吸引設定、対象不在と適用途中失敗の警告1回・owner限定ロールバックを確認。使い捨てスモークは常設テストへ追加しない。
- Unityの実画面、実ソケットの協力プレイ、実プレハブの上限数値は未確認。10桁表示の可読性と実画面の吸引は実機確認が必要。
