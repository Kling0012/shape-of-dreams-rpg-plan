# 料理のエッセンスの食材を自動で吸い寄せる

本体の「料理のエッセンス」（`Gem_L_Culinary`）が落とす食材を、MOD側で近くの旅人へ自動で吸い寄せる。

## 仕様

| 項目 | 値 | 場所 |
| --- | --- | --- |
| 吸い寄せ開始距離 | 9 m（食材と旅人の3次元距離） | `CulinaryMagnet.StartRadius` |
| 落ちてから動き出すまで | 0.6 秒 | `CulinaryMagnet.SpawnDelay` |
| 速さ | 7 m/秒から、1秒ごとに +30 m/秒、上限 24 m/秒 | `MinSpeed`・`Acceleration`・`MaxSpeed` |
| 吸い寄せ先 | 範囲内の生存中の旅人のうち最も近い人（同じ距離なら先に登録された人） | `CulinaryMagnet.SelectTarget` |

- 動かすのはホストだけ。ホスト以外の端末には本体の位置同期で届く。
- 範囲内に誰もいない、または全員が倒れている間は動かさず、吸い寄せの経過時間（加速）も0に戻す。
- 旅人の位置にちょうど置いたあとの拾得は本体の判定に任せる。MODは食材の位置だけを動かし、拾得処理・効果・数には触れない。
- 欠片など他の拾得物にこのMODの吸い寄せはない（本体の挙動のまま）。距離と速さは、本体にそろえる基準がなかったので画面の半分ほどの距離と、走る速さより明らかに速い値として決めた。

## 食材の見分け方

ゲームのDLLがクラウドにないため、食材の拾得物の型名は確認できていない。`Actor` の型名が `Pickup_` で始まり、`Ingredient`・`Food`・`Culinary` のどれかを含むものを食材として扱う（`CulinaryMagnet.IsIngredientTypeName`）。夢のダスト・ポーション・ゴールド宝珠は対象外。

`Pickup_` で始まる型を初めて見たとき、ログに `culinary magnet: pickup type <型名> -> pulled toward travelers`（または `ignored`）を1回だけ出す。食材が動かないときは、ここで型名を確かめて `IsIngredientTypeName` を直す。

## 確認状況

- `CulinaryMagnetTests`（Core）で、型名の判定・最寄りの選択・速さ・1ティックの移動・不正な値を確認した。
- Mod側（`HostAuthority.CulinaryMagnet.cs`）はクラウドではビルドできず、実機でも未確認。実機で確認すること：食材の型名が合っていること、`transform.position` の書き換えが位置同期に反映されること（本体が食材の位置を毎フレーム上書きしていないか）、協力プレイで相手の画面でも吸い寄せが見えること。

## 食材の所持上限（カンスト）の撤廃：未実装

依頼は「食材のカンストをなくす」。上限が本体のどこ（`Gem_L_Culinary` の項目か、拾得側か）にあるかが、クラウドのDLLなしでは分からず、推測で本体の値を書き換えるのは危ないため、まだ実装していない。

調べるために、`Gem_L_Culinary` が現れたとき、数値・真偽値・文字列の項目の名前と値を1回だけログに出す（`culinary essence members of ...`）。値は変えない。このログか、`Gem_L_Culinary.cs` の逆コンパイル結果があれば、上限の場所に合わせてパッチを書く。
