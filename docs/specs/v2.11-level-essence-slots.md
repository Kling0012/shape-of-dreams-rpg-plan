# レベル連動のエッセンス枠（2026-10-11）

## 設定と操作

- 対象は Q・W・E・R の記憶だけ。アイデンティティと回避（Movement）は従来の星図の仕組みを維持する。
- `levelEssenceSlots` はレベルによる追加のON/OFF（既定ON）。OFFでも破損した混沌の共通上限設定は有効。
- `levelEssenceEveryLevels` は何レベルごとに +1 するか（既定10、1〜99）。ゲーム本来の `hero.Status.level` を読み、`floor(level / N)` を追加候補とする。MODの夢レベルは使わない。
- `levelEssenceCap` は基本枠＋破損した混沌＋レベル分の合計の上限（既定4、4〜8）。対象選択 `levelEssenceQ/W/E`、`levelEssenceSlotsR` は残す。QWERは本体では基本3枠。
- 旧 `levelEssenceStages` は読み込み前に除外し、値の型や内容に関係なく無視してログに一度だけ出す。新capがなければ旧 `levelEssenceMaxSlots` の整数値を引き継ぎ、4〜8に収める。新capがあれば新capを優先。旧キーは次回保存に含めない。
- F6記録タブの480幅の設定欄にON/OFF、N、capを表示。ホスト（ソロなら自分）は−/＋で変更し、本体の `SaveConfigsToDisk()` で設定ファイルへ保存、すぐ枠を再評価する。参加者は表示のみ。説明と操作は日英対応。記録タブ全体の既存スクロールを使う。
- English: +1 every N native hero levels, applied to Q/W/E/R only. The per-memory cap includes base, Corrupted Chaos and level slots. Hosts can change and save the switch, interval and cap from F6 Records; participants can only view them.

## 所有・反映・通信

- 通常は1秒ごとにホストが全員の英雄を確認。基本枠・混沌の枠は台帳で所有せず、上限までの余地だけレベル枠を足す。OFF・レベル低下・cap低下では自分が足した分だけ戻す。はみ出すエッセンスは本体の `UnequipGem` で足元へ落とす。
- 台帳キー `dreamforge.gemslot.level.ownership.v1` とQWERの所有数／最終書き込み値の配列形式は変更しない。既存のContinue復元中の保護を維持する。
- 混沌の `NotifyUpdate_Corrupted` はQWERを `3 + currentAddedGemSlot*` に絶対値上書きする。任意のSetMax呼び出しは監視せず、この既知の書き直しのPostfixで所有をリセットしてからレベル分を再適用する。
- 混沌のホスト側 `OnActivateEditSkill` は呼び出し中だけ `addedEssenceSlotMax` を実効capに合わせ、Finalizerで元の値へ戻す。Identity/Movementは4のまま。端末側 `GetTargetInfo` はPostfixでQWERの拒否理由／次の枠数を実効capに合わせる。本体ILの厳密一致は要求しない。
- 設定（ON/OFF、対象、N、要求cap、実効cap）は既存の `GameSettingsManager.customData`（SyncDictionary）で共有する。キー `Dreamforge.LevelEssence.v1`、整数5個の文字列。新RPC／新ネットワークメッセージは足さず、旧版相手も未知のRPCを受信しない。ホスト情報が無い参加者は自分の設定で表示し、実際の枠数と可否はホストが決める。
- 既存の外部枠だけでcapを超えている場合、その枠をMOD所有として削らず、レベル分の追加を0にする。

## 5〜8枠のHUDとfail-soft

- 本体 `UI_InGame_SkillButton_GemGroup.LogicUpdate` は `groups[maxGemCount - 1]` だけを表示する。`groups` はPrefab由来で、提供されたManagedコードだけから実際の長さは確定できない。
- Awake後と準備中の1秒間隔の探索で、実際のgroups長をログに一度記録し、4枠以上の並びの個数、0始まりの連続した `slotIndex`、button参照、本体の編集用コンポーネントを検証する。
- 5〜8枠の並びがなければ直前の並びと末尾の枠を順に複製し、`slotIndex` を0〜7に設定する。編集・ドラッグ・ツールチップは本体の `UI_InGame_GemSlot_EditSkill` / `UI_InGame_GemSlot` を使う。追加した並びは4個ずつ二段に配置し、通常の本体LogicUpdateで選択・表示する。複製と配列確保は準備時だけ。
- QWERのHUDの準備が揃うまでは実効cap4。構成検証・複製・HUDパッチの導入が失敗した場合、この枠機能だけ実効cap4へ縮退してログに一度出し、F6に表示する。混沌の表示・activationパッチ失敗は各パッチだけスキップし本体の4を維持する。混沌の所有追跡パッチが導入できない場合はレベルによる追加だけ無効にしてF6／ログで知らせる。MOD全体の停止条件を加えない。

## 本体コードの調査結果

対象：`~/dev/sod-gamedata/decompiled/sod-decomp`。

- `Dew.Core/HeroSkill.cs`：宝石は固定長配列ではなく `SyncDictionary<GemLocation, SyncedNetworkBehaviour>` と辞書ラッパー。装着はlocationをキーとして登録し、効果の所有先はskillに設定する（927〜968）。空き枠検索はGetMaxGemCountまでループ（1218以降）、宝石列挙は辞書全体。枠数はintのSyncVarとして同期（1887以降）。4枠固定の配列境界は見当たらない。
- `Dew.Core/EditSkillManager.cs`：編集の枠可否とゲームパッドの次枠選択はGetMaxGemCountを参照（756、1372以降）。`Dew.UI/UI_InGame_SkillButton_EditSkill.cs` も空き枠検索を使う。GemSlot_EditSkillのlocationはbutton.skillTypeとslotIndexで作られ、4固定ではない。
- `Dew.Core/DewPersistence.cs`：GemDataは正確なGemLocationを保存し（270以降）、復元はそのlocationでEquipGemを呼ぶ（1315〜1333）。`Dew.Core/Mirror/GeneratedNetworkCode.cs` はGemLocation.indexをintとして読み書き（1693〜1704）。5〜8枠を切り捨てる保存／通信上の制約は見当たらない。
- `Dew.Contents/Shrine_CorruptedChaos.cs`：表示側はハードコード4（152）、ホストのactivationはaddedEssenceSlotMax（183）。`Dew.Core/Se_Shrine_Chaos_StatBonus.cs` は混沌の保存カウンタとQWER絶対値更新を持つ（405〜466）。
- コード調査上のゲームプレイの安全上限は8。実効capは要求capとHUDの準備状況から4〜8に決める。実際のPrefabのgroups数、二段配置の描画・マウス／ゲームパッド操作、5〜8枠の効果／セーブ再開、協力プレイの実機確認は未実施。
