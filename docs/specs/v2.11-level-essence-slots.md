# レベル連動のエッセンス枠（2026-10-10）

## 依頼

「ゲーム本来のプレイ中のレベルに応じて各記憶のエッセンススロット数を増やす。他とある程度独立してよい。10LVで+1、20Lvで+2のように指定でき、Q・W・Eのどの記憶に効くかも選べる。設定はコンフィグかF6メニュー。」

2026-10-11：Rの記憶も同じ段階・上限で対象に追加。

## 仕様

- 設定（`DreamforgeConfig`、ゲームのMOD設定）：`levelEssenceSlots`（入／切）、`levelEssenceQ/W/E` と `levelEssenceSlotsR`（対象）、`levelEssenceStages`（段階）、`levelEssenceMaxSlots`（1つの記憶の枠の最大数、4〜8、既定4）。
- 段階は「レベル:合計」をカンマ区切りで好きなだけ。`10:1, 20:2` はLv10から合計+1、Lv20から合計+2（足し算ではなく累計値）。`Lv10:+1`、全角、`=` や `/` 区切りも読む。読めない記述は捨てて、ログに1回だけ出す。同じレベルが重なったら後の記述、レベルが上がって合計が下がる指定は無視（累計の最大）。段は16まで、1段の合計は8まで。
- 初期値は Q・W・E・R すべて対象、`10:1, 20:2`。既存の設定ファイルに `levelEssenceSlotsR` がなくても既定の `true` で動く。Rにも同じ段階・上限を使い、アイデンティティと回避（移動）は星図の枠だけを使う。
- English: Level-based essence slots apply to Q, W, E and R with the same stages and cap. `levelEssenceSlotsR` defaults to `true` even when absent from an existing config. Identity and Movement remain controlled by the star map.
- 反映はホストだけ。ソロは自分、協力プレイはホストの設定が全員の英雄に反映される（枠の数は `HeroSkill.maxGemCount*` の同期値なので、参加者の設定は影響しない）。Buildには入れず、保存と通信の形式は変えない。
- F6メニュー（記録タブの設定欄）には今の設定を読み取り専用で表示する。変更はMOD設定で行う。

## 実装

- Core：`LevelEssenceSettings`（設定の解析と計算。`Desired(target, level)`）、`GemSlotLedger.Decide` に上限つきの多重定義を追加（既定は従来どおり4）。
- Mod：`HostAuthority.LevelGemSlots.cs`。1秒ごとの確認（`TickLevelGemSlots`）で、全員の英雄の `Status.level` を読み、Q・W・E・Rの枠を合わせる。星図の枠（Identity・Movement）とは別の台帳（所有の記録は再読み込みをまたいで AppDomain に残す）。書き込み・はみ出したエッセンスの落下・継続（Continue）中の保護は星図の枠と同じ `UpdateGemSlot` を使う。レベルが下がる・設定を切ると、足した分だけ戻し、はみ出したエッセンスは足元に落ちる（失わない）。

## 注意（実機未確認）

- **表示上限**：本体の枠並び（`UI_InGame_SkillButton_GemGroup`）は1つの記憶に4つまでしか描かない（v1.27 5.2）。Q・W・E・Rは最初から3つなので、既定の上限4では実際に増えるのは+1まで。Lv20の+2を効かせるには `levelEssenceMaxSlots` を5以上にするが、本体が5つ以上を描けるかは未確認で、描けない場合はその記憶の枠が1つも表示されなくなる（はめたエッセンスは消えない。4へ戻せば直る）。
- **レベルの読み取り**：英雄のレベルは `hero.Status.level`（`HostAuthority.HeroLevelOf`、1か所）。モンスターの `Status.level` は使用実績があるが、英雄でゲーム内の表示レベルと一致するかは実機で未確認。
- **MOD設定の文字列欄**：`levelEssenceStages` は文字列。ゲームのMOD設定画面が文字列欄を描けるかは未確認（描けない場合は、設定ファイルを直接編集するか、数値欄の形に変える）。
- 他のMOD（枠数を増やすもの）や混沌の聖堂の追加枠は、星図の枠と同じく「もとの枠」とみなし、その上に足す（上限を超えない範囲）。
