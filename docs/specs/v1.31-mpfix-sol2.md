# v1.31 multiplayer reconnect / late-join / reload fixes

Scope: `mp-sync.md` #2, #3, #4; `mp-host.md` #6; `mp-ui-save.md` #8, #13. Core remains pure C# 9 / netstandard2.0; Mod remains netstandard2.1. No game launch, GUI verification, game-folder writes, or commits.

## mp-sync #2 — reconnect after zone travel

**Verdict: confirmed.** Same-run `BeginRun` returned without reconciling the native zone. Departed-zone finalization was a one-time broadcast, so a missed commit could permanently block old rewards, current choices, and conclusion.

**Fix:** `RunChoiceProgress.BeginRun` reconciles a later native zone by scheduling every missing arrival, never overwriting the unpaid zone. Settlement waits for each original zone's committed snapshot; old rewards see that zone's depth, waypoint and existing room counters before a new secure point expires them. `TrackRun` performs reconciliation even for the already-active run, after native transition completion.

`RunChoicePublisher.History` retains finalized per-zone encoded snapshots and a terminal victory/defeat snapshot. The host periodically replays history using the existing choice message transport. Terminal history survives empty lobby state and reload, and is retired when a new expedition begins. Reloaded history is reissued under the new authority with fresh revisions, preserving original rules and event identities. A duplicate admitted terminal snapshot can still supply the missed result; retired/stale snapshots cannot. Remote conclusion also waits for the current admitted committed rules. Pending unclassified native deaths block arrival settlement and conclusion.

**Regressions:** `Rejoin_without_native_travel_reconciles_old_rewards_before_current_rules` covers received/missed prior commit × victory/defeat; `Rejoin_skipping_two_zones_waits_for_each_original_commit`; `Terminal_result_waits_for_current_committed_rules_and_rejects_retired_or_stale_snapshots`; `Finalized_history_replays_original_rules_and_terminal_result_until_a_new_run`. Existing delayed/reversed arrival scenarios remain applicable.

**Failing-before evidence:** the new rejoin tests ran before the fix: five failures, including missing pending arrival and no advancement after a two-zone rejoin.

## mp-sync #3 — death before special metadata catch-up

**Verdict: confirmed.** Missing live dictionaries were permanently captured as ordinary reward inputs; later live metadata could not repair an already-recorded death.

**Fix:** `KillClassificationLedger` joins an eligible native death with an immutable host `AuthoritativeRunKill` fact. The host records run/event/netId/classification before native cleanup, saves it, and replays it for the run. Until that fact arrives, the client holds the native death; no ordinary default is awarded. A host fact alone cannot grant loot. Resolution follows native death FIFO even when facts arrive in reverse order across travel. Event IDs and resolved IDs survive profile roundtrip, so retries and reload cannot pay twice. Existing native loot eligibility checks remain in Mod.

**Regressions:** `Early_special_death_waits_for_authoritative_fact_and_settles_once_after_profile_reload` covers nightmare and boosted-shard variant, including reward RNG/tier, shards, star XP, awakening, special/bounty credit, and deduplication; `Catchup_fact_without_an_eligible_native_death_never_grants_loot`; `Reversed_facts_after_travel_keep_native_death_order_and_departed_zone_rules`; `Host_reload_replays_original_special_fact_under_new_authority_without_reclassifying_death`.

**Failing-before evidence:** a console repro against the pre-fix Core assembly exercised the original absent-metadata capture: special credit 0 / star XP 1, versus authoritative special credit 1 / star XP 2. The new ledger APIs did not exist in the baseline; no claim that their tests executed against that baseline.

## mp-sync #4 and mp-host #6 — stale live classifications after host reload

**Verdict: confirmed for both reports.** The native server Actor survives host-only mod reload, while host runtimes and classifications are recreated. Positive-only replay and ignored ordinary entries left client tags and visuals stale on the same netId.

**Fix:** `MonsterAuthorityState` observes the publisher's authority generation, retires obsolete generations and clears live classifications on replacement. Thin client wiring clears nightmare/variant/cue dictionaries and restores variant/cue visuals. Live nightmare/variant/cue messages carry the generation. Periodic publication includes explicit ordinary entries, which remove previous special classifications. Immutable recorded death facts are not cleared by live-authority replacement.

**Regressions:** `Same_live_netId_special_to_ordinary_clears_tags_and_rejects_old_generation` (nightmare/variant); `Same_live_netId_variant_to_nightmare_keeps_only_the_new_classification`; `Explicit_ordinary_replay_removes_special_classification_within_current_generation`; saved original-death replay after host reload.

**Verification boundary:** source-confirmed baseline defect; Core authority transitions exercised by regressions and console smoke. Actual native visuals and live host reload were not exercised.

## mp-ui-save #8 — delayed Build resend after host-only reload

**Verdict: partly fixed in the baseline.** Successfully applying a new current-zone choice snapshot already called `MarkDirty(true)`, so a universal 30-second gap was not established. The remaining defect was blocked catch-up: authority changed but the new current-zone snapshot could not apply, leaving the Build resend deadline unchanged.

**Fix:** authority observation happens before choice-progress application gates. Core marks Build resend required on first/new authority; Mod clears live metadata and immediately sets `_buildDirty`. It does not depend on successful zone advancement or applying current rules.

**Regression:** `Authority_change_requires_build_resend_even_when_new_zone_snapshot_cannot_apply`; console smoke confirms Build resend required while the stale live classification is cleared.

## mp-ui-save #13 — shutdown unpaid rewards / finished-run reload

**Verdict: confirmed.** `Unwire` discarded unpaid queues before the final save, and the completed run ID existed only in session memory. Reloading on the result screen could recreate the finished expedition and increment run statistics.

**Fix:** `RunRecoveryState`, `RunChoiceProgress.Durability`, and additive profile-format-3 codec fields preserve the tracked original zone, queued arrivals, committed rules, unpaid kill facts, pending result, publisher history/terminal result, and unpaid dividend receipts/deduplication. `KillClassificationCheckpoint` preserves pending native deaths, host facts and resolved event IDs. Profile cloning includes recovery state, so asynchronous saves retain the same value snapshot.

`SaveNow` captures recovery state with the profile; `Unwire` saves and flushes before clearing handlers/queues, and later quit saves retain that pre-detach checkpoint. Construction and profile switching restore recovery. No rewards are forced through missing/default host rules. `Rules.EndRun` persists `CompletedRunId`; `Rules.BeginRun` refuses that finished ID before rolling bounties, modifying RNG, or incrementing Runs. Client tracking also restores the completed ID.

**Regressions:** `Shutdown_awaiting_host_rules_roundtrip_pays_original_zones_once_and_retains_result`; `Saved_departed_zone_commit_retains_room_counters_while_new_zone_rules_wait`; `Shutdown_preserves_unpaid_dividends_and_paid_receipt_deduplication`; `Result_screen_reload_cannot_restart_completed_run_or_increase_runs` (victory/defeat).

**Failing-before evidence:** console repro against the pre-fix Core assembly: finished-run profile roundtrip/restart produced active=True / Runs=2; expected active=False / Runs=1.

## Protocol and persistence decision

`Protocol.Version` changes once, **12 → 13**. Existing Build multipart grammar, thousandth values, and shared-choice encoded grammar are unchanged. Live classification generations and terminal result fields are additive; `DreamforgeMonsterKillMsg` is new. Behavioral compatibility with a protocol-12 host is impossible: that host cannot replay authoritative dead-monster facts, so a new client would wait forever. No unsafe downgrade to stale/missing local classification is provided. All co-op participants must update together.

Profile version remains **3**, with additive optional recovery fields. Existing format-3 profiles without those fields remain readable. Incidental protocol-number pin assertions were removed rather than repinned; transport behavior tests remain. A build-blocking `Array.Empty`/codec helper name collision was corrected by qualifying `System.Array.Empty`.
