# v1.29 仕掛けの実装記録 / Gimmick implementation

G12〜G22を既存の記憶の仕掛けへ追加した。Coreは純粋なC#のまま、星の検証・間隔・対象ごとの状態・同じ発動の集計・継続ダメージの時計を担当する。ホストは本体の対象とAPIを解決する。既存の効果IDは変更せず、末尾に11効果を追加した。

G12–G22 extend the existing memory gimmicks. Pure C# handles validation, intervals, target windows, cast grouping and wound timing; the host resolves native actors and applies the results. The original effect IDs retain their values.

## 発動の帰属と上限 / Attribution and caps

通常の発動は `EntityEvent_OnCastCompleteBeforePrepare` で本体が渡す記憶のルートインスタンスに通し番号を付ける。その子の投射物・状態効果・召喚獣は同じ番号を使う。ビルドが遅れて届いた場合は、記憶へ直接つながる既存の効果インスタンスを1回の発動として扱う。親鎖にGemがあるものは従来どおり記憶へ帰属させない。記憶トリガーから直接出たダメージなど、発動インスタンスを確認できない経路ではRampartとCrescendoは発動しない。フレームや時刻だけから別の発動だと推測しない。

Cast roots receive a host serial before preparation. Descendant projectiles, status effects and summons reuse that serial. An already-running root instance can establish a serial when a build arrives late. Gem ancestry remains excluded. Rampart and Crescendo stay inactive when a cast instance cannot be established; timestamps and frames are not treated as proof of separate casts.

Crescendoが有効な間は記憶の冴えと加算し、`Links.EquippedCap(MemoryDamage, 3)` と120%の小さい方で合計を制限する。これは設計の最大2.2倍を守るため。Crescendoが有効でない既存の覚醒済み連携は従来の上限を保つ。複数のCrescendoの星は有効な最大値だけを採用する。

While Crescendo contributes, its sum with memory damage links is limited to the lower of the equipped link cap and 120%, matching the specified maximum multiplier of 2.2. Existing awakened links retain their previous caps when Crescendo is inactive. Multiple Crescendo stars use only the strongest active value.

Weakspotの通常攻撃は、既存の会心率をc、追加分をbとすると、通常の会心に失敗した場合だけ `min(1, b / (1-c))` で再判定する。したがって基礎会心率に追加分を足した確率になる。記憶には本体共通の会心率判定がないため、最終的に非会心の記憶ダメージへ追加分の確率を使う。本体の会心が既に付いたダメージと、確定会心の通常攻撃はそのまま通す。

For basic attacks, the second roll uses `min(1, b / (1-c))` after a failed native roll, producing an additive critical chance bonus. Memory damage has no universal native critical roll, so its additional roll uses the bonus percentage on attributed damage that remains noncritical after receiver processing. Existing critical hits are unchanged.

新しい11効果はすべて、Buildの収集・符号化・復号とruntimeで共用する検証を通る。`St_M_` の移動記憶を拒否する。Dazeは設計で挙げられた既存スタン記憶のルートを、Primedは通常攻撃を使わない固有ルートを拒否する。値・Arg・きっかけも効果別に検証する。既存の星配置データは変更していない。

All eleven effects share validation across build collection, encoding, decoding and runtime. Movement memories beginning with `St_M_` are rejected. Daze rejects the named native stun routes; Primed rejects the native routes without basic attacks. Values, arguments and triggers are checked per effect. Existing route data is unchanged.

## 本体の確認先 / Native evidence

宣言はリポジトリの `.ref/dump`、実装は読み取り専用で得た `%LOCALAPPDATA%/sod-decomp/Dew.Core` を確認した。

- 追加ダメージ・順序：`.ref/dump/Actor.txt`、`DamageData.txt`、`FinalDamageData.txt`、`DamageAttribute.txt`。`Actor.cs:834-860,864-1060` は送信処理、受信処理、確定ダメージ、命中通知、撃破の順。`DamageData.cs:95-129,169-173,218-222` は属性・増幅・軽減・隔離マーカー。無属性・攻撃効果強度0への最終化は既存の `GimmickDamageIsolation` を再使用する。
- 通常攻撃・会心：`.ref/dump/Actor.txt`、`EntityStatus.txt`。`Actor.cs:1063-1121` は会心フラグと会心倍率を命中通知より前に適用する。`Entity.cs:676-679` は受信側処理。`Se_Elm_Light.cs:14-32` は光が3つ以上のとき受信側で会心を確定させるため、記憶のWeakspotはこの後へ接続する。
- 発動の識別：`.ref/dump/EventInfoCast.txt`、`AbilityTrigger.txt`、`Entity.txt`。`AbilityTrigger.cs:1012-1074` は新しいインスタンスをprepare前のイベントへ渡す。`Actor.cs:2369-2384` は子から親へ送信処理を集める。ルートが非アクティブになっても子の投射物が残る場合があるため、発動記録は消滅かゾーン切り替えまで保持する。
- スタン：`.ref/dump/StunEffect.txt`、`MonsterType.txt`、`Se_GenericEffectContainer.txt`。`Actor.cs:1435-1491` は識別子の照合・期限更新・耐性設定。`Se_GenericEffectContainer.cs:32-39` はタイマーとBasicEffectの設定。
- 回復：`.ref/dump/HealData.txt`、`Entity.txt`、`ActorManager.txt`。`Actor.cs:767-801` は送信側・受信側の処理後に実回復を確定する。`Entity.cs:681-684` は受信回復処理。`HealData.cs:25,67-71,139-143` は現在値・軽減・マーカー。Siphonだけを識別する受信処理後の上限制御により、回復補正を含めても最大HPの1.5%を超えない。
- 支援の出どころ：`ActorManager.cs:109-116` は親なしの `ServerActor` の生成。`Actor.cs:1257-1268` は障壁の量・期限。回復・障壁とも `serverActor` から送り、旅人の支援通知を起こさない。Rampartは `Se_GenericShield_OneShot.cs:18-33` と `ShieldEffect.cs:13-38` の実障壁量を比較する。
- 召喚獣：`.ref/dump/Summon.txt`、`ActorManager.txt`。`Summon.cs:102,191-195` は所有する旅人を親鎖から記録する。`ActorManager.allEntities` のコピーを取ってから回復するので、回復通知中の生成・消滅で列挙を壊さない。
- 属性・範囲：`.ref/dump/EntityStatus.txt:88-91`、`%LOCALAPPDATA%/sod-decomp/Dew.Core/DewPhysics.cs:186`。既存の反応と同じ範囲検索・敵の関係判定・生存判定を使い、借りたリストは必ず返す。

追加ダメージはすべて `GimmickRuntime` マーカーと同期ガードを使う。命中・会心・撃破・属性の別効果を連鎖させず、HPを減らす作用は元のイベント完了後へ送る。回復・障壁は親なしのserverActorから送る。ゾーン切り替え・解除では対象参照、未処理の作用、継続ダメージ、発動番号、敵への軽減処理を片付ける。

All additional damage uses the existing isolation marker and synchronous guard. Damage application is deferred until the originating event has completed. Support originates from the root server actor. Zone changes and detachment release temporary targets, pending effects, wound state, cast attribution and enemy damage processors.

通信は既存の `g` セクションを使用し、新しいフィールドを送らない。一時状態はホストだけに存在する。この仕掛け追加単独では通信形式の変更は不要。Coreの境界検証とゲーム外の配置先へのReleaseビルドで確認した。Unity内の実戦・表示・協力プレイは未確認。

The existing `g` section carries the appended IDs without adding wire fields. Temporary state remains on the host. These gimmicks alone require no protocol-format change. Core boundary checks and a Release build to an external staging directory were verified; live Unity combat, presentation and multiplayer remain untested.
