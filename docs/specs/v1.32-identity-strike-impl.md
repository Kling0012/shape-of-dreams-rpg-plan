# v1.32 C：空殻の記憶の改変（エンジン実装）

設計は [v1.32-star-additions.md](v1.32-star-additions.md) C、調査は [v1.32-research.md](v1.32-research.md) §2・§3・§7。ここは**エンジン（型付きの部品・生成器対応・試験）**の記録で、星のデータ行（JSON）は含まない。

## 1. 「記憶が与えたダメージ」になる仕組み（逆コンパイルで確認）

- `Actor.DealDamage(damage, target)` は、**ダメージを与えたActor自身と、`parentActor` をたどった全ての祖先**の `dealtDamageProcessor` を通し（`ProcessDealtDamage`）、その後 `InvokeOnDealDamage` で同じ連鎖の `ActorEvent_OnDealDamage` を呼ぶ。
- `Gem_L_DivineFaith.OnEquipSkill(skill)` は `skill.TrackKills(6 s)`（`KillTracker` が `skill.ActorEvent_OnDealDamage` を購読）と `skill.dealtDamageProcessor.Add(Amplify)` を登録する。つまり**ダメージの発生元が、はめた記憶（SkillTrigger）自身かその子孫**であるときだけ、追跡も増幅も効く。
- `hero.PureDamage(..)` は発生元が**空殻本人**になるので届かない（旧来の経路）。そこで `IdentityStrike` は、装備中のアイデンティティ記憶の `SkillTrigger` から `skill.PhysicalDamage / MagicDamage(...)` で `DamageData` を作り `Dispatch` する（`HostAuthority.IdentityStrikes.cs` の `FireIdentityStrike`）。
- 突進攻撃（風の傷のダッシュ攻撃）は別：`At_D_ScarOfTheWind_DashAtk` は `Se_D_ScarOfTheWind_NextAtkDash` の `DoAttackOverride` で作られ、`EntityStatus` が `trigger.parentActor = entity`（**空殻本人**）に設定する。したがって `Ai_D_ScarOfTheWind_DashAtk.OnHit` の追加ダメージ（`Damage(bonusDamage)…Dispatch(entity)`、闇75%）は基本攻撃の連鎖に属し、記憶には帰属しない（設計者の指摘どおり）。
- 実IL（`Dew.Contents.dll`）：`Ai_D_ScarOfTheWind_DashAtk.OnHit` は `DamageData::Dispatch` を**1回だけ**呼び（追加ダメージ）、回復は別型の `HealData::Dispatch`。`NativeWindScarBonusAsMemory`（Harmony Transpiler）はその1呼び出しだけを静的ラッパー `DispatchBonus(ref DamageData, Entity, ReactionChain)` に置換し、星を取っている間だけ `damage.SetActor(風の傷の記憶)` にして `Dispatch` する（ダメージ量・方向・属性はそのまま、**増えない**）。C02の正確なネイティブ範囲（`NativeMemoryPayloadScope.Source`）は呼び出しの間だけAiから記憶に差し替え、終了後に戻す。置換できるのは1呼び出しのときだけで、本体が変わって呼び出しが1つでなくなれば例外で適用しない。

### 実行の流れ
- **主基本攻撃の命中**（`PublishAttributedFinalDamage` の主パケット）で、活性化ごとの最初の命中だけを数える（複数命中の攻撃は1回）。条件が揃えば**次のホストtickで**斬撃を実行する（基本攻撃自身の `DealDamage` の途中でダメージ・撃破を出さないため）。斬撃自身は主パケットではないので再入しない（深さガード付き）。
- 対象は、当たった敵に加えて前方の扇／直線に入る敵（`OverlapCircleAllEntities` ＋ `IdentityStrikeDefinition.Contains`）。ダメージ種は高い方が魔力なら魔法、そうでなければ物理。
- 装備中のアイデンティティが星の指定と違う、または死亡・装備変更のときは発動せず、カウントも捨てる。同じビルドの再送ではカウントを保つ。

### 残す速さ・殺意の滋養（一歩一殺）
- `Se_D_TheKillingFlow` は `finalStatsProcessors` の優先度10で攻撃速度倍率を1に潰し攻撃力に足す（`DataProcessorGroup` は優先度の昇順・同順位は挿入順）。MODは優先度9で変換前を記録し、優先度11で「残す割合」を攻撃速度と攻撃力から戻す。同期変数 `gainedAd` も変換した分だけに更新する（一歩一殺の斬撃の「変換した追加攻撃速度」はこの値から `gainedAd ÷ 0.5` で復元）。
- 回復は `hero.dealtHealProcessor` に係数を掛ける（MODの `HealPower` と同じ仕組み）。対象は**命中ごとの回復（吸血）の発行箇所**だけ（`_onHitHealDepth` で囲む）。係数＝失った攻撃速度の倍率（変換前÷変換後）、1〜上限（既定2倍）。

### 滅殺態勢「剣気の鍛え直し」
- 剣気は `Ai_R_AnnihilationStance_Projectile.OnEntity` が `Damage(damage, 1)`（ScalingValueの `apFactor`＝400%、`adFactor` が0なので魔法）で作る。`hero.dealtDamageProcessor`（子孫のActorにも適用される）で、`ScalingValue.GetValue` を「魔力の項に攻撃力を入れた値÷本体の値」の**厳密な比**で `ApplyRawMultiplier` し、`SetSourceType(Physical)` で物理にする（`DamageData.source` は公開で、`SetSourceType` が使える）。態勢の攻撃+35%・攻撃速度+30%はそのまま。

## 4. 実機で未確認のこと（必ず確認する）
1. 風の傷＋神聖なる信仰を**アイデンティティ枠**に入れて、斬撃で撃破したときにスタックが増え、`+0.4%/スタック` が斬撃のダメージに乗ること（`TrackKills` の6秒と `Amplify`）。一歩一殺でも同様。
2. 記憶（SkillTrigger）の `parentActor` が空殻本人であること（本体の処理器が祖先として効くための前提。想定どおりのはずだが未確認）。斬撃は記憶の連鎖でもMODの `rt.DamageDealt`（`MemorySource` が記憶名を返す）を通り、アイデンティティ向けの「記憶の冴え」が乗る。既存の `QueueGimmicks(OnHit)` がアイデンティティの命中仕掛けとして斬撃にも反応する（意図どおり）が、二重発動がないか確認。
3. 突進攻撃の追加ダメージの置換：実際のHarmony適用後に、追加分が記憶に帰属してスタックが増えること、主ヒットは基本攻撃のままであること、`NativeMemoryPayloadScope` の差し替えで `native.wind-scar.additional` の既存の帰属（刻印「風傷の芯」）が崩れていないこと。
4. 斬撃の見た目・当たり範囲（扇4.5m・120度などの数値）と、命中直後の次tickに出る遅延の体感。方向は「当たった敵の方向」。
5. 一歩一殺の `gainedAd ÷ 0.5` による変換速度の復元（本体の `atkSpdPercentageToAdRatio` は `ScalingValue` で、説明の0.5を仮定。丸めの誤差あり）。残す速さと表示の整合（`gainedAd` の同期と、装備中のUIの表示）。
6. 殺意の滋養の対象：MODの吸血（`PowerRuntime.OnAttackHit` の `Heal`）のみ。ほかの命中時回復（他の記憶・精髄）には掛からない。必要なら対象の追加を決める。
7. 剣気の鍛え直し：`projectile.effectiveLevel` と ScalingValue の評価が本体と一致するか（基礎値・レベル項があると、比がわずかにずれる）。物理への切替で敵の防御に当たる点が意図どおりか。
8. 協力プレイ：すべてホスト側で完結（クライアントは星の取得状態を送るだけ）。クライアントの表示（`gainedAd` はSyncVar）の確認。
