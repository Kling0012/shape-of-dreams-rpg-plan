# v1.31 特性の洗い直しの実装記録 / Affix reroll implementation

鍛冶タブで、遺物の特性を**全部まとめて**引き直せるようにしました。仕様は [v1.31-affix-reroll.md](v1.31-affix-reroll.md)。結果はすぐに確定し、取り消せません。特性の数・レア度・土台・強化値・限界突破・覚醒・固有品の固有効果は変わらず、新しい遺物を作るときと同じ抽選で引き直します。既存の再調律（1つの特性を3つの候補から選ぶ）はそのまま残ります。

## 費用の計算（整数だけ）

費用は欠片 60×(レア度+1) と調律石 2×(レア度+1) に、その遺物で済ませた回数 `AffixRerolls` ぶんの 1.5^n を掛けて切り上げます（`Rules.AffixRerollCost`）。浮動小数点の誤差を持ち込まないため、1.5^n は有理数 3^n / 2^n として long で計算し、切り上げは `(base × 3^n + 2^n − 1) / 2^n` の整数除算で行います。コモンの並びは欠片 60→90→135→203→304→456→684、調律石 2→3→5→7→11→16→23 です。3^n が long に収まらなくなる回数（実質的に届かない領域）では、欠片の所持上限と同じ int の上限に張り付けます。回数の上限はありません。

## 引き直しの抽選

`Rules.AffixReroll` は、プロフィールの乱数（`TakeRng` / `StoreRng`）を使い、`Loot.RollAffixes`（`RollBaseRelic` / `RollUnique` が新しい遺物に特性を足すのと同じ経路）で引き直します。したがって候補も値の範囲も、その土台・レア度・アイテムレベルの新品と完全に同じです（`src/SodRpg.Core/Game/Loot.cs` の `RollAffixes` / `RollAffix` を確認）。

特性の**数**は保存の対象なので、強化の節目（+3・+5・+10・+15）で増えたぶんも含めて、洗い直しの前後で同じにします。引き直す前に `Affixes` を空にして、元の個数になるまで `RollAffixes` で足し戻します。能力値の種類が尽きて足りなくなったぶんは、再調律と同じ扱いで重複を許して埋め、個数を守ります（実際の内容では起きません）。土台の暗黙値と同じ能力値は避けます。

## 対象外と断り方

次の遺物は `InvalidOperationException` で断ります（文言は `Loc.T` の日本語・英語。プロフィールは変わりません）。

- 鍵つき（`Relic.Locked`）
- どこかに装着中（`Profile.IsEquippedAnywhere`）
- 取引（分解の予約）の待ち（`TradeLedger.IsReserved`）
- 再調律の候補が出ている本人（`RequireNoRetuneOffer`。ほかの遺物の候補は妨げません）
- 欠片または調律石が足りない（必要な両方の実数を文面に出す）

## 保存

回数は `Relic.AffixRerolls`（`Relic.Clone` もコピーします）。プロフィール保存では遺物ごとに任意キー `"affixRerolls"` を書き、読み込み側は無ければ 0 にします。古い保存を読めるよう、保存形式の版は従来のまま（4）で上げません。未知のキーは既存の読み込みが無視するため、古いMODがこの保存を読んでも壊れません（新しい回数の情報は失われます）。

## 鍛冶タブのUI

再調律のUIの下に「特性を洗い直す（欠片X・調律石Y）」ボタンを置きます。危険な操作なので2回押しで確定し、1回目は取り消せない旨と費用を赤字で示します。素材が足りないとき・取引の予約中は押せず、足りない実数を表示します。鍵つき・装着中は押したときに理由が画面下の状態行に出ます。結果（引き直し前後の一覧）は既存の通知経路（`GameEvent`）で流れます。装着中を断るので、この操作で装備のビルドは変わりません。

## 確認した経路と判断

- `Loot.RollAffixes` / `Loot.RollAffix` / `Content.AffixCount`：`src/SodRpg.Core/Game/Loot.cs`・`Content.cs` の既存実装を確認。新しい遺物と同じ抽選をそのまま再利用し、`Loot.cs` は変更していません（必要な可視性は既にありました）。
- `Rules.Retune` / `ChooseRetune` / `Enhance`：`src/SodRpg.Core/Game/Rules.cs` の既存の断り方（予約・候補・保管庫）と乱数・支払いの順序を踏襲。
- `ProfileCodec.WriteRelic` / `ReadRelic`：`src/SodRpg.Core/Game/ProfileCodec.cs`。任意キーの追加は `limitBreaks`（v1.27）と同じ形。
- ゲーム本体のAPIは新しく使っていません（UIは既存のIMGUI呼び出しの踏襲）。

Coreの自動検証は、レア度ごとの費用の式と1.5倍の伸び（整数の切り上げ）、両素材の支払いと回数の増加、保存の往復と古い保存の既定値0、特性の数と他の全項目の保存、種まかせの再現性、対象外4種と素材不足の断り、固有品の固有効果の固定、プロフィール乱数と新品抽選との一致を含みます。実機での画面表示は未検証です。
