## A. ルールとホスト（GPT）

対象ファイル：`src/SodRpg.Core/Game/Rules.cs`・`Feats.cs`・`Relic.cs`・`Loot.cs`、`src/SodRpg.Mod/HostAuthority.cs`・`ClientSession.cs`。

1. **夢喰いの獏（Tapir）の稼ぎすぎ**：1個あたりの欠片を `Content.SalvageShards(r.Rarity)`（コモン3〜伝説60）にする。調律石は `count / 3`（切り捨て、0もありうる）。エピック以上は食べさせない（鞄に残す）。欠片は鞄の欠片（SatchelShards）に入れるが、確保時の潜行ボーナスの対象にしない（`RunState` に「潜行ボーナスの対象外の欠片」を別に持つか、保管庫側の素材に直接入れる。後者でよい）。
2. **勇気の門で潜行が変わったら、Build を送り直す**：潜行が変わる出来事（CourageGate）の後は `ClientSession` 側で Build を dirty にする（`MarkDirty(true)` 相当）。出来事全般で dirty にしてよい。
3. **遺物の良さの比べ方**：`Relic.Score` を、レア度を最優先にする（例：`Rarity * 1000 + ItemLevel * 2 + Enhance * 10` のように、アイテムレベルや強化でレア度を逆転しない）。泉・鏡・祠・鞄あふれ・一覧の並びがこれに従う。
4. **錬金の釜**：作る遺物のアイテムレベルを、溶かした3つの最大のアイテムレベルにする（`p.BestItemLevel` ではなく）。
5. **依頼「レア以上を見つける」（Treasure）**：`AdvanceRelicBounties` でも進める（撃破以外で見つけた遺物も数える）。撃破時の二重カウントに注意。
6. **偉業の判定の抜け**：合成・製作・偉業の受け取り・遺物を手に入れる確認用コマンドの後にも `Feats.Check` を呼ぶ。さらに `Feats.Check` は「セットをそろえる」の判定（CompletedSets）を、保管庫が変わったときだけ数え直すようにキャッシュする（撃破のたびに数え直さない）。
7. **先制（OpeningStrike）**：HP の判定を、その攻撃が当たる**前**のHPで行う（命中後のHPを使っているなら、与えたダメージを足し戻す）。本体の DamageData・イベントの順序を逆コンパイル（`%LOCALAPPDATA%\sod-decomp\Dew.Core`）で確かめてから直す。確かめられなければ、そのまま報告する。
8. **ホスト側の無駄なメモリ確保**：`DamageAround` の一時リストと判定のクロージャを使い回す。スキル使用時の `new[] { Q, W, E }` を static readonly にする。`ScanArea` の配列とクロージャを使い回す。
9. **伝説のセット品を狙う依頼の出やすさ**：依頼「固有品を見つける」「セット品を見つける」は、遠征の開始時の潜行（今はいつも0）では達成がほぼ無理なので、`Bounties.Roll` で `PerRun` 個を選ぶとき、この2つの重みを下げる（他の依頼の 1/3）。
