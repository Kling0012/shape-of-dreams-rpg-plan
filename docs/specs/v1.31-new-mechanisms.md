# v1.31 canonical new mechanisms

Design contract; not an implementation-complete claim. Companion: [design review](v1.31-design-review.md). Cluster tables remain the value/consumer manifests. Their local M/N/Y/AU/B/H labels are references to the canonical contracts below, not independent systems or new enum numbers.

## Baseline, units, precedence

Current engine: `ClusterStarKind = MemoryDamage, MemoryHaste, GimmickBoost, GimmickParam, Notable, Choice, Stat` (`StarClusters.cs:7–8`); `Amount` and `GimmickDef.Value` are integers. Generated IDs are numeric list positions; Choice is exactly one rank; ordinary parameters apply memory-wide; ownership validation restricts memory regions to their route and Outer to hero routes. None of explicit suffix IDs, prerequisite predicates, ranked legacy choices, scoped receiver modifiers or new effects below is silently supported.

Protocol 11 already aggregates equivalent Links, has 512 gimmick entries and a 131,072-character Build limit (`Build.cs:221–243,309–310,348,435–436`; `Gimmicks.cs:106`). The historical 32/40 limits are not the current baseline. Existing engine examples are not the full design registry.

Authored percentages use percentage units:1 means1%; probability additions use percentage **points**. Typed `ValueUnits`, `ModifierUnits` and `ProbabilityUnits` store integer hundredths of a percent:1%=100units,100%=10000units. Convert once at generation, once to a float ratio at application; never mix authored coefficients with encoded units. Seconds/metres/target counts remain distinct types. C03 keeps0.01% resolution through aggregation/serialization; never floor a1% shield boosted by2% back to1%. Integer target/charge counts remain integer. Caps are maximums, not permission to leave paid inert stars.

Global invariants: Movement is a receiver only. The sole movement-event exception is the existing Husk keystone `h.husk.key2` (瞬歩の刃). Dark5/Light5/Cold1/Fire unlimited; MOD effects do not consume stacks. Generated gimmick, bridge and reaction damage is non-elemental, attack-effect coefficient0, and cannot start another gimmick/bridge/reaction or native stack gain/consumption. Genuine native payloads with a ReactionChain need an exact C02 adapter, not blanket acceptance of nonempty chains. Healing/shield dispatch starts at root `serverActor`, never the hero. Base-game healing, sacrifice, summons, charges and native constellation tradeoffs remain unchanged.

Calculation: authored base × ranks → sum genuinely equivalent Value contributions → one scoped GB multiplier → parameter changes → scoped keystone layer → final effect/pool caps. Native damage has its own MemoryDamage layer, optional RelayWindow layer and one keystone layer; generated damage is not re-amplified by native damage modifiers. Consumer-specific lower caps remain explicit table data. Wound Duration preserves baseline tick rate, not fixed total; final lifetime total ≤120% of max(AD,AP), including duration and keystones, with tick phase preserved. Sap≤15% (boss/miniboss half), ElementEdge≤40% per type/4 types, Ricochet≤50%, Primed≤120%; remaining existing caps come from `Gimmicks.Cap`. A duration/total tradeoff explicitly authored by a keystone is one final C07 transform, not a second general Wound runtime.

## C03 — FractionalScopedModifiers

**Depends:** C01/C02. **Kind:** aggregation and numeric model extension.

Fields: `ValueUnits`, `ModifierUnits`, `ScopeKind={Memory,EffectChannel,Receiver}`, `ScopeMemory`, `TargetEffectIds`, `TargetEffects`, `Param`, `CapProfileId`. Scope is explicit: no sender GB multiplied by receiver GB. Author ID-scoped Duration/Radius rows use EffectChannel, not today's memory-wide Param. Current MemoryHaste remains the existing **OnUse self-CD reduction**; passive haste is not an alternative interpretation. Fractional native damage additions use the declared cap profile; a separate star-only cap (e.g. Yubar120%) is a required extension, not a claim about today's equipped Links cap.

Canonical channel key: owner/source/trigger/effect/Arg/receiver/equipment predicates/pair-success ID/activation budget/clock policy/scope. Equivalent additive contributions form one Value and one firing; effects with different conditions, intervals, expiry or source are not merged. Cross-channel Sap/Expose/Wound keep strongest one. Separate Recharge requests compose multiplicatively; contributions explicitly belonging to one authored recharge channel add **before** that channel's multiplier. Serialize contributor identity when needed for expiry/refund/intervals.

Duration/Radius only modify meaningful fields. ExtraTargets does not boost native summon limits. Chance is percentage points: Element's guaranteed whole stacks remain, final extra-stack roll clamps to100%; ReceiverRecharge and PressureDividend have their own typed probability caps. Reload and whole target counts are not GB recipients. Internal cooldowns, Echo delay and native memory duration/radius are not Duration fields.

**Consumers:** every authored D/H/B/GB/P/GP/U/R/RB/RC/RH modifier, including Choice options; bridge boost families; `outer.*.{a3,b3,a4,b4}` and explicit GP options; fractional Cetus bridge `.choice`, Yubar0.5% entrances, all movement receiver modifiers. **Hook/evidence:** `DECOMP/Dew.Core/Actor.cs:1257–1265` takes float shields; `AbilityTrigger.cs:720–723` takes float ratio-derived time. `CORE/Gimmicks.cs:61–75`, `StarClusters.cs:31–43` currently use integers; current boost floor/parameter support are not this extension.

## C04 — DirectedRecharge

**Depends:** C02/C03. **Kind:** Notable payload extension; old RechargeTarget/ReceiverRecharge/Recv/T names are authoring references, not separate enums.

Fields: `SourceSelector={Memory,EquippedQ,EquippedR,EquippedIdentity,EquippedQOrR}`, `SourceTrigger`, `RecipientSelector`, `ValueUnits`, `ProbabilityUnits=10000`, `EveryN=1`, `Condition`, `Budget`, `ModifierScope`, `EquipmentEpoch`. Resolve selectors to actually equipped, nonduplicated instances; verify both ends at event and deferred dispatch. Movement may only be Recipient. Explicit Ultimate recipient is allowed; RechargeOther still means other equipped actual Normal memories, excluding Identity/Movement/Ultimate.

No time cooldown. Table lower cap80% remains where declared; otherwise a request≤100%. Each independent channel changes the **current** remaining cooldown: `Rafter = Rbefore × product(1-r_i)`. Equivalent contributions within one channel add first. Never add independent fractions and round to100%, never renormalize all channels to an event-wide fixed budget. EveryN has one counter per owner/channel; increment once per admitted C02 notification, fire at N and reset; unequip/death/zone clears, Build retransmission does not. Probability roll once per admitted notification, not per target when budget is activation-wide. Conditions such as changed target, element types or shielded state are typed predicates, not overloaded Arg meanings.

Adapter ratio is `remaining_current/max_current × r`; the base API applies that ratio to **all reducible configurations using each configuration's maximum CD**. It is not an API for individually reducing every config by its own remaining ratio. Respect canReceiveCooldownReduction, zero/full charges, actual maxCharges and processors. Charges are not directly incremented by this mechanism.

**Consumers:** all movement route seed/entry/choice/satellite families; Cetus `cetus.mem.frost-charge.c1..c4.*`, `cetus.bridge.b3/b4.*`, `cetus.outer.o4.*`; Vesper charge route and movement bridges; Lacerta nimble-dodge, Husk flash-step, Mist fast-feet, Yubar flicker families; `nachia.mem.dreamy-waltz.c1..c4.*`, `nachia.bridge.b3/b4.*`; `bismuth.mem.distorting-sprint.c1..c4.*` and bridges b2/b3; Aurena feathery-dash and return-path consumers. **Hook/evidence:** `DECOMP/Dew.Core/HeroSkill.cs:471–483`; `Actor.cs:1637–1639`; `AbilityTrigger.cs:702–747` (maximum-CD basis, config loop, permission, charge ceiling).

## C15 — EffectiveAllocationValidation

**Depends:** C01/C03/C07/C14. **Kind:** mandatory anti-inert purchase/refund validation.

Fields: `CandidateStarId`, `SelectedOption`, `OldEffectiveChannels`, `NewEffectiveChannels`, `PrerequisiteViolations`, `SaturatedChannels`, `AffectedRefundIds`, `RefundCost`. For a candidate or each rank, at least one declared effect must have a positive attainable marginal difference while its normal equipment/event conditions are met. Reject complete saturation, unsupported field, strongest-effect domination or a missing recipient/prerequisite. Do not reject normal combat unavailability (no enemies, full HP, temporarily full CD, currently un-equipped branch) as permanent inertness; the table remains a valid alternative build.

Choice/keystone/equipment changes exposing permanently disabled allocations require explicit atomic point refund before the new configuration is finalized. No auto-substitute effect/option and no paid dead weight. Refunds use original rank cost and preserve ID stability; prerequisites/reachability are reevaluated. This does not prove balance: it proves a purchased star can actually change a permitted output. Generation computes all table headroom, and UI shows exact cap/disabled IDs, not an unexplained purchase failure.

**Consumers:** every modifier/strongest-effect channel; especially capped Sap/Daze/ElementEdge sigils in Bismuth, Aurena zeroed Echo/Wound/Burst tradeoffs, the corrected Mist MemoryDamage-erasing key, Yubar separate D cap, and shared Outer probability/ward caps.

**Hook/evidence:** no base-game allocation hook for MOD stars. `DECOMP/Dew.Core/HeroSkill.cs:471–483` provides equipment facts; allocation/refund/choice are Core-owned. Existing engine parameter support validation checks an authored supporting effect exists somewhere, not whether the player has obtained it or a positive marginal benefit.

**Evaluation cost and the dependency rule:** a build is computed per marginal check, so a purchase must not re-check every allocated star. The preview builds the original and the proposed allocation once (recording which stars combine into which output in `StarDependencies`) and re-checks only stars that share an output with a changed star (rank, choice, refund, or a star whose reachability changed); every other star's verdict is provably unchanged, so the decisions are identical to checking all of them (the frozen original algorithm in `Testing/ReferenceEffectiveAllocationValidation.cs` and `AllocationEquivalenceV131Tests` enforce this, and `VerifyPruning` evaluates every skipped star in those tests). Keystone and equipment changes, and any refund under an allocated keystone, still check every star. **Any new code that combines several stars into one output (a total, a merged channel, a modifier/boost reaching a recipient, a bridge reading endpoints, a replaced star, a shared cap or strongest-effect comparison) must record it with `StarDependencies.Touch` at the place it combines them**; a missed join is the only way the analysis can hide a refund, and `AllocationEquivalenceV131Tests` has one cascade per existing kind of shared output.

**Cases:** weak Expose permanently dominated by mandatory stronger predecessor fails; GB1% on fractional Value1 gives positive difference; top-capped coefficient purchase rejects; selecting a key that disables already-paid Echo returns exact points and clears dependent-only routes atomically; full current HP/CD does not reject otherwise valid effect; choice option A saturated/option B effective→A refused but B available; no silent fallbacks.
