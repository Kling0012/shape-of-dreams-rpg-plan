### 各种类的最小可填写例子

下面是一张**合成演示表**，不是设计星注册或平衡建议。使用明确 ID、真实 common memory、现有 payload；可在使用 `SodRpg.Core.Game` 和 `System.Linq` 的 C# 方法中构建。Profile 必须先获得真实连接路径和点数，再经 C15 购买。注册 profile 一次，不要在每次 build 时重复注册。

```csharp
const string hero = "Hero_Cetus";
const string memory = "St_C_FlashFreeze";
const string anchor = "outer.example.s1";
FractionalScopedModifiers.RegisterCapProfile(new NativeStarCapProfile {
    Id = "example.native.damage", Kind = LinkKind.MemoryDamage,
    Maximum = ValueUnits.FromPercent(5m)
});
FractionalScopedModifiers.RegisterCapProfile(new NativeStarCapProfile {
    Id = "example.native.haste", Kind = LinkKind.MemoryHaste,
    Maximum = ValueUnits.FromPercent(5m)
});
FractionalScopedModifiers.RegisterScopedCapProfile(new ScopedModifierCapProfile {
    Id = "example.scoped.boost", MaximumModifier = ModifierUnits.FromPercent(10m)
});

AuthoredStarDef Node(string id, ClusterStarDef effect, string[] required = null) =>
    new AuthoredStarDef {
        HeroKey = hero, LocalStarId = id, ClusterId = "outer.example",
        Region = ClusterRegion.Outer, AnchorId = anchor, Shape = ClusterShape.Ring,
        RequiredStarIds = required ?? System.Array.Empty<string>(), Effect = effect,
        MemoryOwnership = new MemoryOwnership { TargetMemory = memory }
    };

// Stat：s1 自身有真实效果，不另造 anchor 占位节点。
var stat = Node(anchor, new ClusterStarDef {
    Kind = ClusterStarKind.Stat, Name = new Txt("霜の守り", "Frost Guard"),
    Stat = Stat.Armor, Amount = 1
});
// MemoryDamage：typed 百分比；不借用装备 Link 的上限。
var damage = Node("outer.example.damage", new ClusterStarDef {
    Kind = ClusterStarKind.MemoryDamage, Name = new Txt("霜の冴え", "Keen Frost"),
    Memory = memory, NativeModifier = new NativeMemoryModifierDef {
        Memory = memory, Kind = LinkKind.MemoryDamage,
        Value = ValueUnits.FromPercent(0.25m), CapProfileId = "example.native.damage"
    }
});
// MemoryHaste：使用这个非 Movement 记忆时缩短它自身的冷却，不是被动 CD 速度。
var haste = Node("outer.example.haste", new ClusterStarDef {
    Kind = ClusterStarKind.MemoryHaste, Name = new Txt("寒気の巡り", "Chill Cycle"),
    Memory = memory, NativeModifier = new NativeMemoryModifierDef {
        Memory = memory, Kind = LinkKind.MemoryHaste,
        Value = ValueUnits.FromPercent(0.5m), CapProfileId = "example.native.haste"
    }
});
// Notable / Gimmick：已有原生 Shield handler，值为最大 HP 的 1%。
var shield = Node("outer.example.shield", new ClusterStarDef {
    Kind = ClusterStarKind.Notable, Name = new Txt("霜の障壁", "Frost Shield"),
    Memory = memory, Gimmick = new GimmickDef {
        Trigger = GimmickTrigger.OnHit, Effect = GimmickEffect.Shield,
        Value = 1m
    }
});
// GimmickBoost：只增幅此记忆的 Shield；0.5% 是相对增幅，不是加 0.5 个 HP 百分点。
var boost = Node("outer.example.boost", new ClusterStarDef {
    Kind = ClusterStarKind.GimmickBoost, Name = new Txt("強まる障壁", "Stronger Shield"),
    Memory = memory, ScopedModifier = new ScopedModifierDef {
        ScopeKind = ScopeKind.EffectChannel, ScopeMemory = memory,
        TargetEffects = new[] { GimmickEffect.Shield },
        Amount = ModifierUnits.FromPercent(0.5m), CapProfileId = "example.scoped.boost"
    }
}, new[] { shield.LocalStarId });
// GimmickParam：按精确 star ID 定向 Duration，不扩大到同记忆的其他效果。
var duration = Node("outer.example.duration", new ClusterStarDef {
    Kind = ClusterStarKind.GimmickParam, Name = new Txt("長く残る障壁", "Lingering Shield"),
    Memory = memory, ScopedModifier = new ScopedModifierDef {
        ScopeKind = ScopeKind.EffectChannel, ScopeMemory = memory,
        TargetEffectIds = new[] { shield.LocalStarId }, Param = GimmickParam.Duration,
        Amount = ModifierUnits.FromPercent(0.25m)
    }
}, new[] { shield.LocalStarId });
// Notable / Power：使用现存 Barrier payload；没有声明新的 handler。
var power = Node("outer.example.power", new ClusterStarDef {
    Kind = ClusterStarKind.Notable, Name = new Txt("霜の護り", "Frost Ward"),
    Power = Power.Barrier, Amount = 2
});
// Choice：仅保存父节点 ID；必须明确提交选项 0 或 1。
var choice = Node("outer.example.choice", new ClusterStarDef {
    Kind = ClusterStarKind.Choice, Name = new Txt("霜の分岐", "Frost Fork"),
    Options = new[] {
        new ClusterStarDef { Kind = ClusterStarKind.Stat,
            Name = new Txt("霜の器", "Frost Vessel"), Stat = Stat.MaxHealthPct, Amount = 2 },
        new ClusterStarDef { Kind = ClusterStarKind.Notable,
            Name = new Txt("薄氷の障壁", "Rime Shield"), Memory = memory,
            Gimmick = new GimmickDef { Trigger = GimmickTrigger.OnHit,
                Effect = GimmickEffect.Shield, Value = 0.25m } }
    }
});
var defs = new[] { stat, damage, haste, shield, boost, duration, power, choice };
stat.Edges = defs.Skip(1).Select(d => new AuthoredStarEdge(anchor, d.LocalStarId)).ToArray();
var registry = StarClusters.GenerateAuthored(defs, HeroSigils.TreeFor(hero));
var tree = registry.TreeFor(hero);
var validator = new EffectiveAllocationValidation(tree);
Rules.RegisterAllocationValidation(hero, validator);
```

## C03：单位、范围、处理顺序

- `ValueUnits`：百分数的百分之一；`0.25% -> 25 units -> 250 ValueMilli`。`ModifierUnits` 同为百分之一，但表示相对 modifier。`ProbabilityUnits` 表示百分比点，范围 0..10000；`ExtraTargets` 为整数。
- `GimmickDef.ValuePrecise` 为百分数的千万分之一，解决 `0.25% × 1.005 = 0.25125%` 无法以 legacy thousandths 表示的问题。`Value` 是 exact decimal；读取不能精确表示的 `ValueMilli` 会抛错，绝不向零 floor。
- Build、codec、dispatch 保留精确值；只在原生 float API 应用边界转换。描述展示百分数、真实叠层/秩上限、费用与 applicable cap；Chance 明示 percentage points，目标数明示整数。
- 明确同 identity 的 channel：owner/source/receiver/trigger/effect/arg、装备条件、pair condition、budget、clock、scope/channel ID、参数和内在冷却均参与身份。旧未声明 channel 的不同 star 继续独立，不能凭同 memory/effect 合并。
- 顺序：同等 channel 贡献相加 → 匹配 GB 相加并执行 scope cap → 一次 GB → 匹配 GP 的每字段相加并执行 scope cap → key transform → final effect cap。不同 recharge channel 按当前剩余冷却依次缩短，故 `10 × 0.8 × 0.7 = 5.6s`，不把 20%+30% 拼成一次 50%。
- `ScopedModifierDef.CapProfileId` 可引用明确 `ScopedModifierCapProfile`。GB 使用 `MaximumModifier`；Duration/Radius 用同字段，Chance 用 `MaximumProbability`，ExtraTargets 用 `MaximumTargets`。GP scope cap 含 payload 已有参数。无 ID 表示现存默认参数/final-effect 限制；不是未声明新设计平衡值的兜底。
- 同接收字段存在冲突 profile、未知 profile、错误单位、低于 intrinsic 参数的 cap 都拒绝。Native MD/MH 的 `NativeStarCapProfile` 必须显式登记，且与装备 Link cap 分离；native MH 与装备 OnUse Link 在真实入口共享最终 100% 限制。
- `ScopeKind.Memory` 可覆盖该记忆正常适用的效果；`EffectChannel` 可按类型、ID 定向；`Receiver` 不能与 source boost 私自相乘。没有可达的已拥有 recipient 的 GB/GP 不可以买。
- Wound 以原 tick rate、原 phase 推进；延长 Duration 不降低 rate，结算末尾非整 tick，含 duration/key 的单次最终 lifetime budget 120% 不提高。

## C15：生产路径与事务

`EffectiveAllocationValidation(tree, policy, layout)` 使用同一个 `Build.ComputeForTree`、typed compose、key/final caps 结果；比较的是 attainable effective output，不是仅比较已填字段。

- 每次增秩必须有正的边际；部分触 cap 的秩可买，完全不增长的秩拒绝。保留实际 rank cost。
- 强制拥有且在相同 predicate/clock 下永远更强的 strongest 效果支配弱者；其他事件/记忆的正常可达条件不是永久支配。冷却目前未就绪、HP 满、记忆暂未装备不作为永久无效。
- key 永久禁用、recipient 改选消失、装备使最终 cap 吃掉增益、退款切断前提时，预览给出原费用与依赖闭包；没有明确批准不改变 profile。
- 只处理本次变更导致的 effective→inert 或 connected→disconnected；不把无关交易当存档迁移，顺手清扫原本 dormant/inert 的旧保存秩。
- `EffectiveAllocationPlan` 含 `CandidateStarId`、`SelectedOption`、old/new channels、前提违规、saturated IDs、`Refunds`、`AffectedRefundIds`、`RefundCost`。`SaturationDetails` 含星/秩/字段/单位/值/上限/支配值/profile，另保留 declared modifier ceiling hundredths/count。
- `Preview` 不写状态。`Commit` 验证 engine、完整原状态及准确批准 ID 集合；错误、少批、多批、stale plan 不部分应用。
- `AnalyzeHeadroom(profile, hero, attainableAllocation)` 枚举未分配选项与后续各秩；报告 reachable、可达有效秩数、实际费用、首个无效秩的 exact 诊断。工具须传入真实可达前提状态；locked 行 `Reachable=false` 不等于永久无效结论。没有枚举所有可能装备/未来数据机制并代替平衡审批。

```csharp
var change = new AllocationChange {
    Kind = AllocationChangeKind.Choice,
    CandidateStarId = "outer.example.choice", SelectedOption = 1
};
var preview = validator.Preview(profile, hero, change);
// UI 展示 preview.Refunds / RefundCost / SaturationDetails；用户可取消。
// 仅在用户明确批准整张退款计划后传这个准确集合。
validator.Commit(profile, preview, preview.AffectedRefundIds);
var report = validator.AnalyzeHeadroom(profile, hero, profile.Hero(hero));
```

`Rules.AddTalentRank`、`SetTalentChoice`、`RefundTalentRank`、`SetKeystone`、`Equip`、`Unequip` 已使用该引擎。UI 捕获 `AllocationValidationException.Plan` 可展示/批准退款；当前既有 UI 遇需批退款时拒绝变更，未新增自动选择或静默退款对话。

C07 等外部机制使用 `EffectiveAllocationPolicy.PermanentDisables` 与 `ApplyEffectiveTransforms`，并在星可购买之前 `Rules.RegisterAllocationValidation`。回调必须是实际运行时同一最终 capped transform；本次未编造 C07 payload/极性实现。原生记忆装备事实的接收者分析仍是未来原生装备事务集成的输入，不用 Core relic UID 冒充 native memory slot。
