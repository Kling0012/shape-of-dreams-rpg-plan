# v1.32「低レアの装備を増やす」設計書

利用者（設計者）の指摘（2026-10-03）：伝説の固有品は1190種あるのに、コモン〜エピックを担う土台は360種（各枠60）しかない。低レアは名前が繰り返され、レア度の違いは特性と固有効果の抽選結果だけになっている。低レアの**種類**と**集める物**を大きく増やす。

この文書は設計だけで、実装はしない。数は「相対的な比」までにとどめ、絶対的なドロップ率は書かない。

## 1. 現状（コードで確認した事実）

- `BaseDef`（`Content.cs:64`）は枠・系統（Line）・名前・基礎能力1つだけ。土台は6枠×60＝360。コモン〜エピックはこの360から等確率で選ばれる（`Loot.RollRelic` → `PickWeighted`、系統の狙いは2倍）。
- `RollBaseRelic`（`Loot.cs:126`）：特性はコモン1・アンコモン2・レア以上3。固有効果はコモン／アンコモンが0、レアが弱い1つ、エピックが範囲どおり1つと弱い1つ。エピックの名前は1つ目の固有効果の銘（`Epithets`）が土台名に付くだけ。攻撃力%・魔力%の特性と、条件付きの攻撃力・魔力の固有効果は、エピック以上だけ（`AffixDef.MinRarity`、`PowerAllowedForRarity`）。
- 伝説は `UniqueDef` 1190種（固定の土台・名前・2つの固有効果）。セットは `SetDef`（3点）。
- 1遠征で出る低レア（v1.30 の BalanceSim 結果）はおよそコモン4・アンコモン5・レア2〜3・エピック1〜1.5。つまり**低レアは1遠征に約13個**出るのに、見た目と名前の種類は各枠60しかない。
- 保存：`Relic` は土台ID・固有品ID・特性・固有効果の値をすべて保存している（`ProfileCodec.WriteRelic`）。読み込みは未知の土台ID・固有品IDで例外（`ProfileCodec.cs:521-524`）。図鑑は `Codex`（文字列の集合）で、土台ID／固有品IDを入れる。**図鑑の星ポイントは6項目ごとに1点・最大4点なので、すでに24項目で頭打ち**。図鑑が増えても強さには影響しない。
- アイコンは `icons/<土台ID>.png`（`RelicIcons.cs`）。固有品は土台のアイコンを使う。

土台を120にしない理由：アイコン・基礎能力の組・名前が各枠で120種あると、同じ基礎能力の重複が避けられず、見分けがつかない「水増し」になる。名前と見た目で区別できる上限は各枠100（家系10×各10）と見る。さらに増やす分は銘品（名前・一言・固有効果で区別できる物）に回す。

## 3. 推奨プランの数

### 3.1 土台（案A）：各枠60→100、計360→600（+240）

- 10家系 × 各枠10種。既存の60は家系にタグ付けするだけ（名前・基礎能力・IDは変えない）。新規は各枠+40、計+240。
- 家系（案）：無垢（Plain、色づけなし）／氷霜／炎／光／闇／守り／疾風／癒し／召喚／記憶。
- 同じ枠・同じ家系の中で、基礎能力（能力値と値）の組が重複しない。基礎能力は固定値か控えめな%（攻撃力%・魔力%は付けない）。
- 見た目：全部の土台に別のシルエット。同じ枠の他の家系と、形が似ない。

### 3.2 銘品（案B）：各枠60、計360

| レア度 | 各枠 | 計 | 固有効果 |
| --- | ---: | ---: | --- |
| アンコモン | 24 | 144 | 弱い固有効果1つ（範囲の下3分の1の値で固定）。条件付き攻撃力・魔力は不可 |
| レア | 24 | 144 | 中くらいの固有効果1つ（範囲の下半分の値で固定）。条件付き攻撃力・魔力は不可 |
| エピック | 12 | 72 | 1つ目は範囲の6〜7割の値、2つ目は下半分の値。条件付き攻撃力・魔力は1つ目だけ可 |
| 合計 | 60 | 360 | |

- 銘品は固定の土台・名前・一言（Lore）・固有効果を持つ。**特性は通常どおり抽選**（個体差は残す）。
- 土台は銘品の家系の傾向に合わせて選ぶ（例：氷霜の土台に冷気・シールド系の固有効果）。同じ枠の同じ固有効果の組を、銘品どうしで重ねない。
- 属性の上限（闇5・光5・冷気1・火は上限なし）、状態の重なりの上限は、既存の固有効果の定義がそのまま守る。銘品は既存の固有効果（88種）しか使わず、新しい仕組みを足さない。回避で発動する効果は使わない。
- **組（小セット）**：30組。2点の組が18（部位36）、3点の組が12（部位36）。計72部位（銘品の2割）。部位は同じ組に属する別の枠の銘品。
  - 組のボーナスは小さく：2点＝固定値か%の能力値1行（%は特性の最大値以下、固定値は特性の中央値以下）。3点＝加えて弱い固有効果1つ。
  - アンコモン・レアの部位を含む組は、攻撃力%・魔力%と条件付き攻撃力・魔力を一切使わない。全部位がエピックの組だけ、3点の固有効果に条件付きを使ってよい。
  - 攻撃力%・魔力%の合計上限120は変えない。銘品が追加する分は、エピックの条件付き固有効果の枠内に収める。

### 3.3 家系（案C）

- `BaseDef` に `Family`（列挙）を足す。家系ごとに「好む能力値」（4〜6種）と「好む固有効果」（4〜6種）の表を持つ。
- `RollAffix`：好む能力値の重みを2倍にする。**レア度の下限（`MinRarity`）の判定は今のまま先に行う**ので、アンコモン・レアに攻撃力%・魔力%は出ない。除外は変えない。
- 固有効果（`AddMinorPower` とエピックの1つ目）：好む固有効果の重みを2倍にする。`PowerAllowedForRarity` は先に通す。
- 無垢の家系は重みを変えない。**無垢の土台は、今の抽選と同じ乱数列で同じ結果になる**（回帰試験の基準）。
- 好みは「傾向」であって禁止ではない。好まない能力値も出る。

### 3.4 抽選（相対的な重み）

低レア（アンコモン・レア・エピック）で、枠を決めたあとの候補は「その枠の土台」と「その枠・そのレア度の銘品」。

- 土台：重み1（枠100種）。
- 銘品：1種あたりの重みをレア度ごとに定数で持つ（アンコモン2・レア3・エピック6、土台を1として）。結果として、その枠・そのレア度の抽選で銘品が出る割合は、アンコモンで約3分の1、レアとエピックで約5分の2。
- 図鑑にまだない銘品は3倍、始めた組の未所持部位は4倍（伝説の組の補助60倍より弱い。低レアは数が多く、頻繁に出るため）。
- 狙い系統（Line）は土台と同じく2倍。系統は銘品の土台の系統。
- コモンは土台だけ。伝説は今のまま。
- 双子の鏡（`Rules.cs:756`）・賭場（`:648`）など「同じ土台でレア度を上げる」処理：銘品の土台は同じだが、**銘品ではなく通常の遺物**として抽選し直す（固定の固有効果を持ち越さない）。
- 固有効果を交換する出来事（記憶の井戸・るつぼ）：銘品は固有品と同じ扱いで**対象外**（`Relic.HasFixedPowers` = `UniqueId != null || NamedId != null`）。再調律は特性だけを変えるので、そのまま使える。

### 3.5 図鑑（案D）

- 図鑑に2つの分類（銘品・組）を足す（`CodexCategory.Named` と `MiniSets`）。土台の分類は600項目、銘品は360項目。図鑑の総数は約1550→約2150（セットの部位を除く概算）。
- 図鑑の星ポイント（6項目で1点・最大4点）は変えない。もう24項目で頭打ちなので、図鑑が増えても強さには影響しない。
- 家系の完成：家系ごとの土台60種（6枠×10）のうち30種で称号「○○の見習い」、60種で称号「○○の名匠」。称号は見た目だけ。10家系で称号20。
- 組の完成：30組それぞれ、全部位をそろえた時に称号1つ（30）と、一度だけ星XP 20（星への供物の半分）。星XPの合計は最大600。多すぎると判断した場合は10に減らす（BalanceSim と星図の必要量で確認する。要確認）。
- 受け取り済みの記録は新しい集合 `Profile.CollectionClaims`（文字列）に持つ。

## 4. 保存と互換

- `Relic` に `NamedId`（文字列、既定は null）を足す。`ProfileCodec` は任意キー `"named"` で保存する。**古い保存には無いので null として読む。保存の版（`CurrentVersion = 3`）は上げず、データのリセットも要らない。**
- 銘品も土台ID・特性・固有効果を従来どおり保存しているので、**銘品の定義を後で変えても保存された個体の数値は変わらない**。名前・一言・組の判定だけが `NamedId` から引かれる。
- 読み込みで `NamedId` が定義にない場合は例外にせず、通常の遺物として読む（固有品と違って落とさない）。ただし土台ID（新規240を含む）は今のとおり未知で例外。**ID は追加のみ。変更・削除をしない**（ID 台帳の試験で守る）。
- 図鑑の文字列：土台と固有品は今のまま。銘品は `n:<ID>` の接頭辞を付け、固有品・土台のIDと衝突しない。
- `PlainName`：`NamedId` があれば銘品名。エピックの銘（`Epithets`）は付けない。
- 新しい `NamedDef`（`UniqueDef` に近い形）：`Id`・`BaseId`・`Rarity`・`Name`・`Lore`・`Powers`（1〜2）・`MiniSetId`（null 可）。`MiniSetDef`：`Id`・`Name`・部位ID（2〜3）・2点のボーナス（`StatLine`）・3点のボーナス（`PowerLine`、2点の組は無し）。装着中の組のボーナスは既存の `SetDef` の集計に並べて足す（別の集計で、重複して数えない）。
- 古い版のゲームが新しい保存を読む場合は、`"named"` を無視して通常の遺物として表示される（強さは保存した値のまま）。

## 5. 試験

1. **回帰**：無垢の土台で、同じシードなら今のコミットと同じ遺物（特性・固有効果）が出る。
2. 家系の色づけ：好む能力値が出やすくなる（相対的に）。アンコモン・レアに攻撃力%・魔力%の特性と条件付き攻撃力・魔力の固有効果が**決して出ない**（多数のシードで）。
3. 銘品の抽選：レア度・枠・系統の絞り込み、重み（定数どおりの比）、図鑑未所持の3倍、組の未所持部位の4倍。コモンと伝説に影響しない。
4. 銘品の生成：固有効果が定義どおり。特性がレア度の個数。固有効果の値が `PowerRange` の範囲内で、定めた帯に入る。
5. 保存：新旧の往復。`named` なしの古い保存の読み込み。未知の `NamedId`。未知の土台ID（例外）。強化・限界突破・覚醒・再調律を経た銘品の往復。
6. 固有効果を交換する出来事・双子の鏡・賭場・分解・鍵：銘品の扱い（対象外／通常に抽選し直す）。
7. 組：2点・3点の集計、重複しない、攻撃力%・魔力%の合計上限120に影響しない。
8. 図鑑：新しい分類、検索、称号の達成と受け取りが一度だけ。
9. データ検証（`tools/NamedVerifier`、次節）をCIで走らせる。
10. BalanceSim：装備のレア度の平均が v1.30 の結果と変わらない（±0.05）。銘品の装着率と、銘品が増えた分の戦力の伸びを、アンコモン・レア別に出す。

## 10. リスク

- **戦力の膨張**：アンコモンの銘品が固有効果を持つ。対策：下3分の1の値、条件付き攻撃力・魔力の禁止、BalanceSim でレア度別の伸びを確認する。逆転（アンコモンの銘品がレアの通常品を上回る）を検証ツールで拒否する。
- **ツールチップの混雑**：銘品の一言・組の進み・家系が増える。対策：一言は1行（全角30字以内）、組の進みは装着画面の既存のセット表示を使い回す。家系は紋章のみで文字は出さない（詳細は図鑑）。
- **図鑑の肥大**：約1550→約2150。対策：分類と絞り込みで見やすくし、未所持の銘品の名前は「？」で隠す。図鑑の星ポイントは頭打ちのまま。
- **水増しに見える**：同じ基礎能力・同じ見た目の土台。対策：検証ツールで基礎能力の重複を拒否、各枠100を上限とする。
- **収集が重い**：360の銘品。対策：未所持3倍、組の補助、称号は途中の段階（30種）でも出す。
- **抽選の乱数列が変わる**：固定シードの既存試験が変わりうる。対策：無垢の回帰試験を基準にして、変わる試験は意図を明記して更新する。

## 11. 最初の実装手順
