# v1.31 ビスマスの星団設計

対象は `Hero_Bismuth`。取得できる星は **735個**（共有外縁160個を含む）、始まりの星を描画上で数える場合は736個。本書で追加する星は510個、既存65個を保持する。本書の全体能力値だけの星は **0個**。設計値であり、実機で実装済みという意味ではない。

## 調査と戦い方

2026-10-03に `D:/app/stm/steamapps/common/Shape of Dreams/RawData/ja-JP/{travelers,memories,stars}.json` を読み取り専用で照合した。`loadoutTrait` は `St_D_PrismaticEyes` の1要素のみ。QとRは共通の4候補から異なる2つを装着する。本が基本攻撃を自動で行うことと、固有星座「本が紡ぐ物語」が記憶を自動発動することは別の仕組みである。どちらの場合も本書の命中・撃破条件は同じように働く。本人が通常攻撃を入力する条件、回避・ダッシュで発動する追加効果、アイデンティティ変更を要求する星はない。

コミュニティでは勇敢なる心を連続発動し、固有星座の障壁で守る構成に強い実績がある。[Steamのビスマス攻略](https://steamcommunity.com/sharedfiles/filedetails/?id=3571270789) と [最終ボスの攻略議論](https://steamcommunity.com/app/2444750/discussions/0/688615526773236070/) を確認した。ただし古い攻略には同一QRの2枚装着と回避による再充填が含まれる。本書では現在の指定に従い異なる2記憶を使い、その回避効果を追加強化しない。無垢な魂・業火物語の魔力型、勇敢なる心・歪な精神の攻撃力型、本の自動攻撃を軸にした属性支援を並列に設計する。現行環境でどの構成が最強かの順位は要確認であり、攻略の旧数値を設計値に転用しない。

計画、キット一覧、旅人調査、v1.28仕掛け仕様・表、v1.30合わせ技表、属性反応仕様、`Gimmicks.cs` と `GimmicksV129.cs`、`HeroStarRoutes.cs`、`HeroSigils.cs`、`HeroTreeLayout.BranchOrder`、`Content.cs`、列挙型の実際の定義元 `Ids.cs` を照合した。

## 数え方・値・接続の契約

- 新星はすべてランク1。Choiceの2選択肢は1星であり、ランク数・接続線・派生弾・条件分岐は星数に含めない。共有外縁は1旅人につき1回だけ数える。
- 新IDは `bismuth.mem.<slug>.c1〜c4.<suffix>`、橋は `bismuth.bridge.b1〜b8.<suffix>`、新刻印は `bismuth.key.<slug>`。省略記法は以下の表により一意に全IDへ展開できる。既存の `h.bismuth.*` は別IDとして維持する。
- 記憶の並びは **P → I → S → F → V → D → P**。各星団は対応する幹の第7星から分岐する。入口6星は `e1→e2→e3` と `e4→e5→e6` の2本。前者から `n1→a1→a2→a3→a4`、後者から `n2→b1→b2→b3→b4`。両方の末端から `q` に接続する。大星を迂回してパラメータだけ取る経路は設けない。
- 1星団は **入口6＋Notable2＋枝葉8＋Choice1＝17星**。fan/ring/chainは配置形状であり効果の違いを水増ししない。ringでも大星未取得の枝葉へ裏から入れないよう取得条件を保持する。
- `MD(M,x)` = MemoryDamage、記憶M由来の本来のダメージだけ+x%。`MH(M,x)` = MemoryHaste、M自身の発動によるM自身のCD短縮+x%。PはCDなしのためMHを置かない。**Sへ現行MHを使わない**。現行MHはOnUse処理であり、回避起点を禁止する本仕様と衝突するためである。
- `GB(M,x)` = GimmickBoost、その記憶の仕掛けValueを+x%。`GP(M,D/R/C/T,x)` = GimmickParamのDuration% / Radius% / Chanceの百分率ポイント / ExtraTargets。MがSの場合は後述の受信台帳だけが対象。仕掛けのない記憶を装着しただけで全体能力値が上がる効果はない。
- GBは加算して基礎Valueへ1回掛ける。C03で0.01%単位を保持し整数切捨ての無作用星を作らない。Elementは100ごとに1確定スタック＋端数抽選。GP(C)は端数確率へ百分率ポイントを加えて最終100%clamp、既存整数スタックを変えない（ちょうど100%の抽選は1確定と等価）。属性上限は変えない。
- GP(D)は実在する有益な時間窓のみ、GP(R)は実在する検索半径のみを伸ばす。Echoの0.3秒遅延・発動間隔をDurationで延ばさない。WoundはValueが継続時間全体の総量であり、通常GP(D)の対象から外す。Dazeは最終0.8秒まで、同じ敵に5秒の免疫、ボス・ミニボス無効を保持。RicochetのTは基礎1体→2体のみ。新規のT星は記憶につき1個で、最大2体を超えない。
- GB合計は記憶ごと最大+160%、通常のGP(D/R/C)は+100% / +80% / +40ポイントまで。この設計単体はその上限以下。効果ごとの既存上限も最終適用する。装備を含めて上限に達した場合、UIに実効値と超過分を出す。効果全体が無効な星は登録しない。
- `G(M,Trigger,Effect,Value,Arg,CD)` はそのままGimmickDefの完全指定。表中の `Hit/Kill` は `OnHit/OnKill`。記載のないOnUse・OnCritは加えない。すべてのGは元の記憶の命中だけを受け、仕掛け・反応・エッセンス派生ダメージを起点にしない。
- 火は無上限、闇5・光5・冷気1。属性は消費・移送・置換しない。ElementEdgeは最大4種類、Value最大40%、合計160%まで。追加ダメージは無属性・攻撃効果0で連鎖しない。Expose/Sap/Woundは同じ対象に最も強い1つだけ、時間を更新。ExposeはEclipseとも最大値1つ。障壁と回復は `ActorManager.instance.serverActor` 経由で旅人の付与通知を再発火させない。
- 普通ShieldはC06：所有者/受け手ごと残量maxの1枚、受け手HP15%上限、再付与は期限更新。Rampartは別に5体・10%・同時1枚。本体/装備/固有星座障壁はプール外。serverActorの実ハンドルを保持し、SetAmount再処理による二重増幅を避ける。回復は瞬間、HP上限まで、本体OverflowingLife等の既存挙動を無断抑止しない。

### 歪な疾走の4星団：受け手だけを伸ばす
