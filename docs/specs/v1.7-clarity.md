# v1.7 仕様B：画面と文章の分かりやすさ

担当：Codex（実装）。文言のレビューと実機の画面確認は Claude。

## 背景

実機の画面で見ると、説明が短すぎたり硬すぎたりして、何をすれば良いか・なぜそうなっているかが伝わりにくい。
例：セットの説明が「2点：火属性効果 +10%・攻撃力 +5%／3点：火種 30・烈火 50」となっていて、「火種 30」が何を意味するのか分からない。

利用者の指示：GUIの作り・遊び方・各仕組みの意図が分かるようにする。文章は自然な日本語にする。

## 文章の書き方（日本語）

- 体言止めや「・」で名詞を並べるだけの書き方を減らし、文として読めるようにする。
- 数値には意味を添える。「火種 30」ではなく「通常攻撃が当たると30%の確率で火を付ける」。
- 直訳調の言い回しを避ける（例：「〜を加えます」より「〜が手に入ります」）。用語はゲーム本体の表記に合わせる。
- 1文は短めに。説明が長くなる所は改行や箇条書きで区切る。
- 英語（`Loc.T` の第2引数）も同じ内容に合わせて直す。

## やること

1. **セットの説明**（`SetDef.Describe` 付近）
   - 2点と3点を別の行に分け、3点の固有効果は `Content.FormatPower`（または同等の文章）で「何が・いつ・どれだけ」起きるかを書く。
   - 装着画面では「いま何点そろっているか」と「次に何が起きるか」が分かるようにする（例：「残火の誓約 2/3　あと1つで：…」）。
2. **各タブの先頭に「ここでできること」**（装備・鍛冶・星図・工房・記録）
   - 1〜2文。例（装備）：「遠征で持ち帰った遺物を、旅人ごとに3つの枠へ装着します。遠征中は確保地点でだけ付け替えられます。」
3. **遊び方**（記録タブの「遊び方」）を次の順に書き直す
   - このMODの目的（本体の遠征に、持ち帰れる装備の育成が加わる）
   - 1回の遠征の流れ（倒す→拾う→ゾーンの入口で確保か潜行を選ぶ→持ち帰る）
   - 確保と潜行の考え方（安全に持ち帰るか、危険を取って良い物を狙うか。全滅したらどうなるか）
   - 装備の育て方（鍛冶・星図・刻印・工房の役割を1行ずつ）
4. **ようこその案内とヒント**（`Onboarding.cs` の文言）を、同じ書き方で自然な文に整える。内容（何を伝えるか）は変えない。
5. **確保地点の選択画面**：「確保する」「深く潜る」それぞれを選ぶと何が起き、何を失う危険があるかを1文ずつ添える。
6. **HUD**：「未確保」など初見で分かりにくい語に、短い言い換えを添える（例：「未確保（まだ持ち帰っていない）」）。表示が長くなりすぎないよう、簡潔表示（Compact）では従来どおり短くてよい。
7. その他、画面に出る日本語で明らかに不自然なものを直す。固有品・セット・刻印の**名前**は変えない。

## 守ること

- 性能：OnGUI の中で毎フレーム文字列を組み立て直さない。既存のキャッシュ（HUDの文字列キャッシュなど）を壊さない。長い説明文は静的な文字列か、内容が変わったときだけ作り直す。
- 本体のマネージャーは `.instance` ではなく `.softInstance` で参照する（`.instance` は不在時に毎回 `FindObjectOfType` を走らせ、重くなる原因だった）。
- ルール・数値（ドロップ率や価格など）は変えない。今回は文章と表示だけ。
- 試験は追加・変更しない。文言の変更で落ちる既存の試験があれば、ファイル名と試験名を一覧にして報告する（Claude が直す）。
- `dotnet build src/SodRpg.Mod -c Release` はゲームが無い環境では参照不足で通らないことがある。その場合は `dotnet build src/SodRpg.Core` と `dotnet test tests/SodRpg.Core.Tests` を確認し、MOD側は変更箇所を目視で見直す。
