# #461 戦闘中の処理・通信削減と実機確認

## 実装

- `NativeActorLifetime` は異常時だけ `Lifetime` を作る。異常記録が0なら弱参照表を参照しない。正常復帰と `Actor.OnDisable` で記録を外す。フレーム側は既知の異常だけを止め、victim/caster の `activeInHierarchy` 判定は `Actor.LogicUpdate` に集約する。クライアントの未解決参照と、一時的に非表示の生存victimは更新を保留し、永久破棄しない。既存のdespawn・cleanup・Sanctification作成時の保護は残す。
- 回復・シールド・属性撃破は英雄別に固定長のカウンターへ蓄積し、ホストtick末に送る。元素は元の4ビットマスク別に数え、複数元素の撃破を保持する。解除・本体保存・終了・ロビー帰還前にも残りを送る。
- 数つきの任意メッセージは、受信登録に成功し `bountyCounts=1` を広告した参加者にだけ送る。ローカルホストも同じtransportでの受信登録成功を確認する。未広告・旧版・登録失敗時は従来パケットを各1件へ展開する。旧支援パケットの `value=1`、Helloの固定schema、Protocolは変えない。カウンター加算は既存の依頼進捗上限・達成済み判定を使う。
- Waypoint名簿は所有者の2つの集合を再利用する。呪い再同期はrun・hero・authorityの値比較を使う。
- 低品質死亡FXのLightとFxPointLightの配列はGameObjectを弱キーとして保持する。同じインスタンスの再利用時は再検索せず、破棄済み部品は無視する。
- 決闘者・突破・前衛・後衛・見守りの事実取得は、それぞれの能力を持つ場合に限定する。ビルドから毎回判定するため能力の取得・解除も追随する。
- 魂の祠はActorManagerの追加・除去で追跡し、managerが変わった初回だけ既存Actorを取り込む。ボス戦／魂待ち以外は判定しない。Continue以前に生成済みの祠も初回取り込み対象に含める。
- HUDの全リソース検索は起動後／シーンロード後の1回に限定する。後から生成されたHUDは既存のAwake hookで処理する。追補 #470 では設定変更・強制更新時にも再検索を許可した。配列所有権・受信解除通知・参照箇所の点検と実機確認項目は [#470 の記録](issue-470-combat-followup.md) を参照。

## 実機計測手順（R12 / R19、未実施）

1. 同じPC、ゲーム版、1920x1080、描画品質、エフェクト品質、MOD設定、フォーカス状態で比べる。vSyncとFPS上限は揃え、制限で差が隠れない条件にする。機種・CPU/GPU・解像度・品質・vSync・上限値・ゲーム版・MOD版を記録する。
2. 比較条件を「MODなし」「変更前MOD（2489166）」「変更後MOD」の3つにする。MODなし比較はMOD全体の費用、変更前後比較は今回の差を見る。セーブを複製し、同じマップ・人数・ビルド・敵種・状態異常数・操作を可能な限り揃える。MODなしで完全同一条件を作れなければ差分を記録する。
3. 敵60体前後が生存する戦闘区間を選び、30秒のウォームアップ後に60秒以上を各条件3回計測する。条件の順番を入れ替え、ロード・メニュー・終了のフレームを除外する。敵数、状態異常数、同時支援回数を各試行に残す。
4. Unity Profilerまたは同じ外部フレーム計測器でフレーム時間の中央値・p95・p99・最大、Main Thread CPU時間、GC Alloc/frameとGC回数を記録する。GPU制約で差が見えない場合はその旨を残す。`dreamforge_perf` は補助情報として同じ条件で採取するが、Harmonyで差し込んだ本体メソッドの費用すべてをMOD Update時間だけで評価しない。
5. Profilerで `Actor.LogicUpdate`、`Actor.FrameUpdate`、`StatusEffect.FrameUpdate` を確認する。正常な状態異常でLifetime生成がなく、フレーム側の `activeInHierarchy` 呼出しが消えたことを確認する。深い計測の有無を揃え、通常計測と別に記録する。

## ゲーム内の動作確認（未実施）

- 状態異常：通常の付与／時間切れ／victim死亡／despawn／部屋切替／pool再利用。クライアントでvictim参照が遅れて届く場合と、victimを一時的に非表示にして戻す場合に効果が再開すること。Sanctificationのbeam/caster消失で例外や演出残留がないこと。生存確認を本体の約30HzのLogicUpdateへ移したため、フレーム途中で失効した対象の検出が次のLogicUpdateまで遅れる点を重点確認する。
- 支援と属性撃破：同じtickに複数回発生させ、依頼進捗と報酬が逐次処理と同じこと、複数元素を持つ撃破が各元素へ加算されること。ソロ／ホスト／新版参加者／旧版参加者／旧版ホストと新版参加者で確認する。新版同士は英雄あたり通常tickに1通、旧版向けは従来形式の件数が送られること。最後の支援直後に保存・勝利・純白の主撃破・ロビー帰還を行い、最後の報告が精算前に反映されること。
- 周囲走査：関連能力なし、決闘者のみ、突破のみ、前衛／後衛／見守りそれぞれ、途中取得・解除、味方の死亡・復活で効果と対象が従来どおりであること。
- 魂の祠：初回ボス、同managerで次のボス、ボス撃破後の遅延spawn、Continueで既に存在する祠、祠除去、次の部屋・遠征への移動。検出・選択への移行に漏れがないこと。
- HUDと死亡FX：タイトル／ロビーに留まっても毎秒全検索しないこと、シーン移動後と遅延生成HUDで拡張が反映されること。低品質で同じ敵のpool再利用を繰り返しても死亡光を再検索せず抑制できること。設定切替・破棄・再生成時にも例外がないこと。
