## 1. 敵の定義・出現の仕組み（本体）

### 1.1 クラス構成
- `Monster : Entity`（Dew.Core）。フィールド: `MonsterType type`、`chaseRandomness`、`chasePredictiveness`、`disableLoot`、`List<MonsterAbilityPool> abilityPools`。プロパティ: `populationCost`（SyncVar）、`isHunter`（SyncVar）、`campPosition`、`selectedPool`、`defaultOwner`、`spawnPosOverride/spawnRotOverride`。`OnStartServer/OnCreate/AIUpdate(EntityAIContext&)/PoolAIUpdate` を持つ。
- `Monster.MonsterType`（byte enum）: Lesser / Normal / MiniBoss / Boss。（Core の `MonsterTier` へは `Math.Min(Boss, (int)m.type)` で対応）
- `BossMonster : Monster`（`isHiddenBoss`、`GetUniqueReward()`、`GetUniqueRewardChance()`）。既存の悪夢化は BossMonster を除外。
- 具象は Dew.Contents に約120型 `Mon_<Zone>_<Name>`。通常敵の例:
  - Forest: Hound, Scarab, SpiderSpitter, SpiderWarrior, Treant
  - DarkCave: CaveBat, CaveSpider, DarkElemental, NightOlm, Oppressor
  - Despair: Displacer, DreadBug, ParalyticFly, UnstableRat, WretchedArtillery
  - SnowMountain: IceElemental, LivingShards, Scavenger, SnowWolf, VikingWarrior
  - LavaLand: FireElemental, InfernoSpider, Magmadon, SuperheatedWolf
  - Ink: Archer, DivineAnimal, GhostBlade, GhostSpear, Tiger, EgoSword
  - Sky: Baam, BigBaam_*, LittleBaam, StarSeed, StellaMatter
  - 特殊: GoldenLizard_ElusiveLizard, MorasDomain_NightmareBlob, RedGiant, RedMan, Mon_Special_AmbushSpawner
- `Dew.allMonsters : IReadOnlyList<Type>` で全モンスター型を列挙できる。`Dew.IsMonsterIncludedInGame(string, DewGameContentSettings)`。
- 能力: `EntityAbility.attackAbilityPreset : AssetRef<AttackTrigger>` / `abilityPreset : AssetRef<..>[]`。モンスターは `abilityPools[].abilities[] : PoolAbilityInfo { triggerPrefab(AssetRef<AbilityTrigger>), chance, healthConditionEnable, normalizedHealthRange }`。実行時は `EntityAbility.AddAbility<T>() / SetAbility(int, AbilityTrigger) / SetAttackAbility(AttackTrigger)`。
- 行動: `Mon_*.AIUpdate(EntityAIContext&)` をオーバーライド。補助は `EntityAI.Helper_CastAbilityAuto / Helper_ChaseTarget / Aggro(Entity,bool)` など。
- ミニボス化: `ISpawnableAsMiniBoss`（`OnBeforeSpawnAsMiniBoss`, `OnCreateAsMiniBoss`, 静的 `GiveGenericMiniBossBonus(Entity, float)`）。付与される効果は `MiniBossEffect : StatusEffect` の派生: `Se_MiniBoss_BloodThorn / IceAura / OrbSpitter / SpinningArrow / UnstableExplosive`。

### 1.2 出現（スポーナ・部屋・波）
- `Room` → `Room.monsters : RoomMonsters`（RoomComponent）。主要API:
  - `SpawnMonsters(SpawnMonsterSettings)` / `UniTask SpawnMonstersAsync(...)`、`SpawnMiniBoss(settings, Entity, StatusEffect)`、`SelectMiniBoss(ref Entity, ref MiniBossEffect, DewRandom)`、`OverrideMonsterType(Monster)`、`FinishAllOngoingSpawns()`、`RemoveAllCamps()`。
  - 倍率フィールド: `spawnedPopMultiplier`、`maxPopulationMultiplier`、`addedMirageChance`、`addedHunterChance`、`campDensity`、`campPopulation`、`disableMiniBossRewards`、`disableEnvSpawn`、`envSpawnPoolOverride`。
  - フック: `SafeAction<Entity> onBeforeSpawn / onAfterSpawn`（ホスト側。出現の前後に全敵へ介入できる）。
- `SpawnMonsterSettings`: `hero, section, rule, monsterSpawnData, beforeSpawn(Action<Entity>), afterSpawn, spawnPopulationMultiplier, initDelayFlat/Multiplier, spawnPosGetter(Func<Vector3>), spawnRotGetter, onFinish, earlyFinishCondition, ignoreTurnPopMultiplier, ignoreCoopPopMultiplier, random, positionRandom`。`Clone()` あり。
- `MonsterSpawnRule`（ScriptableObject）: `pool: MonsterPool`、`initialDelay`、`isBossSpawn`、`wavesMin/Max`、`populationPerWave`、`nextWavePopulationThreshold`、`waveTimeoutMin/Max`、`spawnMin/MaxDistance`、`onOverPopulation: OverpopulationBehavior`、`stallCancelTimeout`。
- `MonsterPool`（ScriptableObject）: `entries: List<SpawnRuleEntry>`。`SpawnRuleEntry { AssetRef<Monster> monster, chance, minCount, maxCount, conditions(List<MonsterSpawnCondition>), useAnd }`。条件 `MonsterSpawnConditionType`: CurrentZoneClearedNodes / GlobalRoomIndex / ActivatedCombatAreas。
- 人口（population）制: 各 Monster の `populationCost` を波の `populationPerWave` に対して消費。`DewDifficultySettings.maxPopulationMultiplier`、`Se_HunterBuff.populationMultiplier`、`LucidDream_Overpopulation.popMultiplier` が倍率として効く。
- 部屋修飾（敵に効く）: `RoomModifierBase`（`ModifyEntities(Action<Entity> onStart, Action<Entity> onStop)`、`spawnType`、`chance`、`allowedZones`、`zoneIndexRange`）。派生: `RoomMod_Ambush`（`ContributeMonsterPrewarm`）、`RoomMod_ChallengingFight`（`addedMirageChance`, `spawnedPopMult`）、`RoomMod_SpawnMiniBoss`（`GetMiniBossCount`）ほか。
- 本体の「敵が敵を呼ぶ」例: `Ai_Mon_Despair_BossAzurak_SpawnMonsters`（`spawnCount/spawnInterval/spawnRadius`）、`Ai_Mon_Forest_SpiderWarrior_SpawnScarabs`、`Mon_Special_AmbushSpawner`。能力から子を出す際の標準手段は `Actor.SpawnEntity<T>(T entity, Vector3 pos, Quaternion? rot, DewPlayer owner, int level, Action<T> beforeSpawn)`。

### 1.3 プレハブ検索（DewResources）
- 全て `DewResources`（静的）経由。使える検証済み関数: `GetByType<T>() / GetByType(Type)`、`GetByShortTypeName(string)`、`GetByName(string)`、`GetByGuid(string)`、`FindAllByType<T>()`、`FindAllByTypeSubstring(string)`、`FindAllByNameSubstring(string)`、`FindOneByIdSubstring`、`GetNetworkedPrefab(uint id)`、`GetNetworkAssetId(string guid)`、`Preload(guid)`。
- 既存MODは `DewResources.FindAllByType<MirageSkinEffect>()` を使用済み（HostAuthority.AttachMirageSkin）。モンスター型でも同じ要領。
- `DewResourceDatabase` が `netObjectAssetIdToGuid`、`guidToNetAssetId` を持つ。つまりネットワーク対象プレハブは「assetId(uint) ↔ guid」で管理される。

### 1.4 Hunter とエリート（MirageSkin ほか）
- ハンター: `Monster.isHunter`（SyncVar）、`HunterStatus`（None/AboutToBeTaken/Level1-3）、`ZoneManager.hunterStatuses`、`AdvanceHunterTurn`、`currentHuntLevel`、`DewDifficultySettings.hunterSpreadChance`。付与効果は `Se_HunterBuff`（`populationMultiplier, movementSpeedPercentage, attackSpeedPercentage, abilityHaste, shadowWalk*`, `enableGoldAndExpDrops`）。`RoomMonsters.addedHunterChance`、`Ai_HunterArtillery_Big/Small`、`Rev_KillHunters`。
- MirageSkin（本体エリート）: `MirageSkinEffect : StatusEffect`（`tier, maxHealthRatio, shieldMaxHealthRatio, enableSpecialAttack, specialAttackInterval(Vector2), allowWhenChanneling, breakStunDuration, fxBreak, customAmount(float?)`、`OnSpecialAttack()`）。派生（tier別は FindAllByType で取れる。既存MODが tier0/tier1 に分けている）: `Se_MirageSkin_Armor / Delusion / Oblivion / Oppression / Pulverization / Sanctification`。専用攻撃 `Ai_MirageSkin_*`。
- 抽選: `GameMod_MirageSkin`（`baseChancesByPlayerCount[]: MirageSkinChancePerPlayer{zone0..zone5}`、`GetCurrentBaseMirageChance()`、`currentZonePool`）。`GameMod_Limbo.d4MirageSkinChance` で Limbo 深度4以降の増加。
- 見た目: `EntityVisual.mirageSkinObjects`、`MirageSkinDecoObject.targetEffect`。

### 1.4b ステータスと難度スケーリング
- `EntityStatus`: `baseStats: BaseStats`（attackDamage, abilityPower, maxHealth, healthRegen, armor, critChance…）、`scalingStats / bonusStats: BonusStats`（`maxHealthPercentage, attackDamagePercentage, attackSpeedPercentage, movementSpeedPercentage, armorFlat, abilityHasteFlat, tenacityFlat, attackRangePercentage, *EffectAmp` 等）、`finalStats: FinalStats`、`AddStatBonus(StatBonus)` / `RemoveStatBonus(StatBonus)` / `MarkStatsDirty()` / `SetHealth(float)`。`StatBonus` は `StatusEffect.DoStatBonus()` でも作れる（効果が消えれば外れる。永続させたい敵には `AddStatBonus` が簡単）。
- 本体の倍率: `GameManager.difficulty : DewDifficultySettings`（`enemyHealthPercentage, enemyPowerPercentage, enemyMovementSpeedPercentage, enemyAttackSpeedPercentage, enemyAbilityHasteFlat, miniBossArmor, heroicBossArmor, healthFactorBeforeLoop/AfterLoop, damageFactorBeforeLoop/AfterLoop, maxPopulationMultiplier, hunterSpreadChance`）。`GameManager.GetRegularMonsterHealthMultiplierByScaling(float zoneIndex)` 等（Regular/MiniBoss/Boss × Health/Damage の6種）、`GetMultiplayerDifficultyFactor(bool reduceWhenDead)`、`ambientLevel`。`IMonsterNoScaling` を実装した型はスケーリング対象外。
- Limbo: `GameMod_Limbo`（`depth` SyncVar、`atkMovSpdPerDepth(+Max)`、d1 `skillHaste/huntSpeedAmp`、d2 `damageAmp/armor`、d3 `goldPriceAmp/expReduction/shieldReduction`、d4 `mirageSkinChance/elementalDurationAmp`、d5 `bossAtkSpd/bossMovSpd`）。本MODの「夢の深度」(Heat 0-5, Content.MaxHeat=5) とは別系統で、Limbo 深度は本体側が敵を強化する。
- 重要: 既存MODの深度は「プレイヤーが受けるダメージ増（防御-6・最大HP-4%/段）」で表現し、敵側の底上げは悪夢化のみ。プレイヤー側成長（6枠・334固有・星図・覚醒）に対し、敵の基礎値はレベルや深度で伸びない。ここがバランスの穴。

## 2. ホストが実行時に安全にできること

前提: 既存の HostAuthority は `ActorManager.ClientEvent_OnEntityAdd` で全敵を捕捉し、`StatBonus` と `CreateStatusEffect` を適用済み（実運用で動作確認済みの経路）。同じ経路を拡張するのが最も安全。

### 2a. 追加の本体モンスターを出す
- 高水準（推奨）: `Room.monsters.SpawnMonsters(SpawnMonsterSettings)`。人口・位置・遅延・波が本体と同じ扱いになる。`rule`（MonsterSpawnRule）と `monsterSpawnData` が必要なので、現在の部屋の既存ルール（`RoomMonsters.defaultRule` か、進行中の `ongoingSpawns` のキー設定）を `Clone()` して `beforeSpawn/afterSpawn` で加工するのが無難。`spawnPopulationMultiplier` で増援量を調整。
- 低水準: `Dew.SpawnEntity<Monster>(T prefab, Vector3 pos, Quaternion? rot, Actor parent, DewPlayer owner, int level, Action<T> beforeSpawn)`（静的）。プレハブは `DewResources.GetByType<Mon_Forest_Hound>()` 等。owner は `DewPlayer.creep`（敵陣営）。`level` は `GameManager.ambientLevel` が候補（未検証）。サーバ専用: クライアントでは呼ばない。ネットワークは本体が内部で Mirror の `NetworkServer.Spawn` 相当（`PrepareAndSpawnActor_Imp`）を行うので、MOD が自分で `NetworkServer.Spawn` を呼ぶ必要はない（プール再利用 `reuseInRoom` も本体が管理）。
- 注意: 人口外で出した敵は部屋クリア判定（出現完了と全滅）に影響しうる（未検証）。通常の `SpawnMonsters` 経由なら安全。直接 SpawnEntity で出す敵は「部屋の戦闘が終わらない」「クリア後に残る」ケースがあるので、`section`/`isSleeping`/`disableLoot` を実機確認する。報酬は既存の悪夢化と同様に MOD 側で `RewardTier` 抽選しているので `disableLoot` との整合を取る。

### 2b. 既存モンスターの改変
- ステータス: `m.Status.AddStatBonus(StatBonus)`（実績あり）。`BonusStats` の項目は上記。ベース値自体は `Status.NetworkbaseStats`（SyncVar、setter あり）。現在HPは `Status.SetHealth`。
- スケール: `EntityVisual.GetNewTransformModifier()` → `EntityTransformModifier.scaleMultiplier` / `localOffset`、`Stop()` で解除。ネットワーク同期されるか未確認（`GetNew*` に Local 接尾辞が無い）。同期されない場合の保険: 既存の `DreamforgeNightmareMsg` と同様に MOD RPC（`CustomRpc_SendMessageToAllClients`）で netId→見た目コードを配り、各クライアントで `ActorManager.allEntities` から該当 Entity に modifier を適用する。
- 色: `EntityVisual.SetShaderProperty(string key, Color value)`（ネットワーク版、ローカル版 `SetShaderPropertyLocal` もあり）、`GetNewColorModifier()`（`baseColor, emission, opacity, dissolveAmount`）、`GetNewShellModifier()`（`color, opacity`: 輪郭シェル）、`Visual.renderers`（Renderer リスト）。Unity 標準の `MaterialPropertyBlock` を `renderers` へ直接使うのはクライアントごとのローカル操作。色は ColorModifier が本体流で最も安全。
- 状態異常/エリート効果: `Actor.CreateStatusEffect(Type, Entity victim, CastInfo, Action<StatusEffect>)`（実績あり）。付けられる既存効果の候補: MirageSkin 全種、`Se_MiniBoss_*`（5種）、`Se_HunterBuff`、`Se_Curse_*`、`Se_GenericShield_OneShot`（`GiveShield`）、`Se_GenericStealth`（`ApplyStealth`）、`CreateBasicEffect(victim, BasicEffect, duration, id, DuplicateEffectBehavior)`（汎用: スロー/スタン/沈黙等）。
- 能力変更: `Ability.AddAbility<T>() / SetAbility(index, trigger)`、`SetAttackAbility`、`Status.DoAttackOverride`、`StatusEffect.DoAbility(Func<AbilityTrigger,bool>, Func<AbilityTrigger,Action>)`。他種のスキルを流用して追加するなら、`DewResources` から AbilityTrigger のプレハブを取り `Dew.CreateAbilityTrigger<T>()` する。敵がそれを使うかは AI 次第（`Monster.AIUpdate` が呼ぶ能力は `abilityPools/selectedPool` 管理）。確実に動かすなら StatusEffect 内の `ActiveLogicUpdate(dt)` でタイマー駆動（MirageSkin の特殊攻撃がこの方式）。
- イベントフック: `Entity.EntityEvent_OnTakeDamage`、`EntityEvent_OnDeath`、`Actor.ActorEvent_OnDealDamage`、`takenDamageProcessor / dealtDamageProcessor`（`DataProcessorGroup<DamageData,Actor,Entity>`）。ここで「特定の戦い方への対策」（被ダメ上限・反射・無効化）を実装できる。
- 敵を MOD 側で作る StatusEffect/Actor 派生の型は、MOD アセンブリ内の C# クラスとして実装できるか（Mirror のネットワーク型登録・プレハブが要る）が不明。Actor 派生はプレハブ（NetworkIdentity）が必要なので、MOD 内に新規 StatusEffect 型を作って `CreateStatusEffect(Type…)` に渡す方式は未検証で危険。既存の本体型の組み合わせと、MOD 側のタイマー処理（HostAuthority 内の Update ループ）で実現するのが安全。

### 2c. 「新しい」モンスターを既存プレハブから作る
- 方式: 本体プレハブ（例 `Mon_Forest_Hound`）を `SpawnEntity` し、`beforeSpawn` / `afterSpawn` で `AddStatBonus`、色・スケール、名前札、効果付与を行う。
- 名前: Entity は `GetActorReadableName()`。既存MODは頭上名札を HostAuthority→`DreamforgeNightmareMsg`(netId, affixes) → ClientSession で表示している。新規種は同様に `DreamforgeVariantMsg(netId, variantId)` を足し、クライアントが名札・色・スケール・説明を適用する。
- 見た目差分は「色相・スケール・シェル（輪郭）・エフェクト（fx）」が限界。メッシュ・アニメは変えられない。
- 利点: Mirror のプレハブ登録が不要。全クライアントは本体プレハブを知っているので、MOD を持たないクライアント（ホストのみMOD）でも同期上の不整合は出ない（見た目の名札と色だけ欠ける）。
- 本体の `DewMod.RegisterJsonOverride(...)`（`jsonOverrideTargets`）という JSON によるプレハブ値上書き機構もある。敵の数値（ability の field 等）を直接書き換える手段になり得るが、型ごとの JSON 形式が未検証。調査価値あり（`DewMod.BuildJsonOverrideOriginal(typeName)` で元値を出せる）。

### 2d. カスタム3Dモデル（Blender / AssetBundle）
実現性: 見た目だけの追加は技術的に可能だが難度は高い。完全に新しいネットワーク同期キャラの追加は、本体のリソース DB・プール・Mirror のプレハブ登録に自前で割り込む必要があり、現時点では高リスク。

- AssetBundle 読み込み: `AssetBundle.LoadFromFile(path)` は Unity の標準 API。MOD フォルダに同梱可能。ただしバンドルは「このゲームと同じ Unity バージョン（要確認: `Shape of Dreams_Data/globalgamemanagers` のバージョン）」かつ互換ターゲット（Windows）で、かつ Unity エディタでビルドする必要がある。シェーダー（本体の URP/独自シェーダー）を参照する Material は、バンドルに含めるか、実行時に本体のマテリアルへ差し替える必要がある。Mac/Linux 向けには各 OS 用にバンドルが要る（AGENTS.md の複数OS前提と衝突）。
- 本体のモデル経路: `Entity.LoadEntityModelLocal()`、`EntityVisual.LoadModelLocal(EntityModel m)`、`EntityVisual.model`。つまりモデルは「各クライアントがローカルで読み込む」設計で、Entity 自体（ネットワークオブジェクト）とモデルが分離している。これは追い風。方針: 敵は本体プレハブで出し（Mirror 登録不要）、各クライアントで `LoadModelLocal(customEntityModel)` を呼んで見た目だけ差し替える。メッセージは `DreamforgeVariantMsg(netId, modelId)`。
- 必要部品: モデル側に `EntityModel` コンポーネント（`bodyRenderers, healthBarPosition, idle/stagger/death の AnimationClipWithSpeed, locomotion の run* クリップ, fxDeath, customMappings`）が要る。AnimationClip と Humanoid か Generic リグの互換が必要。本体能力のアニメ（`PlayAbilityAnimation(DewAnimationClip…)`）の置換 `abilityAnimationReplacements` も要る。つまりアニメ制作工数が大きい。
- Mirror 登録を伴う完全な新規モンスター: 新プレハブは `NetworkIdentity` を持ち `NetworkClient.RegisterPrefab(go, assetId)` で全端末が同一 assetId で登録する必要がある。さらに本体は `DewResourceDatabase.netObjectAssetIdToGuid / guidToNetAssetId` と `DewResources.GetNetworkedPrefab(uint)` でアセット解決するため、本体DBに入れないと Dew.SpawnEntity、プール、room 保存（`ShouldBeSavedWithRoom`）、再読み込みで不整合が出る恐れ（未検証）。`Monster` 派生型は MOD アセンブリに置けるか、Mirror の Weaver（IL 書き換え）が MOD の DLL に走らない点も問題（SyncVar/Rpc が使えない）。結論: 新規 Monster 型は避け、既存型のプレハブへモデルだけ差す。
- マルチプレイ制約: 全員が同じ MOD とバンドルを持つ前提（既存MODはホストにだけ必須）。モデルを差す場合は「各クライアントがバンドルを持っているか」を MOD バージョンメッセージ（Protocol.Version）で確認し、持たない者には色替えのフォールバックを使う。
- アセット配信: Steam Workshop は MOD フォルダ全体を配るので、バンドルも同梱可能（`about/metadata.json` と同じ階層）。

## 3. 敵側のバランス調整レバー

現状の穴: プレイヤー側は 6枠・固有334・星図・覚醒で伸びるが、敵は (a) 悪夢化（深度1で通常2%/エリート20%、深度5で通常10%/エリート52%）と (b) 本体の難度/Limbo だけ。深度は主にドロップを増やす。MOD 導入者の Build（Heat）は `PartyDepth()` で既にホストへ届いているので、これを敵へ反映するのが最小変更。

レバー一覧:
1. 悪夢化確率: `Nightmares.Chance(tier, depth)`、`Roll(.., chanceMult)`。Lesser 1%×深度、Normal 2%×深度、MiniBoss 20%+8%×(深度-1)、Boss は対象外。プレイヤー強度（星図ポイント・平均装備レベル・覚醒数）を係数に足す。
2. 深度別の全敵倍率: 悪夢でない敵にも `AddStatBonus`（`maxHealthPercentage`、`attackDamagePercentage`、`armorFlat`）。例: 深度dごとに 最大HP +8%・攻撃力 +4%（上限）。本体の `GetRegular…ByScaling` は触らず StatBonus で上乗せすれば Limbo と加算的に動く。
3. 悪夢の接頭追加（NightmareAffix は Flags の int で、`Sanitize` が既知ビット以外を落とす。ビット 1<<6 以降が空き）。新案: 吸収の盾（`Actor.GiveShield`）、反射（`takenDamageProcessor`）、耐性（被ダメ減衰）、分裂（死亡時に `SpawnEntity`）、狙撃（遠距離反撃）、障壁・沈黙（`CreateBasicEffect` で一時沈黙）、冷気/火/光/闇の `*EffectAmp` で属性対策。
4. プレイヤー戦略へのカウンター: 戦略別メトリクスを Build から読む（`Build.Compute` の結果）。
   - 速攻・火力偏重（攻撃速度・クリ）→ 鋼殻/被ダメ上限（1撃で最大HPの X%）。
   - 長期戦・回復偏重 → 「傷の呪い」: `Heal` を減らす（`takenHealProcessor` / `Se_Curse_Fragility` 系を流用）。
   - 召喚・設置系 → 範囲攻撃/Overkill の敵。
   - 状態異常（スタン/スロー）偏重 → `tenacityFlat` を足す、または `isKilledByCrowdControlImmunity` 系。
   - 回避偏重 → 追尾/広範囲攻撃（Delusion 系）。

### 層C: Blender / AssetBundle による完全新規敵（工数 大、リスク高）
手順案:
1. Unity のバージョン確認（`Shape of Dreams_Data/globalgamemanagers` or `ProjectSettings`）。同一バージョンのプロジェクトで AssetBundle をビルド（Windows、必要なら Mac/Linux も別ビルド）。
2. Blender でモデル（Humanoid か Generic リグ）、AnimationClip（idle/run/attack/stagger/death）を作成、FBX 出力。
3. Unity で Prefab 化: `EntityModel` コンポーネントを付与（`bodyRenderers`, `healthBarPosition`, `idle/stagger/death`, `run*`, `fxDeath`）。マテリアルは本体のシェーダーを参照できない場合があるので、実行時に本体の Material へ差し替えるコードが必要。
4. MOD 起動時に `AssetBundle.LoadFromFile`（MOD フォルダ、パスは `DewMod` の MOD ディレクトリ）で読み込み、モデルを辞書に登録。
5. 見た目の差し替え: 敵は本体プレハブで出し、全クライアントが `DreamforgeVariantMsg` を受けて `Entity.Visual.LoadModelLocal(EntityModel)` を実行（ネットワーク登録不要）。HP バー位置や当たり判定（`GetBodyBounds`）の再計算に注意。
6. 能力は本体の AbilityTrigger を流用（`DoAbility` 等）。アニメ同期は `Animation.ReplaceAnimation / ReplaceAnimationLocal`、`PlayAbilityAnimation`。
7. バンドル配信確認: Protocol.Version とバンドル有無を通信し、無い端末は色替えにフォールバック。
8. 全 OS 向けのバンドル（Windows/Mac/Linux）と CI 手順（tools/）。

リスク:
- Unity バージョン/シェーダー/URP 設定の不一致でピンク表示・クラッシュ。
- `LoadModelLocal` の想定外（プール再利用でモデルが残る、リセット、HP バー位置）。
- 新 `Monster` 型や NetworkIdentity プレハブの追加は Mirror Weaver／本体リソース DB への割り込みが必要で、現実的ではない（避ける）。
- アニメ・リグ制作工数、ファイルサイズ（Workshop 配布）、OS 別バンドル。
- 本体アップデートでの破損。

工数目安: 調査・基盤（バンドル読込・モデル差し替え・メッセージ）1〜2週、モデル1体あたり（モデリング・リグ・アニメ・Unity 設定）数日〜1週。v1.24 では C は「技術検証（本体の既存敵1体の見た目を静的メッシュで差し替える PoC）」までを推奨。
