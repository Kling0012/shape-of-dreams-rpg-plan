# 敵への命中演出の上限

2026-10-20。本体の `Dew.Core.dll` と逆コンパイル済みコードを調べ、各端末で敵への命中演出を縮小する処理を追加した。設定は `nativeEnemyHitFxBudget` で、既定は有効。

## 経路の調査

| 出どころ | 内容と再生先 | ホスト・参加者と通信 | 今回の扱い |
| --- | --- | --- | --- |
| `EntityVisual.HandleTakeDamage` → `model.fxTakeDamage` | 全攻撃に共通するモデルの被弾FX。粒子・閃光・ライト・FX内の音 | サーバから `FxPlayNewNetworked`。各端末の `DewEffect.PlayIntoPool` → `Play_Imp` で再生 | 敵と元のモデルFXが一致した再生を通常枠で扱う |
| `EntityVisual.RpcShowHitEffect` → `UserCode_RpcShowHitEffect` → `EntityHighlightProvider.ShowHit` | 被弾グロー。0.1秒で減衰する値を1へ戻す | サーバの送信は本体で0.05秒間隔。ホスト・参加者の受信先は共通 | 敵のグロー値が正なら再設定を省く。送信は維持 |
| `MeleeAttackInstance.fxHitMain / fxHitSub` | 近接攻撃の主対象・副対象の命中FX | `FxPlayNetworked`。受信した各端末の付着再生先 | 攻撃固有の情報を保つため情報枠で扱う。`OnHit` と攻撃判定は維持 |
| `DamageInstance.hitEffect` | 範囲攻撃などの命中専用FX | `FxPlayNewNetworked` → 各端末のプール再生 | 情報枠。`mainEffect`、ダメージ計算、属性付与、状態処理は対象外 |
| `Projectile.UserCode_RpcPlayOnEntityEffect__EntityHit` → `effectOnEntity` | 弾の命中位置のFX。新規・切り離し・プールの分岐がある | RPCの受信側から `FxPlayNew / FxPlayDetached / PlayPooledLocal` | 付着再生・プール再生で命中用フィールドを識別して情報枠。飛行・完了・消散FXは対象外 |
| `ClientEventManager.UserCode_InvokeOnTakeDamage__EventInfoDamage` → `FeedbackManager.EffectPool.Play` | 通常・会心・DoT・DoT会心の与ダメージフィードバック | 被弾イベントRPCを各端末で処理。ローカルの注視対象によって再生 | 与ダメージの4プールだけ対象。会心または属性情報があれば情報枠。被ダメージ・回復・汎用フィードバックは対象外 |
| 命中FX内の `DewAudioSource` → `DewAudioManager.Play` | 命中音。`OnEnable` と `IEffectComponent.Play` の両方から呼ばれる | 各端末のローカル音声。プールの有効化中にも再生される | 命中FXに含まれる音源と同じクリップの短時間重複を省く。ループ音は対象外 |
| `FlavourManager` の被弾シェイク・`hitStopDealDamage` | 被弾の揺れ、時間停止 | 被弾イベント、ネットワークFX | 変更しない。ヒットストップを含むFXは縮小からも除外 |
| `Actor.TriggerAttackEffects` | 攻撃効果のゲームイベント | ダメージ処理から発火 | 見た目専用ではないため変更しない |
| `ElementalStatusEffect` | 属性の持続FXと状態処理 | Actorの生成・スタック同期 | 生成・状態処理・持続FXを変更しない。既存予算の火属性だけは従来どおり |
| `FloatingWindowManager` などの被弾イベント購読 | ダメージナンバー、UI、カメラ等 | 同じ被弾イベントRPCを購読 | イベントと全購読者を実行し、表示内容を変更しない |

`EntityVisual.HandleTakeDamage` は死亡時にも使う被弾方向の累積値を更新する。近接・弾・範囲攻撃の命中処理もゲーム処理と同居しているため、これらのメソッド全体を省略しない。

## 間引き規則

- 通常枠は同じ敵に0.1秒で1回、端末全体で任意の0.1秒間に12回までを通常量で再生する。
- 情報枠は同じ敵に0.025秒で1回、全体で0.1秒に24回までを通常量で再生する。攻撃固有FXは会心・属性の情報を含む可能性があるため、すべて情報枠に入れる。クライアントに同期されない `isCrit` を判定の根拠にしない。
- Low品質または `perfPressureStrength > 0` なら全体枠を通常6回、情報12回に下げる。敵ごとの間隔は維持する。
- 上限を超えた通常FXは粒子を合計8個を目安に各システムへ配分する。情報FXは合計32個を目安にする。各システム最低1個を残すため、システム数がこの値より多い場合は合計も増える。色・種類・位置は変えない。
- 超過分の時間当たり放出倍率は通常2、情報8以下、距離当たりは1以下にする。元の値が小さければ増やさない。粒子ライトと通常のライトは無効にし、`FxPointLight` の更新も止めて再点灯を防ぐ。
- 最初の再生で出たバースト粒子にも上限を適用する。固定32個のバッファを使い、粒子を再起動せず減らす。
- 同じ命中音は通常0.1秒、情報0.025秒以内の重複を省く。音量、クリップの種類、ピッチの設定は変更しない。元のクリップ選択・ピッチの乱数処理を通した後、`TickVoice` で再生を始める直前に重複音源を解放する。遅延再生も残さない。
- 点滅は本体の `_hitValue` が正の間、敵に対する `ShowHit` の再設定を省く。`ShowHit` 自体はfloatの代入で、マテリアル配列の作り直しはない。減衰・描画更新は本体に任せる。

敵の記録は通常・情報それぞれ1024枠の固定配列。インスタンスIDが衝突したら次の枠を探し、期限切れの枠を再利用する。全枠が間隔内の記録で埋まっていれば保守的に縮小する。敵の参照を保持せず、敵数が増えても記録容量は増えない。時刻が戻ったら履歴と全体枠をリセットする。音の記録は128枠で、期限切れの枠を再利用する。

## ゲーム処理と再利用

`Play_Imp` 自体は省略しない。FXのsetup、任意のコールバック、乱数消費、生成、プール登録を本体どおり実行した後で粒子とライトを縮小する。新規生成の削減より、ゲームの結果を保つことを優先した。

攻撃予告の `ArcTelegraphController / BoxTelegraphController / FxCastTelegraph`、`FxStopTime / FxUnityEvent / FxEntityInvoke / FxNetworkedEffect` を含むFXは粒子・ライト・音を含めて縮小対象から外す。粒子のtrigger、衝突メッセージ、stop callbackがある場合も同様。ヒットストップやイベントの呼び出しを間引かない。

部品一覧と復元値の配列はプール個体ごとの初回に作り、`ConditionalWeakTable` に置く。再生ごとの新しいリスト、配列、クロージャは作らない。縮小した個体は次の再生前に元の値へ戻す。設定を無効にした後の再生でも復元し、その再生には上限を適用しない。すでに再生中のFXは次の再生まで縮小状態が残る。

再生の文脈は構造体で保存し、Harmonyのfinalizerで例外時も元へ戻す。別のFXへ再帰した場合は外側の予算を重ねない。APIが欠けた部分はパッチを取り付けず、警告を1回だけ出す。実行中の例外も当該機能を止め、本体の再生を続ける。

## 既存予算との分担

`NativeFxBudget.Find(actor)` に一致するActorの命中FXは今回の対象から除く。従来の炎・弾・範囲FXの粒子とライトの上限は既存実装だけが担当する。同じ再生に通常枠と情報枠、または既存Actor予算を二重に課さない。

モデル共通被弾FXとローカル与ダメージフィードバックは別の再生なので、それぞれの枠を使う。送信を省略するパッチは追加しない。参加者も受信後の同じ再生処理で縮小するため、通信形式やゲーム処理の同期は変わらない。
