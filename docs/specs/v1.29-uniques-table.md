# v1.29 固有品559とセット24の設計表

`v1.29-double-content.md` の目標（固有品を倍、セットを倍）の2段目の設計。コードは書かない。固有品559（6枠）と新しいセット24を、新しい固有効果44（`v1.29-new-powers.md` の P1〜P44）と属性の反応4つ（蒸気・蝕・燃え殻・氷晶）を使って組んだ。GLM（データ化）が機械的に取り込めるよう、枠ごとに同じ列の表にした。

## 0. 読み方と約束

- 列は固定：`| id | base | 名前 | Name | 言い伝え | Lore | P1 | V1 | P2 | V2 | LinkRequires | LinkKind | LinkValue |`。`id` は `unique.` から始まる ASCII。`base` は `Content.Bases`（360）の既存の土台ID。連携が無い行の最後の3列は `-`。
- 固有効果の名前：既存の44は `Content.PowerName` の日本語名（連撃・追い風など）をそのまま使う。新しい44は **`P1`〜`P44`**（日本語名と動きは `v1.29-new-powers.md`、下の §1 に対応表）。属性の反応4つは **蒸気・蝕・燃え殻・氷晶**。
- 値（V1・V2）：既存の効果は既存の固有品の値の範囲（観測の最小〜最大）かつ `PowerCaps` 以内。新しい効果は `v1.29-new-powers.md` の「エピック1個の値の範囲」内。1つの固有品に付く2つの効果は別の効果で、**同じ枠の中で効果の組（順不同）が他の固有品と重ならない**（既存487＋この559の全体で検査済み。既存の試験と同じ決まり）。
- 枠に付けられる新しい効果は、`v1.29-new-powers.md` の見出しの「枠」に従った（例：P3 盾打ちは Weapon・Hands だけ）。
- 連携（LinkRequires）：`+` で区切った1〜3個の型名（`St_`＝記憶、`Gem_`＝エッセンス、`Hero_`＝旅人）。種類と上限は `Links.Cap`：単体は同調・守り25、記憶加速50、記憶の余韻40、記憶の冴え40。条件2つで1.6倍、3つで2.2倍。値はどれも上限の約5〜8割に収めた（覚醒の倍率後も `EquippedCap` を超えない）。記憶加速・記憶の余韻・記憶の冴えは、条件に記憶を1つ以上含む（`Links.Validate`）。
- 連携先の記憶は、旅人記憶・アイデンティティ記憶なら **遠征の前に選べる装備（`v1.27-traveler-kits.md`）にあるものだけ**。同じ連携に別の旅人の記憶を混ぜていない（旅人は1人だけ）。共通のアイデンティティ記憶（燃え盛る拳・極寒の気迫など）は連携先にしていない。レジェンダリー・ユニークの記憶（`St_L_*`・`St_U_*`）とエッセンス（`Gem_*`）は、自由に組み合わせてよい。
- 絆（`id` が `bond_` で始まる行、18個）：条件が `Hero_A+Hero_B` の2人。**いまの `Links.RequirementSatisfied` は旅人の条件を「自分がその旅人か」で判定するので、2人の旅人を同時に満たせない。`v1.30-horizontal-ideas.md` の C1（近くの味方の旅人の型名を条件に足す）が実装されるまで、絆の18個は取り込みを保留するか、C1 の実装後に有効にする。** ほかの541個は、いまの仕組みのまま有効。
- 名前・言い伝えに人名は使っていない。新しい名前は、既存の固有品・セット・この表の中で重ならない（日本語・英語とも、検査済み）。
- 効果の値は控えめに。条件つきの攻撃力・魔力%（P4・P25・P30・P35・P13・P23・P33・P38）は、一つの固有品で `v1.29-new-powers.md` の範囲内、装備全体の合計は同書の総上限（覚醒前120）で切る。
