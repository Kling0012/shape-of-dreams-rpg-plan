# v1.30 絆の実装 / Traveler bonds

旅人を指定する連携は、自分がその旅人なら従来どおり有効になる。自分が別の旅人でも、その型の生きている味方旅人が10m以内にいれば有効になる。異なる旅人を2種類以上指定する連携は、自分が指定された旅人の1人で、残りの旅人がそれぞれ10m以内にいるときだけ有効になる。周囲に指定の旅人がそろっていても、自分がその組に含まれなければ有効にならない。

A traveler requirement accepts the wearer or a living allied traveler of that type within 10 m. A bond naming multiple traveler types also requires the wearer to be one of those types. Memories and essences must still be equipped by the wearer.

## 判定と表示

`Links.RequirementSatisfied` と `Links.Satisfied` は、ホストが集めた近くの味方の型名を受け取る。既存の呼び出しは省略可能な引数を使わず、従来どおり自分だけで判定できる。`Links.IsBondAlly` が生存・味方・距離をまとめて判定する。距離10mちょうどは含め、負数や無効な距離は含めない。

ホストは `ActorManager.allHeroes` を調べるため、Dreamforgeの装備情報を送っていない味方も絆に数える。`isActive`、`isAlive`、`!isKnockedOut` を満たす味方だけを、`GetRelation` と `agentPosition` で選ぶ。既存の0.25秒の連携更新で効果を付け外しする。条件を失った記憶の余韻も既存の `RetainLinkSurges` で解除する。

画面の ✓／・ は、クライアントが受け取った味方の位置・生存状態を0.5秒ごとに調べた目安である。通信や更新時刻によってホストの判定と一時的にずれる。実際の効果は常にホストが決める。旅人がまだ生成されていないロビーでは従来どおり印を付けない。

## 本体APIの確認箇所

| API | 確認した資料 | 用途 |
| --- | --- | --- |
| `ActorManager.allHeroes` | `.ref/dump/ActorManager.txt`、`field List<Hero> allHeroes` | 参加中の旅人を列挙 |
| `Entity.isAlive`、`Entity.agentPosition`、`Entity.GetRelation(Entity)` | `.ref/dump/Entity.txt` | 生存・距離・味方の判定 |
| `Hero.isKnockedOut` | `.ref/dump/Hero.txt` | 倒れている旅人を除外 |
| `Actor.isActive` | `.ref/dump/Actor.txt` | 無効になった個体を除外 |

## 通信

連携は既存の `LinkDef.Requires` の `Hero_` 型名で表す。装備の送受信形式、列挙値、追加の状態メッセージは不要。絆のためのプロトコル変更は行わない。
