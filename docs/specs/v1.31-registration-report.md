### 根本原因と修正

1. **Choiceの所有記憶が空（Husk 4・Lacerta・Cetus・Yubar他）**: `gen_cs.py` は `MemoryOwnership` を行の `receiver` からだけ作っており、効果が `options` にある Choice では `null` だった。そのため受け手・送信元（例 `St_Q_Laceration`）が所有宣言に入らず「Mechanism memory is outside verified ownership」になった。各選択肢の受け手・送信元・identity 起点を集めて宣言するようにした（動きの記憶は受け手のみ、という規則は変えていない）。
2. **Reloadを持つ記憶への全体B（Lacerta・Mist）**: 記憶全体への `GimmickBoost` は、その記憶のReloadにも届き、`FractionalScopedModifiers.ValidateTree` が「意味のある受け手がない」として拒否する（Reloadの値1は%で変わらない）。設計の「効果は名指しで」に従い、全体Bは Reload を除いた当記憶の効果をID指定で宛先にする（`boost_recipients`）。Choiceで同一IDに含まれる別の選択肢が混ざる場合は効果集合でも絞る。
3. **他記憶へのRecvが送信元側のBも受ける（Lacerta、遊んだ時に判明）**: 登録は通るが、Recv（例 `h.lacerta.route.nimble-dodge.7`: Incendiary→NimbleDodge）が送信元記憶の全体B（source scope）と受け手側のB（receiver scope）を同時に受け、`Source/receiver double boost is forbidden` で購入が落ちた。Recvは受け手scopeだけが強化する、という設計（source/receiver separation）に合わせ、他記憶へのRecvを全体Bの宛先から外した。診断メッセージには channel ID を足した。
4. **他記憶へ受け取る星（Nachia 3・Yubar 5）**: `Recv(囁,OnUse,8,舞,1)` のように星が送信元の領域にあり、受け手は別の検証済み旅人記憶。契約の「Receiver target does not own this region」が受け手＝領域の記憶を強制していて、設計表の星が書けなかった。契約を「受け手が領域の記憶でないときは、領域の記憶がその星の明示的な送信元であり、受け手が検証済みの旅人記憶であること」に限って許可した。受け手と送信元の対応は従来どおり `ValidateAuthoredMetadata`（Recharge の Source/Recipient 宣言）が検証する。契約テストを追加。`@ID`（identity 起点）の星は、起点の記憶（Heart/Circle）も所有宣言に入れた。
5. **橋のB/T/Rの宛先（Nachia 84）**: 旧ringの橋を対象にする星（`target.star = h.nachia.ring.*`、設計N3）が、(a) その橋の型付き基底（`ManifestBaselinePair`）を持たず宛先が存在しない、(b) scopeが行の便宜上の `memory`/`receiver`（`ring.resolve` は印側の蛇、b4は受け手の舞）になっていて橋の実際の払い出し記憶と合わなかった。ジェネレータが対象の橋の基底を出し、scopeを橋の払い出し元記憶（`payoff_memory`）の EffectChannel にした。
6. **外殻アンカーと混在Choice（Cetus）**: `ManifestRetained` は登録済みの外縁アンカー（`h.cetus.outer.abyssal-shell`）を Keystone 領域にしていたため「Stats ... in Outer clusters」で拒否された。`IsOuterAnchor` は Outer 領域にした。混在Choice（Shield と Recharge が同一ID）への Duration は、効果集合でも絞った。
7. **召喚Ward（Aurena）**: `outer.summons.a2/b2` の `AlliedWard arg=1`（召喚への Ward）に Aurena だけ `includeOwner: true` を付けており、`AlliedWardDefinition` が「Owned-summon selection cannot include a traveler」で構築時に例外。召喚向けには旅人を含めない。

### 橋の窓/印の持続時間（Nachia、設計決定による追加）

`GimmickParam` に `WindowDuration`（その橋のペアの窓 `BridgeSuccessDefinition.WindowSeconds`、native lifetime の窓は host が渡す終了までの残りを拡大）と `MarkDuration`（Markペアの印 `MarkSeconds`、既定4秒）を追加した。%の意味・上限（`ScopedModifierCapProfile`）は他の Duration と同じで、窓は60秒、印は12秒を上限にする。契約（`AuthoredMechanisms.Supports`）は WindowDuration を Window ペア、MarkDuration を Mark ペアにだけ許し、他は登録時に拒否する。コーデック・指紋・host（`PairComboRuntime` の窓/印の寿命）・星の説明・割り当て検証（専用チャンネル）に通した。マニフェストは `nachia.bridge.b1.q`（印）、`b2/b5/b6/b8.q`（窓）、`b7.q` の印の選択肢（Shield の選択肢は `Duration` のまま）。`validate.py` は橋の `GimmickParam` で target.star が ring ID の行にだけ許し、Window/Mark の別は `gen_cs.py` が実際のペアで検査する。
