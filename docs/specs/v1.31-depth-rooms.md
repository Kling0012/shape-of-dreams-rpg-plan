# v1.31 dream depth adds rooms to each zone

Dream depth now grows each zone's map: `+2` rooms (world nodes) per depth step, `+10` at depth 5, `+0` at depth 0 (the unchanged game). The decision logic lives in Core as pure functions; a Harmony patch in the Mod applies it to the host's zone generation only.

## Patch mechanics and error safety

- Prefix computes `DreamDepth.ZoneNodeOffset(depth, NetworkServer.active, zone.useSpecialGeneration, run != null)` and, when non-zero, does `worldNodeCountOffset += add` and remembers `add` in a patch-local field (`GenerateWorld_Imp` is non-reentrant: its only callers are `GenerateWorldAuto`/`GenerateWorldWithSeed` and it never regenerates a world internally).
- `Postfix` runs after normal completion and restores; the `Finalizer` runs after any exception (Harmony skips postfixes when the original throws) and performs the same restore. The restore subtracts exactly the remembered amount once and zeroes it, so the second of the two handlers is a no-op — the offset can never stay modified, and exceptions still propagate (void finalizer, nothing swallowed).
- Patch registration: `[HarmonyPatch(typeof(ZoneManager), "GenerateWorld_Imp")]` (private method, resolved by name) in the Mod assembly; `DreamforgeMod.Awake` applies `harmony.PatchAll(typeof(DreamforgeMod).Assembly)` (`src/SodRpg.Mod/DreamforgeMod.cs:50`) and `OnDestroy` calls `harmony.UnpatchAll(harmony.Id)` (`src/SodRpg.Mod/DreamforgeMod.cs:267`), so live reload removes it with every other patch.

## Depth source (reused, not invented)

The patch reads `ClientSession.HostRun?.DreamDepth` — the same source DreamPressure uses (`src/SodRpg.Mod/HostAuthority.cs:313-314`). `ClientSession.HostRun` (`src/SodRpg.Mod/ClientSession.RunChoices.cs:23-24`) is non-null only when `NetworkServer.active` and the host session has an active run, which supplies both the `isServer` and `runActive` gates; `RunState.DreamDepth` is clamped on set (`src/SodRpg.Core/Game/Profile.cs:52`), and `ExtraZoneNodes` clamps again regardless.

## Multiplayer reasoning

- World generation happens once, on the server/host. The offset is added and restored inside that single server-side call, so no client ever observes a modified `worldNodeCountOffset` and no network message changes: clients simply receive the longer `nodes` sync list.
- Clients therefore need no matching logic or protocol version for room counts; a non-host participant without the patch would still see the host's larger maps, exactly like any other server-generated world.
- All players keep the same world: the count is part of the generated map derived from `worldSeed` plus the offset at generation time; saves store the resulting `nodes` and do not regenerate on load.

## Verification status

Core decision logic is covered by the new unit tests (values 0–5, clamping, and the client/special/inactive gates). The Release Mod build compiles against the installed game assemblies. **In-game behavior is not verified: no game launch was allowed in this environment, so the actual larger maps, the exception-restore path, and co-op replication remain untested in the live game.**
