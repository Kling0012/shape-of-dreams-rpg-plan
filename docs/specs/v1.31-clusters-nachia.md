# v1.31 ナキアの星団設計

対象は `Hero_Nachia`。共有外周160星を一度だけ含めて **735星**。始まりの表示点、選択肢の数、段数を星数に足さない。このファイルの全体能力値だけの星は **0**。新設星はすべて1段。これは実装用の設計表であり、新機構の実機確認が済んだという報告ではない。

枝順は `pack-heart → sylvan-call → natures-whisper → dreamy-waltz → circle-life → moonlight-pact → serpent-blessing` を維持する。Q・R・移動の全星団はIdentity二択のどちらでも有効で、プレイヤーや召喚獣の移動・標的選択を自動変更しない。

コミュニティの実走報告では、生命の循環で能力共有を伸ばす多頭召喚、フェンリルの継続攻撃と障壁で耐える構成が強いとされている。数値の極端な報告を採用せず、「召喚獣の命中を生かす」「本人の安全な位置取りを保つ」を設計へ採用した。[召喚・循環・フェンリルの構成報告](https://www.reddit.com/r/shapeofdreams/comments/1np7tsf/nachia_build_tips/)。群れの心臓では回復・障壁・バフを団結へつなぐ構成も紹介されているが、MODの回復・障壁で団結を自動循環させる根拠にはしない。[回復と団結を使う構成](https://games.gg/shape-of-dreams/guides/shape-of-dreams-meta-nachia-build/)。以上は構成の傾向であり、現行版の最強順位を測った結果ではない。

## 記法・実効値・接続

表の記憶略号は `心=pack-heart`、`循=circle-life`、`舞=dreamy-waltz`、`森=sylvan-call`、`月=moonlight-pact`、`囁=natures-whisper`、`蛇=serpent-blessing`。それぞれ上表の完全な記憶IDに展開する。`Q*`・`R*`・`D*`はその枠に**現に装備中の自分の候補1つ**を指し、候補の同時装備を要求しない。

|記法|星の種類と厳密な意味|
|---|---|
|`D(x)`|`MemoryDamage(当該記憶,+x%)`。本体の当該記憶のダメージだけ。仕掛け・反応を再増幅しない|
|`H(x)`|`MemoryHaste(当該記憶,x%)`。現行`LinkKind.MemoryHaste`と同じ、当該記憶使用時に**最大CDのx%**を自己CDから短縮する（本体の短縮不可設定を尊重）。残CD割合のRecvとは別物。恒常的なスキル加速とは呼ばない。循・舞・月には置かない|
|`B(x)`|`GimmickBoost(当該記憶,+x%)`。当該記憶の仕掛けのValueだけを加算率で強化。Reloadの回数・対象数・CD・本体記憶の係数は伸ばさない|
|`T(id,x)`|`GimmickParam(memory,Duration+x%,effectId=id)`。期限を持つ指定仕掛けだけに作用。瞬時回復・Echoの0.3秒遅延には使わない|
|`R(id,x)`|`GimmickParam(memory,Radius+x%,effectId=id)`。範囲のある指定仕掛けだけに作用|
|`C(id,x)`|`GimmickParam(memory,Chance+xポイント,effectId=id)`。Elementの端数抽選のみ。100%到達時は確定の1スタックへ繰り上げる|
|`X(id,1)`|`GimmickParam(memory,ExtraTargets+1,effectId=id)`。SummonWardの対象数だけ。元から全召喚獣対象のPackMendには使わない|
|`G(M,t,e,v,a,c)`|`Notable:GimmickDef{Memory=M,Trigger=t,Effect=e,Value=v,Arg=a,Cooldown=c}`。Memoryはentry側の指定。記載のないCDはなく、すべて明記する|
|`F`|新しい`GimmickTrigger.OnBasicAttack=5`。本人が基本攻撃を発射し、生存する自分の召喚獣が1体以上いる通知。既存OnUse/OnHitの別名ではない。N1参照|
|`Recv(S,t,V,T,n)`|新しいNotable `RechargeTarget`。送信元集合Sのtをn回受信すると、受け手Tの残りCDをV%短縮。Arg=0、CD=0、カウンター上限n。n=1は毎回。N2参照|

新星IDは `nachia.mem.<slug>.c<1..4>.<e1..e6|n1|l1..l6|q>`。各星団は **入口6＋中心Notable1＋枝葉6＋Choice1=14星**。Choiceは表のA/B二択だけで、1星・最大1段。`q.a/q.b`は保存する選択値で星ではない。省略配列は左から番号へ一対一展開するため、同じ値が並ぶ場合も別IDの取得可能な星である。

接続は旧幹の有効な仕掛けの星から `e1→e2→e3`、そこから扇形では`e4/e5/e6`へ分岐、輪形では`e4→e5→e6`で輪を作り、鎖形では6入口を直列にする。すべて`n1`へ接続し、`n1→l1→l2→l3`と`n1→l4→l5→l6`を経て`q`へ接続する。条件は連結だけでなく、B/Paramが参照する旧幹の仕掛けと、枝葉が参照する`n1`の取得を必須とする。Choiceも両選択肢の参照先を取得済みにしてから開く（循c2なら旧幹`.4`を追加必須）。先に無効な倍率だけを取得する順路を作らない。

GimmickBoostは固定小数点で集計し、例`PackMend 1% × B(2)=1.02%`を保持する。現在のint Valueへ星ごとに丸めない。最終HP/CDの適用まで小数を保持する必要がある（N3、要確認）。Bの全取得合計は当該記憶+160%まで、Durationは+100%、Radiusは+80%、SummonWard対象数は3体まで。この文書の通常星を全取得しても上限に達しない値にする。刻印は明示した別の変換を行う。MDは現行Linksの装備上限、Crescendo併用時は合計+120%を守る。

`Heal(Arg=1)`の量は使用者の最大HPを全員へ流用せず、**各受け手の最大HP×Value%**に使用者のHealPowerを掛ける。`HostAuthority.PairCombos.cs:ApplyGimmick`の本人`hero.maxHealth`／味方`ally.maxHealth`の現行処理を維持する。PackMendも各召喚獣の最大HPが基準で、回復量の上限Value8%。新しいSummonWardは各対象最大HPのValue%にShieldPowerを掛けた後、その対象の星図SummonWard残量10%上限へ収める。上限超過分を既存本体障壁から差し引かない。

Elementは光5・闇5・冷気1・火は本体どおり上限なし。付与時にも上限を増やさず消費しない。Echo/Burst/Wound/ElementEdgeは既存の無属性・proc0・連鎖禁止マーカーを使う。ExposeとEclipseは旅人・敵ごとに最大1つだけ。回復は欠損HPまで、障壁は同IDの大きい方で期限更新し、同IDの加算積みは0段。複数星由来の通常Shieldの合計追加残量は本人最大HP20%まで、SummonWardの合計は各召喚獣最大HP10%まで。この上限は本体の障壁を削らない。
