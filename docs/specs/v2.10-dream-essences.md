# MOD独自の記憶・エッセンス：native 試作と候補一覧（2026-10-07）

利用者の依頼（2026-10-07）：「独自の記憶とエッセンスを作成，追加検討」。
位置づけ：**本体の Gem / SkillTrigger を使う開発専用試作の設計と、候補の記録**。候補表の全項目を実装するものではない。下記の根拠はソース・DLL の調査であり、Unity 上の表示・実際の協力通信・Continue はまだ実機確認していない。

## 0. 決定と範囲

1. 利用者の決定は **A：本体の記憶・エッセンスとして追加する**。実装は新しい CLR 型を足すのではなく、**既存の具体型の独立したプレハブ複製**で行う（§2 の c）。本体の拾得物、通常の装着枠、装着・解除の寿命管理を使う。疑似ソケットや MOD 専用の記憶枠で代用しない。
2. 開発専用の2品は **護りの種／Seed of Shelter** と **芽吹きの種／Seedling**。前者は native `Gem_C_Quicksilver`、後者は native `St_C_MassProtection` の具体型と既存 `assetId` を保つ。複製元は変更せず、印のある個体だけ元の効果を置き換える。
3. **既定は無効**。起動時に `Application.persistentDataPath/QuickSave/Mods/DreamforgeRPG/` の **`dev.flag` と `native-dream.flag` の両方**がある場合だけ有効。協力で試す場合は全参加者が同じ MOD と両フラグを使う。ホストだけ導入すれば同じ試作が見える、とはしない。
4. 入手はホストの **`dreamforge_native_give kind`** だけ（`kind=0` は Gem、`kind=1` は記憶）。本体のワールド拾得物を作り、通常操作で拾って装着する。**`dreamforge_native_status`** は有効状態と2品それぞれの登録 readiness をログへ出す。
5. 新しい CLR ネットワーク型・SyncVar・RPC・`assetId`・保存型は追加しない。元の型名で保存し、既存の永続同期辞書に文字列の印を載せる。無効・MODなし・その品の初期化失敗では **元の vanilla オブジェクトとして読み込める**ことを設計上の条件にする。保存側の型名書換えで代用しない。
6. **独立した native カタログにはまだならない**。ランダムドロップ・ショップ・図鑑・実績へ別の品として自動登録しない。独自IDを native の保存済み抽選プールやプロフィールの辞書へ入れない。制限と根拠は §3。

PR #279 の12種の定義・上限確認は **候補資料として保持**。`DreamEssences.cs` は候補値と既存上限の評価に限定し、旧 `DreamSocketing` / `ToEntry` / `Resolve` 等のソケットAPIと、その接続試験は削除する。以前の **B（疑似エッセンス）・C（専用枠の自動発動記憶）の推奨は、この A の決定で置き換える**。

## 2. 方式の比較と選択

大分類 **A** は「本体の Gem / SkillTrigger として拾い、普通の枠へ装着する」。その実装の選択肢を小文字 a / b / c で比較する。

| A の実装 | 内容 | 利点 | 根拠に基づく問題 | 判断 |
| --- | --- | --- | --- | --- |
| a | 既存具体型の clone に **新しい `assetId`** を付ける | ネットワーク上で別の clone プレハブを直接選べる。既存の woven コンポーネントを使える | 新IDの client spawn handler と lookup が全 peer に必要。MODなしの相手は未知のIDを解決できない。保存・ショップ・図鑑の型名は元のままで、独立カタログにはならない | 今回は採用しない。新IDは真の native オブジェクトの必要条件ではない |
| b | Weaver を追加しない MOD の `Gem` / `SkillTrigger` subclass | 新 SyncVar / RPC がなければ既存 serializer を継承でき、実DLLのRPC dispatcherも基底型への代入互換で判定する | それだけではプレハブ・resource DBの登録は成立しない。保存IDとメンバー接頭辞が MOD の新具体型となり、MODなしでは解決できない。IDだけの saver 書換えでも解決しない | ネットワーク継承と保存互換は別問題。今回の native 保存互換条件には不採用 |
| **c（採用）** | **既存具体型・base `assetId` の clone ＋ `persistentSyncedData` の文字列 discriminator** | 本体の network schema / 型名保存を保ち、無効時は元の品になる。元のプレハブを変えず、独立個体に効果を付けられる | 受信・復元・装着前の印による再設定が必要。native の同型装着制約と、独立カタログでない制限は残る | **利用者の A の決定を、この native-compatible identity で実装** |

以前の B「夢のソケット」と C「専用2枠の自動発動」は採用しない。D「Power / 星へ似た効果だけを足す」も今回の native 拾得物の代替にはしない。新型を実機で通せるかどうかを先に利用者へ要求する S1 や、Remote Control を追加の前提にする進め方は取り下げる。

## 3. 開発専用2品と互換性の契約

### 3.1 固定の試作品

| 品 | 開発 lookup ID | native 具体型 | 試作で固定する効果 |
| --- | --- | --- | --- |
| 護りの種／Seed of Shelter | `Gem_Dreamforge_SeedOfShelter` | `Gem_C_Quicksilver` | **品質I固定**。装着先の記憶の cast-complete で、自分へ最大HPの **3%** の障壁を **4秒**。発動は **8秒に1回** |
| 芽吹きの種／Seedling | `St_Dreamforge_Seedling` | `St_C_MassProtection` | **通常記憶枠へ装着する native passive 記憶**。装着中の hero が **Monster を5体撃破**するごとに、自分と **10m以内の味方 hero** を、それぞれ **回復対象自身の最大HPの8%** 回復。自分を重複して数えない |

固定品質Iは候補表の I / II / III のうち I の効果量だけを試すという意味。本体の quality 数値（`G/Dew.Core/LootManager.cs:202-207`、`G/Dew.Core/Gem.cs:295-309`）と候補の3段階を混同しない。Seedling は押して発動する技でも、MOD 専用枠に隠した自動効果でもない。

Seedling の撃破数は既存辞書の文字列キー **`Dreamforge.NativeDream.Seeds.v1`** に保持し、5到達時に **先に0へ消費してから**回復する。解除・再装着・Continue で途中の撃破数を保持するが、解除中の撃破は数えない。

### 3.2 印・template・失敗時

- 印のキーは **`Dreamforge.NativeDream.v1`**。本体の既存 `persistentSyncedData` に文字列として入れ、辞書自体を差し替えない。有効フラグ・その品の readiness・正しい native 具体型・一致する印が揃う個体だけを試作品として扱う。
- 独立 template は所有する inactive / DontDestroy root の子に置く。template 自身の `activeSelf` は元の **true** を保ち、template を直接 `SetActive(false)` する運用にはしない。元のプレハブは一切変更せず、終了時に独立 root / template を破棄する。
- 印は生成個体の `beforePrepare` で書く。保存からの host prepare と client lifecycle でも、印のある個体を native 装着前に設定する。プールの mapping ができた後に公開 `SpawnManager.InvalidateInstance` を使い、印つきの個体を vanilla の再利用プールへ戻さない。
- 共通 lookup / lifecycle を用意し、各品の効果 patch と template 登録が両方成功してから、その品だけ ready にする。失敗は **品ごとに警告1回**で止め、他の品・通常の MOD 起動・vanilla 復元は続ける。private API / IL の厳密一致を MOD 全体の起動条件にしない。
- 保存は **`Gem_C_Quicksilver` / `St_C_MassProtection` ＋既存辞書内の文字列の印**。新保存型・新 network schema・saver のID書換えはない。無効・MODなし・失敗した品は元の vanilla オブジェクトとして動く。印があるだけでは試作の効果を実行しない。
- Quicksilver と Shelter は同じ native 具体型なので、**同時に装着できない**。この同型一意制約は変更しない。一方、**試作品と原型の交差合成は拒否する**。拾得時の native 自動合成でも、別物を消費してはいけない。

### 3.3 入手・カタログの現在の制限

本体の drop / shop / shrine / déjà-vu / codex に **独立した品を追加する機能は今回含めない**。開発 grant が作るのは本物の native 拾得物だが、独自 lookup ID は native 型名の代わりにはならない。native の unlocked items・保存される loot の全 pool / rarity / tag 辞書・profile の unlock / discovery / statistics map へ独自IDを足さない。元の品の登録と抽選は維持し、試作 clone 自体を `excludeFromPool` とする（これは loot 除外であって SpawnManager の pool 再利用禁止ではない）。

図鑑画面も `Dew.allSkills` / `allGems` と具体型名の profile を使うため、**試作は独立した図鑑行を持たず、元の品の発見・統計と共有し得る**。実 DLL の `Dew.UI.dll → UI_Collectables_ObjectItemProvider_Gem.cs:5-8`、`UI_Collectables_ObjectItemProvider_Skill.cs:44-47` も `targetObj.GetType().Name` で辞書を参照する。新しい実績も追加しない。実際の shield / heal が既存実績の進捗になる可能性は native の通常動作として残る。

名称・説明は印のある個体に限定して「（試作）」付きの名前と固定値の説明を表示し、通常品の翻訳行を全体で差し替えない。`G/Dew.Core/DewLocalization.cs:759-761,812-829,851-853,901-918` の object overload / key API だけでは足りず、実 DLL の `Dew.UI.dll → UI_Tooltip_GemDescription.cs:60-107`、`UI_Tooltip_SkillDescription.cs:23-69`、`UI_Tooltip_GemTitle.cs:22-44`、`UI_Tooltip_SkillTitle.cs:44-85` は型名による元の説明・名前へ進む。そのため tooltip の `OnSetup` と地面の拾得表示の `OnActivate` でも印を見て差し替える。結果・履歴・chat / ping 等の型名だけの経路（`G/Dew.Core/ChatManager.cs:359-372`、`G/Dew.Core/PingManager.cs:181-195`）や図鑑の元の行は原型の identity が残る制限として扱う。

## 6. 実際のPCでの短い確認手順

以下は **これから確認する手順**で、成功済みの Unity 証拠ではない。普段使うPCで本体と MOD を有効にし、フラグ変更後はゲームを再起動する。

1. **起動・登録**：`Application.persistentDataPath/QuickSave/Mods/DreamforgeRPG/` に `dev.flag` と `native-dream.flag` を置いて起動。開発者コンソールで `dreamforge_native_status` を実行し、有効状態と Gem / 記憶の readiness、品ごとの警告をログで確認する。
2. **拾得・普通の装着**：ソロまたはホストで `dreamforge_native_give 0` と `dreamforge_native_give 1`。足元の native 拾得物を通常操作で拾い、Shelter を本体のエッセンス枠、Seedling を通常記憶枠へ装着する。Quicksilver と Shelter の同時装着不可、両者を合わせても交差合成で消費されないことも確認する。
3. **cast / kill**：Shelter の装着先を使い、3%・4秒の障壁と8秒の間隔を見る。Seedling を装着して Monster を5体倒し、自分と10m以内の味方 hero がそれぞれ自身の最大HPの8%回復することを確認する。4体目までは発動せず、範囲外の味方へは届かないことも見る。
4. **解除・部屋移動**：2品を外して追加効果が止まること、再装着と部屋移動後に効果が重複しないこと、通常 Quicksilver / MassProtection に試作の名前・効果が漏れないことを確認する。
5. **ソロ Continue と fallback**：装着した状態を本体の通常中断保存で残して再起動・Continueし、名前・装着・効果を確認する。同じ保存を両フラグの片方を外して再起動、さらに MOD 無効で再開し、元の Quicksilver / MassProtection として装着・表示・動作できること、試作の効果が出ないことを確認する。登録失敗がログに出た品も、その品だけ vanilla fallback と他の通常機能の継続を見る。
6. **協力**：全参加者を同じ MOD・両フラグへ揃え、各PCの `dreamforge_native_status` と警告ログを確認。ホストの grant で作った品を双方から見て拾得・通常装着し、障壁、5撃破後の範囲回復、解除、部屋移動を確認する。各PCの表示とホストの効果判定が揃うかを記録する。

結果には品・host / client・有効フラグ・操作・観察した値・関連ログを残す。表示・同期・Continue が未確認なことを、コード調査や通常のコンパイルだけで「実機確認済み」に置き換えない。
