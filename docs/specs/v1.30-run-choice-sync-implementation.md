# v1.30 道標・夢の深さ：選択画面と協力プレイ

道標と夢の深さはホストが選び、同じ遠征にいる全員へ共有する。遺物、欠片、契約、確保するか潜るかの個人の選択は各プロフィールに残す。日本語と英語の画面文を用意した。

## 選択画面

- 遠征前のメニュー上部に夢の深さ0〜5を表示する。ホストだけが変更でき、選択値をプロフィールに保存する。遠征中は固定し、HUDで夢の圧と並べて表示する。
- 確保地点のパネルに3枚の道標と「道標を選ばない」を表示する。ホストの選択を全員に表示し、確保・潜行の後は有効な道標をHUDに表示する。道標は次の確保地点または遠征終了で消える。
- ホストが確保または潜行を決めるまで、参加者の個人の確保・潜行ボタンと対応する操作は待機する。その後の選択では、ホストと同じ道標を引き継ぐ。
- 選択画面を残して戦闘を続けた場合は、選択中の道標、未選択なら道標なしで潜行する。契約は追加しない。ホストの最初のダメージ処理で確定し、撃破通知にも予備の処理を置く。参加者は確定した状態を受け取ってから同じ扱いにする。遠征を先へ進めたまま未解決の選択が残る場合も、古い選択を終えてから新しい候補を出す。
- 純白の入口では戦闘を続けても自動潜行しない。ホストが道標を確定しても参加者の個人選択は解除せず、本人が確保／潜行を選ぶまで撃破報酬を保留する（#53・#88）。本人の選択後の精算では、撃破時に記録した深さと道標を使う（#71）。保留中の勝利確定は例外として選択待ちだけを解除し、潜行で深さを増やさず精算する。
- 道標のカード文字列を言語ごとに再利用する。HUDの文字列は既存の更新間隔で組み直す。

## 通信と順序

v1.30 導入時の通信版は **7**（版6と非互換）。現在は **17**。純白の参加者を自動潜行させる旧版との混在を拒否し、各自の明示選択を待つ扱いをそろえる（#88）。通信項目と保存形式5は変更せず、既存セーブの読込を維持する。

既存の `serverActor` のホストから参加者へのCustomRpcを使う。選択変更は `DreamforgeRunChoicesMsg` ですぐに送信し、定期送信も行う。既存の `DreamforgePressureMsg` に同じ内容を添えて、途中参加でも現在の夢の圧と選択を受け取れるようにした。

共有するのは遠征ID、ゾーン番号、道標の世代、更新番号、夢の深さ、有効な道標、選択中の道標、選択済み・確定済みの状態、提示した3枚。純C#の `RunChoiceSnapshot` が符号化と検証を担当する。未定義の道標、候補の重複、過剰な候補、壊れた形式を拒否し、夢の深さは0〜5に補正する。遠征IDとゾーンを照合し、古い更新で新しい選択を上書きしない。

参加者は遠征開始時にホストの深さを受け取ってから自分の遠征を開始する。受信待ちに起きた撃破は、遠征・ゾーン・部屋・敵の区分・レベル・悪夢化・変種・使用中の旅人の識別情報だけを保存し、対応する確定状態で一度だけ報酬へ反映する。Unityの敵オブジェクトは保持しない。最後の撃破が受信待ちなら遠征の精算もその処理を待つ。

ゾーン到着の通知とCustomRpcの到着順が前後しても、前のゾーンの確定状態で残りの報酬を処理してから新しい候補を適用する。参加者への適用では、個人の撃破数、所持品、契約、確保回数を上書きしない。同じ状態の再受信で報酬を再付与せず、道標の部屋内回数や保留中の戦利品も繰り返し初期化しない。

## 確認した本体API

| API | 用途 | 確認先 |
| --- | --- | --- |
| `Actor.CustomRpc_RegisterClientMessageHandler<T>` / `CustomRpc_UnregisterClientMessageHandler<T>` / `CustomRpc_SendMessageToAllClients<T>` | ホストから全員への通知と解除 | `.ref/dump/Actor.txt`。同じ経路を既存の夢の圧・悪夢化通知が使用 |
| `ActorManager.serverActor` | 共有メッセージを送受信するActor | `.ref/dump/ActorManager.txt` |
| `GameManager.runId` | 別の遠征から届いた情報を除外 | `.ref/dump/GameManager.txt` |
| `ZoneManager.ClientEvent_OnZoneLoaded`, `currentZoneIndex`, `currentRoomIndex`, `isInAnyTransition` | 道標の期限、受信との順序、部屋ごとの制限 | `.ref/dump/ZoneManager.txt` |
| `DewPlayer.local` / `hero` | 自分の旅人と報酬先 | `.ref/dump/DewPlayer.txt` |
| `EventInfoKill.victim` | 撃破時の報酬情報の取得 | `.ref/dump/EventInfoKill.txt` と既存の `ClientSession.OnDeath` |

既存API宣言とコンパイルで結合を確認する。通信の符号化、深さの補正、候補と選択の一致、世代とゾーンの除外、個人の進行を保つこと、撃破報酬の一度だけの反映はCoreの自動検証対象。Unityを起動した協力プレイと実画面の操作は未確認。
