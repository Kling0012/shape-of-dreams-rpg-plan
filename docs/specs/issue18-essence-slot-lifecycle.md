# Issue #18：追加エッセンス枠の後片付け（2026-10-03）

## 原因と修正

`Unhook(HeroRuntime)` が星図で増やした枠を戻さずにruntimeを捨てていた。同じHeroSkillを使うライブリロードでは、増えた状態を次のruntimeの基準として再加算していた。

ゲーム接続層を `HostAuthority.GemSlots.cs` へ分け、`Unhook` の先頭から `RestoreGemSlots` を呼ぶ。元のHeroSkillコンポーネントと自分の加算数を記録し、その加算だけを取り除く。本体や別効果による変更は保持する。IdentityとMovementは独立して処理し、一方の失敗で他方の解除を止めない。

本体 `Dew.Core.dll` の `HeroSkill.SetMaxGemCount` はSyncVarに上限を代入するだけで、自動でエッセンスを外さない。`UnequipGem` は同じGemを装着辞書から外し、所有者・親を解除して足元へ移し、通知する。どちらもILSpyで確認した。

上限を変えた直後に実際の値を読み直して加算記録を更新し、その後に枠外のGemを番号の大きい順に外す。個数が上限以内でも、穴があいて番号だけが上限外に残るケースを処理する。上限の代入後や外す途中で例外が起きても、再試行で同じ1枠を二度引かない。

## 検証

`EssenceSlotLifecycleTests` は製品の `HostAuthority.GemSlots.cs` そのものをテストへコンパイルし、HeroSkill等の狭いAPIだけをテスト用実装へ置き換える。計算式を複製した試験ではない。

- 両方の星と別効果+1を持つ状態で5回の解除・再適用。枠が累積しない。
- 満杯時は同じGemオブジェクトを落とし、残った数＋落とした数を保存する。
- 枠に穴がある場合の上限外のGemを外す。
- 片方の代入前・代入後の例外で、実際に変更した分だけを戻す。
- エッセンスを外す処理の例外後に再試行しても二重減算しない。他方の解除は成功する。
- 振り直し後の解除、解除の重複、HeroSkillの交換、初回適用前の解除。

対象試験13件成功（既存5件＋新規8ケース）。実ゲームDLLへのReleaseビルド成功。Unity実機でのライブリロードと通信は未検証であり、API代替を使った試験と区別する。

最終回帰：全1,611件成功、失敗0、スキップ0。Releaseビルド成功（既存警告2件）。
