## 共通の扱い / Shared rules

- 次の通常攻撃への上乗せは、EchoingDodge・ShadowStep・RunUp・Primedから最大の1つだけを使う。同値のときも1つだけで、残りの予約と本来の期限は保持する。主対象への通常攻撃で消費し、追加ダメージは元の命中・撃破通知が終わった後に与える。 / A primary basic hit consumes only the largest armed bonus. Other bonuses retain their original expiry.
- 条件付きAD/APは、Vigor・Overload・Resonance・UltimateSurge・Devotion・CrystalResonance・LucidBoon・PreyPride・Retaliation・GleamingWard・Medleyを共通の覚醒前120%枠で制限する。発動中の覚醒前合計が120を超えた場合、その割合で実効値を縮める。連携の同調・記憶の余韻はこの装備固有効果の枠に含めない。 / Active conditional gear bonuses share a proportional 120% budget before awakening. Link bonuses retain their separate rules.
- Buildの任意の `u:` セクションに、強化後・覚醒前の条件付き効果量を保持する。省略された値は実効値と同じと扱う。受信した値は実効値と最大覚醒倍率から許される範囲へ制限する。既存の個々のPowerCapsは維持する。 / Optional pre-awakening metadata preserves awakening while retaining existing per-power caps; missing metadata is conservative.
- 条件付きAD/APの11種類すべてをエピック以上に制限する。レアの通常生成に加え、強化の節目と記憶の井戸による再抽選にも同じ判定を使う。 / The rarity restriction also covers enhancement milestones and Memory Well rerolls.
- 通常記憶は装着中のQ/W/E/Rのうち `SkillType.Normal` のもの。IdentityとMovementは含めない。Ultimateは枠名から推測せず、現在の `SkillType.Ultimate` を使う。星座で種類が変化したものもこの読み出しに含む。W/EはAPIと本体の枠解決処理に存在するが、実際のロードアウト画面での確認は未実施。 / Ordinary memories exclude Identity and Movement; Ultimates are identified by their current native type. W/E declarations are verified, but their live loadout availability has not been exercised.
- 残りクールダウンの割合を、本体が受け取る最大クールダウンに対する割合へ換算する。本体の短縮禁止設定を無視しない。口火は使用直前の状態を保存し、本体がクールダウンを設定した後に短縮する。 / Remaining-cooldown reductions are converted to native maximum-cooldown ratios and respect reduction opt-outs.
- 新しい追加ダメージは `GimmickRuntime` マーカーと同期ガードを使う。受信側処理の最後で属性と攻撃効果を除き、追加分から命中・会心・撃破・属性の固有効果を再発動させない。確定ダメージの割合を再利用する薙ぎ・飛沫・過剰分はPureで送り、防御を二度掛けない。 / Added damage is non-elemental, has zero attack-proc strength, and cannot chain. Fractions of already-final damage do not undergo armor twice.
- 新しい回復・障壁は親なしの `serverActor` から与える。送り手の回復・障壁補正は明示的に適用し、受け手の補正は本体へ任せる。分けた障壁を再び分けず、同じ効果の障壁は受け手ごとに大きい方を残して期限を更新する。 / Support uses the root server actor and cannot manufacture native traveler support notifications.
- 位置・敵数・前衛と後衛の順位はホストで判定する。順位は各旅人から最も近い生存敵への距離で決め、同距離なら双方を認める。敵なしでは無効、ソロの前衛は半量、後衛は無効。 / Host distance rankings allow ties and preserve the solo rules.
- Buildの再送で効果の間隔をリセットしない。外した効果の蓄積は破棄し、ゾーン切り替えで移動距離、被ダメージ蓄積、対象・発動参照、未処理の作用を片付ける。 / Resending a build preserves intervals; unequipping removes its accumulated benefit, and zone transitions clear transient references and pending work.

The public ClientEventManager notifications pass through RPCs. Host combat evaluation therefore uses direct Entity events and synchronous Actor methods, keeping the originating damage scope intact.

## 通信と互換性 / Protocol decision

プロトコルを **7から8** に更新した。理由はP34の個人の出来事を知らせる `DreamforgeDreamEventStartedMsg` と、共通120%枠の覚醒前情報を同じ意味で扱う必要があるため。新しい通知はプロトコル、遠征ID、選択世代、正しい出来事IDと送信者の旅人をホストが確認する。同期中の再送を許し、同じ本人・遠征・世代では一度しか作用しない。装備を再送しても使用済み記録は消えない。

Protocol **8** is required for personal dream-event notifications and the shared pre-awakening budget. Existing Power/Gimmick IDs are unchanged; new values are appended. Runtime timers and target references are never persisted. Bonds and gimmicks continue using their existing Build sections.
