# 星図登録の起動性能（Issue #459）

星の内容・保存ID・登録順を維持し、生成された初期化コードのJITと、使われない配置計算・一覧の再構築を減らす。

## 変更

- 9人分の生成星を文字列データ表と共通の型付き読み込み器へ変換する。元と同じコンストラクター・補助関数を呼び、実行時のreflection・動的コンパイル・JSONライブラリは使わない。表と共通リーダーは常にまとめて生成する。
- 同内容の `TargetEffectIds` は共有の `static readonly` 配列へまとめる。登録時の `CopyModifier` は従来どおり配列をコピーする。
- 調整済み配置表が星ID集合・件数に一致し、全星の有限な座標を重複なく持つ場合だけ `PlaceSectors` を省く。検査は座標の適用前に完了させ、不足・不正・不一致なら全体を従来の配置計算へ戻す。
- 従来の表で省略されていた固定星・未移動星の座標を、変更前の最終配置から補完した。今後の `StarMapRender --optimize` も未移動星を含めて出力する。線と取得条件は変えない。
- `NormalizeAuthored` の星一覧検索を事前辞書へ置き換える。先頭一致の選択順と、参照された橋ペアが重複した場合の `SingleOrDefault` 相当の例外を維持する。
- `HeroSigils.All` の一覧を登録指紋でキャッシュする。同じ内容の再登録でも新しい星インスタンスを返すため、登録・解除・移行規則の変更時にキャッシュを無効化する。
- Issueが挙げた未使用のクラス・メソッド・プロパティを、ソース・テスト・ツールの参照を確認して除去した。

## ローカルで実行した比較

| 通常JIT・1回目 | 6491 ms | 3504 ms | 793 ms | 729 ms |

共有ホストの負荷は変動しており、途中の単発計測では通常JITの変更後が変更前より遅い値も出た。この表はビルド後に同条件で交互に測り直した結果で、統計的な性能保証や実機Monoの秒数への換算には使わない。ファイルキャッシュを消しておらず、ここでの冷えた状態は新規プロセスの初回呼び出しを意味する。

- 全9人の生成星ID・順序と、最終配置のノードID・座標・隣接ノード順を出力して完全一致。

既存の登録・移行・配置・指紋テスト83件、効果・生成旅人の登録・既存星維持・到達性テスト115件、MOD起動テスト16件が合格した。生成器の `--all --check` とbalance生成器の `--check`、CoreおよびゲームDLLを参照するMODのReleaseビルドも成功した。新規テストは追加していない。

## PR #471 の差分テスト選択の修正

パイプラインではMODビルド・生成チェック・全体テストは成功したが、`python3 tools/test_changed.py` が2400秒でタイムアウトした。差分選択だけを実行する `--list` も修正前は60秒で打ち切られ、プロファイルでは大半を `select_tests` の正規表現検索が占めた。大量の生成行から抽出した各トークンについて、全テストファイルを繰り返し検索していた。

`tools/test_changed.py` はテストファイルの単語索引を一度作り、型名・メンバー名の参照を索引から取得する。句読点を含む文字列リテラルは、その構成単語を持つファイルに絞ったうえで、従来と同じ部分文字列・単語境界の照合を行い、結果を差分ファイル間で共有する。60%超の全体実行条件と選択条件は維持する。

修正後の実PR差分の `--list` は7.564秒で813クラスを選択した。既存のPythonテスト25件が合格し、CIのslow matrixも一致した。MOD Releaseビルド、全旅人と単一旅人の生成チェック、balance生成チェック、前述の対象.NETテスト214件をこの修正ラウンドでも実行してすべて成功した。既存の比較プログラムを再実行し、登録指紋 `af21595cb500a7df`・内容指紋 `10705-5d36c5dcc3db448c`・件数7605が変更前後で一致し、全星のID順序・座標・隣接順も完全一致した。

差分テストの実行全体とfull/slowスイートは、10分を超えうる検証を実装中に実行しない指示に従って未実行。選択処理のタイムアウト原因は局所検証で解消を確認したが、パイプラインでのコマンド全体の完走は再確認が必要。

## 実機のPlayer.logで比較する手順（未実行）

同じPC・ゲーム版・MOD構成・保存データで、変更前後をそれぞれゲームプロセスの終了後に起動する。タイトル画面まで到達したら、次回起動で上書きされる前に `Player.log` を別名で保管する。数回ずつ比較し、初回のファイル読込と連続起動を区別する。

ログの場所はWindowsでは通常 `%USERPROFILE%\AppData\LocalLow\Lizard Smoothie\Shape of Dreams\Player.log`、Protonでは対応するprefix内の同じLocalLow配下にある。環境によって場所が違う場合は、ゲームが実際に書き込む `Player.log` を使う。

1. 起動開始の時刻と `[DreamforgeRPG] Loaded DreamforgeRPG` の時刻の差を記録する。ログに時刻がない環境では外部時計でゲーム開始からその行までを測る。これはゲーム自体と他MODの読込も含む。
2. 変更後は `[DreamforgeRPG] Generated star maps registered in N ms.` が星図登録だけの経過時間を示す。`Loaded` 行末の `Startup: N ms.` は `Awake` 本体開始からその行までのMOD初期化時間を示す。`Awake` 呼び出し前の型初期化・ゲーム本体・タイトル画面の描画完了は含まない。
3. `Generated star map disabled for ...` や `Startup stopped during ...` があれば、その実行を成功した性能測定に数えず、原因とともに記録する。
4. タイトル画面に到達し、星図が表示できることを確認する。時間だけで成功判定しない。

本作業環境では実機Unity/Mono・タイトル画面・Player.logの実測は未実行。ログ計測と手順を用意した段階であり、実機で短縮したとは判定していない。full/slowスイートも実装ワーカーの実行範囲外のため未実行。欠損配置表や同指紋での再登録だけを狙う独立した実行検証は行っておらず、分岐と既存の対象テストで確認した。
