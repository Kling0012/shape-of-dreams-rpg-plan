# v3.7.0 本体の軽量化

対象は C6、C1、C2。実装を `src/SodRpg.Mod/NativePerfPatches.cs` にまとめた。ゲームの設定画面で次の3項目を個別に切り替えられる。既定はすべて有効。

| 設定 | 対象 |
| --- | --- |
| `nativeStatusDurationSync` | C6：残り時間の通常更新を0.5秒間隔で同期 |
| `nativeWeaponFxScan` | C1：結果に影響しない武器FXの処理を省略 |
| `nativeObstacleAvoidance` | C2：変わっていない回避品質の設定を省略 |

## C6 状態効果の残り時間

`StatusEffect.FrameUpdate` 内の通常の減算だけを差し替えた。本体の0.1秒ごとの計算と端数の精算は保ち、間引く更新はサーバのフィールドへ直接代入する。SyncVarのsetterを呼ぶ間隔は、ゲーム内の時間で0.5秒以上とした。サーバの残り時間、期限判定、粘り強さによる時間補正、セーブと途中参加者への初期値は本体と同じ計算を使う。

開始、SetTimer、ResetTimer、StopTimer、期限切れ、破棄の経路は間引かない。通常の減算でも1回の差が0.5秒以上なら即時にsetterを呼ぶ。間引いたあとに明示的な時間変更があれば、内部値と同じ値でも残り時間のdirty bitだけを立てる。ほかのSyncVarのdirty bitは消さない。ここでの「即時」は本体のsetterをその呼び出し中に通す意味で、実送信は従来のMirrorの送信周期に従う。

通信の型、dirty bit、シリアライザー、受信側の補間は変更していない。古いMODやMODなしの相手も同じ形式で受信できる。C7のfillAmountと、スキルの使用可否・クールダウン・チャージの同期は変更していない。

## C1 武器FXの空リストと走査

本体DLLのILでも、武器FXのリストにレンダラを追加せず、走査中にレンダラを変更していないことを確認した。ただし無効なレンダラを見つけるとreturnし、後続の納刀武器の表示更新を飛ばす。調査報告の「毎フレームの確保」は厳密には非表示へ切り替わるときの確保で、非表示の間は本体も非nullのリストを再利用する。

空リストの確保を共有の空リストに置き換えた。階層走査は、納刀武器のTransformがないときに空のFX一覧を渡して省く。納刀武器がある場合は本体の走査と早期returnを残した。見た目が変わり得るため、全条件での走査省略は見送った。武器の拡縮、表示切り替え、FXレンダラの状態、判定は変更していない。

## C2 回避設定

本体は半径を差が0.01を超えたときだけ設定し、優先度も変化したときだけ設定していた。無条件だった回避品質のsetterだけを、NavMeshAgentの現在値と比較する呼び出しに置き換えた。

半径、agentの有効・無効の切り替え、NavMesh上の判定、優先度の計算は本体のまま。衝突無効、ボス・英雄、行動阻害への耐性、召喚・モンスターの分岐も本体が評価する。前回値のキャッシュを持たず、ほかの処理がagentを変更した場合も現在値から判断する。

## 異常時と二重読み込み

本体の基底更新後の値と分岐を保つため、呼び出し箇所を限定したTranspilerを使った。C6は2か所のsetterのうちMoveTowards直後の1か所、C1は空リストの生成とFX一覧の読み出し、C2は回避品質のsetterの1か所だけを差し替える。

対象やフィールドが見つからない場合は該当クラスを外す。ILの形が違う場合は入力のILをそのまま返し、項目ごとに1回だけ警告する。既存のクラス単位の導入処理により、導入に失敗してもMOD全体は止めない。二重に適用されたTranspilerは、すでに差し替わった箇所を再度変更しない。毎フレームの一覧の確保は追加していない。C6の送信時刻は弱参照の表で効果ごとに保持する。
