# v1.28「記憶の仕掛け」：ルートを記憶の動きに合わせる

利用者の指摘（2026-10-03）：
- 元のルート分けは旅人の記憶やアイデンティティに合わせたはずだが、シナジー感が薄い。
- 多くのルートは能力値を伸ばすだけで、その動きに合わせた仕掛けを用意できていない。プレイヤーは新しい仕掛けを期待するはず。

調べた結果：ルートの星の約3分の1（157個）が「その記憶を装着している間、攻撃力・魔力%（同調）／最大HP%（守り）」で、記憶の動きと関係しない汎用の値だった。

## 1. 新しい連携「記憶の冴え」（`LinkKind.MemoryDamage = 5`、定義は済み）
- その記憶で与えるダメージ +X%。アイデンティティ記憶の受け身で出るダメージ（例：サラマンダーパウダーの4発目の爆発、エキゾチック物質の爆発、群れの心臓の光の爆発）も含む。
- 上限は記憶加速などと同じ考え方（1つ 40、2つ 1.6倍、3つ 2.2倍。覚醒Ⅲまで含めた上限は `Links.EquippedCap`）。
- ルートの「同調」は、ほとんどをこれに置き換える（守りは盾役の記憶だけ残す）。

## 2. 記憶の仕掛け（新しい仕組み）
ルートの星に「仕掛け」を持たせる。仕掛けは、その星のルートの記憶（`RouteMemory`）に反応する。

```csharp
public enum GimmickTrigger { None = 0, OnUse = 1, OnHit = 2, OnKill = 3, OnCrit = 4 }
public enum GimmickEffect
{
    None = 0,
    Element = 1,    // 当てた敵（OnUse は近くの敵）に属性を付ける。Arg: 0 火 1 冷気 2 光 3 闇。Value: 100 ごとに1つ、残りは%の確率でもう1つ
    Burst = 2,      // 当てた敵の周り（OnUse は自分の周り）4m に、攻撃力か魔力の高い方の Value% の追加ダメージ（魔力の方が高ければ魔法）
    Shield = 3,     // 自分に最大HPの Value% の障壁（4秒）
    Heal = 4,       // 自分を最大HPの Value% 回復。Arg=1 なら近くの味方（10m）も
    Recharge = 5,   // その記憶の残りクールダウンを Value% 縮める
    Quicken = 6,    // 4秒間、攻撃速度 +Value%（重ならず時間を延長）
    Empower = 7,    // 4秒間、攻撃力・魔力 +Value%（重ならず時間を延長）
    Expose = 8,     // 当てた敵は4秒間、自分から受けるダメージが Value% 増える（重ならず時間を延長）
    Echo = 9,       // 当てたダメージの Value% を、0.3秒後にもう一度与える
}
public sealed class GimmickDef
{
    public GimmickTrigger Trigger; public GimmickEffect Effect;
    public int Value;       // 1段あたりの値（段を振るほど伸びる。頂点は1段）
    public int Arg;         // 効果の補足（属性の種類、味方も回復するか）
    public float Cooldown;  // 内部の間隔（秒）。0 なら制限なし。OnHit は同じ敵ごとではなく、その星ごと
}
```
- `TalentDef.Gimmick`（`GimmickDef`、なければ null）。説明文は `Gimmicks.Describe(def, memory, ranks)` で自動で作る（「『ハンドキャノン』が当たると、敵に火を1つ付ける（1秒に1回）」のように。上限・間隔を必ず書く）。
- 1つのルートに2つ：**4番目の星**（いまの固有効果の星。3段）と、**頂点**（7番目。1段）。頂点は「記憶の冴え」と仕掛けの両方を持ってよい。
- 回避（移動の枠の記憶）のルートには、回避で発動する仕掛け（OnUse など）は置かない（v1.28 の方針）。移動の記憶のルートは OnHit／OnKill／OnCrit のある記憶だけ、ないものは常時の効果で。
- つり合い：仕掛けの強さの目安
  - Element：1〜2つ（Value 100〜200）、間隔 0.5〜1秒
  - Burst：40〜120%、間隔 1〜3秒
  - Shield／Heal：3〜8%、間隔 3〜8秒
  - Recharge：10〜30%、間隔 0〜5秒
  - Quicken／Empower：8〜20%
  - Expose：8〜15%
  - Echo：15〜40%、間隔 0.5〜2秒

## 3. 記憶の判定（ホスト）
- 与えたダメージがどの記憶から出たかを、本体の型でたどる（`DamageData` の actor → `AbilityInstance` → その発生元の `SkillTrigger` の型名、アイデンティティの受け身も含む）。判定の対応表は調べて文書に残す。
- OnUse：`OnSkillUse` の `info.skill` の型名。OnHit：記憶のダメージが敵に当たったとき。OnKill：記憶のダメージでとどめを刺したとき。OnCrit：記憶のダメージが会心したとき。
- 仕掛けで出たダメージ（Burst・Echo）からは、仕掛けを起こさない（連鎖させない）。

## 5. 方針（利用者の指示、2026-10-03）
**ステータスをただ高く伸ばすのではなく、遊び方を横に広く広げることが重要。**
- 仕掛けは、その記憶の使い方・判断・組み合わせを変えるものを中心にする（倒すとクールダウンが戻る、属性でほかの記憶や四元の共鳴につなぐ、弱らせて仲間や別の記憶の起点にする、残響で手数を変える、仲間を回復・守る）。
- 一時的な能力値の上昇（攻撃力・魔力、攻撃速度）はルート全体の2割以下。
- 「記憶の冴え」（ダメージ+X%）はルートの中で数を減らし、仕掛けの比重を上げる（各ルートで2〜3つ以内）。
- 9種類で表せない仕掛けは、新しい効果として足すことを検討する（本体の仕組みを確かめてから）。

## 6. 方針：今の戦い方の邪魔をしない（利用者の指示、2026-10-03）
**そのキャラをよく調べて考えて、今ある戦闘系統に対して違和感がないようにする。新しく入れたものが邪魔になったらダメ。**
- 仕掛けごとに、その旅人の今の戦い方（アイデンティティ記憶・旅人記憶・固有星座・コミュニティの構成）と食い違わないかを確かめ、設計表に「邪魔にならない理由」を書く。
- してはいけない例：距離を取って戦う旅人（Lacerta・Yubar）に敵を引き寄せる。自分で通常攻撃しない Bismuth に通常攻撃の条件。攻撃速度を攻撃力に変える Husk に攻撃速度の効果（意味が変わる）。HP を捧げる Aurena に HP を高く保つ前提の効果。本体の仕組み（Vesper の4発目、Cetus の氷の血脈のスタックなど）を上書きしたり勝手に動かしたりする。プレイヤーの操作を奪う（勝手に移動・向きを変える）。
- 設計表ができたら、別のレビューで「邪魔になっていないか」を旅人ごとに確かめてから実装に入れる。
- **アイデンティティ記憶は付け替えられる**（利用者の指摘）。上の例の多くはアイデンティティ由来（Husk の一歩一殺、Bismuth のプリズムの視界）なので、旅人ごとに決めつけない。
  - アイデンティティ記憶のルートの仕掛けは、そのアイデンティティを着けているときだけ効く。そのアイデンティティの性質に合わせてよい。
  - 旅人記憶（Q・R・移動）のルートの仕掛けは、その旅人が**遠征の前に選べる**アイデンティティ（自分の2つ）のどちらと組んでも成り立つ（少なくとも害にならない）ようにする。遠征中に拾う共通のアイデンティティは考えない（利用者の指示）。
  - Bismuth はアイデンティティを変えられない（プリズムの視界で固定）。Bismuth のルートはすべて「自分では通常攻撃せず、本が自動で攻撃する」前提でよい。共通のアイデンティティ「華麗なる芸術家」のルートは使われないので外し、Bismuth は6ルートに戻す。
