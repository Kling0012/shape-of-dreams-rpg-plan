# #460 レビュー提案の対応記録

2026-10-18、#623 の改善案台帳にある #460 の提案17件を確認した。

## 読み込み時のアクセス失敗

L3 について、`ReadRoot` は JSON 解析の失敗を読み込み不能として返し、
`Load` は本体を `Quarantine` で写してからバックアップを選ぶ。
本体もバックアップも読めない場合も、本体があれば同じ写しを試みる。
未知の内容を除外して本体を採用する場合は `PreserveBeforeExclusion` を通る。
これらの経路は既に実装されていた。

`ReadRoot` と写しの処理にはアクセス例外の捕捉があったが、
`Load` による存在の再確認と、写し先の名前を選ぶ処理が例外処理の外に残っていた。
今回、次のように変更した。

- `ReadRoot` が確認した存在の有無を `Load` で再利用し、例外処理の外での再確認をなくした。
- 旧データと除外前のデータの写し先を選ぶ処理も、既存の例外処理の中へ移した。
- 旧データの写し先が決まらなかった場合は、作りかけの写しを片付ける処理を呼ばない。
- スロット読み込み中の存在確認の失敗を、読み取り失敗と同じく記録する。
  `CompleteSourceReads` で切替を中断し、失敗した読み込みの後に復旧用の写しや移行保存へ進まない。

失敗時の扱いは従来どおりで、除外前の写しを作れなければ注意を残して読み込みを続ける。
旧データの写しを作れなければ、そのプロフィールの保存を止める。
