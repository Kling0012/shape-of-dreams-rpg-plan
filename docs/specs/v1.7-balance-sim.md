# v1.7 仕様A：バランス用シミュレーター（tools/BalanceSim）

担当：Codex（実装）。数値の決定とレビューは Claude。

## 目的

実際に遊ぶときの手応えを数字で確かめたい。よくある遠征を何百回も模擬し、
「1回の遠征で何がどれだけ手に入り、何回遊ぶとどこまで育つか」を表で出す。
ゲーム本体は使わず、純C#のコア（`src/SodRpg.Core`）の公開APIだけで動かす。

## 作るもの

- `tools/BalanceSim/BalanceSim.csproj`：net8.0 のコンソールアプリ。`src/SodRpg.Core` をプロジェクト参照する。
- `SodRpg.sln` に追加する（既存の試験プロジェクトの設定を壊さない）。
- 実行例：`dotnet run --project tools/BalanceSim -- --runs 20 --players 300 --seed 1`
- 出力はMarkdownの表を標準出力へ。`--out <path>` でファイルにも書く。

## 模擬する内容

1人のプレイヤーが新しいプロフィール（`Profile.CreateNew`）から始めて `--runs` 回遠征する。これを `--players` 人分くり返して平均・中央値・10/90パーセンタイルを出す。

1回の遠征（既定値。すべてコマンド引数で変えられるようにする）：
- ゾーン数 4（`--zones`）。1ゾーンに戦闘部屋 5（`--rooms`）。
- 戦闘部屋1つあたりの撃破：Lesser 10・Normal 8・MiniBoss 0.25（確率で1体）。各ゾーンの最後に Boss 1。
  （本体の部屋構成の実測値ではなく仮定。表の冒頭に仮定として明記する）
- 2ゾーン目以降の入口で確保地点。方針は `--policy`：`secure`（毎回確保）／`delve1`（潜行1まで潜ってから確保）／`greedy`（潜行3まで潜る）。
- 全滅率 `--wipe 0.15`（遠征の途中のランダムなゾーンで全滅。以降の撃破なし）。踏破時は勝利扱いで終える。
- 遠征の合間に「自然な遊び方」をする：空き枠と、より良い遺物（Rarity が上・同じなら ItemLevel が上）を自動で装備し、欠片で装着中の装備を強化できるだけ強化し、保管庫があふれそうなら弱い遺物を分解する。依頼は達成条件をコアのAPIで判定できる範囲で進める（難しければ達成率 `--bounty 0.6` の確率で達成扱いにしてよい）。
- 今日の夢・契約・悪夢化・Limbo は既定で無し（引数でオンにできれば尚よいが必須ではない）。

ルールの呼び出しは必ずコアの `Rules`（`BeginRun`・`OnKill`・確保・`EndRun`・強化・分解など）を通す。コアのコードは変更しない（足りないAPIがあれば変更せずに報告する）。

## 出力する表

1. 遠征1回ごと（1回目, 2回目, … `--runs` 回目）の平均：遺物の数（レア度別）、確保できた数、欠片・調律石の増減、夢のレベル、装着中装備の平均レア度と強化値。
2. 節目に届くまでの遠征回数（中央値・10/90パーセンタイル・届かなかった割合）：初めてのレア、初めてのエピック、初めての伝説（固有品）、初めてのセット完成（同じセット3点を保管庫か装備に持つ）、夢のレベル5/10/20、装着中の装備がすべて+3。
3. 保管庫・鞄が上限に当たった回数。
