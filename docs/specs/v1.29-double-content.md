## 守ること（これまでの指示）
- **能力値を伸ばすより、遊び方を横に広げる**（`dreamforge-breadth-over-stats`）。新しい固有効果・仕掛け・契約・出来事は、判断や組み合わせを変えるものを中心に。単に%を足すだけのものは2割以下。
- **今の戦い方の邪魔をしない**。旅人のキット（`v1.27-traveler-kits.md`、遠征の前に選べる装備の表を含む）を調べ、食い違うものは入れない。アイデンティティ記憶ごとの扱い、回避で発動する効果を星図に置かない方針、属性の上限（闇・光5、火なし、冷気1）も守る。
- **依存する値と発動条件を正しく**（攻撃力・魔力・最大HP、どの行動で発動するか）。重なる効果は上限を必ず書く。説明文は%で書く（「平均○スタック」は使わない）。
- **間隔（何秒に1回）は本当に必要な場合だけ**。記憶の連打は仕様。
- **装備の%は控えめ**（攻撃力%・魔力%はエピック以上、%はアイテムレベルで伸びない）。
- **敵側のつり合い**：プレイヤーの強化に合わせて、敵側（変種・悪夢化）も増やす。夢の圧と重ねて強すぎないか BalanceSim で見る。
- 自然な日本語と英語。人の名前は使わない。テスト用コマンドやドロップ率は公開の文書に書かない。
- 本体の API は型の一覧と逆コンパイル（読むだけ）で確かめ、確かめた場所を残す。実機での確認は未確認と書く。

### 本体APIの確認場所

- 属性付きの撃破：`.ref/dump/EventInfoKill.txt` の `actor` / `victim`、`.ref/dump/EntityStatus.txt:88-91` の `hasCold` / `fireStack` / `lightStack` / `darkStack`。読み取り専用の逆コンパイル `%LOCALAPPDATA%/sod-decomp/Dew.Core/Entity.cs:781-838` で、ホストの死亡通知が破棄より前に呼ばれることを確認した。属性はその時点で採取する。
- 回復：`.ref/dump/Actor.txt` の `ActorEvent_OnDoHeal`、`.ref/dump/EventInfoHeal.txt`。逆コンパイル `Actor.cs:767-801` で実回復 `amount` と余剰 `discardedAmount` の区別、`Actor.cs:2077-2084` で親アクターへの通知を確認した。
- 障壁：`.ref/dump/Actor.txt` の `ActorEvent_OnGiveShield`、`.ref/dump/EventInfoShield.txt`。逆コンパイル `ShieldEffect.cs:43-73` で上限適用後の `finalAmount` と付与後の通知、`Actor.cs:2147-2154` で親アクターへの通知を確認した。
- 記憶：`.ref/dump/Hero.txt` の `ClientHeroEvent_OnSkillUse`、`.ref/dump/EventInfoSkillUse.txt`。逆コンパイル `SkillTrigger.cs:839-875,1511-1515` で使用完了時の枠と記憶の参照を確認した。この経路はクライアントRPCを受けるゲームのホスト向けで、クライアントを持たない専用サーバーでは未対応。
- ゾーン移動：`.ref/dump/ZoneManager.txt` の `ClientEvent_OnZoneLoaded` と、逆コンパイル `EventInfoLoadZone.cs:1-10` の `isTraveling` / `isLoadingFromSave`。
- 連携・仕掛け・夢の圧：既存の `HostAuthority.UpdateLinks`、`GimmickRuntime.Fire`、`HostAuthority.SendPressure` を利用する。成功した判定だけを依頼へ送る。強化・限界突破・覚醒・悪夢と変種の識別は既存のCore操作・ホスト通知から数える。

### 採用しなかった案と確認の範囲

- 無被弾でのエリート撃破：戦闘全体の無被弾履歴を確実に判定できる経路を確認できなかったため、依頼にしていない。
- 一時的な星図ポイント・協力で共有する一時連携・部屋のエリート数の変更：既存の持続状態や適用経路がないため、別の仕組みを仮実装せず、遺物や素材を使う取引を選んだ。星への供物は小さな恒久の星の経験を利用する。
- 契約の解消：本体の呪いの解除まで確実に反映する追加の接続が必要なため、今回の出来事には入れていない。
- 道標の依頼：並行実装中の道標に依存させていない。ゾーンの突破を推測せず、本体が報告する移動を数える。

Coreの全試験とReleaseビルドが成功。独立した実行シナリオでも追加した13の取引を保存から解決し、回復の依頼を保存後に達成して未確保の報酬を受け取る流れを確認した。配置先はゲーム外の一時フォルダ。実機の表示・戦闘・協力プレイは未確認。
