## 1. 星図の枝の新しい並び（決定済み）

同じ枠の候補どうしが隣り合うと同時に装備できない問題は、例外の仕組みではなく、**枝の並びを変えて**解決する。放射状にこの順で隣り合い、最後は最初につながる。「A」「B」は travelers.json の loadout の並び順（v1.27 キット一覧の末尾の表の順）。

- 7ルートの8人：**アイデンティティA → Q-A → R-A → 移動 → アイデンティティB → Q-B → R-B（→ アイデンティティA）**
- Bismuth（6ルート）：**プリズムの視界 → 無垢な魂 → 歪な疾走 → 業火物語 → 勇敢なる心 → 歪な精神（→ プリズムの視界）**

橋（夢の輪）は、隣り合う2本の枝の**4番目の星**（`RouteOrder = 4`、3段の星）の間にある。この並びなら、橋の両側は必ず違う枠どうしなので、両方を同時に装備できる。

| ② | Q-A × R-A | Q×R |

Bismuth の橋：①視界×無垢な魂、②無垢な魂×歪な疾走、③歪な疾走×業火物語、④業火物語×勇敢なる心（QR×QR）、⑤勇敢なる心×歪な精神（QR×QR）、⑥歪な精神×視界。QR×QR の橋（④⑤）は、**その2つを両方装備したときだけ**働く（Bismuth は4つの QR から2つを選ぶので、起きるのは6通りのうち1通り）。無垢な魂が関わる①②は、無垢な魂が Q 枠・R 枠のどちらにあっても成り立つ。

残りの夢の輪（7ルートの旅人は8個目、Bismuth は7・8個目）は6番目の星の間にある外側の橋で、この表の対象外。今のまま夢の輪の能力値として残す（要確認：外側の橋にも合わせ技を置くかは別の判断）。

### 有効条件

1. 橋の星に1段以上。
2. 橋の隣の2つのルート（4番目の星）に、どちらも1段以上。
3. その2つの記憶を**両方とも装備**している。

## 2. 合わせ技の共通の決まり

2つの記憶が「A の動き → B の動き」の順に働く（表の「ルートA」「ルートB」は橋の隣り合う順で、引き金になる方は各行に書いた）。つなぎには、敵に付ける連携印か、自分に開く窓を使う。同じペアの印や窓は、起点の動きが続くと残り時間が更新される。

- **印（連携印）**：片方の記憶が敵に当たったとき、その敵にこのペア専用の印（Expose の一種、4秒）を付ける。橋の1/2/3段で脆さが 2/3/4% になり、印を付ける・更新する時点の段で決まる。印は付けた本人の攻撃だけに働き、ほかのペアや仕掛けの Expose とは**別のID**で持つ。同じ敵への連携印、既存の仕掛け（Gimmicks）、属性反応（Reactions）の Expose が重なっても、脆さは**最大値の1つだけ**を使い、足し合わせない。受け手の効果が出ても印は残り、4秒の期限、敵の撃破、ペアの解除・記憶の装備解除、エリア移動で消える。Mist のプリオリテ本体の「マーク」（周囲のランダムな1体、爆発する）とも別物で、区別のため「**連携印**」と呼ぶ。
- **窓**：当たりが出ない記憶（使用だけで効く）のときは、使った瞬間に自分へ「窓」を開く（能力値は上げない）。**窓の長さは4秒。ただし Ultimate が起点のときは、その Ultimate の持続時間に合わせる**（エルの聖域10秒、カタクリスム12秒、蛇の祝福12秒、不屈の意志12秒など）。
- **段2**：もう片方の命中・会心・撃破が「印のある敵」（または窓の間）に当たったときだけ効果が出る。
- **「印の敵が倒れる」（型B）**：「**記憶B（その行で受け手になる記憶）で倒したときだけ**」を指す。味方・召喚獣・ほかの記憶の撃破は数えない。表では「B で倒した敵のみ」と書く。
- **「1回につき1回」（型C）**：多段に当たる記憶で効果が連発しないよう、**時間の間隔は使わず、「1回の発動（技1回・振り1回・射撃1発・爆発1回）につき1回」まで**にする。1回の発動で何体・何回当たっても、段2は1回だけ。表では「1回につき1回」と書いた行が対象。時間の間隔を残したのは、1回の発動に区切れない継続攻撃（召喚獣の攻撃、基本攻撃）の Nachia ②⑤ だけ。
- **既存の仕掛けと重複させない（型A）**：橋の合わせ技は、その記憶のルートがすでに持つ仕掛けと同じ「引き金＋効果の種類」にしない。重なる場合は、相手の記憶の Recharge、属性の付与（反応・四元へつなぐ）など別の効果に替えた。
- 値の目安は v1.28 に合わせた：Burst 30〜100、Echo 15〜40、Shield・Heal 1〜8、Recharge 10〜30（Ultimate への Recharge は10〜20）、RechargeOther 10〜15。**移動の記憶への Recharge は30〜50%**（クールダウン3〜3.7秒に対して意味のある量にするため）。
- 追加のダメージ（Burst・Echo）は属性なし・連鎖なし（v1.28 の決まり）。仕掛けや合わせ技が生む追加ダメージには Expose の脆さを適用せず、印や窓を付ける・更新する・受け手の効果を出す起点にもならない。回復・障壁は `serverActor` 経由で、Nachia の団結を自動で付けない。属性の付与は既存の `Actor.ApplyElemental` 経由で、スタックを消費しない。
- 表の「効果の指定」の書き方：`① 起点: トリガー → 印/窓 ／ ② 受け手: トリガー[条件] → 効果 値(1/2/3段) Arg CD`。値は橋の星の1・2・3段目の値。
- **回避（移動の枠）を引き金にする効果は置かない。** 移動の記憶が引き金になるのは、**ダメージを出す重装タックル（Vesper）とフロストチャージ（Cetus）の OnHit だけ**（例外。回避そのものは引き金にしない）。ダメージのない移動の記憶は**受け手だけ**：相手の動きで移動の再使用が近づく（Recharge、相手指定）。
- 「アイデンティティ」は遠征の前に選べる2つだけを考える（共通のアイデンティティは考えない）。ペアに入っていないほうのアイデンティティを装備していても、Q・R・移動のペアは成り立つ。

### 新しい仕組みが要る組

- **N0**（有効条件）：全62組が前提。そのうち印・窓の照会が要るのは54組（残り8組は「相手の動き → 移動の再使用」だけ）。
- **N1**（Recharge の対象を相手の記憶に指定）：23組。
- **N3**（基本攻撃の引き金）：2組（Nachia ④⑤）。
- 新要素はどれも小さい：印・窓は既存の Expose の台帳にペアIDを足すだけ、N1 は既存の `ApplyCooldownReductionByRatio` の対象指定、N3 は既存の基本攻撃の通知、「B で倒した」「1回の発動につき1回」は判定の条件。

### 同じ枠が隣り合う橋

新しい並びでは、62橋すべてが違う枠どうしで、同じ枠の隣り合いはない。QR×QR は Bismuth の④⑤だけで、両方装備が条件（6通りのうち1通りで起きる）。

### その他の注意

- ダメージのない移動の記憶（Lacerta、Yubar、Husk、Mist、Nachia、Aurena、Bismuth）は受け手だけ（14組）。移動の記憶が引き金になるのは、重装タックルとフロストチャージの OnHit だけ。回避後の短い窓を許すなら、起点になる組を増やせる。判断は保留。
- 連携印の Expose は2〜4%だけで、ほかのルートの Expose（8〜15%）と別ID。重なっても脆さは最大値の1つだけ（v1.28 の決まり）。
- 外側の橋（8個目。Bismuth は7・8個目）は今のまま夢の輪。
- 並びの変更は `HeroTreeLayout` の枝の並べ方（`RouteId` の初出順）に依存するため、`HeroStarRoutes.cs` の登録順を新しい並びに合わせる必要がある（この文書の範囲外）。
- 検証案（Core の試験）：①2つの記憶を両方装備していない組は起動しない、②橋・隣接星の段が足りないと起動しない、③Burst・Echo の追加ダメージからは印・窓が増えない、④すべての橋が違う枠の組であること、⑤ペアに入っていないほうのアイデンティティを装備しても Q・R・移動のペアが成り立つ、⑥「B で倒した」は味方・召喚獣・ほかの記憶の撃破を数えない、⑦多段命中でも発動1回につき段2は1回。
