## 表記、効果、上限

`D(m,x)` = MemoryDamage(m,+x%)、`H(m,x)` = MemoryHaste(m,+x%)、`B(m,x)` = GimmickBoost(m,+x%)。`P(m,Duration,x)` / `P(m,Radius,x)` は行中で指定した仕掛けIDへのGimmickParamで、本体記憶の持続・半径を変更しない。`G(m;Trigger,Effect,Value,Arg,Cooldown)` は完全なGimmickDefを持つNotable。略号mは上表の型名へ厳密に展開する。数値はすべて1段あたり、記憶ダメージ・効果量は%である。

`T(source;trigger,x)` は `G(source;trigger,Recharge,x,0,0)` に **target=frost-charge** を結ぶNotable。sourceは非移動記憶だけ。`RB(source,x)` は GimmickBoost(frost-charge,+x%) の受信側指定で、そのsourceから届くRechargeのValueだけを強める。source/targetの分離は後述M1であり、標準GimmickDefがすでにこの指定を持つと誤認しない。`Q装備/R装備/ID装備` は上表の実際に装備した1個、`全受信` はその非重複の和集合。未装備の同枠候補を同時に要求しない。

### 15星の記憶星団テンプレート

各ID接頭辞は `cetus.mem.<slug>.c1`～`.c4`。下の接尾辞を付け15個の固有IDを生成する。例えば `cetus.mem.icy-veins.c1.e1`。Nは非移動、Rは受信専用。

|接尾辞|星数|Nの各星の値|Rの各星の値|
|---|---:|---|---|
|e1,e2,e3,e4,e5,e6|6|各B(m,1)、6個で+6%。|それぞれRB(source,1)。6個で受信量+6%。|
|n1,n2|2|記憶表のGを各1個|記憶表のTを各1個|
|choice|1|c1/c2/c3は **D(m,2) または B(m,3)**。c4は **B(m,3) または P(m,Radius,4)→c4のHeal（icy-veinsはn1、他はn2）**。各2択、片方だけ|**T(source;OnKill,4) または T(source;OnUse,1)**、片方だけ|
|s1,s2,s3,s4,s5,s6|6|B(m,1), B(m,1), P(m,指定,4), B(m,1), B(m,1), P(m,指定,4)|それぞれRB(source,1)。6個で受信量+6%。|

追加Dは非移動ルートごとc1/c2/c3のChoice3個だけに抑える。入口Bは当該記憶の既存幹の仕掛けを伸ばすのでNotable未取得でも働く。Pは指定G取得後の衛星にしか置かず、空の予告星にしない。Rの入口は既存幹の同じsourceを含むTを伸ばす。移動にHを置かず、自分の回避使用を受信元とする解釈を排除する。

入口の循環を防ぐため、始まりから各非移動ルートの既存幹.2へ接続を追加する。核のBと置き換えたback-off.1のBは、選んだ記憶の幹.2または.4の仕掛け取得が前提。移動は始まりから既存幹.1/.3へ接続し、受信Bには一致するsourceを持つTの取得を必須とする。追加するのは辺だけで、星数は増やさない。PとBを先に買って後で有効化する経路は設けない。

接続：入口e1→e2→e3→e4→e5→e6の6星からn1/n2へ分岐。n1→s1→s2→s3、n2→s4→s5→s6。choiceはn1/n2の両方が前提。輪形の閉じる線からNotableを飛び越えて取得できない。c1/c2は幹.4、c3/c4は幹.7に接続する。各記憶はちょうど4星団。

## B. 橋の領域

### 発生元の確認結果と追加アダプター

M3a（帯電の放電単位）：`Se_D_ChargedAnguillian.ActiveLogicUpdate` は1回の処理のループ内で1～3個の `Ai_D_ChargedAnguillian_Lightning` を作る。各Lightningの親はSe、Seの親はSt_Dであり、OnEntityの光ダメージまで帰属をたどれる。現行の親StatusEffectだけの判定では複数回の放電を1発動と誤認するため、同メソッドのPrefix/Postfix/Finalizerでスコープを開閉し、例外時も必ず解放して、`ActorEvent_OnAbilityInstanceBeforePrepare` で最初のLightningを見たときだけ放電serialを発行する。同一呼び出しの兄弟Lightningへ同じserial、次の呼び出しで生まれる放電へ別serialを付ける。GimmickActivationはインスタンスの明示serialを親StatusEffectより先に読む。タイマー・帯電数・放電対象数を変更しない。これは読み取り専用で確認した本体生成経路への接続設計であり、実戦試験済みという意味ではない。

M3b（礼儀注入の拳）：`Se_R_FrozenFists.OnCreate` の `DoAttackOverride<At_R_FrozenFists_Attack>` は、攻撃triggerをHeroの子へ登録する。このため `Ai_R_FrozenFists_Attack→At_R_FrozenFists_Attack→Hero` にはSt_Rの親が残らない。`EntityEvent_OnAttackFiredBeforePrepare` で **実際の発射元がAt_R_FrozenFists_Attack、所有者が一致、St_R_FrozenFists装備中** を確かめ、info.instanceへ記憶IDと新しい拳serialを付ける。本設計の拳のOnHit/OnKillは、その実際の主打撃を読む。Se_Rから別途発生する `DoAttackEmpower` の追加ダメージはReactionChain付きなので、現行の一括拒否を解除せず、仕掛けの別発動に数えない。主打撃と追加payloadの二重発動を防ぐ。再発動の `Ai_R_FrozenFists_PunchDash` はR記憶の本体ダメージとして帰属させ、別serialを使うが、ダッシュ開始/終了通知を起点にしない。移動枠の回避を発動元にすることはない。MemoryDamageの補正先も主打撃への明示タグと、帰属が既知のSt_R追加payloadを区別し、同一ダメージへ二重適用しない。

M3c（氷の血脈の爆発）：本体の正確な型は `Ai_D_IcyVeins_Damage`。`Se_D_IcyVeins.EntityEventOnAttackEffectTriggered` がこれを生成し、`ai.chain = obj.chain.New(this)`、スタックを反映した威力と会心フラグを設定してから、本体の盾付与とSeの消費を行う。この正当な本体爆発にもReactionChainが付くため、現行HostAuthorityの非空chain一括拒否では全爆発が落ちる。`ActorEvent_OnAbilityInstanceBeforePrepare` で **このAiの正確な型、親Se_D_IcyVeins→St_D_IcyVeins、所有者** を照合し、新しい爆発serialと捕捉したSeを記録する。このネイティブな第1世代のchainだけを許可し、生成マーカー、Gem、属性反応由来の祖先を除外する。chain一般を許可しない。同一Aiの複数命中は(serial,敵)で扱い、橋とTはserial全体で1回。`Ai_D_IcyVeins_Damage.OnDisable` でタグを消し、プール再使用時には新しいserialを発行する。実際の会心はOnBeforeDispatchDamageが設定するIsCritを読み、MODが再抽選しない。本体の冷血スタック消費、盾、攻撃効果通知は一切変更しない。

M3a/M3b/M3cのタグ台帳は、該当AiのOnDisable・破棄、記憶の装備解除、エリア移動で解除する。プールから再使用するAiは必ず新しいserialにする。Prefixの一時スコープはPostfixだけでなくFinalizerでも閉じ、例外や中断後に別攻撃へ帰属が漏れないようにする。主打撃と追加payloadを識別できない命中を推測でタグ付けしない。
