### 1.3 協力プレイで安全に増やす方法（案）

- **撃破ゴールド**：ホストで各人の `DewPlayer.monsterKillGoldMultiplier` を `+= Δ`／`-= Δ` の加減算にする（本体の星 `Se_Star_I_KillGoldBonus` と同じ形。上書きすると本体の星とぶつかる）。per-player・ホストのみ・SyncVar でないので通信は不要。ゴールドの丸めは本体が人ごとに行う。
- **撃破以外のゴールド全般**：ホストで `DewPlayer.ClientEvent_OnEarnGold` に購読し、増分を `AddGold`（`Earn` でなくイベントを再発火しない側）で上乗せする。再帰しないが、イベントはRPC経由なので**付与とは別フレーム**になりうる（要確認：ホスト自身のオブジェクトでの発火順）。仲間からの贈り物（`isGivenByOtherPlayer`）は `Add*` でイベントが出ないので、倍率の抜け道（受け渡しで水増し）にならない。
- **ダスト**：`Pickup_DreamDust.onGiveDreamDust`（童話の神と同じ手法）が、分解を含むほぼ全部のドロップを覆う。`isGivenByOtherPlayer` の拾いは除外する。MOD自身の取引（`HostAuthority.Trades.cs` の `EarnDreamDust`）は `Pickup` を通らないので別扱い（倍率を掛けるか、掛けないと決めて文書に書く）。分解だけを増やすなら `dismantleDreamDustMultiplier`（SyncVar、ホストで変えるとクライアントに同期される）を加減算する。
- **経済のインフレ**：ダストは確保地点で欠片（メタ通貨）に換わる（100→10）。ダスト獲得を増やす星は欠片の入手量を直接押し上げるため、遠征あたりの上限（またはメタ通貨側の換金上限 `MaxBatchesPerTrade` の維持）を設計に含める。`docs/specs/v1.31-economy-tuning.md` の既存の釣り合いと照合する（要確認：中身は未読）。
- 星の値は整数％でなく端数を許す `GimmickDef.ValuePrecise`（10^-7 %単位）を使う既存機構がある（`Gimmicks.cs`）。新しい `Stat` を追加するなら、`Stat` 列挙の**末尾に追加**し、既存の保存・通信の番号を変えない（`docs/specs/v1.28-passive-tree.md` の `Power.ShadowStep` 実装記録と同じ方針）。`HostAuthority.cs` 1700行付近の `switch` では、「ネイティブ `StatBonus` に入らない能力値」は no-op の群に入れる（`HealPower` など前例）。
- 全体能力値だけの星は星図全体の2割以内（v1.28 方針、現状 32/879 = 3.641%。`v1.31-clusters-husk.md`）。通貨の%増加は能力値の枠に入れるより、条件つき（撃破・ボス・潜行の深さ・確保）の仕掛けにする方針（`v1.32-plan.md`）と整合する。

## 3. 成長型の精髄「神聖なる信仰」（`Gem_L_DivineFaith`）と空殻の相性

### 3.1 精髄の実装（`Dew.Contents` を逆コンパイル）

説明（`raw_essences.txt`）：「この記憶で敵を撃破するたびに信仰スタックを獲得し、最大 75 スタックまで獲得できます。信仰スタック1つにつき、この記憶が与える敵へのダメージ量と味方への回復量が0.4%増加し、自身の最大HPが4増加します。」伝説（Legendary）。

- スタックを増やす唯一の契機：`OnEquipSkill` で `newSkill.TrackKills(gracePeriod = 6f, IncreaseAmp)`。`IncreaseAmp` は `obj.victim is Monster` かつ `currentStack < maxStacks`（`ScalingValue`＝品質で変わる。表示値は75）のとき +1。`StatBonus.maxHealthFlat = maxHealthPerStack × currentStack`（+4/スタック）を更新。`currentStack` は `[SyncVar][SaveVar]`（保存される）。品質が下がると上限に切り詰める。
- `KillTracker`（`Dew.Core/KillTracker.cs`）：対象の `Actor`（＝**はめた記憶**）の `ActorEvent_OnDealDamage` で被弾した敵を記録し、**その敵が6秒以内に死んだら**（だれが倒しても）コールバック。`Actor.InvokeOnDealDamage` は親アクターの連鎖（`parentActor`）をたどって上へ通知するので、記憶の弾・状態効果・召喚獣の与えたダメージも記憶に帰属する。**つまり「その記憶が与えたダメージの対象が、6秒以内に死ぬ」ことが条件**。
- 増幅：`newSkill.dealtDamageProcessor` と `dealtHealProcessor` に `Amplify` を足す。**その記憶（とその子孫）が与えるダメージ・回復だけ**が `currentStack × 0.4%` 増える。
- 上限：75スタックで +30%（その記憶のダメージ・回復）・最大HP +300。
- 同じ型の本体の精髄は `Gem` 基底の `OnEquipSkill` / `OnUnequipSkill` で、はめた `SkillTrigger` 個別に動く。

### 3.2 なぜ空殻のアイデンティティと噛み合わないか（実装からの根拠）

1. **アイデンティティの枠は本体では0**：`Se_Shrine_Chaos_StatBonus.cs` 466行は `SetMaxGemCount(HeroSkillLocation.Identity, currentAddedGemSlotIdentity)`（Q/W/E/R は `3 + added`）。本体にはアイデンティティにはめる基本の枠がなく、混沌の聖堂の効果とMODの星（`Stat.EssenceSlotIdentity`）だけが枠を足す。`Hero_Husk` の既定の枠数そのものは **要確認**（プレハブの値）。
2. **一歩一殺はダメージを出さない**：6秒の追跡は「記憶のダメージ」で始まるため、神聖なる信仰は**スタックが一度も増えず、増幅するダメージもない**（空のソケット）。MODの `native.killing-flow.main` はMOD側の帰属であり、本体の `KillTracker` / `dealtDamageProcessor` には届かない（要確認：基本攻撃の `parentActor` が記憶になるかは未検証だが、`St_D_TheKillingFlow` のコードには基本攻撃との結びつきがない）。

### 3.3 改変の方向性（案、実装前に要確認）

- 本体の精髄（`Gem_L_DivineFaith` の `TrackKills` と `dealtDamageProcessor`）は**はめた記憶のアクター木**でしか動かない。MOD側が `hero.PureDamage(...)` で出すダメージは `hero` が発生元で、**記憶に帰属しない**（`HostAuthority.GimmicksV129.cs` 268行、`HostAuthority.PairCombos.cs` 296行、`HostAuthority.BridgeSuccessEffects.cs` 139行。`v1.31-clusters-outer.md` も「仕掛けのダメージは親を持たない `serverActor` 経由」「ジェム系譜は除外」と規定）。したがって、
  - 案A：アイデンティティの発動（会心化した通常攻撃・突進斬り）を**実際の記憶のダメージ**にする——例：風の傷の突進斬りを移動の記憶のあと1回でなく、会心になる各基本攻撃にも出す。`Ai_D_ScarOfTheWind_DashAtk` に似た子アクターを記憶の下に作る必要があり、`Mirror` のネットワーク型の新設は現実的でない（`v1.24-monster-research.md` 71〜86行）ので、既存の `At_/Ai_` を再利用する形になる（要確認）。
  - 案B：MOD側で、はめた精髄の効果（信仰スタック）を**MODの成長機構として再実装**し、空殻のアイデンティティの発動（移動・会心の準備・命中）を契機にスタックを増やす。本体の `Gem_L_DivineFaith` と二重にならないよう、`Stat.EssenceSlotIdentity` の星を取っていない場合の挙動も決める。
  - 案C：精髄を直接いじらず、アイデンティティを「選べる2択」（星の `Choice` または刻印）にして、「風の傷：移動のあとの斬りが2回／各4発目に出る」「一歩一殺：変換した攻撃力に比例して記憶のダメージを出す」のように、**記憶そのものにダメージを持たせる**。
- 既存の刻印との整合：`husk.key.single-edge`・`husk.key.wind-cut` の `NativeDamage` はMOD側の帰属で、本体の精髄の増幅には届かない。**新しい改変がこれらの刻印や `ShadowStep`（瞬歩の刃）と二重に効かない**ようにする。

### 4.3 ホスト側の状態の寿命（設計に直結）

`HostAuthority.HeroRuntime`（`HostAuthority.cs` 29行〜）は `Hero` をキーにした辞書 `_runtimes` に入る。`PruneAndApplyPending`（1175〜1215行）は、`kv.Key == null || !kv.Key.isActive` のヒーローの `HeroRuntime` を捨て、新しく生まれたヒーローに `_builds`（受信した装備）から `ApplyValidatedBuild` で付け直す。つまり**ヒーローが非アクティブになる（復活・再生成など。起きる条件は要確認）と、`HeroRuntime` の中の状態（`PowerRuntime` のスタックなど）は失われる**。遠征を通して残すスタックは `HeroRuntime` の外（`DewPlayer` またはプレイヤーID単位の別の辞書）に置く必要がある。セッション終了・ホスト切替（`HostAuthority.cs` 905〜925行、1020〜1035行で `_runtimes`・`_builds` を全消去）では消える。遠征の途中での再接続時の扱いは **要確認**。

## 6. コミュニティの知見（リポジトリ内の文書に要約があるもの）

出所：`v1.27-traveler-research.md`（Steam・攻略wiki・note、確度「中」）、`v1.31-clusters-husk.md`、`v1.31-clusters-vesper.md`、`v1.31-clusters-cetus.md`、`v1.31-clusters-outer.md`。**どれも「単一の最強」は確定していない**とされている。

- **空殻（Husk）**：①裂傷の連打（回避→通常攻撃→赤の裂傷、記憶加速・会心）、②滅殺態勢を常用する型、③追加攻撃速度を攻撃力に変換してAD記憶を伸ばす型（一歩一殺）。**守りが薄い**ことが共通の弱点。青型の裂傷で高難度を攻略した報告、APを剣気へ寄せる報告もある（本文は未取得、補助情報）。操作重視と変換重視で意見が割れる。
- **Vesper**：①慈悲で殴って回復し継戦（攻撃速度→最大HP→攻撃力、魔力は不要）、②規律の連打（内蔵のCD短縮で無限スタン）、③洗礼の近接連打、④決意＋魔力型の残酷な太陽。「被弾して戦う盾役」。
- **Cetus**：シールドを保つ冷気型（魔力>記憶加速>防御>HP）、吹雪の連続配置で味方の盾と火力を両立。最終ボスの火力が不足しがち。
- **全体**：回復・障壁を攻撃に結び付ける構成、Nachiaの召喚維持、Bismuthの自動詠唱が強い構成として挙がる（`v1.31-clusters-outer.md`）。
- **プレイヤーが空殻に求めるもの（文書から読める範囲）**：回避・ダッシュ・テレポートからの連鎖（会心の準備、突進斬り）、攻撃速度→攻撃力の変換の維持、ステルス・無敵時間による生存、守りの補い。**アイデンティティの発動を、遠征中に伸びる成長型の精髄につなげたい**という要望は、利用者の指摘（本調査の依頼）が唯一の出所。
- **タンクが求めるもの**：被弾・障壁の維持、味方への障壁・回復、最大HPの成長（Vesperの「丈夫な肌」「驚異的な筋肉」、Cetusの「保護の冷気」）、挑発。

## 7. 設計上の制約（発見したこと）

### 7.1 使えるフック

- 撃破・命中：`Hero.ClientHeroEvent_OnKillOrAssist`、`EntityEvent_OnDeath`、`Actor.TrackKills(grace, callback)`（記憶単位）、`ActorEvent_OnDealDamage`（親連鎖で上へ通知）。

### 7.2 協力プレイで危ない点

- 通貨・スタック・ダメージはすべて**ホストが権威**。`EarnGold`・`AddGold`・`EarnDreamDust`・`AddDreamDust` は `[Server]` で、クライアントからは呼べない。クライアントは星の取得状態（装備の文字列）を送るだけで、ホストが検証して反映する（`_builds`・`ApplyValidatedBuild`・`HostBuildValidation.cs`）。
- 倍率は**プレイヤーごと**（`DewPlayer` 単位）。共有ドロップ（`target == null`）は人数で割って各人に配られる。**贈り物（`isGivenByOtherPlayer`）には倍率を掛けない**（水増しの抜け道を塞ぐ）。
- 増分のイベントは **RPC経由で非同期**（`ClientEvent_OnEarnGold`）。付与した金額と掛けた量の整合は、再帰（`Earn`→イベント→`Earn`）を避けるため `Add*` で上乗せする。
- **ホスト側の状態が遠征をまたいで残らない**（`HeroRuntime` は非アクティブになると捨てられる）。遠征を通して残すスタックは `HeroRuntime` の外（プレイヤー単位）に置く必要がある（4.3）。
- 乱数・確率丸め：本体は `DewMath.RandomRoundToInt`（確率丸め）を使うため、小さな%の効果は期待値で効く。複数人でのゴールドの総量は、人数補正済みの `GetKillGoldAmount` に各人の倍率が掛かる。
- 本体の `SaveVar` は精髄のスタックを保存するが、MODの追加スタックの保存形式は**保存形式を上げない**方針（`v1.32-plan.md`）と整合させる必要がある（遠征中だけの状態にするか、遠征の復帰保存 `RunRecoveryState.cs`・`ProfileCodec.RunRecovery.cs` に入れるか。要確認）。

### 7.3 避けること・守ること

- **ダストはメタ通貨（欠片）に換わる**ので、獲得%の増加は遠征あたりの上限を決める（`MaxDustEarnPerTrade` 等の既存上限と整合）。ゴールドは遠征内で完結するが、商人価格（`MerchantGoldBase`）・本体の価格・夢の圧とのつり合いを BalanceSim で確かめる。
- 本体の星（富の蓄え・童話の神など）と**同じ倍率を二重に掛けない**。加減算（`+=` / `-=`）で本体のスタックと共存させ、解除時に必ず戻す（`Unhook` / `RemoveBonuses`）。
- 能力値だけの星は全体の2割以内。通貨の%は条件つきの仕掛けにする（`v1.32-plan.md` の方針）。
- 一歩一殺に**攻撃速度を増やす効果を置かない**（変換の意味が変わる）。風の傷は**実際の斬りの命中**を条件にし、準備状態を発火条件にしない。回避の記憶で発動する効果は星図に置かない（`ShadowStep` だけが例外、`v1.28-passive-tree.md`）。
- MODが出すダメージ（`hero.PureDamage`）は**記憶に帰属しない**ので、本体の精髄（神聖なる信仰、`Gem_*`）の増幅・追跡の対象にならない。空殻の改変は、記憶そのものにダメージを持たせる（案A・案C）か、MODの成長機構（案B）で完結させる必要がある。
- アイデンティティ記憶は付け替えられる。旅人記憶（Q・R・移動）の星は、その旅人が選べる両方のアイデンティティと組んでも成り立たせる（`v1.28-memory-gimmicks.md` §6）。空殻のアイデンティティ改変の2択は、それぞれ独立に成り立つようにする。
- 新しい `Stat`・`Power`・`GimmickEffect` は列挙の**末尾に追加**し、既存の保存・通信の番号を変えない。星のIDは追加のみ（`v1.32-plan.md`）。星図のポイント上限500を超えない。
- 本体のネットワーク型（`NetworkIdentity` を持つ新規アクターや `StatusEffect`）をMODから新設するのは現実的でない（Mirror の登録・プレハブが要る。`v1.24-monster-research.md`）。既存の型の再利用か、`StatBonus` ・ホストの処理で実現する。
