# v1.11 仕様：遊びの幅を広げる（夢の出来事と偉業）

担当：内容（名前・説明・数値）と画面は Claude、ルールと保存の実装は GPT（OMP 経由）。
利用者の目標（2026-10-02）：「コンテンツと遊戯性をいっぱい増やす」。

v1.10 で量（固有品100など）は増えたので、v1.11 では**遠征中の選択**と**長く遊ぶ目標**を増やす。

1. 確保地点の「夢の出来事」を 4種 → 12種にする（毎回の確保地点で、選ぶ楽しみが増える）。
2. 「偉業」（実績）を新しく 43個 入れる。達成後に記録タブで欠片と調律石の報酬を受け取れ、進み具合も見える。

## 1. 夢の出来事（+8）

`enum DreamEvent` の末尾に足し、`DreamEvents.Name / Describe / CanUse / Roll` と `Rules.UseEvent` に処理を足す。
「未確保」は鞄（`run.Satchel` / `run.SatchelShards` / `run.SatchelTuning`）のこと。

- `EventDropBonus` / `EventLuck` は `RunState` に足し、撃破時のドロップ抽選（ドロップ率と幸運）に加える。保存（ProfileCodec）にも読み書きを足し、古い保存では 0 とする。
- `DreamEvents.Roll`：これまでどおり 50% で出来事が出る。候補は「その時点で使える出来事」すべて（迷い人の灯は遺失物があるときだけ、など）。使えない出来事は候補に入れない。ただし夢の商人はゴールド払いを前提（`goldPaid=true` 相当）に判定し、欠片の所持量では候補から除外しない。
- 名前・説明（上の表の文章）は Claude が書いたもの。Archive の説明は数値を埋めて表示する。

## 2. 偉業（新しい仕組み）

### データ

- `FeatDef { string Id; Txt Name; FeatKind Kind; int Target; int RewardShards; int RewardTuning; }`
- `Profile.Feats`（達成した偉業の id の集合）を追加し、ProfileCodec で保存する（古い保存では空）。
- `Profile.FeatsClaimed`（報酬を受け取り済みの偉業の id の集合）を追加し、ProfileCodec で `featsClaimed` として保存する（古い保存では空）。`Profile.Clone` でも独立した集合にコピーする。
- `ProfileStats` に数を足す：`PactsSworn`（悪夢の契約を結んだ回数）、`EventsUsed`（夢の出来事を使った回数）、`BountiesDone`（依頼を達成した回数）。それぞれ該当する処理で +1 し、保存する。
- 進み具合 `Feats.Progress(Profile p, FeatDef f)` は `FeatKind` ごとに次の値を返す：

| FeatKind | 値 |
| --- | --- |
| Kills | `Stats.Kills` |
| Runs | `Stats.Runs` |
| Victories | `Stats.Victories` |
| Legendaries | `Stats.LegendariesFound` |
| Relics | `Stats.RelicsFound` |
| CodexPct | `Codex` の件数 × 100 ÷（土台の数＋固有品の数）（切り捨て） |
| DepthSecured | `Stats.BestHeatSecured` |
| Nightmares | `Stats.NightmaresSlain` |
| DreamLevel | `DreamLevel` |
| Pacts | `Stats.PactsSworn` |
| Events | `Stats.EventsUsed` |
| Bounties | `Stats.BountiesDone` |
| SetsCompleted | 保管庫（装着中を含む）に同じセットの3部位がそろっているセットの数 |

- `Feats.Check(Profile p)`：未達成の偉業のうち `Progress >= Target` の物を `Profile.Feats` に記録し、`GameEvent`（`EventKind.Info`）を返す。素材は渡さない。文：「偉業「{名前}」を達成！ 記録タブで報酬を受け取れます」 / `Feat "{name}" complete! Claim the reward in the Records tab.`
- `Rules.ClaimFeat(Profile p, string featId)`：達成済みかつ未受け取りなら、報酬の欠片・調律石を**保管庫側の素材**（`p.AddMaterial`）に足し、`Profile.FeatsClaimed` に記録して `GameEvent`（`EventKind.Info`）を返す。遠征中も受け取れる。未知の id・未達成・受け取り済みなら、日本語の理由文を持つ `InvalidOperationException` を投げ、プロフィールは変更しない。文：「偉業「{名前}」の報酬を受け取った：欠片{n}・調律石{m}」 / `Claimed "{name}": {n} shards, {m} tuning`
- `Feats.Unclaimed(Profile p)`：定義済みの偉業のうち、達成済みかつ未受け取りの件数を返す。
- `Check` を呼ぶ場所：撃破の後、確保の後、遠征の終了の後、出来事を使った後、契約を結んだ後、依頼を達成した後、装備の付け替えの後（`Rules` の該当関数の末尾で、返す GameEvent に加える）。

## 画面（Claude が担当）

- 記録タブに「偉業」の欄を足す：達成数（例：12／43）、達成済みは名前と報酬、未達成は名前・条件・進み具合（例：「敵を合計500体倒す 213/500」）。
- 達成時は通知（トースト）に出す。

## 守ること

- 既存の enum の値・保存形式を壊さない（古い保存を読めること）。
- 試験は GPT が書かない（Claude が確認し、必要なら別担当に頼む）。既存の試験は通ること。
- `EventDropBonus` / `EventLuck` は撃破時のドロップにだけ効き、確保・遠征終了で必ず 0 に戻す。
