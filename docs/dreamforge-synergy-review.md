# Dreamforge RPG：全要素のシナジー再評価（v0.1〜v1.0）

2026-10-01 実施。基準は「Shape of Dreams の MOD として、本体の仕組みに乗り、それを強めているか」。本体の事実は逆コンパイル（`Dew.Core`）と `RawData/!ModResources/overrides`、`RawData/ja-JP` で確認した。

## 判定の区分

| 区分 | 意味 |
| --- | --- |
| **残す** | 本体と重ならず、本体の遊びを補っている |
| **作り直す** | 狙いは良いが、本体の同種の仕組みと並走・重複している。本体の仕組みに乗せ替える |
| **統合** | 本体にほぼ同じものがある。MOD独自のものはやめ、本体の値を読んで噛み合わせる |
| **縮小** | 残すが範囲を絞る |

## 本体の主な仕組み（判断の前提）

- **ラン内の成長**：Memory（スキル、Q/W/E/R/特性/回避、レベル）、Essence（品質、合成・分解）、Chaos の祭壇の能力ボーナス、ラン内通貨のゴールドとドリームダスト。
- **恒久の成長**：星座（Destruction／Life／Imagination の3系統＋旅人専用、Stardust で購入）。
- **難しさを選ぶ仕組み**：難易度（Normal／Nightmare／Limbo）と、**Limbo の深度**（Evil の明晰夢 N 個で深度 N。ハンターの広がり、被ダメ、エリート化率、ボス強化が段階的に上がる）。
- **エリート**：`MirageSkinEffect`（見た目と専用の攻撃を持つ。tier 0/1）と `MiniBossEffect`。`GameMod_MirageSkin` が出現後に確率で付ける。
- **呪いと見返り**：Hatred の祭壇で呪い（`CurseStatusEffect`、Mild／Potent／Powerful）を受け、報酬祭壇から報酬。解除はキル数などの依頼。
- **出来事**：イベント部屋、祭壇（Luck・Paradox・Maw of Doom・Mirror of Remorse など）、商人（Jonas・Smoothie）。
- **属性**：火（DoT）、冷気（減速）、光／闇（スタックでその属性ダメージ増、光3重で確定会心）。

## 要素ごとの判定

| 版 | 要素 | 判定 | 理由 | 作り直しの方向（土台にする本体API） |
| --- | --- | --- | --- | --- |
| v0.1 | 遺物（3枠の恒久装備） | **残す**（中身は作り直す） | 本体に「持ち帰る装備」はなく、計画書の柱。ただし汎用の能力値だけでは本体のビルドと噛み合わない | 特性を本体のビルドに効くものへ寄せる：属性増幅（v1.0済）、Memory Haste、4発目の位置（`everyFourAttackStartIndexFlat`）、通常攻撃の射程（`attackRangeFlat/Percentage`）、Essence/Memory に関わる効果。汎用の攻撃力%は上限を下げる |
| v0.1 | 確保と夢の深度 | **作り直す** | 「深度」という言葉が本体の Limbo 深度と衝突し、紛らわしい。代償（防御・最大HPの減少）が本体と無関係な数値いじり | 名前を「**潜行**」に変える。代償を本体の仕組みにする：ハンターの広がり（`hunterSpreadMultiplier`）、エリート化率（MirageSkin）、被ダメ増は本体と同じ表現に。見返りの遺物は維持 |
| v0.1 | 遺失物 | **残す** | 本体にない「失敗しても次に繋がる」仕組み | 回収の場を本体の祭壇（Maw of Doom 等）に寄せる案は将来検討 |
| v0.1 | 夢のレベルと星図（汎用ツリー） | **作り直す** | 本体の星座（恒久の能力ツリー）とほぼ同じ役割で重複。汎用の攻撃力・HP・防御ノードは星座の焼き直し | 汎用ノードを廃止し、**旅人ごとの刻印**へ：各旅人のキットに効くノード（例：Vesper/Lacerta は4発目、Cetus は冷気、Yubar は Memory 使用、空殻はダッシュ後）。夢のレベルは刻印の解放に使う |
| v0.1 | 鍛冶（強化・再調律・分解・製作）と欠片 | **縮小**＋橋渡し | 遺物の育成には必要。ただし欠片はドリームダストと並走する独自通貨 | ラン内のドリームダストを確保地点で欠片に換えられるようにする（`OnSpendDreamDust`／ホスト経由の `SpendDreamDust`）。遺物の分解はラン中ならドリームダストを返す（`PickupManager.DropDreamDust`、星座「分解ボーナス」に乗る） |
| v0.1 | 協力（ホストが反映・各自保存） | **残す** | 本体の協力に沿っている | — |
| v0.2 | 狙い系統（攻勢・守勢・共鳴） | **作り直す** | MOD独自の3系統。本体の星座は Destruction／Life／Imagination の3系統 | 系統を本体の星座系統（**破壊・生命・想像**）に揃える。狙いは「属性」（火・冷気・光・闇）も選べるように |
| v0.2 | 系統セット | **作り直す** | 同上 | 星座系統に揃え、同系統の遺物は、その旅人が装着している同系統の星座と重ねて効く形を検討 |
| v0.2 | 遠征結果パネル | **残す** | 本体の結果画面を補う情報 | — |
| v0.3 | 依頼（撃破数など） | **縮小** | 撃破数・部屋数だけの依頼は本体の行動と無関係 | v1.0 の本体行動の依頼（Chaos・商人・強化・合成・分解・ハンター）を主にし、撃破系は減らす。将来は本体のクエスト表示（`QuestManager`）に載せる |
| v0.4 | 悪夢の契約 | **作り直す** | 本体の呪い（Hatred）と Evil の明晰夢と同じ発想で並走 | 契約の代償を**本体の呪い**（`CurseStatusEffect` を付与）にする。見た目・挙動・解除の依頼が本体のものになる。見返り（遺物・欠片）は MOD 側 |

| v0.6 | 今日の夢 | **残す** | 本体に日替わりはない。属性の固有効果を強めるようにした（v1.0） | 本体の属性・星座系統に寄せた内容へ少しずつ入れ替える |

| v0.7 | 開始深度（深淵の段階） | **統合** | 本体の Limbo が「深度Nから始める」をすでに持っている | MOD独自の開始深度はやめ、本体の Limbo 深度（`GameMod_Limbo.depth`）を読んで、遺物のドロップ率・品質に倍率をかける |
| v0.7 | 雷鎖・爆砕・守護霊・血の渇き | **作り直す** | 汎用の ARPG 効果で、本体のビルドと無関係 | 雷鎖＝光を付与しながら跳ぶ、爆砕＝倒した敵の属性スタックを周囲へ広げる、守護霊＝本体のシールド系と同じ扱い、血の渇き＝ Aurena（HPを犠牲にする）と噛み合う形へ |
| v0.8 | 夢の工房 | **縮小** | 本体の星座（Stardust）と同じ「恒久強化」の層が増える | 鞄・保管庫の容量と依頼の引き直しだけ残す（MOD自身の利便性）。それ以外は刻印・本体の仕組みへ移す |
| v0.9 | 夢の出来事（商人・泉・杯・灯） | **作り直す** | 本体の祭壇・商人・イベント部屋と役割が重なる | 支払いと報酬を本体のラン内通貨（ゴールド・ドリームダスト）にする。本体の祭壇を使ったとき（`Shrine.ClientEvent_OnSuccessfulUse`）に遺物が絡む形へ |
| v0.9 | セット遺物 | **作り直す** | セットの中身が汎用 | セットを旅人・属性のテーマに（例：《灯守》＝光と回復で Nachia/Aurena、《潮鳴り》＝冷気で Cetus） |
| v1.0 | 属性・4発目・Memory・本体行動の依頼 | **残す** | 今回の方針どおり | — |

## 作り直しの順番（v1.1 以降）

1. **v1.1 本体のエリートと Limbo**：悪夢化を本体の MirageSkin に乗せ替える／開始深度をやめて Limbo 深度を読む／「夢の深度」を「潜行」に改名し、代償を本体の仕組みへ。
2. **v1.2 旅人の刻印**：汎用の星図・熟練度の能力%・図鑑ポイントを、旅人ごとのキットに効く刻印へ置き換える（保存の移行を含む）。
3. **v1.3 呪いの契約と系統の統一**：契約の代償を本体の呪いに／系統を破壊・生命・想像へ／セットを旅人・属性テーマへ。
4. **v1.4 経済の橋渡し**：ドリームダスト→欠片、出来事の支払いをゴールドに、工房の縮小。

各段階で、既存の保存データは移行して失わないようにする（廃止した要素の分は欠片で返す）。
